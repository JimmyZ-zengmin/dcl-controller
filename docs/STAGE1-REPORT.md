## 1. 空拍 ISR 成本

```
min / max / last = 79 / 95 / 95 cyc        均值 94.99 cyc
极差 = 16 cyc = 40.0 ns
```

对照 ESP32-S3：

| | ESP32-S3 | STM32H723 |
|---|---|---|
| 空拍骨架 | 49 cyc @240MHz = **204 ns** | 95 cyc @400MHz = **237 ns** |
| 周期数 | 49 | 95（≈1.9×）|
| 绝对时间 | 204 ns | 237 ns（≈1.16×）|

> 周期数翻倍、绝对时间只多 16% —— 这是 M7@400MHz 对 LX7@240MHz 的净效果。
> **但更要紧的是下面这条。**

---

## 2. ★ 发现：flash 常驻 ISR 的成本被「代码布局 / 取指」主导

同一份 ISR（只有清标志 / 翻转 / 计数几行），不同构建给出：

| 构建 | 空拍 ISR | 备注 |
|---|---|---|
| 首版 | **86 cyc**（min=max=86）| 极差 0 |
| 改 `calibrate()` 之后 | **79~95 cyc** | 极差 16 |
| 模式 2（**删掉 10 条统计指令**）| **98 cyc** | ★代码更少反而更慢 |

**结论：加 10 条统计记账指令的成本，低于「对齐 / 取指」造成的波动。**
即 —— flash 常驻代码的 WCET 在 ±10% 量级上不可预测。

⇒ 这直接证明 **阶段 2 把 ISR 搬进 ITCM 是必要的，不是优化**：
ITCM 零等待、无 cache，ISR 成本才回到「真实指令数」，抖动才可预测、可预算。

---

## 3. ★ 拍周期抖动 = 0 个 CPU 周期

```
拍周期（相邻 ISR 入口的 CYCCNT 差）:  min = max = last = 40000 cyc
期望 40000 cyc  (= 100μs @400MHz)
极差 = 0 cyc   →   抖动 < 2.5ns（1 个 CPU 周期）
```

**这比 LA 的分辨率更细**（LA 16MHz 量化 62.5ns）。两者互补：

| 手段 | 分辨率 | 性质 |
|---|---|---|
| 固件 CYCCNT | **2.5ns** | 内部计数，依赖固件自报 |
| LA 外部 | 62.5ns | **独立物理证据** |

两条独立路径指向同一结论：**NVIC 入口延迟恒定，拍是硬的。**

---

## 4. DWT 标定（证明周期计数可信）

| 方法 | 结果 |
|---|---|
| nop×1000（`noinline` + volatile 计数）| 9050 cyc ≈ **9.05 cyc/迭代** —— 合理的小稳定整数 |
| 读对自身开销 | **1 cyc** |
| ★**权威标定** | 拍周期 40000 cyc ÷ LA 实测 100.0000μs = **400.00 MHz** |

最后一行才是硬证据：**内部计数频率被外部仪器独立确认**（比任何 nop 循环都强），
因此第 1、3 节的周期数可以放心使用。

## 5. PA9 线路验证（新增通道 CH1）

固件在 PA9 上每 32 拍翻转一次（模式 3）→ LA 单通道抓 CH1：

```
预期：32 × 100μs = 3200μs 半周期
实测：边沿间隔 3200.0000μs  (众数 92.1%)
      异常项 1/633 (0.158%)
```

→ **CH1 ← PA9 线路可用**。这排掉了以后「UART 不通到底是线的问题还是代码的问题」。

## 6. 途中踩的坑（已记档）

1. **默认 halt 连接会失败**：目标调试态异常时 `pyocd cmd` 报
   `No cores were discovered`；`connect_mode=under-reset` 能恢复。
   读运行态统计必须**单会话**完成（连接 → reset → sleep → 读），
   否则重连会（在语义上）把统计从头开始。
2. **ELF 产物无扩展名**：CMake 目标文件是 `build/dcl_h723`（不是 `.elf`），
   `.bin / .hex / .map` 是同名前缀。
3. **`--gc-sections` 会回收无人读的全局**：`g_isr_mode` 就这么从符号表消失了
   → 「这一版是什么形态」改从源码解析报告。
4. **nop 标定必须 `noinline` + volatile 计数**：否则编译器把不同迭代数的循环
   优化成不同形状 —— 首版 n=1000 得 1602 cyc、n=2000 得 60007 cyc，
   差分算出 58 cyc/迭代这种荒谬值。
