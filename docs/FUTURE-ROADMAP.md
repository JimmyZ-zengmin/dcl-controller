# DCL 确定性控制系统 — 未来升级与研究方向

> 本文档记录从「时序确定性控制」到「空间数据流处理器」的完整演进路径。
> 既是产品开发的时间线，也是底层计算架构的研究路线图。

---

## 0. 核心问题

**我们到底在做什么？**

不是在做更快的PLC。是在探索一个问题：**在通用计算硬件（MCU）上，能否实现接近专用硬件（FPGA/ASIC）的确定性？**

如果可以——那意味着确定性的成本可以大幅降低，工业控制的门槛可以重构。

### 基础原则 (2026-07-14 实验后确定)

- **DMA 搬 GPIO 输出是错觉**: 链路 SHADOW → DMA5 → ODR 太长, IWDG 反复 reset 导致不稳定. ISR 直写 ODR 更短更确定.
- **DMA 搬 ADC → DTCM 是唯一正确保留的 DMA 用法**: 异步外设→内存, CPU 零参与.
- **IWDG 必须 main() 第一行立刻 feed**: 不修改 PR/RLR, 不配置依赖.
- **确定性 = ISR 周期扫描的固定时序**: DMA 搬输出帮不到这个等式.

## 1. 理论根基

### 1.1 确定性的三个层次

| 层次 | 名称 | 实现方式 | 当前状态 |
|------|------|---------|---------|
| L1 | 周期确定性 | 硬件定时器强制时间锚点 | ✅ 已在工程中验证 |
| L2 | 抖动确定性 | DMA搬运 + ITCM执行零等待 | ✅ 7ns抖动已测得 |
| L3 | 计算确定性 | 空间数据流 + 无CPU瓶颈路径 | ⬜ 研究方向 |

**L1+L2 = 产品级确定性（晶振级抖动输出）**
**L3 = 研究级确定性（空间计算架构）**

### 1.2 从"时间换空间"到"真正的空间"

数字电路有两种建模范式：

```
时序模型（Temporal）：
  数据动，计算不动。
  CPU在固定位置，数据被搬运到CPU，算完再搬走。
  → 冯诺依曼瓶颈：取指/解码/总线竞争
  → 确定性靠"足够快地反复执行"来保证

空间模型（Spatial）：
  数据不动，计算动（或者说：数据在流动，计算节点固定）。
  数据沿着预配置的通路流经各个计算节点，每个节点同时处理不同的数据。
  → FPGA / 数据流处理器 / 天然并行
  → 确定性是物理结构内禀的
```

当前系统（Level 0）是**L1+L2 + 时序模型=最聪明的时间换空间方案**。

它用了一个技巧：把"数据不动"变成了"寄存器空间绝对地址固定"——数据虽然在DTCM里没动，但CPU按顺序扫过去算，等价于数据在流经一个固定计算节点。

这个方案的**天花板是CPU频率**。

### 1.3 两种架构的统一框架

最终，我们希望做到：

> **一个编译器，同一个DCL源文件，根据目标硬件能力，生成不同形态的执行产物。**

```
DCL 源文件
    ↓
编译器前端（词法/语法/语义 — 不变）
    ↓
数据流图（DAG）
    ↓
    ├── 目标：L0 时序模式   → 生成 Thumb-2 扫描循环（当前方案）
    ├── 目标：L1 DMA路由模式 → 生成 DMA链配置 + 精简CPU介入点
    ├── 目标：L2 外设互联模式 → 生成 DMA+定时器+比较器的硬连线配置
    └── 目标：FPGA           → 生成 Verilog / 位流
```

**编译器是统一的，执行后端是异构的。**

## 2. 产品路线图（资金流）

### Phase A：晶振级确定性PLC（0-12个月）

**目标产品**：替代中高端PLC的定位，核心卖点是确定性和抖动指标。

产品特性：
- **晶振级抖动**：边沿抖动 < 10ns（测量+认证）
- **高精度脉冲输出**：4路PWM + 4路GPIO同步输出（DMA影子寄存器统一触发）
- **脉冲计数/测量**：高速计数器硬件直连
- **运动轴协同**：2-4轴（先做同源时钟的多轴同步）
- **通讯**：CANopen（已有）+ Modbus RTU（补全）+ 预留EtherCAT接口

**收入模式**：中小批量出货 + 定制运动控制方案。

技术关键：
- 补全PWM占空比的实时同步更新逻辑（当前ACTUATOR_STATUS→TIM1_CCR的DMA映射）
- 多轴插补引擎（CPU做，算法复杂度中等）
- 安全相关：看门狗 + 双冗余校验 + ECC启用（降频必要性确认）

### Phase B：多轴协调运动控制器（12-24个月）

**目标产品**：切入CNC/机器人/半导体设备的多轴控制。

技术方向：
- 编码器输入（正交ABZ）→ DMA计数
- 多轴同步：所有轴共用同一个TIM1定时器作为时间基准，各轴PWM由同一定时器统一刷新
- 前瞻插补：在Phase A的双线性插补基础上，增加S曲线加减速
- 电子齿轮/电子凸轮：用LUT_DATA实现运动表，DMA自动查表输出

### Phase C：从运动控制器到通用确定性平台（24-36个月）

此时应已积累足够的行业know-how和资金，开始**返回研究线**——用产品收入支撑空间计算架构的研究。

## 3. 技术演进路线（研究线）

### Level 0：当前 — 时序扫描架构（已实现）

```
CPU ──(按顺序)──→ 路由0 → 路由1 → ... → 路由N
                                  （每条用DTCM寄存器访问，单周期）
```

里程碑指标：100μs周期，35条路由，7ns抖动。✅

**研究问题**：这个模式的理论极限在哪？

回答：在H723@544MHz下，极限周期 T_min = N × T_route_min。如果平均 T_route ≈ 15周期（DIRECT/SCALE/CMP内联 + 内存访问），则：
- N=10时，T ≈ 2.2μs
- N=35时，T ≈ 7.7μs（但100μs内算完，有充足裕量）
- N=100时，T ≈ 22μs

所以100μs周期可以支持 **~500条简单路由** 或 **~150条含原语调用的路由**。Level 0的设计裕量充足。

### Level 1：DMA数据路由（在Level 0基础上增量）

**核心思路**：CPU做计算，DMA做搬运。数据通路从CPU手中解放出来。

```
当前（CPU搬+CPU算）：
  CPU: [读ADC] [算路由] [写WIRE] [读WIRE] [算路由] [写WIRE] ... 

Level 1（DMA搬 + CPU算 + DMA搬）：
  ISR入口:  DMA已经在上一个周期把ADC数据→定了位置
  CPU:      只需 [算路由0] [算路由1] ...
  ISR出口:  CPU把配置好的DMA描述符提交，DMA自动搬WIRE→执行器
```

核心机制：
- **输入侧**：ADC由TIM1_TRGO硬件触发，DMA搬运到SENSOR_MAP。CPU不需要参与。
- **输出侧**：当前是ISR中CPU直接写WIRE_MAP，然后DMA从SHADOW_GPIO搬到GPIOE_ODR。这已经是半DMA化了。Level 1要做的是**等CPU算完后统一触发全部DMA搬出**，而不是边算边搬。

架构变化：ISR从"搬入+计算+搬出"三件套变成纯"计算"，搬入搬出完全由DMA自主完成。

CPU节省：每个周期约 N×2 次总线事务（原先是CPU取WIRE）变成 DMA硬件总线主控，CPU总线压力降低约30-40%。

**这个改动小（不改架构），收益大（释放CPU裕量），应该是最先做的研究工作。**

### Level 2：外设互联硬路

**核心思路**：某些简单原语不需要CPU介入，用DMA/比较器/FMAC自动完成。

**FMAC（Filter Math Accelerator）** 是STM32H723自带的一个常被忽略的外设。它可以在1周期内完成 IIR/FIR滤波 + FIR卷积。FIR Y[n] = a×X[n] + b×Y[n-1] 正好覆盖：
- LPF（FMAC IIR直接算）
- SCALE（a×x + b，FMAC FIR）
- LUT（FMAC不支持查表，DMA搬）

**开窗比较器（Analog Watchdog / COMP）** 可以设置高/低阈值。**如果比较器输出可以直接联动TIM1的PWM使能（H723支持定时器刹车输入），那么 CMP + CLAMP 可以完全由硬件完成。**

```
纯硬件快路径（Level 2）：
  ADC ──DMA→ 输入缓冲 ──FMAC→(LPF/SCALE)──开窗比较器→ 自动拉低PWM/触发GPIO

  CPU从不介入 → 零周期消耗 → 真正的空间并行
```

CPU慢路径仍然是现在的时序扫描，用来处理PID/COUNTER等状态复杂的原语。

**Level 1 + Level 2 是时序架构和空间架构之间的渐变地带：原语集合被分成两类，"快原语"逐渐脱离CPU获得物理并行度，"慢原语"仍然由CPU处理。编译器负责做这个划分。**

### Level 3：空间数据流编译器

这是最远期的目标。**编译器输出的不再是Thumb-2机器码，而是外设DMA配置描述符的集合。**

```
输入：DCL程序（声明式数据流图）
                ↓
编译器前端：解析 → 构建DAG → 拓扑排序
                ↓
        ┌──────────────────────────────────┐
        │   空间映射器（Spatial Mapper）│
        │   每个节点→物理资源    │
        │   每条边→DMA通道/总线路径 │
        └──────────────────────────────────┘
                ↓
输出：DMA配置树 + 定时器级联图 + 中断触发矩阵
         + CPU只在需要时介入的原子例程
```

这时，**整个系统看起来像一个小型FPGA配置包：**
- 每个DMA流是一个"可编程连线"
- 定时器级联定义了全局时钟树
- FMAC和比较器是"硬核IP"
- CPU是一个"软核处理器"，只在其他资源无法胜任时被调用
- 原语不是"被CPU执行"的函数，而是"被配置在外设上的处理单元"

如果做到这一步，输出二进制的大小不再取决于原语数量（每个原语只是几十字节的配置描述符），而是取决于**数据通路的拓扑复杂度**。这个二进制的大小将接近 FPGA bitstream 的概念——描述的是硬件连接，不是软件指令。

## 4. 研究命题

以下是需要深入回答的学术/工程问题：

### 4.1 空间映射的优化问题

给定一个DAG（有N个节点，E条边），把节点映射到物理资源（DMA通道、FMAC、CPU……），把边映射到总线通路（DMA流、共享内存……），使得：

1. 总延迟最小（关键路径最短）
2. 没有资源冲突（两路DMA不能同时用同一个流）
3. 满足环路约束（任何环路必须至少有一个节点经过一个跨周期寄存器）

这是**NP-hard问题**（可以归约到图着色/调度）。对于N<100的规模，启发式+约束满足足够。

### 4.2 时序-空间混合执行的编译验证

Level 2的混合模式（部分硬路、部分软路）需要编译器证明：**硬路段和软路段之间没有时序违约。**

具体说：如果路由A（CMP，硬路）的结果是路由B（PID，慢路）的输入，那么CMP的比较器输出→DMA→STATE_TABLE→T1→写PID的状态变量，这条路径的延迟必须小于一个CPU周期——否则PID拿到的是旧值。

这是一个**时序约束验证（Timing Constraint Verification）**问题。

### 4.3 环路的数据流正确性证明

拓扑排序保证了前馈路径的正确，但跨周期的反馈环路（PID积分、COUNTER累加）需要编译器证明：**环路经过至少一个STATE_TABLE寄存器（z⁻¹延迟）**。否则要么逻辑错误，要么硬件竞争。

形式化方法：每条边的延迟≥0，任何环路的总延迟必须≥1个周期。如果编译器检测到零延迟环路，报错（类似FPGA的综合器报"combinational loop detected"）。

### 4.4 MCU vs FPGA 的根本差距分析

这个研究问题的最终形态：**在什么工作负载下，MCU方案可以追平FPGA的确定性？在哪一点上，差距是物理上的、不可缩小的？**

这决定了Level 2 Level 3 的实际价值天花板。理论分析 + 实际benchmark。

## 5. 开放设计决策

以下问题没有"显然正确"的答案，需要在实施中验证：

| 决策 | 选项A | 选项B |
|------|-------|-------|
| 降低频率+开ECC vs 保持高频 | 544MHz无ECC（当前）安全裕度紧 | 360MHz开ECC（IEC路径）裕量大 |
| 梯形图编译路径 | LAD→netlist→现有DCL编译器 | LAD直接→原生中间表示 |
| Level 1先做还是Level 2先做 | Level 1更稳妥（增量优化） | Level 2收益更大（FMAC利用） |
| 是否考虑FD-CAN替代CANopen | 完全兼容现有代码 | FD-CAN 8Mbps，需要新物理层 |
| 产品线规划 | 单一硬件平台+软件差异 | 高中低端不同MCU型号 |

## 6. 引用概念索引

以下概念在本路线图中反复出现，值得深入研究：

- **同步数字设计（Synchronous Digital Design）**：系统的理论根基。一切确定性的来源是"时钟边沿之间的组合逻辑路径满足建立/保持时间"。当前系统的100μs周期就是同步设计的全局时钟。
- **静态数据流（Static Dataflow vs Dynamic Dataflow）**：当前路由器更接近静态数据流（拓扑预先确定，无运行时调度），这是确定性的保证。
- **脉动阵列（Systolic Array）**：一种空间计算范式，规则的数据通路网格。如果原语集合精简到8-12个，可以考虑映射到脉动阵列结构。
- **FPGA时序分析（Static Timing Analysis）**：MCU方案如果能用一套类似STA的工具验证确定性，可信度大增。
- **编译器的中间表示（IR）**：设计一套与执行后端无关的IR（比如Petri网的变体），让它能同时后端到时序Thumb码和空间DMA配置。
- **Heterogeneous Computing**：CPU+FMAC+DMA的异构协作，和NPU/GPU编程模型面对的资源分配问题是同构的。

## 7. 终极问题

如果Level 3实现——MCU输出的是空间数据流配置包，CPU只是数据处理的一个节点——**那它和FPGA的区别到底是什么？**

区别可能是：FPGA是物理上的并行（每个LUT同时翻转），MCU方案是时间上的抢占式并行（DMA分时复用总线，宏观上看起来同时，微观上轮流）。这个差距是物理本质的，不可消除。

但反过来想：**如果MCU的频率高到"轮流"足够快，快到并行度的差距只剩一个常数因子，那这个架构就已经成功了。**

FPGA跑100MHz，100个LUT同时翻转 = 10GMOPS。
MCU跑544MHz，1个ALU轮流做100个操作 = 5.44GMOPS。

差大概2倍——**一个常数因子。** 这个数字漂亮到令人兴奋。
