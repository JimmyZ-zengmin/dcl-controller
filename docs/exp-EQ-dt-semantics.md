## §1 判据的形态：**全篇不提 dt**，只问“声明的物理量实现了吗”

| 声明（程序里写下的） | 判据（实测必须是什么） | 观测通道 |
|---|---|---|
| `LPF τ = 2.0 s` | 实测时间常数 = 2.0 s | `ln(1−y)` 对 tick 回归 |
| `PID Ki = 1.0 /s`，`err = 1` | 输出斜率 = 1.0 **秒/秒**（输出就是流逝的秒） | 输出对 tick 回归 |
| `TIMER PT = 3/5/7 s` | 翻转时刻 = 声明秒 | tick 计数 |
| `SEQ 超时 = 2/4/6 s` | 步号翻转时刻 = 声明秒 | tick 计数 |
| `RATE`／`PID` 的 D 项（**÷dt 族**） | 对已知单位阶跃必须报 `1/dt` 的**整数量子** | 强制源 + 锁存梯 |

**为什么判据里不能出现 `dt`**：判据的内容**就是**「dt 必须等于该档的实际扫描周期」。
`dt` 一旦出现在期望值里，把 `dt` 改错就会让期望**跟着错** ⇒ 判据永远 PASS ⇒ **空判据**。
⇒ 期望值只从**结构量**导出（工具从 `src/engine.h` 解析 `TICK_PERIOD_US` 与
`BUCKET_DIV2_PHASES_USED`，`DT_SLOW` 的源码文本只被**打印出来做对照**）：

```
div0: 1  拍 × 100 µs = 0.000100 s
div1: 10 拍 × 100 µs = 0.001000 s
div2: 64 拍 × 100 µs = 0.006400 s      ← 期望 dt2 = 6.4 ms, 不是 10 ms
```

### 1.1 三个档全测，而 **div1 是对照组**
`DT_MID = 0.001f` 本来就是对的（10 拍 × 100 µs）。⇒ 它必须在**任何**构建下都 PASS。
若它跟着 FAIL，说明测到的不是 dt，而是别的东西。**注入档实测：div1 全部 PASS**（见 §4）。

## §2 两处观测通道的设计（本次最费工夫的地方）

### 2.1 时间轴必须用 **ISR 直写**的那个 tick
`OFF_ENG_TICKS (0x3820)` 是**主循环镜像**（`main.c:4948`）。本工具会连续做大块 `0x22` 读，
而那段读**正是在主循环里服务的** ⇒ 镜像可能滞后**整整一个主循环周期**（实测 ~17 ms = 170 拍），
于是“读到的时间”与“读到的 wire 值”不同刻。
⇒ 改用环头里的 `g_tick_count`（`main.c:1488`，**ISR 每拍写**，无滞后），并**顺带**拿到环写计数
做交叉核对：**环写增量 == tick 增量，差 +0**（四轮一致）——这条同时证明“RUN 段 1:1 拍”。

`tick = 100 µs` 本身也**必须实测**，不能当假设：对**上位机墙钟**回归得
**9993.1 / 10000.8 / 10010.1 / 10001.3 Hz**（四轮，容差 ±0.3%）。

### 2.2 ÷dt 族：**轮询抓不到脉冲，必须把瞬态变永久状态**
`RATE`/`PID-D` 只在“源变化后的**那一次**执行”上非零，宽度 = 一个扫描周期（div2 = **6.4 ms**）。
而读一次串口要 **17 ms**（2 字与 18 字都是 ~17 ms ⇒ 这是**固定开销**，不是载荷）——
**观测通道的分辨率低于被测现象的宽度**。第一版还额外在阶跃后 `sleep 15ms`，
实测 **0/200 命中**（快照永远落在脉冲之后）。

解法：用 `HYST` 当**一次性锁存器** —— `prim_hyst` 在 state=1 时靠 `src < value_b` 复位，
取 **`value_b = 0`** ⇒ `src < 0` 恒假 ⇒ **置位后永不复位**。它同时就是比较器
⇒ **一个阈值 = 一条路由**，不需要 CMP 串联。

```
正确 dt ⇒ RATE   div2 峰值 = 1/0.0064 = 156.25
陈旧 dt ⇒                     1/0.01   = 100
  阈值梯 105 / 125 / 145 / 165  ⇒ 正确: 1,1,1,0（区间 (145,165]）; 陈旧: 0,0,0,0
PID-D div2（Kd=0.5）: 78.125 vs 50.0  ⇒ 阈值 55 / 85 ⇒ 正确: 1,0 ; 陈旧: 0,0
```

★ **免竞态**：锁存路由是 **div0**（每拍都跑），而脉冲在 wire 上留 64 拍
⇒ 锁存器必然在其中某一拍看到它。**上位机什么时候读、读多慢都不影响结果。**

★ 两个方向的读数都必须对才算 PASS：只判“超了 145”无法排除“超得多得多”。

### 2.3 两个强制源 —— 因为 `RATE` 与 `PID-D` 对源斜率的要求**相反**
`PID-D = Kd·(err−prev)/dt`，而 `err = sp − src` ⇒ **D 的符号只由 `d(src)/dt` 决定，与 `sp` 无关**。
⇒ 递增源给 `RATE` 正值、却给 D **负值**（−78.125 被 PID 输出的 `[0,100]` 夹成 0）。
第一版只用一个递增源 ⇒ PID-D 恒 0，而症状看起来像“锁存梯没锁上”。
⇒ `wire[30]` 递增给 RATE、`wire[31]` 递减给 PID-D（两者都**无生产者** ⇒ 0x10 的欠采样门不适用）。

## §3 ★ 顺带挖出的**同名缺陷第二现场**：顺序档的 dt（活缺陷，已修）

排查“还有谁在选 dt”时发现 `engine_seq_tick`（`engine.c`）里**另抄了一份 dt 表**：

```c
if      (pd == PERIOD_DIV_IDX_FAST) dt = 0.0001f;
else if (pd == PERIOD_DIV_IDX_MID)  { if (ph1 != ph) continue; dt = 0.001f; }
else if (pd == PERIOD_DIV_IDX_SLOW) { if (ph2 != ph) continue; dt = 0.01f; }   // ← 陈旧的 0.01
```

它**从不引用 `DT_SLOW`** ⇒ 路由档修好之后，同一句错话在顺序档**原封不动地活着**，
而且**没有任何断言看得见它**（`engine.h` 的三条闸门只管路由档那一份）。

### 3.1 实测量化（修复前，`40f24cf1…`，run4）
顺序超时声明 **2 / 4 / 6 s**，与 div0 孪生实例**同拍配对**（两条 wire 在同一次快照里读）：

| 声明 PT | div2 − div0（tick） | 实现率 | 实际触发时刻 |
|---|---|---|---|
| 2 s | **−7167** | 64.2% | **1.284 s** |
| 4 s | **−14340** | 64.2% | **2.566 s** |
| 6 s | **−21506** | 64.2% | **3.849 s** |

对“陈旧 `0.01f`”的独立预言是 `−0.36 × PT × 10000` = **−7200 / −14400 / −21600**
⇒ 三处吻合到 **0.4% / 0.4% / 0.4%**。三轮重复（run2/3/4）给出同样的数。
而部署 ACK、步号单调推进、无任何报错 —— **与路由档当初的缺陷逐字同族**。

### 3.2 修法：**合并成一份语义**，不是“再改一个数字”
```c
if      (pd == PERIOD_DIV_IDX_FAST) dt = DT_FAST;
else if (pd == PERIOD_DIV_IDX_MID)  { if (ph1 != ph) continue; dt = DT_MID;  }
else if (pd == PERIOD_DIV_IDX_SLOW) { if (ph2 != ph) continue; dt = DT_SLOW; }
```
`DT_FAST/DT_MID/DT_SLOW` 由 **(相位数 × 拍长)** 导出、且被编译期断言守着
⇒ “相位模数 / 拍长 / dt”三者在**两个域里都不可能各自漂移**（原来只有路由域受这条保证）。
★ 一个副产物就是证据：现在改 `DT_SLOW` 会**同时**打到两个域（§4 的注入档里顺序档与路由档
一起 FAIL）—— 而在合并之前，改 `DT_SLOW` 对顺序档**毫无影响**。

## §4 故障注入：证明**判据能失败**，而且**只在该失败的地方失败**

把 `DT_SLOW` 临时改回历史值 `0.01f`（`engine.h`，注入后 `git checkout` 还原），
重建 → 烧录（`d4b1ba73…`，`programmed 69632 bytes`）→ 同一套判据：

| 判据 | 修复档（`322f6f27`） | 注入档（`d4b1ba73`） | 陈旧值预言 | 判 |
|---|---|---|---|---|
| LPF **div2** τ_eff | **1.9980 s** | **1.2836 s** | 1.28321 s（−35.8%） | FAIL |
| PID 积分 **div2** | **0.99999 /s** | **1.56237 /s** | 1.5625 /s（+56.2%） | FAIL |
| PID-D **div2** 峰值 | **78.1250** | **50.0000** | 50.0 | FAIL |
| RATE **div2** 锁存梯 | `1,1,1,0` | `0,0,0,0`（峰值 <105） | 100 | FAIL |
| TIMER **div2−div0**（PT=7） | **0** | **−25194** | −25200 | FAIL |
| SEQ **div2−div0**（PT=6） | **0** | **−22248** | −21600 | FAIL |
| LPF **div0 / div1** | 1.9975 / 1.9953 | 2.0081 / 2.0062 | 不受影响 | **PASS** |
| PID 积分 **div0 / div1** | 1.00070 / 0.99994 | 1.00076 / 1.00001 | 不受影响 | **PASS** |

★ 数值也对得上：LPF τ 与 PID 斜率分别命中 1.2836 vs 1.28321、1.56237 vs 1.5625（0.03% / 0.008%）。

## §5 历史影响的定量结论（回答“那个 dt 到底错出了什么后果”）

在 **div2 档**（`PERIOD_DIV_IDX_SLOW`）上，修复前**所有** dt 消费者都偏 56%（同一常量）：

| 语义 | 声明 | 实际 | 实现率 |
|---|---|---|---|
| `LPF` 一阶惯性时间常数 τ | 2.0 s | **1.284 s** | **64.2%** |
| `PID` 积分项（Ki，/s） | 1.0 /s | **1.562 /s** | **156.2%** |
| `PID` 微分项（Kd，s） | Kd | **0.64 × Kd** | **64.0%** |
| `TIMER` 到时（PT，s） | PT | **0.642 × PT** | **64.2%** |
| `SEQ` 步超时（s） | PT | **0.642 × PT** | **64.2%** |

★ **I 与 D 偏在相反方向**（+56% / −64%）：闭环里这不是“整体增益偏了”（那种能靠调参补回来），
而是**积分与微分的时间尺度互相错位** —— 同一个 `dt` 同时出现在分子和分母上。

★ 源码注释当初预估的是“D 项只有预期的 64%”—— **实测 64.0%**，预估正确；
本次补上的是**其余四项**以及它们在**两个域**里的普遍性。

## §6 不判的（**SKIP ≠ PASS**，逐条写明为什么）

| 不判的 | 原因 |
|---|---|
| `RATE`/`PID-D` **div0** | 脉冲宽 = 1 拍 = 100 µs，而锁存器也是 div0 且**同拍内排在 RATE 之后** ⇒ 它读到的永远是 0（**结构性不可测**）。div0 的 dt 由 TIMER/LPF/PID-I 三条覆盖。 |
| `PID-D` **div1** | `Kd/dt = 0.5/0.001 = 500` 会撞 PID 输出的 `[0,100]` 上限 ⇒ 测到的是**钳位值**不是 dt（假 FAIL）。div1 的 ÷dt 由 `RATE div1` 锁存梯覆盖。 |
| TIMER/SEQ 的 div0 **三点拟合斜率** | 翻转检测粒度 = 一个采样周期（实测 ~480 拍），3 点拟合的斜率噪声 ≈0.3%、6 点合并 ≈0.5% —— **与容差同量级 ⇒ 会随机 FAIL**。 |

### 6.1 一处方法学收获：**判据要挑分辨率够的那个观测量**
“绝对秒”最初用翻转时刻拟合 ⇒ 噪声 0.5%（比 ±0.5% 的容差还大，四轮实测
+0.28% / +0.15% / −0.17% / −0.26%）。同一个物理量换个观测方式：
**`PID` 积分输出就是“流逝的秒”**，200 个连续样本上回归 ⇒ **精度 0.01~0.08%**，
高一个数量级。⇒ 绝对秒判据改用 `Q3`；翻转时刻只保留**同拍配对**（免拟合、免偏斜）。

## §7 同名缺陷的**第三、第四个现场**（都在上位机）

### 7.1 `tools/h723_tick_ring.py` 的相位模数写死 100
该工具的 P1 判据（模型预言均值 vs 实测窗口均值）在本次回归中 **FAIL：+106 cyc / 53 个标准误**。
排查后：工具用 `B2P = 100`（**桶表尺寸**）算 `pred_nrun`，而固件选 div2 相位用的是
`BUCKET_DIV2_PHASES_USED`（**64**）⇒ “128 条 div2 路由”被预测成
“36/100 拍跑 0 条、64/100 拍跑 2 条”（均值 **1.28**），真相是**每拍都跑 2 条**（均值 **2.00**）。
⇒ 修：从 `src/engine.h` **解析**相位模数（解析不到就当场退出，**拒绝静默退回 100**），
并用 `lcm(10,64) = 320` 拍作为一个完整周期。修后偏差 **+106 → +15 cyc**。

### 7.2 容差必须包含**模型常数自己的不确定度**
修完结构后仍 FAIL（+7.1 cyc = 6.7 个标准误）：因为判据容差只取 `3×标准误`（= 6.3 cyc），
而窗口均值 256 拍的标准误只有 ~2 cyc ⇒ 判据实际问的是
“**标定常数是不是精确到 2 cyc**”，而不是“模型对不对”。
`c0/c_route` 是 E1 两点法标定的，**自带 ~±12 cyc 的标定散布**（该文件 docstring 记录：
留点检验 +1.6(±11.4) / −0.6(±13.2)）。
⇒ 修：`容差 = max(σ×标准误, 标定不确定度)`（`--tol-cyc`，默认 15）。
★ 判据**仍然能失败**：它抓到过的真实偏差是 **+106 cyc**，是这条容差的 **7 倍**。

## §9 边界与未决

1. **只测了“声明的秒 vs tick”，以及“tick vs 上位机墙钟”各自到 ~0.1%**。
   两段串起来 ≈ 0.1~0.2%；更强的绝对秒溯源需要外部时基（LA/频率计）。
2. `RATE`/`PID-D` 的 **div0** 仍不可直接测（§6），只有“同一常量被 div0 的 TIMER/LPF/PID-I 验证”这一层。
3. 判据覆盖的是**均匀单原语 + 少量固定形状**的程序；混合程序的 dt 语义未单独验证
   （dt 只由档位决定，与 op 无关 —— 这一点由**四个不同原语在同一档上给出同一个 dt** 间接支持）。
4. `--seconds 10.5` 的观测窗决定 TIMER/SEQ 能测到多大的 PT（当前上限 7 s）。
5. 顺序档修复后**未做**“超时 + 阈值条件同时使能”等更复杂路径的回归（只测了纯超时步）。
