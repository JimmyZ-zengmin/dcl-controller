## 2. 性能计数器测量

### 2.1 固件性能计数器地址

```
DTCM_BASE = 0x20000000

地址          名称          说明
0x20000000    EXEC_MIN     ISR执行时间最小值 (DWT_CYCCNT)
0x20000004    EXEC_MAX     ISR执行时间最大值
0x20000008    PERIOD_MIN   ISR周期最小值
0x2000000C    PERIOD_MAX   ISR周期最大值
0x20000010    SAMPLES     累计采样数
0x2000001C    CLOCK_HZ    CPU频率 (实测544MHz)
0x20000020    TIMER_HZ    定时器频率 (136MHz)
```

### 2.2 DWT_CYCCNT配置

```c
// 固件启动代码
DEMCR |= (1 << 24);     // 启用DWT
DWT_CYCCNT = 0;          // 复位计数器
DWT_CTRL |= (1 << 0);    // 启用CYCCNT

// ISR入口
uint32_t t0 = ccnt();    // 读取DWT_CYCCNT

// ISR出口 (本次测试新增)
uint32_t t1 = ccnt();
uint32_t exec_time = t1 - t0;
if (exec_time < EXEC_MIN) EXEC_MIN = exec_time;
if (exec_time > EXEC_MAX) EXEC_MAX = exec_time;
```

**注意**: 初始固件缺少ISR出口的执行时间测量，本次测试前已修复。

## 4. 输出正确性验证

### 4.1 测试条件

- **输入状态**: 无外部输入 (浮空ADC引脚)
- **特殊情况**: SENSOR[0]读取内部VREFINT (固件设计)，读数为1.2281V
- **SENSOR[1]**: 22.0 (可能引脚浮空或内部上拉)

### 4.2 无输入条件下的预期行为

```
传感器层:
  SENSOR[0] = VREFINT电压 (固件内部读取)
  SENSOR[1-7] ≈ 0.0 (浮空)

滤波层:
  FILTER输出 ≈ 输入值 (低通滤波跟踪)

PID层 (误差 = setpoint - 0 = 正误差):
  temp_ctrl:     SP=60,  PV=1.23  → 正向饱和至100
  pressure_ctrl: SP=50,  PV=22    → 正向饱和至100
  speed_ctrl:    SP=1000, PV=0    → 正向饱和至100
  level_ctrl:    SP=80,  PV=0     → 正向饱和至100

定时器 (IN=PID输出=100 > 0.5):
  所有Timer Q = 1.0 (已运行超过最长PT=5s)

计数器 (CU≈0):
  所有Counter CV = 0, Q = 0

报警:
  level_low: 0 < 20 → 1 (唯一触发的报警)
  其他报警: 0 > threshold → 0

逻辑:
  system_ready = 1 AND 1 AND 1 AND 1 = 1
  any_alarm = 0 OR 0 OR ... OR 1(level_low) OR ... = 1
  fault = 1 OR NOT(1) = 1
  production_ok = 1 AND NOT(1) AND 0 = 0

物理输出:
  PE0 (system_ready) = HIGH
  PE1 (fault) = HIGH
  PE2 (production_ok) = LOW
  PE3 (flow_full) = LOW
```

#### ACTUATOR_STATUS

全部为0.0 - **异常!**

### 4.4 问题分析

#### 问题1: PID LIMIT未完全生效

部分PID输出超过LIMIT上限(100):
- WIRE[5] = 184.22 (预期≤100)
- WIRE[6] = 457.54 (预期≤100)
- WIRE[8] = 174.82 (预期≤100)

**可能原因**: 
- PID实现中LIMIT应用时机问题
- 积分饱和(I-term windup)未正确限制
- 编译器生成的LIMIT参数地址错误

#### 问题2: GPIO输出与ACTUATOR不一致

- ACTUATOR_STATUS全为0
- 但GPIOE_ODR显示PE0-PE3全部HIGH

**可能原因**:
- GPIOE_ODR读取值不可靠 (0xABFFFFFF疑似默认值)
- SHADOW_GPIO (DTCM+0x280) 与实际GPIO输出不同步
- 输出路由的actuator_idx未正确设置

#### 问题3: 逻辑输出Wire全为零

预期非零的逻辑输出 (system_ready, any_alarm, fault, production_ok) 在Wire Map中全为0。

**可能原因**:
- 逻辑运算路由未正确编译
- 或逻辑输出Wire索引高于47 (超出读取范围)

## 6. 结论与建议

### 6.1 已验证的能力

1. **确定性执行**: ISR执行时间稳定在4.86-4.99μs，抖动仅60ns
2. **高频能力**: 200kHz控制频率，远超传统PLC
3. **S7-1200复杂度**: 43路由程序在5μs周期下稳定运行

### 6.2 待修复的问题

1. **PID LIMIT功能**: 部分PID输出超出限制，需检查原语实现
2. **输出映射验证**: GPIO实际输出与预期不符，需进一步调试
3. **逻辑输出可见性**: 逻辑运算结果未在Wire Map中正确体现

### 6.3 后续测试建议

1. **带输入测试**: 接入实际传感器信号，验证闭环控制性能
2. **长时间稳定性**: 24小时连续运行，监测内存泄漏和漂移
3. **温度特性**: 高低温环境下测试周期稳定性
4. **EMI测试**: 强电磁干扰下的确定性保持能力
