# E-D 结果：扫描段已从整段 ISR 中夹出（2026-09-18）

> 固件改动：`main.c` 在 `engine_tick()` 调用**前后**各取一次 `tb_cyc()`（那两个读本来就存在），
> 差值写进新 SHM 域 `OFF_SCAN_CYC_*`（`0x3800` 起，`engine.h`）。
> 工具：`tools/exp_ed.py`。

---

## 1. 结果

| 配置 | 扫描段均值 | 整段 ISR 均值 | **拍内其它工作** | 其它占比 |
|---|---|---|---|---|
| PID div0 n=128（`nrun=128`） | 8315.1 TB | 8790.9 TB | **475.9 TB (952 cyc)** | 5.4% |
| DIRECT div0 n=128（`nrun=128`） | 3877.1 TB | 4351.7 TB | **474.6 TB (949 cyc)** | 10.9% |
| PID div1 n=128（`nrun=13`） | 942.3 TB | 1415.7 TB | **473.4 TB (947 cyc)** | **33.4%** |

★★ **"拍内其它工作"三次测量 = 475.9 / 474.6 / 473.4 TB（极差 2.5 TB = 5 cyc）。**

这是一个**新的、干净的常数**：**每拍固定 474 TB = 948 cyc**，
与程序、原语、条数**全都无关**（三组配置的 op/div/n 各不相同，而它不变）。

### 判据

| 判据 | 结果 |
|---|---|
| **D-1** 扫描段 + 其它 ≈ 整段 | ✅ 恒等式成立（定义如此）；关键是"其它"只有 **5.4%~33.4%** |
| **D-3 ★ 反证** STOP 后扫描段拍数冻结 | ✅ **16724 → 16724**（1.2 s 内不涨）⇒ 夹取点确实在引擎门之后 |
| D-4 `nrun` 与扫描段同批读出 | ✅ 同一 `0x22` 突发 |

★ **D-3 是这一步最重要的判据**：它排除了"夹错位置"（夹到一个与引擎无关的量上）。
若 STOP 后拍数仍在涨，说明夹的是别的东西 —— 而那种错**在数值上看不出来**。

## 2. 这一步修好了什么

**§5.47 记的"观测口径不一致"已经被解掉。**

此前所有实验用 `di`（整段 ISR）去对"结构侧算出的引擎成本"—— **两边不是同一个量**。
现在有了 `OFF_SCAN_CYC_*`，结构侧可以直接对**扫描段**。

而"其它 474 TB"的量级说明了这个错有多要紧：
- 对 PID div0（扫描段 8315）它只占 5.4% ⇒ 影响小
- 对 PID div1（扫描段 942）它占 **33.4%** ⇒ **用 `di` 会比出一个 50% 的假偏差**

⇒ **越是"轻"的程序，用 `di` 的偏差越大。** 这正是为什么轻载下拟合会失真。

## 3. 顺带修正一条旧结论

- 此前（§5.47）用黑匣子开关测出 `bb_kick` 每拍净成本 ≈ 0
  （`--bb on/off`：1375.3 vs 1375.5 TB）。
- 现在知道"拍内其它工作"总共 **474 TB**，而其中**不含** `bb_kick` 的贡献。
⇒ **`bb_kick()` 是"便宜"的这一点仍然成立**，但 474 TB 的构成**仍未拆开**
（候选：`adc_poll_kick` / `rtc_latch` / `i2c_sm_tick` / seq / 时基与统计自身）。
**这是一个新的未决项，登记在下面。**

## 5. 一个必须记下的教训：**硬编码的 SHM 地址随构建静默失效**

- 加 E-D 的 SCAN 域后 `g_shm` 从 **`0x20004E80`** 移到 **`0x20004EA0`**（+32 字节，正好是新域大小）。
- 而 `tools/h723_tick_ring.py` 与 `tools/exp_ed.py` 里都写着
  `SHM_SEEN = 0x20004E80`（当年**刻意**硬编码，为了让"自证探针"能放在任何帧之前）。
- 症状：工具读到垃圾（`环写=927865394 / tick=0`）⇒ 报 **"板子不健康 ⇒ 判无效"**。
  **而板上完全正常**：`samples` 在涨、`run=1`、`n_routes=128`。
- ⇒ **这是 §5.42「工具的隐含前提会随固件改变而静默失效」的第二次实证**，
  而且这次伪装成了"板子坏了"—— 正是本项目最警惕的那类误归因。

**修法**：地址一律**问 `0x38` 要**（那正是 `0x38` 的用途）。
代价是"自证探针"不能放在 `0x38` 之前 —— 但那个探针的**历史使命已完成**
（它一次就证明了"板子在发帧之前就已在复位态"），结论已进文档，不必再用硬编码换它。

## 6. 与 E-A/E-B/E-C 的关系

E-A~E-C 用的都是 `di`（整段 ISR）。由本步可知：

```
di = 扫描段 + 474 TB（每拍固定，与程序无关）
```

⇒ **那三组实验的结论需要重新解读**：
- `nrun` 的**斜率**（每路由边际成本）**不受影响** —— 474 TB 是常数，对斜率无贡献
  （两侧相减时约掉）⇒ **E-C 的 `m_op` 全表仍然有效**
- 但**截距**被抬高了 474 TB ⇒ E-A 拟合出的 `C_base ≈ 583 TB`
  其实是 **扫描段自身的常数**，而不是"每拍总线固定开销"。
  **这一点在 E-D 之前是分不清的。**

★ 下一版模型应写成：

```
di(t)      = C_scan + m_op × nrun(t) + C_other
             ↑         ↑                ↑
        扫描段常数   每路由边际      474 TB（已实测，三组一致）
```
