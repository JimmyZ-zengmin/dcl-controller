## 2. ★★ 你举的三个例子 —— 把它们量化

### 2.1 ADC 频率：我们 100Hz vs 运动控制卡 50kHz ⇒ **差 500 倍**

| 项 | 我们（H723 内部 ADC1） | 工业运动控制卡 |
|---|---|---|
| 采样率 | **10ms/轮 = 100Hz** | **50kHz** |
| 架构 | SAR 16bit、**软件触发、单通道轮询** | 通常 **并行采样 + 硬件触发 + 专用前端** |
| 通道 | 3 路（PA0/PA1/PA4） | 8~16 路，多为差分 |
| 前端 | **无**（源阻抗直入引脚） | INA/PGA（**输入阻抗 1MΩ**）+ RC |
| 基准 | VDDA（板载磁珠滤波） | **外部精密基准** + 零点/满量程标定 |

★ **"50kHz" 的真实含义不是"ADC 芯片更快"**，而是**整套采集链不同**：
  多路复用 + 高阻缓冲 + 硬件触发 + DMA 搬运。
★ 100Hz → 50kHz 这 500 倍**靠换 MCU 解决不了**（我们 ADC 单次转换仅 ~70µs，瓶颈在
  **触发方式与搬运路径**，不在 ADC 内核）。要么**外挂专用 ADC**，要么**采集与控制分离**。

### 2.2 通信物理层：外接模块 → 板载芯片

| 现在 | PCB 版应该是 | 备注 |
|---|---|---|
| TTL 转 485 **模块**（杜邦线外接） | **板载收发器**：SP3485 / MAX3485（3.3V） | 隔离型：ADM2483 / ISO3082 |
| 优点：随时换 | 优点：一致性、EMC、成本、可量产 | ★ 我们实测教训：**PA2/PA3 是 3.3V 域，别用 5V 的 MAX485** |

### 2.3 功能安全：单核 ≠ 可认证（**你的判断完全正确**）

| 系列 | 核 | 硬件锁步 | 等级 | 备注 |
|---|---|---|---|---|
| **STM32H7（我们）** | M7 **单核** | ❌ | **SIL-2（部分型号）** | 有 ECC FLASH/SRAM；**需自行补充大量安全论证** |
| **TI TMS570 / Hercules** | Cortex-R5F | ✅ 双核锁步 | **SIL-3 / ASIL-D** | 预认证文档包（FMEDA + 安全手册） |
| Infineon AURIX TC3xx | TriCore ×6 | ✅ 多样化锁步 | SIL-3 / ASIL-D | 300MHz，汽车/工业通吃 |
| NXP S32K3 | Cortex-M7 | ✅ 单/双核锁步 | ASIL-D | 160MHz（单核锁步）/ 240MHz |
| Renesas RX / RH850 | — | ✅ | SIL-3 | 自检库与文档生态最全 |

★ **"输出内容不能纠错，只能事后发现"这句话抓得很准 —— 这是类别差别，不是程度差别：**

| | 我们现在的机制 | 锁步核的机制 |
|---|---|---|
| 原理 | **事后校验**：CRC / 回读比对 / 故障台账 | **实时检测**：指令级双核比较 |
| 响应 | 下一轮、或下次读台账时才发现 | 不一致立即进安全态（**毫秒级**） |
| 盲区 | **"输出已经错了但还没被发现"的那段时间** | 无此盲区 |
| 依赖 | 软件正确性（软件本身错了就一起错） | 硬件冗余（不依赖软件） |

## 3. 选型决策点（需要拍板的分叉）

### 3.1 ★ 目标定位 —— **第一个要回答的问题**，它决定后面全部

| 如果目标是 | 那么 |
|---|---|
| **实验室自用 / 技术验证** | 保持 H723，补模拟前端即可；**完全不碰安全认证** |
| **求职作品** | H723 + 完整外设 + demo/录屏；EtherCAT 是加分项，但**不必真做现场一致性认证** |
| **能卖的产品** | 必须回答：SIL 等级、EtherCAT 一致性测试、EMC（IEC61000-4）、器件寿命（10~15 年）|

★ 这三条路的**硬件投入差 1~2 个数量级**（一块验证板 vs 一块过 EMC 的四层隔离板）。

### 3.2 单核 vs 双核（安全路径）

| 方案 | 做法 | 代价 | 适合 |
|---|---|---|---|
| **A. 换安全 MCU** | TMS570 / S32K3 一步到位 SIL-3 | **整个平台层重做**（引擎、外设、工具链） | 目标就是能卖的产品 |
| **B. 保持 H723 + 降级宣称** | 明确写"具备 SIL-2 能力的器件、需自行论证" | 0 | 实验室 / 作品 |
| **C. ★ 双芯片分工** | **H723 做确定性引擎** + **小安全 MCU 做安全监督**（独立监控 + 独立切断输出） | 加一颗芯片 + 一条 SPI | ★ **保住已有引擎投入，同时补上安全路径** |

★ **方案 C 值得认真评估**：它把"我们最强的东西（确定性引擎）"与"安全要求的独立性"
  解耦 —— 安全监督核只需要做"心跳 + 输出范围 + 独立切断"，**不需要重写引擎**。

### 3.3 EtherCAT 怎么接（已查实的具体型号）

| 方案 | ESC 芯片 | 实测周期时间 | 评价 |
|---|---|---|---|
| H723 + 外挂 ESC（SPI） | **AX58100**（ASIX，ET1100 衍生） | **15~19µs** | ★ 快 4~6×，寄存器直接寻址、HAL 简单；**但西方渠道难买**（主要 AliExpress） |
| H723 + 外挂 ESC（SPI） | LAN9252（Microchip） | 72~280µs | 渠道好；**间接寻址、HAL 复杂**；**不适合 ≥5kHz 控制环** |
| 单芯片 | **XMC4800**（M4 + 内置 ESC）或 AX58200 | — | 省一颗芯片；**但等于换平台** |
| 单芯片 | ET1100（Beckhoff 原版） | — | ≥$20 且需外接 PHY，通常只做"菊花链首站" |

★ **关键设计点**：EtherCAT 周期是 **µs 级**，我们的拍是 **100µs** ⇒
  需要设计 **"DC SYNC0 → 控制拍"** 的同步桥。
★★ **我们的 100µs 硬拍在这里是优势**：它天然就是一个"确定性应用层"，
  不需要在 MCU 上再搞软实时调度 —— **这正是阶段 1 那套架构的复用点。**

### 3.4 掉电保持：**必须换介质**（阶段 1 已给结论）

实测：H7 的**擦除过程一旦被打断**（掉电/复位）⇒ **FLASH 控制器进入异常态**
⇒ 上电卡在 `Reset_Handler` ⇒ **只能靠调试器/编程器恢复**（平台级，非软件缺陷）。
⇒ 产品化应换**外部介质**：I2C FRAM（如 FM24CL64，无擦除窗口、无擦写寿命问题）
   或 EEPROM；PCB 上加一颗即可，接口简单。

## 4. PCB / 硬件设计清单（每条都来自实测教训，不是抄的）

| 项 | 要求 | 依据 |
|---|---|---|
| **模拟输入** | **运放跟随器（低阻输出）+ RC（1kΩ+100nF）** | 实测：源阻抗 2.5kΩ ⇒ σ=17.6 LSB；源阻抗≈0 ⇒ σ=9.6 LSB（**1.8×**） |
| 模拟电源 | 独立 LDO + 磁珠 + 10µF/100nF | 工业标配（TI PLC 参考设计同款结构） |
| ADC 基准 | 外部精密基准（如 REF3033） | 现在完全依赖 VDDA |
| 485 | 板载收发器 + TVS + 共模扼流圈 | 工业标配 |
| 隔离 | 数字隔离器（SPI/UART）+ 隔离 DC/DC | 现场需要；实验室可省 |
| 看门狗时钟 | **独立时钟源**（不用 MCU 时钟） | 安全要求：MCU 死了也要能复位 |
| ★ 引脚冲突表 | **PA4 = DCMI_HSYNC、PA6 = DCMI_PIXCLK**（官方网络名） | 板上有摄像头座，可能挂器件 |
| ★ 已占用 | PB0/PB1（心跳）、PE0~PE15（DO×16）、PC0~3（DI）、PC8~12（SDMMC） | 选脚前必查 |

## 6. 明确**不做**的（避免走回头路）

- ❌ **不再继续 ADC 噪声优化** —— 已结论：缺的是模拟前端，且软件平均已验证有效（√N）
- ❌ **不在当前板上做安全认证** —— 平台（单核无锁步）不支持，投入无意义
- ❌ **不为"好看"换 MCU** —— 换平台要重做引擎，必须有明确收益（如 SIL-3 或内置 ESC）
