# C_scan 分解结果：扫描段只由两项构成（2026-09-18）

> 工具：`tools/exp_cscan_split.py`。方法：**用 `ROUTE_FLAG_ACTIVE` 做差分**。
> 依据（先读代码再定方案，见 §7 的教训）：`engine.c` 扫描体
> ```c
> for (k = 0; k < n; k++) {
>     if (!(r->flags & ROUTE_FLAG_ACTIVE)) continue;   // 未激活: 只走
>     ... 读源 / 取参数 / 取状态 / wire2 / 有限性 / prim_exec / 写回 ...  // 激活: 全走
> }
> ```
> ⇒ 把 ACTIVE 位清掉，**循环照样转 n 次，但不执行任何路由体**。

---

## 1. 测量

| 配置 | 扫描段 | `nrun` | n |
|---|---|---|---|
| **全未激活** n=16 | **62.3 TB** (125 cyc) | 0 | 16 |
| **全未激活** n=64 | **62.3 TB** | 0 | 64 |
| **全未激活** n=128 | **62.3 TB** | 0 | 128 |
| **全未激活** n=128 **div1** | **62.3 TB** | 0 | 128 |
| 全激活 n=128 div0 DIRECT | 3877.1 TB (7754 cyc) | 128 | 128 |
| 全激活 n=128 div0 PID | 8315.1 TB | 128 | 128 |
| 全激活 n=128 div1 DIRECT | 477.9 TB | 13 | 128 |

## 2. ★★ 结果：扫描段 = **一个纯常数 + 每路由体 × 条数**

```
扫描段 = C_loop + Σ(每路由体)
C_loop = 62.3 TB (125 cyc)      ← 与 n 无关, 与 division 无关, 与 op 无关
```

### 判据

| 判据 | 结果 |
|---|---|
| **Z-4** 全未激活 vs n | **n=16/64/128 全为 62.3 TB**（完全相同）⇒ **循环开销与 n 无关** |
| **Z-3** 全未激活 ≪ 全激活 | 62.3 vs 3877.1 ⇒ **ACTIVE 差分有效** |
| **Z-2 ★★ 交叉验证** | 差分得 DIRECT = **29.80 TB/条**；E-C 回归斜率得 **29.51 TB/条** ⇒ **差 1.0%** |

★★ **Z-2 是本次最有价值的一条**：**两条完全独立的方法**（ACTIVE 差分 / 回归斜率）
给出同一个数，**差 1.0%**。

- 差分法：物理上直接（把体去掉再相减），但**不可用于 PID 这类"去掉后仍要跑"的对照**
- 回归法：可以逐原语做（E-C 全表），但**依赖线性假设**

⇒ **两者一致 ⇒ 线性假设在 div0 区成立，且 E-C 的 19 个 `m_op` 可信。**

★ 自洽检查：`62.3 + 29.80×128 = 3876.7` vs 实测 `3877.1` ⇒ **差 0.01%**。

### 3. ★ 一个反直觉但可解释的发现

`C_loop` **不随 n 变化**（n=16 与 n=128 都是 62.3 TB）。

按直觉，128 次迭代至少要 128 × (1 次 `ldrb` + 1 次 `bpl`) ≈ 128~256 cyc。
实测只多出 **0 cyc**。

**解释（可失败，但机理明确）**：M7 是双发射 + 有分支预测，
而 `continue` 那条分支在"全未激活"下是**完全可预测的恒定模式**
⇒ 取指/译码与分支被**完全重叠**掉。

★ 这条与 §5.52（"关键路径最差、内核是吞吐受限"）**互相印证**：
**在这个内核上，"指令条数"不等于"周期数"的程度可以非常极端。**

## 4. 修正：`C_scan` 的准确值是 **62.3 TB**，不是 100 TB

E-E1 用两参数回归得到 `C_scan ≈ 100 TB`（截距）。
本次差分直接测出常数项 = **62.3 TB**。

两者不矛盾：回归的截距 = 常数 + （拟合残差的系统部分），
而**差分给出的是物理常数本身** ⇒ **以 62.3 TB 为准**。

⇒ **模型收敛成两项**：

```
扫描段(nrun) = 62.3 TB + Σ_ops ( m_op × 该 op 本拍条数 )
               (125 cyc)
```

**`m_op` 用 E-C 的 19 个值。这是本轮拿到的最干净的模型。**

## 5. 扫描窗口内还有一项没拆：`engine_force_apply()`

`main.c` 的夹取窗口是 `ta … tz`，其中**除扫描体之外**还包含：

- `engine_force_apply(g_shm)` —— 每拍一次，按 force mask 把 wire 钉成 FORCE_VAL
- 循环建立、`nrun` 计算、以及 `engine_tick`/`engine_scan_itcm` 的调用开销

这些**落在 62.3 TB 里还是落在别处，尚未区分**。

★ **但两者都已在模型里**：62.3 TB 是实测出来的**总常数**，
不管它内部怎么分，用它算总时间都不受影响。
⇒ **拆它的价值仅限于"能不能省"，而不是"能不能算"。**

**可行的下一步（未做）**：部署 **n=0** 跑一拍 —— 若固件接受空程序，
扫描窗口内就**只剩**常数项，可以把 62.3 TB 再分成"调用+force_apply"与"循环建立"。
`mk()` 目前拒绝 n<1，需要先确认固件是否接受 n_routes=0。

⇒ **建议排在"把 `m_op` 变成可推导"之后**（那才是"能算"与"能标定"的分界）。
