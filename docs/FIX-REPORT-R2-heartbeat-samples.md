# 修复报告 R2 — HEARTBEAT / SAMPLES 同址反义

日期: 2026-09-11 · 项目: `9.10 H723newest`
来源: `docs/audit/REVIEW-MIGRATION-FIDELITY.md` **一级 #2**
状态: **已修 + 已上板对照实证 + 已跑全量回归（含 S3 平移套件未退化）**

---

## 0. 一句话

`0x08`（HEARTBEAT）与 `0x18`（TIMING_SAMPLES）两个 SHM 量的语义与范本**正好对调**。
同址反义是**最危险的一类静默读错**：按"心跳看 CPU 存活"写的上位机会把
**"引擎已停机"读成"CPU 死了"**；按"samples 看本次运行段"写的会把停机后的空拍算进统计段。

---

## 1. 事实（两侧源码逐行核对，不是转述）

| | 范本 `esp32-core0` | H723（修复前） |
|---|---|---|
| `0x08` HEARTBEAT | `core0_isr.c:355` 的 `+= 1` 写在 `if (!run) return` **之前** ⇒ **每拍无条件**（停机也翻）。注释原文: "OA14 (P2, 审计): 心跳必须在 run 门外无条件翻 — 停机也翻 (外部可观测 CPU+定时器存活)" | 写在 `gate && RUN` 门**内** ⇒ 停机就冻 |
| `0x18` SAMPLES | `core0_isr.c:358` 的 `+= 1` 写在 `if (!run) return` **之后** ⇒ **仅 RUN 拍**（OA13 "统计只反映本次 RUN 段"） | `g_isr_n++` 在 ISR 尾部**每拍**加 |
| `0x38` 的 samples 取自哪 | `main.c:242` = `OFF_TIMING_SAMPLES` ⇒ **与 0x18 同口径** | `main.c` `put32(r+0, g_isr_n)` ⇒ 与 0x18 同源（但口径错） |

⇒ **两个地址的语义完全对调**，而 `0x38` 的 samples 是它们的第三个去向。

**为什么回归没抓到**：`tools/h723_w1.py` 的 S2/S2b 判据当初**就是照着这个对调后的语义写的**
（"STOP 后 HEARTBEAT 停、samples 仍涨"）—— 判据跟实现一起错，于是两侧自洽、全绿。
这正是本项目反复强调的"**自洽的假验证**"。

---

## 2. 修法（三处，判据跟着契约走而不是反过来）

| # | 文件 | 改动 |
|---|---|---|
| ① | `main.c` ISR | `HEARTBEAT++` **移出门之外**（放在 `g_tick_count++` 之后、任何门之前）⇒ 语义 = 每拍无条件 = CPU+定时器存活 |
| ② | `main.c` ISR | `g_isr_n++` 加**同一个门**（`gate && RUN`）⇒ 语义 = 仅 RUN 拍 = 本次运行段。★ 副作用(正面): STOP 后 samples 冻结, 让 "0x12 STOP 是可失败判据" 更硬 |
| ③ | `engine.h` | `0x08` / `0x18` 的注释改写为 S3 契约, 并写出**三态表**（明确标注与修复前是**对调**的） |
| ④ | `tools/h723_w1.py` | S2 / S2b / S3 / S4 四条判据跟着契约改；两个 helper 的 docstring 同步 |

★ ⑥ 顺带：`engine.h` 里那句"0x38 的 samples = 拍中断数, 它 STOP 后仍增长"是与范本源码**相反**的
声称，是"注释把错误锁死"的标本，已一并订正。

**信息量没有损失**：两个量成对读仍能区分三态，只是标签对调了 ——

```
0x08↑ 0x18↑   → 引擎在跑
0x08↑ 0x18=停 → ISR 在跑但引擎已 STOP（正常停机态）
0x08=停       → ISR 都没了（固件死了/未启动）
```

---

## 3. ★ 能失败的对照

用**修复之前**构建的固件（`HIL_SAFE=0` 那份 `ctrl.hex`，构建时间早于本项）跑**同一套新判据**：

| 判据 | 旧固件 | 修复档 |
|---|---|---|
| **S2** ★STOP 后 samples 冻结（仅 RUN 拍） | **FAIL** `samples 5131→9235` | **PASS** `samples 0→0` |
| **S2b** ★对照: 同时刻 HEARTBEAT 仍在增长 | **FAIL** `HEARTBEAT 0→0` | **PASS** `HEARTBEAT 5102→9207` |
| S3 START 后 samples 恢复增长 | PASS | PASS |
| S4 二次 START 幂等（samples 不回退） | PASS | PASS |
| `h723_w1` 合计 | **26 PASS / 2 FAIL** | **28 PASS / 0 FAIL** |

★ **S2 与 S2b 必须在同一时刻给出相反结论**：只测其中一个的话，即便两者被对调了也看不出来
（这正是修复前那套判据被蒙过去的原因）。两条一起测，"语义不同"才是可失败的证据。
