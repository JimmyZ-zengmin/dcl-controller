# exp-EZ —— 2.3 `EXEC_BUDGET_CYCLES`：运行期预算随拍长缩放（关掉**耦合 #6**）

> 一句话：`engine.h` 的注释自己就写着"取值: 拍长 40000 cyc，取 **80% = 32000**" ——
> **意图本来就是 80%**，只是把算出来的数**手写**进去了。拍长可配（E-U）之后，
> 那个手写数在 200 µs 档上只剩 **40% 拍** ⇒ 运行期"本拍超载"判据被**静默放宽一倍**，
> 而没有任何东西会响。现在它是**派生量**，并且派生关系由**四条断言**守着。

- 工具：`tools/exp_ez_exec_budget_scale.py` —— **8 项判定 / 0 FAIL**
- 改动：`src/engine.h`（**逐位无回归**：100 µs 档派生值仍 = 32000 ⇒ 指纹 `6daa7e65…` 不变）
- 登记处：PLAN 2.3 · **耦合 #6**

---

## ① 缺陷形态（"手写的派生量"）

```c
/* 原样 */
 *   ★ 取值: 拍长 40000 cyc，取 **80% = 32000**（留 8000 cyc = 20µs 余量 …）
#define EXEC_BUDGET_CYCLES   32000u          /* ← 把 80% 算出来的结果写死了 */
```

| 拍长 | 拍内周期数 | 手写 32000 实际占 | 判据含义 |
|---|---|---|---|
| 100 µs | 40000 | **80%** | 与设计意图一致 |
| 200 µs | 80000 | **40%** | ★ 超载判据被放宽一倍，**无人察觉** |

这正是本项目已四次栽过的那一族（`MB_MAX_FRAME` / `NVIC_ISER` 位移 / `USART1 BRR` /
`BUCKET_DIV2_PHASES`）：**"记得一起改"不是机制**。

## ② 处方：派生 + 四条断言

```c
#define EXEC_BUDGET_PCT      80u
#define EXEC_BUDGET_CYCLES   ((CLK_TICK_CYCLES * EXEC_BUDGET_PCT) / 100u)

_Static_assert(EXEC_BUDGET_PCT > 0u && EXEC_BUDGET_PCT < 100u, "…(0,100)…");
_Static_assert(EXEC_BUDGET_CYCLES < CLK_TICK_CYCLES,           "…必须留余量…");
_Static_assert(CLK_TICK_CYCLES != 40000u || EXEC_BUDGET_CYCLES == 32000u,
               "100us 档必须仍是 32000（交付档逐位回归哨兵）");
_Static_assert(EXEC_BUDGET_CYCLES == ((CLK_TICK_CYCLES * EXEC_BUDGET_PCT) / 100u),
               "必须是**派生量** —— 手写常数会在换档时静默放宽判据");
```

★ **第 ④ 条才是承重的那条**。理由（这是本轮唯一一处"想清楚才写对"的地方）：

- 只加 ①②③ 时，**200 µs 档上手写 `32000u` 仍然全部满足**（40% 拍 < 拍长；
  而 ③ 因 `CLK_TICK_CYCLES=80000` 此刻不生效）⇒ **耦合 #6 原样复发，只是没在 100 µs 档暴露**。
- 断言 ④ 直接要求"展开式逐位相等" ⇒ **任何档**上手写数都当场编译失败。
- ③ 保留为**回归哨兵**：100 µs 档派生值必须仍是 32000（防的是"百分比被改"）。

## ③ 判据

| # | 判据 | 凭什么能失败 |
|---|---|---|
| Z1 | 定义是**表达式**（含 `CLK_TICK_CYCLES` + `EXEC_BUDGET_PCT`），且相关断言 ≥ 4 条 | 有人改回手写数 ⇒ 立刻 FAIL |
| Z2 | ★ **编译期预言机**：真编译器编译探针 TU，`-DCLK_TICK_US=100` + 期望 32000 ⇒ 通过；`200` + 期望 64000 ⇒ 通过 | 值不对就编不过 |
| Z3 | 负对照：200 µs + 期望 **32000** ⇒ **必须编译失败** | 证明"它真的随拍长缩放"，而不是我把宏读错了 |
| Z4 | ★ **变异对照**：临时副本里把定义改回手写 `32000u` ⇒ 200 µs 档**必须编不过** | 证明**断言是承重的**，不是装饰 |
| Z4′ | 同一变异体在 100 µs 档**仍然编过** | 说明这个缺陷**只在换档场景暴露** —— 正是它躲过所有单档测试的原因 |
| Z5 | 交付档 hex 指纹 == `6daa7e65…` | 本项**逐位无回归**的产品证据 |

**为什么用"编译器当预言机"**：`EXEC_BUDGET_CYCLES` 只出现在 ISR 的比较里（立即数），
既不进 map 也不进 `.rodata` ⇒ **读 ELF 读不到它**。而探针 TU 里一条
`_Static_assert(EXEC_BUDGET_CYCLES == PROBE_EXPECT)` 让编译器替我们判 —— 秒级、只看两个头文件。
工具链路径从项目自己的 `cmake/arm-none-eabi.cmake` 读出（不写死）。

## ④ 实测

```
Z1  定义 = ((CLK_TICK_CYCLES * EXEC_BUDGET_PCT) / 100u) ；相关断言 = 4 条
Z2  100µs + 期望 32000 ⇒ rc=0 ；200µs + 期望 64000 ⇒ rc=0
Z3  200µs + 期望 32000 ⇒ rc=1（static assertion failed）
Z4  变异体(手写 32000u) + 200µs ⇒ rc=1（被第 ④ 条抓住）；+ 100µs ⇒ rc=0
Z5  hex md5 = 6daa7e65a778ac308267785104426f17（== 基线）
```
另：**200 µs 档整机固件也构建通过**（四条断言在真档下成立）⇒ 200 µs 档 hex 现值
`87a4a5ac79c1fe578beaac4f7796fea2`（**替代** PLAN 里记的旧值 `38e8d180…` —— 2.1/2.2 动过代码）。

## ⑤ 诚实标注

- 本项**没有**改任何运行期行为：100 µs 档下派生值逐位等于 32000，交付档 hex 指纹不变（Z5）。
- 它关掉的是**换档场景**下的静默放宽。今天的板子跑的是 100 µs 档 ⇒ **当前无可观测差异**；
  价值在于"下一次换档时判据跟着走"。
- `EXEC_DEPLOY_BUDGET`（下载期静态门，26000）**没动**：它是"绝对预算"的**设计选择**
  （E-U 已证明交付档下它结构性不触发），与运行期判据不同源、不可互替（P25 口径）。
  若将来也要随拍长缩放，那是**另一个决定**，不在本项。
