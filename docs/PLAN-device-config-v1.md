# PLAN-device-config-v1 —— 把"驱动器属性"从编译期常量搬成装置配置（GAP-13）

> 起因：2026-09-16 现场"电机响但轴不动"定案 = `g_step_ena_pol` 的**隐藏默认值**与实机接线相反，
> 把「使能 / 失能 / 上电安全态」三处同时弄反（`docs/audit/H723-MOTION-QUALITY-AUDIT.md` §16）。
> 用户追问"成熟工业 PLC / 运动控制卡怎么做" ⇒ 工业做法与出处见 `docs/RELEASE-v2.1.0.md` §6.2。
> 本人（用户）指令：**出方案再动手**。本文档是方案，**未动任何代码**。

## 0. 我的判断（先说结论，再说依据）

1. 上一轮说的"三选一"**不是三选一**，是**两件事**：
   - **② 装置配置持久化** —— 回答"**极性从哪来**"；
   - **③ 使能状态机化（指令 ↔ 反馈）** —— 回答"**发出去之后怎么知道成了**"；
   - **① 改默认值**：**不做**（工业界没有"编译期极性"这一层）。
2. ★★★ **但 ② 真正的卡点不是"写一个配置区"，而是"这台板子现在存不下任何配置"。**
   `persist`（内部 flash sector 6/7）这套**早就写好了，而且写法完全正确**：
   A/B 双副本 + 单调 seq + CRC32 + `hdr_sum` + **头最后写**（掉电不丢）+ 「版本不符 ⇒ 忽略」+
   「CRC 不过 ⇒ 忽略」+ 「只持久化组态、上电回 STOP」。
   **它被显式降级了**：`0x43 落盘` 返回 **NAK**，`DCL_PERSIST_SAVE=0`，
   原因是 **擦 128 KB 时拍 ISR 卡死 ≈210.6 ms ⇒ 喂狗停 ⇒ 看门狗复位**，
   于是"保存"实际表现为"**重启机器**"且配置**从未落盘**（`writes` 恒 0）。真因**未定案**（已排除 5 条静态假设）。
3. ⇒ 所以方案必须**分段**：
   - **P0 = 让"未配置"成为一种真实状态 + fail-closed + 使能反馈** —— **不依赖任何持久化机制**，当天可上，
     而且**单凭 P0 就消灭了本次事故的根因类别**（"未配置 ⇒ 猜一个值 ⇒ 静默跑错"）。
   - **P1 = 装置配置区 + 落盘** —— 前置是解掉上面那个**独立的**已存在缺口。
4. ★★ **载体必须选内部 flash，不能选 SD**：SD 是**可插拔介质** ⇒ **拔卡/换张空卡 ⇒ 机器丢失配置**，
   与"这是**机器**的属性"语义直接矛盾。工业界把装置参数放**控制器/驱动器的非易失参数区**，不是可插拔卡。
   （对照：绑定表跟着**程序包**走是已定决策 GAP-11，那是"**任务级**"描述，两回事 —— 见 §4。）

## 2. P0 —— "不再猜"（**不依赖持久化，可独立交付**）

> ### ✅ **已落地（2026-09-17）** —— a/b/c/d/e/f 六项全部完成，实机 A/B 见
> > `docs/audit/H723-MOTION-QUALITY-AUDIT.md` **§17**。
> > 交付档 `DCL_STEP_ENA_POL=1` / `DCL_STEP_STOP_HOLD=1`（**写死在 `build.sh` 的 DEFAULTS 里**）；
> > 对照档 `-DDCL_STEP_ENA_POL=-1` ⇒ fail-closed 8/8 PASS；交付档 ⇒ 4 PASS / **3 SKIP**（覆盖不到 ≠ 通过）。
> > ★ **未收口的一件事**：核心改动 ⇒ 必须走 **12 套回归**，而本轮回归因 **SD 卡未被识别**
> > （`g_sd_part_ok=0`）导致 **bench 态建不起来** ⇒ 判**无效**。SD 可用后需重跑一次（§17.7）。

### 2.1 为什么先做这个

"**未配置**"这个状态**今天根本不存在** —— 编译期就给了 `0`。
⇒ 于是"接线与默认值相反"只能表现为"**看起来接受了，其实跑错**"（无报错、只有值是错的）。
**这是本次事故最本质的一条**，也是工业界用 fail-closed 专门堵住的那条。

### 2.2 做法（6 条）

| # | 改什么 | 要点 |
|---|---|---|
| **a** | **`DCL_STEP_ENA_POL` 变成显式编译期配置项** | 三态：`-1`=**未配置** / `0` / `1`。进 `build.sh` 的**配置清单**（像 `DCL_DO_LATCH`、`DCL_PERSIST_SAVE` 那样被打印出来）⇒ "猜"变成"**出厂声明**"，而且是**可见**的声明。 |
| **b** | ★★★ **fail-closed** | 未配置 ⇒ `ena(1)` 返回**专用拒绝码**（新码，如 `STEP_RC_ENAPOL_UNSET`），且 `PE9` 保持**物理失能**。**"未配置"必须导致"不可用"，不是"用某个值"。** |
| **c** | ★★★ **把"极性"与"上电态"解耦** | 现在 `step_init()` 无条件把 PE8..PE11 驱成"高"，注释叫它"**上电安全态**" —— 而在本接线下"高"= 光耦不导通 = **物理使能**（于是上电即通电、电机嗡嗡响）。**但不能简单改成"上电断电"** —— 见下面这条。 |
| **d** | ★★★ **新增 `stop_hold_torque`（按轴）** | **"上电/停止后该不该保持力矩"是按轴决定的**：**垂直轴去使能 = 掉力滑车**，工业做法是"保持力矩 + 无脉冲"配抱闸；水平轴则希望断电省热。<br>⇒ **上电态与停止态 = `stop_hold_torque` 决定（保力矩 ⇒ 通电）**；**极性只决定"怎么通电"，两者正交**。<br>★ 这一条纠正我上一轮的说法（我上一轮写"上电态应改成物理失能" —— **那是错的**：它会把垂直轴变得**更危险**）。 |
| **e** | ★★ **使能状态机化（指令 ↔ 反馈）** | ① `ena(1)` 后**回读断言**（对齐 `MC_Power`「等 Statusword 到位」）；② 新增「**指令 vs `PE9` 实读不一致**」的**计数 + 标志**（Radonix 的做法：Ready 异常 ⇒ 报卡 + 停轴）。<br>★ 我们**已经具备观测面**：`0x39 op=19` 同时给出 `ena`(逻辑，+8) 与 `PE9`(引脚实读，+80)。**缺的只是判据用它。** |
| **f** | **修两处"撒谎的注释"** | ① `src/step.h` 顶部接线注释仍写"三个正端并到板 **+5V**"——实为 **3.3 V**（§8.7 的修法，且 `0x4A` 设备表已标 TB6600 **rev2**）。② `src/step.h` 与 `step_init()` 的"**上电安全态**"注释**与电气后果相反**（见 c）。<br>★ 本项目最贵的一类教训就是"注释里的自洽假验证"。 |

### 2.3 验收（**每条都能失败**）

| # | 判据 | 怎么让它失败（对照组）|
|---|---|---|
| **J1** | 未配置 ⇒ `ena(1)` **必拒** + `PE9` = 物理失能 | 反向：配置成 0/1 后 `ena(1)` **必须能进** |
| **J2** | `stop_hold_torque=1` ⇒ 停止/上电后 `PE9` = **导通**（保力矩）；`=0` ⇒ 不导通 | 两档互相对照（任一档若不成立即红）|
| **J3** | ★ `step_init()` 后**两种极性下**都满足 J2 | **这条今天必红**：`pol=0` 过、`pol=1` 不过（这正是本次事故）|
| **J4** | 注入"人工改 `PE9`" ⇒ "指令≠实读"计数**必涨** | 不注入时必须不涨 |
| **A/B** | `pol=0` 臂"轴不动" / `pol=1` 臂"轴在动" | 复用现成入口：`python docs/audit/h723_motion_probe.py enapol 500 2.0` |

## 3. P1 —— 装置配置区 + 落盘（GAP-13）

### 3.1 载体决策

| 载体 | 优 | 劣 |
|---|---|---|
| **内部 flash（`persist` sector 6/7）✅ 选它** | 属于**机器**；拔 SD 不丢；**代码已写好**（A/B+seq+CRC+`hdr_sum`+头最后写+上电回 STOP+版本/CRC 不符即忽略）；**顺带把"掉电保持"这条契约承诺救活** | **前置：`H723-PERSIST-WDT-DEFECT` 未定案**（擦 128 KB ⇒ ISR 卡死 210.6 ms ⇒ WDT）|
| SD（`prog_store` 同族） | 无需解前置 | ★ **可插拔介质 ⇒ 拔卡/换空卡即失配置**（语义矛盾）；且要改 `LOG_END` 计算 ⇒ 碰"旧卡游标钳位 / 绝不升 `LOG_VERSION`"两个老坑 |

⇒ **选内部 flash**。SD 只作"前置未解前的临时过渡"，且**必须在文档里写明"拔卡即失配置"这条语义代价**。

### 3.2 结构（照 `OFF_DEV_BIND` 惯例）

`OFF_DEV_CFG = 0x7360`（紧接 `OFF_DEV_BIND` 的 96 B 之后）

```
MAGIC('DCFG')  N_VALID  CRC(FNV-1a)  REQ_SEQ  DONE_SEQ  REJECT
FIELD_ENA_POL  FIELD_STOP_HOLD  FLAGS
APPLIED_N  REJECT_N  LOAD_OK_N  LOAD_BAD_N
```
- `_Static_assert` **同时守"越出 SHM 末尾"与"越出本区末尾"**（本项目已吃过"只守前者的"）
- ★★ **登记进 `cold_start_reset()`** —— 实验第八条；`IX_MAGIC` 那次整个 G6-3 事务区失联就是漏了这条
- **只在 STOP + 声明窗口内写**（沿用 `WDT_PERSIST_WINDOW_MS`）；**运行期 0 flash 操作**（persist 语义 ④）
- **拒绝码与轮询码分槽**（`DB_RC_*` / `I2C_SM_ST_*` 数值重叠的教训：一个槽一个码空间）

### 3.3 接口

| 面 | 内容 |
|---|---|
| **写** | `0x41 DEVICE_CFG_SET` → 提交后回 `DONE_SEQ`；**拒绝时给 `REJECT` 码**（并有独立 `REJECT_N`） |
| **读** | `0x40 DEVICE_CFG_GET` → `{valid, ena_pol, stop_hold_torque, crc_ok, seq, loaded_src}` |
| **`0x4A` 追加尾块** | 声明"本机有装置配置区 + 偏移 + 版本 + **当前 `ena_pol` 实测值**"。★ 旧的读到 `n_dev` 就停 ⇒ **前 N 字节逐字节相同** |
| **能力位** | ★ 只剩 `0x8000` 一位 ⇒ **二选一**：**(a)** 占 `0x8000` 并**同时做 GAP-3（能力字 u32）**；**(b)** ⭐**不占新位**，以 `0x4A` 尾块为唯一判据（**推荐** —— 不让两件事互相绑架）。<br>★ 若选 (b)，必须在契约里**写明"`0x4A` 尾块是唯一判据"**，否则将来没人知道该信什么。 |

### 3.4 验收（**每条能失败**）

| # | 判据 | 失败方式 |
|---|---|---|
| **J5** | 写 → **真断电** → 上电 ⇒ 值回来，`loaded_src` = flash | 拔卡后仍须成立（区分于 J5'） |
| **J5'** | 同 J5 但**把 SD 拔掉** ⇒ 仍成立 | ★ 这条专门证"装置配置**不依赖可插拔介质**"，是选 flash 的**唯一硬证据** |
| **J6** | ★★ 上传**另一份程序包**（`0x45/46/47`）⇒ 装置配置**逐字节不变** | 这是与 GAP-11 的**分界线**的机检形式 |
| **J7** | CRC 坏 ⇒ **拒绝装载 + 保持"未配置"**（fail-closed） | ★ **不是"退回默认值"** —— 用默认值就退化成今天这个 bug |
| **J8** | `0x4A` 追加块 ⇒ 旧上位机读到的前 N 字节**逐字节相同** | 拿旧版本客户端实测 |
| **A/B** | `DCL_PERSIST_SAVE=0` vs `=1`（**修掉 ISR 卡死之后**） | 现状对照 = `writes` 恒 0 + **板子复位**；修好后必须 `writes` 真涨且**不复位** |

## 4. 与 GAP-3 / GAP-11 的边界（**必须写清，否则将来必吵**）

| | 属谁 | 换程序包会变吗 |
|---|---|---|
| **GAP-11 绑定表**（"这台机器上挂了哪些器件"）| **任务级** | ✅ 会变（跟着程序包走，已定决策）|
| **GAP-13 装置配置**（"驱动器怎么接到本板"）| **机器级** | ❌ **不会变**（判据 J6 就是这条边界的机检形式）|

## 5. 顺序与理由

```
P0 (a→f)  →  解 H723-PERSIST-WDT-DEFECT（独立缺口）  →  P1 结构(3.2)  →  P1 接口(3.3)  →  门面/契约/claims
```
★ **理由**：P0 **不依赖任何未定案的东西**，而且**单独就能消灭本次事故的根因类别**；
P1 的价值（"换机器不用重烧固件"）在 P0 之后才谈得上 —— **先让"错"变成"明确的拒绝"，再让"对"变得可配置。**

## 6. 明确**不做**

1. **不加上板跳线**（板子已量产）。软件等价物 = "**必须显式配置**"—— 保留跳线那一档最关键的性质：**不会被悄悄改掉，且未设置时是"不可用"而不是"某个错的值"**。
2. **不做磨损管理 / 寿命告警 / 坏块管理**（`persist.h` 已如实写明"当前没有"；本方案不扩范围）。
3. **不动 GAP-11 的绑定表位置**（它有已定语义，见 §4）。
4. **不为"安全"引入软件 STO** —— 工业界靠硬线（EMG / STO / 安全继电器）；我们只承诺"**不制造危险状态**"。
5. **不把 `stop_hold_torque` 做成"全局默认"** —— 它必须**按轴**（垂直轴与水平轴的要求相反）。

## 7. 风险

| 风险 | 处置 |
|---|---|
| P0(c) 是**上电行为变更**（本机 `pol=1` ⇒ 上电从"通电"变"按 `stop_hold_torque`"）| 走 A/B + 回归；`stop_hold_torque` **默认值取"保持力矩"**（保守侧：宁可通电发热，不要掉力滑车）|
| P1 前置（ISR 卡死）可能查不出真因 | 那就**降级落 SD** 并把"拔卡即失配置"写进门面；**不许**沉默地留在"配置存不下来" |
| 能力位只剩 1 位 | 选 §3.3 (b)：不占新位；**不把 GAP-3 拖进来** |
| 装置配置被误当成"程序的一部分" | 判据 J6 + §4 的边界表 + 契约 §3.9 写明 |

## 8. Definition of Done

1. 未配置 ⇒ **拒绝使能**（J1 可失败）2. 两种极性下 `step_init()` 都满足 `stop_hold_torque`（J3 可失败）
3. `stop_hold_torque` 决定停止/上电是否保力矩（J2 可失败）4. "指令 ≠ 实读"可注入复现（J4）
5. 装置配置**不随程序包变**（J6 可失败）6. **拔掉 SD** 后配置仍在（J5' 可失败）
7. `0x4A` 追加块不改前 N 字节（J8 可失败）8. 真断电一次，值回来（人工一次）
9. 契约 §3.9 + GAP 表 + `docs/claims.md` 同步（**构建不红**）10. A/B + 12 套回归通过
11. `src/step.h` 两处过期/撒谎注释已修（§2.2 f）
