# ③ `m_op` 程序无关性验证 —— 有效证据 + 一次失败的测试设计（2026-09-18）

> 要检验的命题：`m_op` 是**原语的属性**（与程序无关）⇒ 标定一次、所有程序通用。
> 这是整个"可算"结论的**地基**。若它不成立，模型要在每个程序上重新标定。
> 工具：`tools/exp_eg_mop_validity.py`。

## 2. ✅ 支持"程序无关"的**有效**证据（此前几轮已有，非本次）

`m_op` 全部来自**同一 division 内、只变 n** 的回归 —— 那是干净的对照：

| 来源 | 做法 | 结果 |
|---|---|---|
| E-A | PID，单一 `(C, m)` 拟合**全部 12 点**（跨三档） | 最大偏差 **0.4%** |
| E-C | 19 个原语，div0 内 n=32→128 两点 | 全表 |
| E-E1 | 扫描段口径重标 | `m` 复现 E-C 到 **0.4% / 0.0%** |
| C_scan | ACTIVE 差分（**物理**去掉路由体） | DIRECT **29.80** vs 回归 **29.51** ⇒ **1.0%** |

★ **不同 n ⇒ 不同"每桶条数"与不同"非空桶数"**（例如 div0 的 n=32→128 桶内密度 32→128）
⇒ 这些回归**本身就跨了桶分布**，`m` 仍然恒定。
**这是"与桶分布无关"的间接但真实的证据。**

## 3. ❌ W-1 测试设计错误（撤回其结论）

**原设计**：配对 `(div1, n=10k)` 与 `(div2, n=32k)`，声称"同 k、只差桶数"。

**实际结果**：

| k | div1 | div2 | 结果 |
|---|---|---|---|
| 1 | n=10 ⇒ `nrun=1` | n=36 ⇒ **`nrun=0`** | 无对照（读数为 0）|
| 2 | n=20 ⇒ `nrun=2` | n=72 ⇒ `nrun=1` | ❌ **nrun 不同** |
| 3 | n=30 ⇒ `nrun=3` | n=108 ⇒ `nrun=1` | ❌ **nrun 不同** |
| 4 | n=40 ⇒ `nrun=4` | n=128 ⇒ `nrun=1` | ❌ **nrun 不同** |

**⇒ W-1 比较的是"不同 `nrun`"的两组，根本没有把桶分布隔离出来。**
它打印的 "44.7% / 53.4% ⇒ 模型要重写" 是**虚假结论**，已撤回。

**根因**：我按 `n` 配对，而真正决定"每拍跑几条"的是 **`nrun` = 非空桶数**，
它与 division 的关系不是线性的（div2 下 `nrun = min(非空桶数, n)`，
而 `n=36` 时只有 36 个非空桶 ⇒ `nrun` 取到的是别的值）。

★ **教训**：**配对的量必须是模型里真正出现的自变量（这里是 `nrun`），不是它的一个代理（`n`）。**
本项目的既有形态：§5.60（分组掩盖自变量范围）、§5.66（两把尺子混算）——这是同族的第三次。

## 4. ★★ 更深的问题：低 `nrun` 区**在测量地板之下**

`nrun=1` 时，各配置的扫描段：

| 配置 | 非空桶数 | 扫描段 | 比 `C_loop=62.3` 多出 |
|---|---|---|---|
| div1 n=10 | 10 | 191.1 TB | 128.8 TB |
| div2 n=72 | 72 | 152.2 TB | 89.9 TB |
| div2 n=108 | ~100 | 192.4 TB | 130.1 TB |

**同一个 `nrun=1`，成本却在 152 ~ 192 TB 之间摆动（±25 TB）。**

但注意三件事：

1. **`C_loop = 62.3 TB` 本身就是测量地板**（E-D：全未激活时扫描段恒为 62.3 TB）
   ⇒ 上面这些"多出"的 90~130 TB 里，**有多少是真实成本、有多少是地板噪声，分不开**
2. 这些点的**每拍条数极小**，窗口里的样本高度依赖"到底哪一拍出现了那 1 条"
3. 三个配置的 `nrun` 读数虽然都是 1，但它们**桶结构完全不同**（10 / 72 / 100 个非空桶）

⇒ **用"中位拍的均值"去测 `nrun≈1` 的桶分布效应，分辨率不够。**
这不是"没测出来"，是**这个仪器在这个区间测不了**。

★ **要测它，需要换仪器**：不能再用"整窗口均值"，
而要用**逐拍数据**（`OFF_EXEC_RING` 里已有，但那是 `di` 不是扫描段）
⇒ 需要给扫描段也加一个环形缓冲（或按 `nrun` 分类统计）。

## 5. ★★★ 意外发现：桶表**与固件自己的死槽断言矛盾**

`W-0` 把 div2 n=128 的桶表读出来核对，结果与文档/固件断言**不一致**：

**实测（板上，div2 n=128）**：
```
cnt2[0..27]  = 2   （28 个桶各 2 条）
cnt2[28..99] = 1   （72 个桶各 1 条）
cnt2 总和     = 128 ✓
非空桶数      = 100
```

**而固件自己的断言说**（`engine.c:400` `engine_bucket_dead_slots`）：
```c
/* 死槽 = 相位 64..99 (路由的 6 位 phase 字段到不了那里)
 * ★ H9 第二次修正: 判据的本体没变 (这 72 个槽必须恒 0) */
for (int p = BUCKET_DIV2_PHASE_MAX + 1; p < BUCKET_DIV2_PHASES; p++)
    if (cnt2[p]) bad++;
```

⇒ **固件说 `cnt2[64..99]` 必须恒 0；实测它们是 1。**

**编码上的矛盾**（`engine.h`：`PERIOD_DIV_MASK=0x03`，`PERIOD_PHASE_SHIFT=2`）：

```
period 是 u8;
engine.c:992   r.period = (uint8_t)(dv | (uint8_t)(ph << PERIOD_PHASE_SHIFT));
                                                         ↑ ph=64 ⇒ 64<<2 = 256 ⇒ 截成 0
⇒ 按此式, 相位 64..99 存不进去（会回绕到 0..35）
⇒ 预期 cnt2[64..99] == 0 且 cnt2[0..35] 被二次填充
但实测**恰好相反**（cnt2[64..99] == 1, 而 0..35 只有 2）
```

**⇒ 三者不能同时为真。必有一处我的理解或代码与实测不符。**

★ **本文档不猜是哪一处**，只登记这个矛盾及其证据。
**它是可判定的**：读 `engine_build_buckets`（另一条建桶路径，`engine.c:352`）
的 phase 取法，与 `engine_stage_program` 对比即可。

★ 这件事的**重要性不低**：它涉及
① 桶表是不是按设计构造的、② `engine_bucket_dead_slots` 这条不变量是不是**恒真**
（若恒真它是空判据；若可违反则该报警）。
本项目对"恒真判据"有明确纪律（§5.23 / `h723_audit_full.py` 的 1.1 项就专查这个）。

### 5.1 已排除的解释（防止后来人重复走）

| 假设 | 是否排除 | 依据 |
|---|---|---|
| 我读错了表偏移 | ✅ 排除 | 偏移取 `bkt+20 / bkt+120`，与固件 `engine.c:407` **逐字相同**；`cnt2` 总和 = **128** 精确等于部署条数 |
| 两条建桶路径不一样 | ✅ 排除 | 两条路径读的是**同一段 SHM**；`engine_build_buckets`（`engine.c:356`）与 `engine_stage_program`（`992`）都按 `(period>>2)` 索引 |
| 我读的是陈旧数据 | ✅ 排除 | 读数在 deploy + STOP/START + 0.2 s 之后 |

### 5.2 尚未排除、且**可判定**的解释

**候选**：`q2`（部署器里 `q2++ % 100` 的计数器）可能是**跨 deploy 累积的静态变量**，
而不是每次 deploy 从 0 起。若如此，则同一个 `n=128` 在不同历史下会得到
**不同形状**的桶表（相位偏移不同）。

★ **这个候选可以解释"形状奇特但总和精确 = 128"** —— 但**本文不声称它成立**，
因为我没有去读 `q2` 的声明与初始化。

**判定方法（未做，很便宜）**：读 `q2` / `cur2[]` 的声明处，
看它们是 `static` 还是每次 `engine_stage_program` 里重新初始化。

★★ **无论哪个解释成立，有一条结论已经确定**：
> **`engine_bucket_dead_slots()` 在板上返回的**不是** 0** ——
> 因为实测 `cnt2[64..99]` 全部 = 1，按该函数逻辑 `bad` 至少为 **36**。
> ⇒ 这条"必须恒 0"的不变量，**在真实运行中是可违反的**。
> 这本身就是一个值得单独查的缺陷（它没有报警，也没有拦住任何东西）。
