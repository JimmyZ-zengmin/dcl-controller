## 0. 一句话结论

`h723-core0` 是**同一颗芯片、同一套 100µs 节拍、同一个"路由表 + 原语"思想**的一代**更早**的引擎；
它的**调度与校验能力弱于本工程**（无分档、无下载期校验），但它在**"把输出/输入真正钉在硬件时间网格上"**
这一块，做出了本工程**目前明确缺失**的实证成果——

> 本工程 `src/engine.c:1059` 自己写着：**"GPIO 执行器面在 H723 尚未实现"**。
> `h723-core0` 的输出链 + 输入链，正好是这个缺口的一份**已实测**实现。

⇒ 搬的是**两条硬件链 + 一套非侵入观测范式 + 一份寄存器配方**；
不搬的是它的**调度器、路由表布局、校验层、时钟树**。

## 2. 它真正值钱的机制（三条链 + 一个范式）

### 2.1 输出链：DMA2 S0 硬件锁存 —— **数据面与沿面分离**

实现（`Src/main.c:663-679` + `:890-909`）：

```
[ISR 内 / 数据面]  ACTUATOR[32..63] > 0.5 → 打包 u32 gpio_bits（心跳并入位2）
                    → 写 AXI 缓冲 0x24003000
[ISR 外 / 沿面]    TIM1 上溢 (UDE) 每 100µs → 硬件请求 DMA2 S0 一次 32bit 传输
                    → 锁存进 GPIOE_ODR
```

配方（已实测）：
- `DMAMUX C8 = 15`（TIM1_UP）；`C8` 归属 DMA2（H7：通道 0-7=DMA1，8-15=DMA2）
- 流配置：`M2P + CIRC + PSIZE/MSIZE=32bit + NDTR=1 + 无增量`；使能需**两步**（先写 CCR，再置 EN）
- `DIER = UIE | CC1DE | UDE`（UDE 让 TIM1 上溢产生 DMA 请求）

**它为什么值钱**：输出沿 **不经过 CPU**、由 **TIM1 硬件网格锚定**，实测抖动 σ 落在 **1 个捕获 tick**
（≈4.16ns）= 分辨率下限。这是"输出时刻确定性"的**硬件级**答案，而本工程当前只有
"主循环 10ms CPU 直写 TIM3_CCR1"。

**它踩过的坑（必须继承的教训，比配方更值钱）**：
1. **H723 没有 D2 SRAM**：`0x30000000/0x30020000/0x30040000` 三路交叉验证（CPU/DMA/SWD 写读）
   **全部恒 0** ⇒ 它的输出源原写 `0x30004000` 是**虚空地址**，ACTUATOR 数据**从未到过引脚**
   （`docs/HARDWARE-FINDINGS-2026-09-07.md` 结论 1）。修复 = 改 AXI 区。
   ⇒ **输出源必须在 DMA 可达区**：DTCM 不可达（RM0468 p110），要放 **AXI 0x2400xxxx**（避开 bss/栈）。
2. **`RCC_AHB1ENR.DMA2EN` 是 bit1**，原误写保留位 bit2 ⇒ **DMA2 时钟从未真正开启**。
   这个坑解释了它历史上**全部** DMA2 相关谜团（UART RX 不工作等）。
   ⇒ 与铁律同族：**"写过了"不等于"开了"**。

### 2.2 输入链：MDMA 软触发搬入 —— **精确命中用户口述理论**

用户口述理论原文含：**"拍内 I/O 时间分区：上周期末采样搬入、采样前搬出、计算在设定时间"**。
`h723-core0` 的输入链**就是这句话的落地形态**（`Src/main.c:1054-1105`）：

```
[ISR 头] mdma_input_reclaim()  回收上周期末的快照 → 拆位写 SENSOR_MAP[0..7]  ← 本拍路由可引用
[ISR 末] mdma_input_kick()     软触发 MDMA：GPIO_IDR → DTCM 快照（异步，不等完成）
```

- **CPU 只做"发起 + 回收"，不碰数据路径中间态，零忙等**
- 语义 = "路由本周期消费的是**上周期末尾**采到的输入"（标准扫描模型），与输出链（周期初锁存）**自然错开**

**它是唯一的桥**：DMA1/DMA2 两条总线都**访问不到 TCM**（RM0468 p110），
**MDMA 是 H723 上唯一能访问 DTCM 的 DMA**（经 Cortex-M7 AHBS slave 桥）。
本工程把一切热数据放在 DTCM/ITCM 上 ⇒ 将来任何"外设 ⇄ SHM 直达"都只有 MDMA 这条路。

**配方（它逐寄存器实测验证过，`Src/main.c:935-957`）**：
- 基址 `0x52000000`（D1 AHB3），ch0 寄存器：`CISR@0x40 CIFCR@0x44 CESR@0x48 CCR@0x4C
  CTCR@0x50 CBNDTR@0x54 CSAR@0x58 CDAR@0x5C CBRUR@0x60 CLAR@0x64 CTBR@0x68`，步长 0x40
- 时钟：`RCC_AHB3ENR(@0x580244D4) bit0 = MDMAEN`
- `CTCR 4B 配方 = SWRM(0x40000000) | TLEN=(4-1)<<18 | DINC=2<<2 | SINC=2`
  ⚠ **必须用 byte 尺寸 + inc 编码 2（按 size 递增）**；**word 尺寸会 BSE，勿用**
- `CTBR`（仅 EN=0 可写）总线选择：源在 DTCM → **SBUS(bit16)**；目的在 DTCM → **DBUS(bit17)**；
  GPIO(AHB4) 走默认总线即可直写
- 软触发序列：`CIFCR=0x1F → CCR=0 → CSAR/CDAR → CBNDTR=0 再 =4 → CTCR → CTBR → CCR=1(EN) → CCR|=0x10000(SWRQ)`
- 完成标志 `CISR`：`TCIF=bit4 BTIF=bit3 CTCIF=bit1 TEIF=bit0`；完整块 = `0x1E`
- **已知未落地（它自己标注）**：单块完成后需 **repeat-block / 链表**才自续，
  "周期自触发待下一步"。它的输入链用**每周期软件重发**绕开了这个限制。

### 2.3 SCK1 非侵入自检区 —— **"铁律 0"的一个完整落地范例**

本工程 `README.md:250-254` 的铁律 0：

> **观测不得改变被测对象。** 与单片机交互/观测时，优先走协议内通道；
> 凡会改变目标状态的手段（HALT、复位、关时钟、改 DWT、留运行期配置），
> 只在协议通道表达不了时才用，且用完必须**显式恢复**并**核对已恢复**。

`h723-core0` 的 SCK1（`Src/main.c:1312-1355`）正是这条铁律的正例：

- **固件自己**在主循环每 ~0.5s 用**内部 DWT** 测一次真实 ISR 频率与周期抖动
- 结果写 DTCM `0x20010000`：`[0]='SCK1' [1]=条数 [2]=PLL状态 [3]=CLOCK_HZ [4]=TIMER_HZ`，
  槽 `8+i*8`：`seq, span_tick, isr_hz, PERIOD_MIN, PERIOD_MAX, EXEC_MAX, loop_cnt, engine_running`
- **调试器不参与任何计时/停机**；读取端只需运行后 dump 该区
- 它明说经此避免了 "SWD 运行态读数不可信" 的假象

⚠ 它的读取端有个已知陷阱（`KNOWN-LIMITATIONS.md §1` 第 6 条）：
槽起点是 **word 偏移 `8+k*8`**，曾因误用字节偏移而错判固件异常。

### 2.4 附：全 fault 捕获 + PROGRESS 进度插桩

- `HardFault/MemManage/BusFault/UsageFault` 四个 handler **全部**落 `fault_capture`
  （`Src/main.c:131-174`），记录：`CFSR/HFSR/BFAR/MMFAR/ICSR/SHCSR` + **异常栈帧**(r0-r3,r12,lr,pc,psr)
  + `MSP/PSP` + `progress`
- 取栈帧时用 **`tst lr,#4` 判定压在 MSP 还是 PSP**
- 它的动机原文（`Src/main.c:98-99`）：

  > "此前全是 startup.s 的弱符号，一律落进 `Default_Handler` 的死循环，**错误完全静默** ——
  >  这是死因长时间无法定位的根因。"

这与本工程的 `g_stage` 是同族（本工程已有），但它的**完整栈帧 + MSP/PSP 判定**是更完备的形态。
注意它自己标注：**IMPRECISERR 时 `pc` 不可信**（与本工程 ADC 总线错教训一致 ——
非精确总线错会把现场报到**下一条**寄存器访问处）。

## 4. 搬什么（逐条：解决本工程什么问题 + 适配点）

| # | 搬什么 | 解决本工程的什么问题 | 适配点 / 前置条件 |
|---|---|---|---|
| **A** | **DMA2 S0 硬件锁存输出链** | `src/engine.c:1059` 自述 **"GPIO 执行器面在 H723 尚未实现"**；当前唯一物理输出面 = HIL PWM（主循环 10ms、CPU 直写、比拍慢 100 倍）。搬来后：输出沿由 TIM1 网格锚定、零 CPU、**32bit 原子锁存** | ① 输出源必须放 **AXI**（H723 无 D2 SRAM，DTCM 不可达）—— 这是本工程**必须继承的第一条硬事实**；② 与 `OFF_CTRL_GPIO_MASK` 的 176 位语义问题**天然合流**（见 §6 分叉 2）；③ 必须接进现有 **`eng_register_output_surface` 安全态注册表** —— DMA 锁存面是**又一个物理输出面**，停机安全态必须覆盖它（否则重犯 R1 的"停机≠安全态"）|
| **B** | **MDMA 软触发输入搬入链** | ① 用户理论 **"上周期末采样搬入"** 的落地形态；② 本工程输入面当前 **不定时**：`hil.c:96-101` 的 `adc_read` 是**同步阻塞 16 次平均**（主循环里！），`di.c:43-66` 是主循环 10ms 轮询 ⇒ 采样时刻不确定；③ **MDMA 是 H723 唯一可达 DTCM 的 DMA** ⇒ 未来任何"外设直达 SHM"的**唯一通路** | ① `CTCR` 必须 **byte 尺寸 + inc=2**（word 尺寸 BSE）；② 单块不自续 ⇒ 每拍软件重发（它已如此）；③ 先定输入源形态（ADC 结果寄存器？DI 整端口？）；④ 与"拍内时间分区"设计对齐（见 §6 分叉 3）|
| **C** | **SCK1 非侵入自检范式** | 铁律 0 的**完整正例**；本工程已有协议读回 + `g_*` 观测，但缺"**ISR 频率/拍抖动**由固件内置自测"这一半 | 先核对本工程现有观测面覆盖度，只补缺口，**不搞第二套观测体系** |
| **D** | **全 fault 捕获（栈帧 + MSP/PSP）** | 本工程有 ADC IMPRECISERR 教训；更完整的栈帧能直接定位此类故障 | 与本工程现有 fault 处理**合并**，不并行两套 |
| **E** | **DMA/DMAMUX/MDMA 寄存器配方（纯知识）** | 本工程未来加任何 DMA 都用得上 | 无（这是知识迁移，不是代码迁移）|

**为什么这四条"能解决问题"（而不是"为了搬而搬"）**：
- A 直接填掉本工程**自己写在注释里的缺口**，且带**实测证据**（σ<4.16ns）；
- B 是**用户口述设计理论**中"上周期末采样搬入"的唯一现成实现，且绕开了本工程"输入靠主循环轮询"的确定性弱点；
- C/D 是**铁律 0** 与**防静默失效**两个项目铁律的现成范例；
- E 是纯增益、零风险。

## 5. "它的 PLL 别用了"—— 用户判断的实证支撑

用户指令：**"它的 pll 别用了，不稳定"**。本文档如实指出，这个判断**有它自己的记录支撑**：

1. **VOS0 写的是未实现档位**：`PWR_D3CR@0x58024818 [15:14] = 0b11`。
   RM0468 中该字段的合法档位不含 `0b11`（VOS0 在 H72x 需按官方序列经 `PWR_SRDCR`/`PWR_D3CR` 的正确编码），
   它写的 `0b11` 属**保留/未实现**。
2. **等待条件可能永不成立**：它等的 `PWR_CSR1[14]`(ACTVOSRDY) 在 BYPASS 模式下才会置位，
   而它随后**先切 HSI 再禁 PLL**（`Src/main.c:301-305`）—— 顺序上 RDY 的可见性存疑。
3. **超时不报错**：`while (!(...) && --t) {}` —— **超时后静默继续**，不置错误标记。
   这正是本工程铁律 **"凡'写过了就算'的状态必须补一个能被外部读走的量"** 的反例。
4. **它的版本回归本身自相矛盾**：`ENGINE-OVERVIEW.md §2` 记录 "CR3 写法 480M **全败**"（九版回归），
   却又把"480M 稳定"写进定稿 —— 一个**只在自身日志里成立**的结论，缺独立外部证据（LA/示波器测频率）。

⇒ **处置：整段不搬。** 本工程用 400MHz（HSE）已复测冻结，无任何理由引入一个存疑的时钟源。
若将来要提频，走本工程既有的 `docs/REF-frequency-ceiling.md` 路径（**并用 LA 外部测频率**，不用 SWD）。

## 6. 需要用户决策的分叉（动手前必须先定）

### 分叉 1：只搬 A，还是 A + B？
- **只搬 A**：先补数字量输出面，输入维持现状（主循环轮询）。改动小、可立即验证。
- **搬 A+B**：一次性把"拍内 I/O 时间分区"（用户理论的两半）都落地。范围大，但**更接近用户的设计理论**。

### 分叉 2：输出面的**引脚范围**定案（这决定 `OFF_CTRL_GPIO_MASK` 的语义）
本工程 `engine.h:120-132` 已把这个问题**钉死为前置条件**，二选一：
- ① 扩成 **`u32[6]`** 覆盖 176 位（GPIOA..GPIOK × 16）—— 语义干净，**要改 SHM 偏移**；
- ② 明确 **"只支持 GPIOA"** + 断言 `mask < (1u<<16)` —— **零偏移代价**。

而 DMA 锁存方案**天然给出第三条路**：`DMA2 S0` 一次搬一个 32bit 字到一个 `ODR`
⇒ "**一个端口 = 一个 u32 输出字**"。若接受"每个受管端口一条 DMA 流"，则 `GPIO_MASK`
可以自然变成"**每端口一个 u32**"（≈① 的紧凑形态），语义与硬件一一对应。

⚠ 约束：DMA2 只有 16 条流（S0-S15），且 S0 已被输出链占用。**多端口要么多条流，要么用 MDMA 链表**。

### 分叉 3：B 的输入源与触发方式
- 源：**DI 整端口快照**（一次搬 32bit IDR，拆位——与它的实现一致）？还是 **ADC 结果寄存器**？
- 触发：**软件每拍重发**（它的做法，简单、已验证）？还是 **硬件触发**（`CTBR.TSEL` = DMA 流 TC 事件，它标注"周期自触发待下一步"，未落地）？

### 分叉 4：A/B 都要配**能失败的对照**（项目铁律）
按本工程已确立的纪律（`-DDCL_VTOR_ITCM=0` / `-DDCL_HIL_SAFE=0` 同款）：
新输出面/输入面必须给出**改前行为的对照构建**，用**同一套测量方法**打出两份结果。
对照组量不到差异 ⇒ **判据无效**，不是"修复成功"。
