## 3. 这三天发生了什么（按主题，全部有取证）

### 3.1 09-13 —— 可靠性这一档
| 事项 | 结论 |
|---|---|
| **VTOR 对齐不足**（框架未决问题 B） | ✅ 关闭。根因是**硬件取向量按对齐值掩码**；修复后向量表进 ITCM |
| **ISR 调用树闸门** | ✅ 新增 `tools/gate_isr_itcm.py` 并**接入构建**：ISR 可达却落在 FLASH ⇒ **构建失败**。7 个函数 + `Default_Handler` 搬进 ITCM |
| **看门狗** | ✅ IWDG 落地并验证（`docs/VALIDATE-watchdog.md`） |
| ★ **掉电保持** | ⚠️ **降级**：`0x43` 保存明确 NAK。真因：擦 128 KB 内部 flash 期间**拍 ISR 卡死 210.6 ms** ⇒ 喂狗停 ⇒ 复位 ⇒ 旧行为"点保存 = 重启机器且从未落盘"（`docs/audit/H723-PERSIST-WDT-DEFECT.md`） |
| **RTC** | ✅ 落地（含影子寄存器防撕裂、不依赖 `INITS` 的启动判据） |
| **485 接收故障** | ✅ 定位（ORE 溢出标志未清 ⇒ 接收自锁死），`docs/audit/H723-485-RX-AUDIT.md` |
| **SD 裸块每拍落盘** | ✅ 验收（`docs/AUDIT-sd-log.md`） |

### 3.2 09-14 —— 推翻一条"核心宣称"
| 事项 | 结论 |
|---|---|
| ★★★ **"输出时刻由硬件锚定"被推翻** | 原宣称的"七级触发链 `TIM2_UP→DMAMUX1→DMA2_S0→TC→MDMAMUX→MDMA→ODR`" **不成立**：四个否决性实验全不影响锁存。真因是 **MDMA 在自循环、不消费任何请求源**。**引脚时刻 = CPU 最后一次写影子 + 0.12 µs** |
| **决策：方案 A** | 交付档改 **CPU 直写 BSRR**（`DCL_DO_LATCH=0`）：抖动 3.6 ns vs 锁存的 54~60 ns，**差 15 倍**，且无功能损失 |
| **P0-1**（16 路 DO 只有 8 路可用） | 修复过，但**在交付档下被架空** —— 见 §5-2（`do_latch_init()` 未分档 ⇒ `PE0~PE7` 被每拍清零） |
| 实验归档 | ✅ `docs/exp-2026-09-14-mdma-trigger/`（README + 457 行实验 patch + raw + 脚本）—— **本项目最规范的一次实验** |

### 3.3 09-15 —— 闭环伺服 + 标准化
| 事项 | 结论 |
|---|---|
| ★★★ **"步进不转"真因定案** | 这块 TB6600 的 **ENA = 「光耦导通 = 失能」**（与多数相反）＋ **3.3 V 推挽高电平关不断 5 V 光耦**（mA 档实测两档电流差 ≈ 0）⇒ 无论 `PE9` 高低都失能 ⇒ **电机永远不转**，而所有寄存器读回全对 |
| ★ **修法** | **光耦正端从板 +5 V 改接板 3.3 V** ⇒ 高电平时压差 **0** ⇒ 彻底关断；且保住 MCU 只做 sink（不倒灌） |
| ★★ **开漏方案被否决** | `DS13313 Rev 5` Table 7：`PE8/PE9 = TT_ha`（**3.3 V 容忍，非 FT**），`PA6` 同为 TT 类 ⇒ 开漏高阻被拉到 ~4.5 V，**超绝对最大额定值** |
| ★★ **AS5600 定案** | 器件是好的 —— **SCL/SDA 两根线接反了**。修复后 100% 成功、NAK 归零 |
| **运动品质实测** | 速率偏差 ≤0.4%、2 min 长跑 −0.0%、10 轮往返累积 **0.00 步**、位置锁定 **+0.176°（0.78 步）/ 25 s 零修正零漂移**（峰峰 = 1 LSB） |
| **转速上限** | 带斜坡稳定 **≈31000 Hz ≈ 1170 rpm**；突加仅 **16650 Hz ≈ 627 rpm** ⇒ **固件无加减速，可用转速被砍 47%** |
| **D2/D3 根因定案** | **D2** = `step_tick()` 每次调用 `dt/10` 取整（零运动实测：静默 −35.1%、密轮询 −21.1%，随负载变 ⇒ 排除时钟错）；**D3** = 命令顺序 × `0 双语义`（小限时在 `rate()` 前被吃光 ⇒ 变无限跑） |
| **标准化** | `docs/REF-program-contract.md`（契据 v0）+ `docs/PLAN-dcl-standardization.md`（改革纲领） |
