# MEMORY-USAGE —— 内存怎么用、容量怎么定（**TCM 专文**）

> **范围**：本文只讲 **TCM**（ITCM 64 KB + DTCM 128 KB）与其中的 **SHM（32 KB）**。
> ★ **AXI SRAM（320 KB）不是 TCM**（用户 2026-09-19 明确）—— 它只是"固定地址被占满"的
> 另一块内存，其"将来要大缓冲怎么办"**暂不定**（见 §7）。本文只在"谁碰它"的意义上提到它。
>
> **上游**：`docs/PLAN-memmap-constitution.md`（公理⑤ + 不变量 M1~M6）·
> `src/memmap.h`（固定地址唯一源）· `tools/mem_report.py`（账本）。

---

## 1. 第一原则：**用途必须匹配性质**

TCM 不是"快一点的内存"，它是**两个核心宣称的物理前提**：

| 物理事实 | 绑定的宣称 | 违反的后果 |
|---|---|---|
| 代码在 ITCM ⇒ 零等待、无 I-cache | **每拍成本可算** | 落 flash+I-cache ⇒ 成本变成"命中率"的函数 ⇒ 这就是必须**单独一张 FLASH 成本表**的原因 |
| 数据在 DTCM ⇒ 单周期、无 cache | **每拍数据访问时间确定** | 落 AXI（HCLK=CPU/2 + cache 不可预测）⇒ 每拍时间变随机量 |
| 大缓冲在 AXI ⇒ DMA 可达 | 黑匣子/落盘/程序载荷 | IDMA/MDMA **读不到 DTCM**（硬事实） |

⇒ **"够不够用"是推论，不是问题本身。** 真正要问的是：
**这块内存的性质，与使用它的代码对时间的假设是否一致？** 由三项检查回答：
`gate_isr_itcm.py`（代码）· `shm_layout_ok()` 的 ∩AXI=∅（数据）· `refs` 白名单（谁碰它）。

## 3. ★ 容量模型：**配置期动态，运行期静态**

> 用户要求：**"容量这里要动态，不能浪费 TCM 了，但也要确定性。"**
> ⇒ 这两件事**不矛盾**，但必须把"动态"限定在**正确的时刻**上。

### 3.1 关键区分：动态发生在哪一刻

| 时刻 | 时间尺度 | 允许动态吗 | 为什么 |
|---|---|---|---|
| **编译期**（改 `MAX_*` / 改构建选项） | 分钟 | ✅ 应当 | 尺寸就是参数，一处定义 + 派生 + 断言 |
| **部署期**（下程序时） | 毫秒 | ✅ ★ **这是"动态"的正确位置** | 程序声明它需要多少条 ⇒ 引擎只需这么多 ⇒ **不浪费**；而尺寸一旦装载就固定 ⇒ **成本模型的常数前提不破** |
| **拍内**（100 µs） | 微秒 | ❌ **绝对不行** | 拍内一出现"按需分配"，`C_other`/`C_scan` 就不再是常数 ⇒ `di(t)` 不可算 ⇒ 拿 A 级优势换一点便利 |

**⇒ 一句话：容量在"配置时刻"是动态的、在"运行时刻"是静态的。**

### 3.2 现状哪里在浪费（要治的是这三处）

| 浪费点 | 现状 | 能不能治 |
|---|---|---|
| **① 上限 vs 实际** | 引擎表按 `MAX_ROUTES=128` 保留**地址空间**，而一个 34 条路由的程序只用 34 条 | ✅ **已经部分不浪费**：扫描只跑 `n_routes` 条 ⇒ **不耗时间**；耗的是**地址空间** ⇒ 要治就得让"没用到的槽"能被别的域借用（S2） |
| **② active/staging 两份** | 路由/参数/状态各两份 = **12 KB** | ❌ **不治**：staging 是"热更 ≤1 拍"原子性的前提；省 6 KB 赔掉核心宣称（`MEMORY-LAYOUT §5` 已定案） |
| **③ 上限是编译期常量** | 改上限要改头文件 + 全部断言 | ✅ 治：把上限变成**构建参数**（S1），再让部署期声明需求（S3） |

### 3.3 三步走（S1 现在就能做；S2/S3 是 E 期）

**S1（低成本，建议现在做）：把上限变成构建参数**
照 `-DDCL_TICK_US` 的成功范式：
```
set(DCL_MAX_ROUTES "128" CACHE STRING "路由表上限")
→ -DDCL_MAX_ROUTES=${DCL_MAX_ROUTES}
```
外加：**一处定义 + 派生 + 断言 + 变异对照**（现有 23 条 abut 断言自动跟着守），
`dclc` 的容量**已经**从 `src/engine.h` 派生（C 期做的）⇒ 改一个数，编译器与固件同时跟上。
★ 判据：`-DDCL_MAX_ROUTES=32` 构建 ⇒ 账本必须报 32，且 SHM 段长断言仍成立（变异对照）。

**S2（E 期）：把"没用到的上限空间"显式声明为可借用**
把 `[n_routes·16, MAX_ROUTES·16)` 这段声明成 `FREE`（class + owner + refs），
允许别的域在**编译期**借用（例如 LUT 表、更大的黑匣子索引）。
判据：借用后 `mem_report` 的区表仍平铺、且 `shm_layout_ok()` 仍过。

**S3（E 期，最重）：部署期按需裁**
`dclc` 报"本程序需要 N 条" ⇒ 构建/部署按 N 生成表区。
★ 代价：动 23 条 abut 断言 + PC 侧 + 持久化镜像长度 ⇒ **必须由 E 期触发条件驱动**，不顺手做。

## 4. 谁碰哪块内存（不变量 M1 / M5）

- **唯一地址源**：`src/memmap.h`（全仓只允许它出现固定地址字面量 —— 判据 C0）。
- **归属白名单**：每个区带 `refs=<允许引用它的模块>`；`tools/hardcode_audit.py` 机械执行（C9）。
  ★ 反例（历史血证）：程序载荷缓冲曾落进黑匣子环（照过期注释找"空地"）⇒ 每拍被覆写，
  读回 magic `DLBK`。**C9 让这一类在构建期就红。**
- **静态封闭**：`src/` 里 `malloc/free` 出现次数 == 0（C12）。理由不是碎片，是**成本模型前提**。

## 5. 用户看到什么（③层视角）

- **永远不看地址**：程序只引用**符号** —— 信号名 · `sensor[i]` · `wire[j]` · `actuator[k]`。
- **容量超限给可执行的报错**（C 期已落地）：
  ```
  错误: 路由数超限 —— 板上限 128 条（来源 src/engine.h），本程序排了 131 条。
    ⇒ 可做: ① 把某些信号的 PERIOD= 降档  ② 合并同类中间量
            ③ 拆成两个程序，用 wire[] 交接
  ```
- **一条命令看账**：`python tools/mem_report.py`（含"哪个区用了多少、还剩多少、谁占的最多"）。

## 7. 诚实边界

1. **AXI 不在本文范围**（用户明确）：它已被 15 个固定区铺满，零散空隙共约 6 KB；
   "将来要大缓冲怎么办"**暂不定**。唯一纪律是：谁要用就必须先改 `src/memmap.h` 并重跑账本。
2. **栈水位只"测量"不"证明"**：`mem_stat.c` 给的是**实测最深**，不是静态分析的"最深可能"。
   要用它下结论，得先攒够样本（含最坏路径）。
3. `MEM_STAT` 在 AXI ⇒ **跨复位保持** ⇒ 复位后读到的是**上一轮**的水位（与 `BOOT_REC` 同性质，
   对排障是优点，对"当前值"是陷阱）。
4. **S2/S3 未做**：受 E 期触发条件约束；现在"不浪费 TCM"的可行含义是
   **"没用到的时间不浪费"**（扫描只跑实际条数），而**地址空间**仍是按上限保留的。
