## ① 推翻我自己写错的 SKIP：div0 ÷dt 族**是可测的**

E-Q 第一版写着「`RATE`/`PID-D` 的 div0 **结构性不可测**，因为锁存器也是 div0 且同拍排在 RATE 之后
⇒ 读到的永远是 0」。**这个理由是反的**：div0 组内**按表序扫描**，锁存器排在后面 ⇒ 它读到的
正是 RATE **本拍刚写下的**值。真相只是"我当初把 div0 那两条 dst 一起删了，没接锁存路由"。

补上后（一次运行）：

| 观测量 | 期望量子 | 实测夹逼区间 |
|---|---|---|
| `RATE` div0 | `1/0.0001 = 10000` | **(9000, 11000]** ✓ |
| `PID-D` div0 | `0.005/0.0001 = 50` | **(30, 70]** ✓ |
| `PID-D` div1 | `0.05/0.001 = 50` | **(30, 70]** ✓ |

（`PID-D` 的 div0/div1 是**调小 Kd** 躲开输出的 `[0,100]` 钳位后测到的 —— 第一版删它们的另一半理由
也只是"Kd 太大"，不是"测不到"。）

★ **教训**：SKIP 的理由**也必须能被推翻**。贴上"结构性"三个字，它就没人再看了。

## ③ 编码器零变化 —— 查清了，且它决定了今天运动实验的**有效范围**

`sub=21` 显示 AS5600 **活着**（`ok_n` +94/s、`err_n=0`、`mag_ok=1`、raw=1479），但 raw **1 s 内不变**。

**真因：我没使能驱动器**（E-R/E-S 只写了 `sub=1` 频率，没写 `sub=3 ena`）。
实测：`sub=3 arg=1` 之后立刻有运动 ✓（编码器 raw 变化）。

⇒ **有效范围声明**：E-R/E-S 的所有结论都是**固件时间行为**（脉冲由 TIM3 硬件发出、由 TIM4 硬件计数），
**与机械状态无关**；今天**没有**、也**不需要**任何"轴转了没有"的结论。
★ 顺带：编码器读数率 ~100 Hz，对 1.88 rev/s 的转动本身就是**欠采样**（`Δraw` 跨 4096 回卷不可解读）
—— 与既有结论「反馈率是带宽上限」一致。

## ④ 拍长可配：**一个旋钮**，以及它暴露的 6 处硬耦合

### 扫描结果（"谁假定了 100 µs"）
| # | 位置 | 缺陷 |
|---|---|---|
| 1 | `clock.h` `CLK_TICK_US 100u` | 决定 **TIM2 的 ARR = 真实拍长** |
| 2 | `engine.h` `TICK_PERIOD_US 100u` | 派生 `dt` ⇒ **同一物理常数两份真相**；改这一处 ⇒ 声明的秒/毫秒整体缩放且**无断言会响** |
| 3 | `engine.h` `DT_FAST`/`DT_MID` **手写字面量** | 只在 100 µs 时等于"1 拍 / 10 拍"（`DT_SLOW` 早就派生了 ⇒ 一处派生、两处手写） |
| 4 | `engine.h` `OP_COST_DIV2 64` | 必须 = 实际扫描周期(拍)，**与相位数无任何断言相连** |
| 5 | `step.c` `dv * 10000u` / `dm = s_dl_acc/10u` | 斜坡与限时的 **拍→秒/毫秒换算写死** ⇒ 拍长一改，两者静默变成声明值的 1/N |
| 6 | `engine.h` `EXEC_BUDGET_CYCLES 32000u` | 运行期超预算判据是**绝对周期数**（= 100 µs 拍的 80%）⇒ 拍长翻倍后它变成 40%，**对合法程序报 OVERRUN** |

### 修法（一处定义 + 派生链 + 5 条**能失败**的断言）
```
CLK_TICK_US（唯一定义, 可 -DDCL_TICK_US=...）
  ├─ TIM2 ARR = 200 × 拍长          ← 断言: ≤ 65536（16 位）
  ├─ TICK_PERIOD_US = CLK_TICK_US   ← engine.h 别名, 不可能分叉
  ├─ DT_FAST/MID/SLOW = 相位数 × 拍长
  ├─ BUCKET_DIV2_PHASES_USED = min(64, DIV2_NOMINAL_US / 拍长)   ← 能力位宣称的 10 ms 结构性成立
  ├─ OP_COST_DIV1/DIV2 = 相位数
  └─ STEP_TICKS_PER_S/MS = 1e6/拍长, 1000/拍长   ← 断言: 必须整除
```

### 验证（两道）
1. **100 µs 回归**：10 条静态度量逐条对拍（`DT_FAST==0.0001f`、`DT_SLOW==0.0064f`、相位数 64、
   门除数 10/64、TIM2 ARR 20000、拍→秒 10000、拍→毫秒 10…）⇒ **10/10 与改动前一致**。
2. **200 µs A/B**（`-DDCL_TICK_US=200`，实测 tick 速率 5000.7 Hz）：
   **E-R 11/0 · E-Q 31/0** —— 而量子全部**自动跟着走**：
   `RATE` div2 `156.25 → 100.0`、`RATE` div0 `10000 → 5000`、`PID-D` div0 `50 → 25`（相位数 64→50、dt 6.4→10 ms）。

### ★★ 附带抓到：**"恢复交付档"没有真的恢复**
CMake 选项是**粘性缓存**。`-DDCL_TICK_US=200` 之后，无参 `bash build.sh` **仍然构建 200 µs 档**
⇒ `h723_restore_delivery.sh` 产出的是 **200 µs 的"交付档"**，而它照样打印 hex md5、照样探活
**12 PASS / 0 FAIL** —— **探活判不出拍长**。

**是判据抓到的**：`exp_eq_dt_semantics.py` 的 **Q0a**（tick 速率 vs **上位机墙钟**，一条与源码无关的
独立测量）期望 10000 Hz 而实测 ~5000 ⇒ 17 条判据 FAIL，一眼看出"板子不是我以为的那一档"。

修法：`h723_restore_delivery.sh` ① **显式传交付档全部可粘性选项** ② 构建后**比指纹**
（`EXPECT_MD5`，不符就**中止不烧**）。★ 这条修法本身也适用于既有选项（`DCL_BOOT_SEL` 等同一个坑）。

## ⑤ `C_other` 拆开了 —— 而且历史那个数**拆错了**

E-T 用「空程序（n=0）」把两块分开（`engine_tick` 在桶全空时**不调扫描体**）：

| 量 | 实测（复位后） |
|---|---|
| `di(0)` 纯骨架 | **542.4 TB**（1085 cyc） |
| 19 原语的**截距**（= 骨架 + 一次扫描调用） | **574.9 ~ 596.9 TB** |
| ⇒ **`C_scan(op)` = 截距 − 骨架** | **32.5 ~ 54.5 TB**（均值 73.6 → 实际 33~55） |
| E-C 的 `m_op` 表复现 | 19/19 在 **±0.7%** 内；Spearman **0.997** |

★ 历史记的是 `C_other = 474 TB` + `C_scan = 100~122 TB`。**两者之和（574~596）与我的截距吻合**
—— 所以**预测没错**（这正是留点验证能过 0.04% 的原因），但**拆分错位**：真值是 **542 + 33~55**。

### ★★ 而且 `C_other` **不是"与程序无关"的常数** —— 它取决于**残留的顺序程序**
E-T 第一次跑在**未复位**的板上得到 `di(0) = 816.7 TB`；复位后 `542.4 TB`。差 **274 TB** 就是
板上前一轮留下的 **8 个 seq 实例**（顺序域**没有清除命令**，只能靠复位 —— 见保障图谱缺口表）。
逐点测（0/2/4/8 实例，复位后）：`542.5 / 610.4 / 652.2 / 736.4` TB
⇒ **首个实例 ~34 TB，之后每个 ~21 TB（42 cyc）/ 拍**。

★ 所以模型的"每拍固定开销与程序无关"必须补一个限定：**"且板上没有残留的顺序实例"**。

## ⑥ 门边界：**算术与两个历史实测逐条吻合**，且交付档的门是**结构性不触发**

用「已知实测值反查常数」时当场抓到我自己加错的常数：第一版把源成本按 `SRC_COST_FALLBACK=20` 加，
算出的 FLASH 边界是 97，**与 E-N 实测的 105/106 不符**。真值是 `k_src_cost[CONST] = 0`（已实测的源成本为 0，
fallback 只对表里没有的源类型兜底）：

| 档 / 原语 | 每路由 | 算出的边界 | 历史实测 |
|---|---|---|---|
| FLASH `DIRECT` | 247 | `247×105 = 25935 ≤ 26000 < 247×106` ⇒ **105** | **105/106** ✓ |
| FLASH `PID` | 432 | `432×60 = 25920 ≤ 26000 < 432×61` ⇒ **60** | **60/61** ✓ |
| 交付档 ITCM `DIRECT` | 56 | 464 **> MAX_ROUTES=128** ⇒ **路由数上限先撞** | — |

实测：交付档部署**最大条数 128** 条 DIRECT ⇒ ACK，`budget = 7168`（门的 **28%**）。
⇒ **"预算门从未触发"在交付档上是结构性的**（128 × 最贵原语 145 = 18560 ≤ 26000）；
唯一有牙的是 FLASH 档，而它已在 E-N/E-O 端到端验过。★ 这为评估里那条"不能相信一个从未触发过的判据"
给出了准确答案：**在交付档它无法触发；要验就验 FLASH 档。**

## ⑦ 判据自身的两处修正

**⑦a `Q0a` 的 σ 被低估**：残差自相关（读数延迟在窗口内漂移）⇒ 单轮拟合 σ 只有 ~0.03%，
而四轮之间的实际散布是 ±0.1~0.4%（"差 4σ 却都通过"）。
修法：**分段（split-half）拟合**取两半斜率之差作为漂移实测上界，容差取 `max(0.3%, 3×漂移)`。
实测漂移 0.10% / 0.19% / 0.38% ⇒ 容差自动放宽到 0.3~1.1% ✓ 这才是诚实的 σ。

**⑦b 大块读的板侧占时标定**：`t(K) ≈ 22 + 0.4·K ms`（K = 8…200 字；固定项 ~22 ms 主要是串口往返）。
⇒ E-S 里"每次实测而非查曲线"的选择是对的（三个同参数值 89.5/101.4/135.3 ms 说明它本就抖）。
