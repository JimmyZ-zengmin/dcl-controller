# DCL 确定性控制系统 — 核心理论

> **版本**: v1.1 | **日期**: 2026-07-14
> **硬件**: STM32H723ZG (LQFP144, 单核 Cortex-M7)
> **固件**: 核心0 v1.7
> **原则**: 本文件描述设计理念和实现效果,不绑定具体实现方案

---

## 0. 设计理念 — 三条公理

### 公理 1: 周期确定性由硬件锚点保证

```
晶振 → PLL → 硬件定时器 → 周期锚点
                                  ↓
                         ISR 引擎被硬件触发
                                  ↓
                        软件只能提前完成,不能推迟周期
```

**推论:** 定时不取决于软件负载,取决于硬件定时器。CPU 快 10 倍不能让周期更短,只能留更多余量。

### 公理 2: 输出时刻与 CPU 时刻解耦

```
ISP 计算: 任意时刻完成 (路由表扫描,微秒级)
输出锁定: 固定时刻发生 (DMA 搬运到 GPIO)
```

**推论:** CPU 算得多快不重要,输出时刻永远是周期内的固定位置。外部电路看到的边沿由硬件决定,与 CPU 计算路径无关。

### 公理 3: 数据驻留,计算流动

```
数据不动: 寄存器空间绝对地址固定 (DTCM 零等待)
计算流动: 原语扫描逐个处理 (顺序,无分支)
中间结果: WIRE 总线统一 float32 (无类型转换)
```

**推论:** 每条路由耗时 = 读源 + 算 + 写目标 = 固定若干 cycle。总耗时只取决于路由数,不取决于数据值。

## 1. 实现效果 — 当前实测

### 1.1 周期与频率

| 参数 | 值 | 说明 |
|------|-----|------|
| 引擎周期 | **100.000 μs** | 由 TIM1 硬件定时器保证 |
| 晶振频率 | 8 MHz (HSI) | 经 PLL 倍频 |
| 路由容量 | **1024 条** | 当前实测 47 条稳定 |
| 参数量 | **512 组** | float32 × 4 |
| 状态量 | **256 槽** | PID/LPF/COUNTER 等有状态原语 |
| 单条路由执行 | **~10-15 cycle** | 取决于原语和内联/调用路径 |
| 当前路由计算 | **~3000 DWT cycles** | @320MHz DWT ≈ 12.5μs (for 47 routes) |
| 计算负载 | **~12.5%** | 余量 87.5% |
| DMA 搬运 | **1 个 AHB 事务** | SHADOW → GPIOE_ODR,每周期一次 |

### 1.2 抖动 (核心指标)

| 测量项 | 值 | 方法 |
|--------|-----|------|
| 周期抖动 σ | **~55-140 ns** | 取决于 DMA 是否计入 |
| 周期 3σ | **< 450 ns** | 含最坏情况 |
| 占空比 | **< 0.5%** | 对 100μs 周期 |

**测量方法:** 固件 ring buffer (不停留写入,不停留读取):
- 每周期在 ISR 入口写 DWT_CYCCNT 到 DTCM ring buffer
- buffer 满 (8192 样本) 后自动停止
- pyocd 一次性 halt 读 buffer
- 计算相邻 DWT 差值的分布 = 相邻 ISR 入口间隔

**实测分布 (medium_test.dcl,36 routes):**
```
均值: 99.998 μs   (偏差 < 2ns)
σ:    144 ns      (DMA 搬运引入额外总线竞争)
3σ:   432 ns
```

### 1.3 输出响应链路

```
触发源 (硬件) → DMA request → AHB matrix → GPIOE_ODR → 引脚
     ↓               ↓             ↓           ↓
 TIM1 TRGO        DMAMUX        搬 4 字节    外部电路
 固定时刻         硬件路由       单周期完成   看到电平变化
```

关键路径延迟 = DMA 仲裁 (~0) + AHB 传输 (~3 cycle @480MHz ≈ 15ns) ≈ **可忽略**

## 2. 核心哲学 — 为什么这样做

### 2.1 时间切片 + 空间换时间

| 传统 PLC | DCL |
|---------|-----|
| 轮询整个程序 | 中断触发固定周期 |
| 周期 ≈ 代码执行时间 | 周期 = 硬件定时器 |
| 高速→快不了,低速→更慢 | 高速→更多空闲,低速→周期固定 |

**本质:** 传统 PLC 的"周期 = 工作量",DCL 的"周期 = 常量"。

### 2.2 火车模型 (类比)

```
硬件定时器 = 铁轨调度器 (绝对时刻表)
DMA 采样   = 起点站 (周期开始,异步采集)
ISR 计算   = 车内处理 (封闭,不被打扰)
DMA 输出   = 终到站 (周期末尾,固定时刻发车)
```

关键: 车上的人 (CPU) 不需要知道"几点几分到站" — 车子到了,就被甩出去。

### 2.3 统一 WIRE 总线

所有信号 = float32 存储在 DTCM 固定地址:
- 无类型转换 (REAL/BIT/INT 都是 float32 wire)
- 无 malloc/free (路由数固定,空间预分配)
- 无 cache miss (DTCM 零等待)
- 拷贝 = 1 cycle (读取),不是 memcpy

## 3. 重要设计决策 (与选择同步)

### 3.1 为什么不用 DMA 搬输入 (原始方案)

ADC 采集的异步性:
- ADC 转换时间 ~5 μs (慢速采样)
- 转换完成后 DMA 搬到 DTCM+0xF0
- ISR 只读 DTCM,不触发 ADC (总线空闲)

**唯一保留 DMA 的场景:** 异步外设 → 内存。CPU 不参与,不阻塞。

### 3.2 为什么搬 GPIO 输出

CPU 末尾直写 ODR:
- 抖动 = ISR 抖动 (σ=55ns)
- 时刻 = ISR 末尾 (依赖路由数)

DMA 搬 ODR:
- 抖动 = DMA 总线传输抖动 (<15ns 理论)
- 时刻 = 周期固定位置 (独立于路由数)
- 缺点: 引入 AHB 总线竞争 (~+90ns σ)

**当前状态:** DMA 工作验证通过,功能正确。抖动是否可接受取决于应用场景。

### 3.3 为什么单核

工业级安全控制需要:
- 双核 Lockstep
- ECC RAM
- 硬件 Fault 收集

当前 H723 单核:**已实现 100μs 确定性 + <500ns 抖动,满足绝大多数工业场景**。

双核是目标,单核是当前务实选择。

## 4. 系统边界 (能力与限制)

### 能做什么

- ✅ 100μs 周期确定性控制
- ✅ 1024 条路由并行扫描
- ✅ 35 种原语 (PID/LPF/CMP/TIMER/COUNTER 全覆盖)
- ✅ DCL 声明式编程 (拓扑排序自动推导执行顺序)
- ✅ 在线部署 (pyocd/UART,不停机)
- ✅ 低抖动输出 (<500ns 3σ)
- ✅ 掉电不丢 (DEPLOYED_MAGIC 检查)

### 不能做什么

- ❌ 超高频 (>10kHz 周期受 CPU 速度限制)
- ❌ 安全完整性 SIL3 (需双核 Lockstep)
- ❌ 以太网/现场总线 (仅 USART + CANopen)
- ❌ Web IDE 完整功能 (当前空壳)
