## 1. 原平台 esp32-core0 是什么

**定位**: 一台"文本组态 + 100μs 硬实时引擎 + 下载前静态校验"的 PLC 内核。
2026-09-10 已冻结（只修不增），90 提交 / 20 套回归 / 4 轮外部审计。

**架构一句话**: 双核分工，实时面与非实时面靠共享内存交接。

| 层 | 内容 |
|---|---|
| PC 上位机 | 20 套回归脚本 + `dclc.py` DSL 编译器 + LA 验证工具 |
| 协议 | UART 115200，帧 `[SYNC][STS][LEN:2][PAYLOAD][CRC16:2]`，**20 条命令** 0x01–0x62 |
| Core0 · FreeRTOS | 命令分发、下载前静态校验、deploy→staging、persist、shell / fs / sensors |
| SHM 64KB | Route/Param/State 三表（各 16B）+ 桶表 220×u16 + Force / Seq / Modbus 区 |
| Core1 · ISR | **100μs 硬拍**，三档分频（1×/10×/100×）+ 相位错开，19 个 IEC 原语 |
| 四域 | 连续控制 · 逻辑 · 顺序（Sequencer）· 通信（Modbus RTU 从站） |

**代码规模（wc -l，实测）**

```

  main/main.c            1089   协议命令处理 + 4 个安全守卫
  core0/core0_isr.c       474   引擎 ISR（分档扫描 / Force / Seq / 计时统计）
  core0/shared_mem.h      378   SHM 布局 + 编译期断言
  core0/modbus.c          370   通信域 Modbus RTU
  persist/persist.h       341   掉电保持

```

**引擎最值钱的三条不变量**（迁移中绝不能变）
1. 拍周期 100μs —— 分档 div0/1/2 的基准
2. 表布局与 SHM 偏移 —— 20 套脚本按偏移读，改了就全失效
3. 协议帧格式与 CRC —— 脚本零改动的前提

## 3. ★ 卡点：两根杜邦线，不是代码

### 证据链（本轮实测，可复跑）

| 判据 | 实测值 | 结论 |
|---|---|---|
| pyocd 探针 | Luxiaoban Flash Pro 在线，CPUID `0x411FC272` | 调试口可用 |
| **板上固件身份** | 复位向量 `0x080005FD`、SP `0x20020000`、`0x08002000` = `0xFFFFFFFF` | **是 `min_uart.bin`（1936B）** |
| 对照：dcl_h723.bin | 复位向量 `0x08002295`，15568B | ✗ 不匹配 → **板上不是交付固件** |
| 板子存活 | `g_heartbeat@0x20000020`: `0x51` → `0x5A`（4 秒） | 板子在跑 |
| **RX 方向** | PC 发 32 字节到 COM11，`g_rx_bytes@0x20000024` = **0** | 一字节没进 USART1 |
| **TX 方向** | PC 监听 + 回声测试 = **0 字节** | 心跳也没到 PC |

**双向都不通 ⇒ 排除"TX/RX 接反"（接反只会通一个方向）⇒ 物理连接不存在。**
DAPLink VCP（COM11, VID:PID `0D28:0204`）的 TX/RX 没有接到板子的 PA9/PA10。

### 顺带解决的记录矛盾

22:0x 记 `g_uart_isr_n = 0`（RX 零中断），22:2x 记"ISR 有进入、NE=1"。
真相：那两轮**板上跑的不是同一份固件**（22:2x 那轮是 min_uart）。
⇒ 新纪律：**诊断前先核对"板上固件是谁"** —— 读 `0x08000004` 复位向量与候选 bin 比对，10 秒。

## 4. 下一步

### 立刻（30 秒，用户侧物理动作）
**拔掉 DAPLink 接板子的 TX/RX 两根线，互相短接，PC 自发自收**
- 收到 → DAPLink VCP 是好的，问题在板侧接线（接 H1-5/6，或 U10 pin3/pin6）
- 收不到 → DAPLink VCP 不能当串口用，换 CH340（COM14）

### 接线通了之后
1. 烧回 `build/dcl_h723.bin`（板上现在是 min_uart）
2. `python tools/h723_proto.py --port COM11` → 要 **6/6**

### 然后回到代码（W1 波次）
1. **W1（P0）**: 0x11/0x12/0x13 + 0x20/0x21/0x22/0x23
   —— 把引擎配置态从编译期旋钮搬到运行期；S3 的 4 个安全守卫必须逐字搬
2. **W2（P0）**: 0x24 FORCE + persist（含 0x43 观测面）
3. **W3（P1）**: 0x44 Sequencer
4. **W4（P1）**: 0x60/0x61/0x62 Modbus 通信域
5. **W5（P2）**: macro + 传感器 + ADC

### 验收标准要重定义
`test_dcl.py` 的 T3 依赖 DHT22、T5 依赖 Shell→文件系统，H723 无这两个组件。
目标应是 **18 套全绿 + 2 套标注不适用**，不是"20 套全绿"。
