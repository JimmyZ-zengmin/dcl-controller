# E-K 端到端留点验证：**模型能算一个程序的执行时间**（2026-09-18）

> 本轮（E-A…E-J）每一步都在**标定** —— 测常数。**模型本身从未被"留点预测"验证过。**
> 本步就是那条验证：拿**没参与标定**的点，用模型算，再实测。
> 工具：`tools/exp_ek_holdout.py`。

---

## 模型（全部来自前序实测，本步**不重新拟合**）

```
di(t) = C_other + C_scan + Σ_ops ( m_op × 该 op 本拍条数 )
        474 TB     随 op 略变    m_op = 19 个常数
        （与程序无关） （19×N 两参数拟合）

单 op 程序的均值:  E[di] = C + m_op × E[nrun]
```

**判据**：
- **K-1** 留点偏差 ≤3% ⇒ 最大 **0.04%** ✅

偏差 **0.04%**。

## 2. ★★★ K-4 反证：**模型跨 division 成立**

用 **div0 标定的** `(C, m)` 去预测 **div1 / div2** 的同 op 程序：

| op | div1 偏差 | div2 偏差 |
|---|---|---|
| DIRECT | −0.5% | +0.5% |
| CMP | +3.0% | +0.3% |
| HYST | +3.1% | +0.6% |
| CLAMP | +3.1% | +0.4% |
| LPF | −0.8% | +0.3% |
| PID | −0.8% | +0.4% |

**最大偏差 3.1%，12/12 全过** ⇒ **模型不是"按 division 标定"的。**

★ 这条是本步**最强**的一条判据：它把"程序无关"从推论变成了**留点事实**。
（div1 那三个 +3% 是最大项，仍远小于任何工程判据的容差。）

## 3. 这些数字意味着什么

### 3.1 ✅ 可以主张的

> **给定一个程序，用"桶表（部署期算出的）+ 一张 19 项的原语常数表"，
> 可以在 **3% 以内**算出它的每拍执行时间 —— 而那张常数表与程序无关。**

**这正是原始需求**："程序一装载，预算就是算出来的，不是人填的。"
⇒ **现在这句话有了实测支撑**（留点 0.04%，跨 division 3.1%）。

### 3.2 ❌ 仍不能主张的

- **"零实测输入"**：那 19 个常数仍是**实测**的（E-F 已排除最直接的推导路径）。
  ⇒ 准确说法是"**一次标定、所有程序通用**"，不是"纯粹从代码推出"。
- **"任意程序"**：本步只验了**单 op、均匀**程序。
  混合 op、非均匀分布、`div0+div1+div2` 混合的程序**尚未验证**。
- **`nrun < 1` 区**：`nrun ≈ 1` 附近分辨率不足（E-I 已登记）。

| 3 | `nrun < 1` 区换逐拍仪器 | 已登记 |
| 4 | `dt` 偏 56% 对闭环的实际影响 | 已登记（影响的是控制质量, 不是"可算性"）|

★ **第 1 项最要紧**：模型对混合程序预测的是**求和**，
而"可加性"在本项目历史上**失败过一次**（`docs/exp-TCM-cycles` §A2.3：
`cost = Σc + k×转变数` —— 也就是说**相邻 op 之间有转变代价**）。
⇒ **混合 op 程序的偏差很可能不是 0，而是重现那个 `k`。**
**这正是下一个该测的东西。**
