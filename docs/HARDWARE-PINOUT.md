## 1. 逻辑分析仪接线（Saleae Logic 8，无模拟输入）

| LA 端 | 接板子 | 用途 | 状态 |
|---|---|---|---|
| **CH4** | **PA8** | 拍输出（ISR 每拍翻转一次） | `[实测]` 已接通，100μs 拍验证通过 |
| **GND** | 板子 **GND** | **共地（必须）** | `[实测]` |
| CH1 | PA9（USART1_TX）| 协议 UART 波形 —— 阶段 1 起用于协议级外部验证 | 待接 |
| CH0 / CH2 / CH3 | 待定 | 预留（DO 输出 / 外部触发） | — |

### ★ 三条硬性注意

1. **必须共地。** LA 的 GND 一定要接板子的 GND。不共地时读出来的全是垃圾
   （电平参考点漂移，看起来像"信号不对"）。
2. **信号线尽量短。** 实测 PA8 线上存在约 **0.01~0.12% 的窄毛刺**（几十~几百 ns），
   疑为跳线串扰或 LA 采样。缩短线长、或让 GND 线与信号线并走（双绞）可改善。
   → 测频工具已按"异常项单独计数"处理，毛刺**不影响拍周期**（众数稳定 100.0000μs）。
3. **本机（克隆 Logic 8）双通道数字采集不可靠。**
   单通道 16MHz 稳定；实测双通道 8MHz / 4MHz（CH0+CH4）时 **CH4 恒为 1、无边沿**。
   → 现阶段只用**单通道**采集，需要多信号时分时复用。

### 通道分配约定（建议，后续阶段沿用）

```
CH4  拍心跳 / 关键时序信号 (PA8)      ← 现在
CH1  协议 UART TX (PA9)               ← 阶段 1 起
CH2  DO 输出 / 位置脉冲                ← 接负载后
CH3  外部触发                          ← 需要时
GND  共地 (必接)
```

工具侧用 `--ch N` 指定通道，例如 `python la_tick_freq.py --cpu 400 --ch 4`。

### 4.2 ★ AI（模拟量）接线示例 —— 电位器 `[实测 2026-09-13]`

```
电位器一端   → U9 pin1  (3.3V)
电位器滑臂   → U9 pin10 (PA0 = ADC1_INP16)   ← 唯一必须接对的一根
电位器另一端 → U9 pin13 (GND)
```

- **验证**：`python tools/h723_adc_live.py COMxx`（实时刷新，边转边看）。
  实测两端点都命中：**3.3V 端 = 65535 (≈3.3000V) / GND 端 = 0 (≈0.0000V)**，
  极差 **65535** ⇒ 16bit 全量程可用。
- **三脚怎么认**：先接中间（滑臂）到 PA0；另两端接 3.3V/GND **接反了也不坏**，
  只是旋转方向与读数方向相反。要确认可用万用表：两端间是固定阻值（如 10kΩ），
  中间脚与任一端之间的阻值随旋钮变化。
- ★★ **未接线的 AI 脚应接地，不要悬空**：实测悬空的 PA1/PA4 会**跟随**被测通道一起变
  （极差 46591 / 30735）—— 高阻悬空 + "所有通道给最长采样时间" ⇒
  **采样保持电容的残留电荷串扰**。悬空不能当"干净对照"。

### 4.3 ★ ADC 参考电压链 `[原理图]`

```
3.3V ──[U15 磁珠 BLM18PG121SN1D 120Ω@100MHz]──┬── VDDA   (C16 10µF ∥ C17 100nF)
                                              └──[R1 0Ω]── VREF+
```
⇒ **VREF+ = VDDA = 3.3V（板载已连）**，所以固件里 `raw × 3.3 / 65535` 的量程假设**正确**，
pin12 不需要（也不应该）外接。要更高绝对精度需用 VREFINT 标定，
但 **VREFINT 在 H723 上挂在 ADC3(12bit)**，与 ADC1 的 16bit 通路不是一回事（见 `adc.h`）。

## 6. RS-485 / Modbus 接线 `[实测代码逐条查证 2026-09-13]`

| 板子侧 | 方向 | 对端 | 说明 |
|---|---|---|---|
| **PA2** | TX | 485 模块的 **TXD** | USART2_TX, AF7 (`modbus.c` mb_uart_enable) |
| **PA3** | RX | 485 模块的 **RXD** | USART2_RX, AF7 |
| **GND** | — | 模块 GND | ★ **必须共地**（三台设备连一起） |
| 3.3V | 供电 | 模块 VCC | 仅当模块支持 3.3V |

### 参数（固件侧，勿凭印象）

- **115200 8N1**，轮询收发（非中断），`tick_budget` = 4 字节/拍
- 从站地址 **1**；功能码 03 / 06 / 10
- ★ **地址是"字面 40001 制"**：固件直接判 `start >= 40001`
  ⇒ 第一路寄存器在线上是 **0x9C41**，不是 0x0000。上位机工具务必注意。
- 40001-40064 读区（只读，wire×100 取整）／40065-40128 写区（可读写）
- 写出读区 → 异常 02；qty=0 → 异常 03
- **固件没有 DE/RE 控制脚** ⇒ 模块必须**自动收发**；带 DE/RE 的模块需另行处理
- 默认 `src=0`（RX 走物理口）、`tx_uart=1`（响应从 PA2 真发）
  —— 后者是 2026-09-13 改的开机默认，见 `modbus.c` 的注释
  （零硬件隧道测试改用 `0x62` 切回 `tx_uart=0`；`0x61` 两种模式都能读回响应）

### 三个现场坑

1. **PA2/PA3 是 3.3V 域**。很多 485 模块是 5V 的 MAX485 —— 它的 RXD 输出会灌 5V 进 PA3。
   优先用 3.3V 芯片（SP3485/MAX3485）并从板子 3.3V 供电，或确认模块 TTL 侧是 3.3V。
2. **A/B 先按 A-A、B-B 接**；完全没反应时先对调 A/B（最常见）。
3. **丝印视角**：这类模块的 `TXD/RXD` 是**站在 MCU 视角**标的 ⇒ 与板子 **直连**
   （模块 TXD ↔ PA2、模块 RXD ↔ PA3），不要交叉。若是裸 MAX485 芯片（DI/RO 脚）才要交叉。

### 测试

```bash
python tools/mb_master_test.py --port COMx --counters
```
判据：T0 链路活性必须先过，之后 坏CRC/错站号 必须**无响应**、写只读区必须**异常 02**、
qty=0 必须**异常 03**、越界必须**异常 02**；`--counters` 顺带读固件侧帧计数对账。

### 6.1 实际模块丝印对应 (2026-09-13 用户提供)

手上有两个模块，丝印如下：

| 模块 | 引脚 |
|---|---|
| **USB 转 485** | `A` · `B` · `GND` · `5V` |
| **485 转 TTL** | `A+` · `B+` · `GND`(485侧) · `VCC` · `GND`(TTL侧) · `RXD` · `TXD` |

正确接法：

```
[USB转485]                      [485转TTL]                  [H723]
  A   ────────────────────────  A+
  B   ────────────────────────  B+
  GND ────────────────────────  GND
  5V  ── (可选) ──────────────  VCC        ← ★ 二选一, 不要同时接
                                 GND(TTL侧) ───────────────  GND  ★ 必须共地
                                 TXD        ───────────────  PA2
                                 RXD        ───────────────  PA3
```

★★ **`RXD/TXD` 是站在 MCU 视角标的** ⇒ 与板子**直连, 不交叉**
（"TXD"= 接你 MCU 的 TX）。若模块标的是裸芯片脚 `DI`/`RO`, 那才要交叉。
**不通就把这两根对调** —— 两种标法正好互为镜像, 一次对调就覆盖。

★ **VCC 供电二选一**
- 首选 **板子 3.3V (H1 第 8 脚)**: 电平天然 3.3V, 零风险; 缺点是若模块是纯 5V 的
  MAX485 可能不工作 (现象仍是"没反应")。
- 备选 **USB 转 485 的 5V**: 模块一定能跑, 但那边的 TTL 输出就是 5V ⇒
  建议在模块 `TXD → PA3` 之间**串 1 kΩ** 做限流保险。
  (**PA2/PA3 是否 5V 容忍: 手边没有官方数据手册, 未确认 —— 别赌。**)
- ★ 两处**不要同时接** (3.3V 与 5V 会打架)。

★ **最高频的漏项: 模块根本没供电**。USB 转 485 专门引出 `5V` 就是给对端模块用的。

### 6.2 ★ PA2/PA3 的 5V 容忍性 —— 已从官方数据手册确认

来源: `stm32h723zg.pdf` = **DS13313 Rev 5**, 第 60 页引脚表 (pymupdf 按坐标还原行):

| 引脚 | 表内标注 | I/O 结构 | 结论 |
|---|---|---|---|
| **PA2** | `USART2_TX(boot)` | **`FT_ha`** | **5 V 容忍** |
| **PA3** | `USART2_RX(boot)` | **`FT_ha`** | **5 V 容忍** |
| PA0 | — | `FT_ha` | 5 V 容忍 |
| PA5 | — | `TT_ha` | **仅 3.3 V** |
| PA9 | `USART1_TX(boot)` | `FT_u` | 5 V 容忍 |

图例 (同手册): **`FT` = 5 V tolerant I/O** ／ **`TT` = 3.3 V tolerant I/O**。

⇒ **485 模块用 5V 供电、TTL 侧输出 5V 是允许的, 不必串限流电阻。**
⇒ 唯一的边界: FT 只在**数字模式**下成立; 若将来把 PA2/PA3 配成 ADC 模拟输入,
   电压不得超过 VDDA (模拟模式下无 5V 容忍)。
⇒ 顺带印证: 手册把 PA2/PA3 标为 `USART2_TX/RX(boot)`, 与固件 `mb_uart_enable()`
   的配置 (PA2=TX / PA3=RX, AF7) **一致**。

### 6.3 首次联机的诊断记录 (2026-09-13)

链路: PC → USB转485 → A/B → 485转TTL → TTL → 板子 PA2/PA3

| 检查 | 结果 |
|---|---|
| 固件侧 Modbus 栈 | 正常 (`0x60` 隧道注入 → frames_rx/tx 都对, 响应已推到 USART2) |
| 板子从 PA2 真发一条应答 | **生成了** (`Δframes_tx=+1`), 但 485 口**收回 0 字节** |
| PC → 板子发 Modbus 请求 | 固件侧 `Δframes_rx=0` (一个字节没到) |
| 总线空闲监听 | 静默 (有确定电平); 发请求时偶收 1 字节 `0xff` (dongle 自身驱动毛刺) |

**⇒ 两个方向同时不通。** 板子侧已排除, 嫌疑集中在**双方共用的那部分**:
**A/B 接反** (能同时打死两个方向, 且与"偶收 1 字节 0xff"吻合) 或 **485 侧/ TTL 侧未共地**。
