## 二、编译固件

### 2.1 命令行编译（推荐）

```bash
# 设置路径
export MSYS_NO_PATHCONV=1
export MSYS2_ARG_CONV_EXCL='*'
ST="/c/ST/STM32CubeIDE_1.5.1/STM32CubeIDE/plugins/com.st.stm32cube.ide.mcu.externaltools.gnu-tools-for-stm32.7-2018-q2-update.win32_1.5.0.202011040924/tools/bin"
export PATH="$ST:$PATH"

# 进入目录
cd /d/STM/work/dcl-controller/firmware/h723-core0

# 清理并编译
rm -rf bld && mkdir -p bld/Src bld/Startup
MCU="-mcpu=cortex-m7 -mfpu=fpv5-d16 -mfloat-abi=hard -mthumb"
CFLAGS="$MCU -std=gnu11 -g3 -O2 -ffunction-sections -fdata-sections -Wall --specs=nano.specs -DSTM32 -DSTM32H7SINGLE -DSTM32H723ZGTx -DSTM32H7 -DDEBUG"

# 编译 startup
arm-none-eabi-gcc $MCU -x assembler-with-cpp -c Startup/startup_stm32h723zgtx.s -o bld/Startup/startup.o

# 编译 main
arm-none-eabi-gcc $CFLAGS -c Src/main.c -o bld/Src/main.o

# 编译 syscalls/sysmem
arm-none-eabi-gcc $CFLAGS -c Src/syscalls.c -o bld/Src/syscalls.o 2>/dev/null
arm-none-eabi-gcc $CFLAGS -c Src/sysmem.c -o bld/Src/sysmem.o 2>/dev/null

# 链接
arm-none-eabi-gcc $MCU -T STM32H723ZGTX_FLASH.ld --specs=nano.specs -Wl,--gc-sections -static --specs=nano.specs -mfpu=fpv5-d16 -mfloat-abi=hard -mthumb -Wl,--start-group -lc -lm -Wl,--end-group bld/Startup/startup.o bld/Src/main.o bld/Src/syscalls.o bld/Src/sysmem.o -o bld/core0_h723.elf

# 检查结果
ls -la bld/core0_h723.elf
```

### 2.2 编译标志说明

| 标志 | 说明 |
|---|---|
| `-mcpu=cortex-m7` | 目标CPU |
| `-mfpu=fpv5-d16` | 硬件浮点单元 |
| `-mfloat-abi=hard` | 硬件浮点调用约定 |
| `-O2` | 优化等级 |
| `-DSTM32H723ZGTx` | 芯片型号宏 |
| `-ffunction-sections` | 函数分段（用于链接时去除未用代码） |
| `-Wl,--gc-sections` | 链接时垃圾回收（减小二进制） |

## 三、烧录固件

### 3.1 烧录命令

```bash
# 烧录并验证
/c/Espressif/tools/python/v6.0.1/venv/Scripts/pyocd.exe flash -t stm32h723xx -e chip /d/STM/work/dcl-controller/firmware/h723-core0/bld/core0_h723.elf

# 仅烧录不验证（更快）
pyocd flash -t stm32h723xx /d/STM/work/dcl-controller/firmware/h723-core0/bld/core0_h723.elf
```

### 3.2 烧录后验证

```bash
# 读取关键寄存器
pyocd cmd -t stm32h723xx --read 0xE000ED08    # VTOR - 应为0x08000000
pyocd cmd -t stm32h723xx --read 0x20000010    # SAMPLES - 应递增
pyocd cmd -t stm32h723xx --read 0x20000018    # HEARTBEAT - 应递增
pyocd cmd -t stm32h723xx --read 0xE000ED28    # CFSR - 应为0x00000000（无故障）
```

### 3.3 烧录失败排查

| 症状 | 原因 | 修复 |
|---|---|---|
| "No target found" | DAP-Link未连接 | 重新插拔USB |
| "Flash failed" | Flash被写保护 | `pyocd erase -t stm32h723xx --chip` |
| "Verify failed" | 时钟配置异常 | 检查PLL/HSE配置 |

## 四、读取WIRE值

### 4.1 命令

```bash
# 读取WIRE[0..63]（前64路信号）
pyocd cmd -t stm32h723xx --read 0x20000300

# 读取特定WIRE
pyocd commander -t stm32h723xx -c "read32 0x20000300 4; exit"
```

### 4.2 WIRE_MAP布局

```
DTCM_BASE = 0x20000000
WIRE_MAP  = DTCM_BASE + 0x0300 = 0x20000300

地址           WIRE编号    典型用途
0x20000300    WIRE[0]     传感器输入(ADC/直接)
0x20000304    WIRE[1]     滤波后信号
0x20000308    WIRE[2]     PID输出
0x2000030C    WIRE[3]     限幅后输出
...
0x20000400    WIRE[64]    报警信号
0x20000500    WIRE[128]   数字输出影子
0x20000600    WIRE[192]   PWM占空比
```

## 五、调试技巧

### 5.1 排查BusFault

```bash
# 读取故障寄存器
pyocd commander -t stm32h723xx -c "read32 0xE000ED28 8; exit"

# CFSR位定义
# bit 0: MMARVALID (MemManage地址有效)
# bit 9: PRECISERR (精确数据总线错误)
# bit 15: NOCP (协处理器不可用)
# BFAR = 0xE000ED38 (故障地址)

# 清除CFSR（写1清除）
pyocd cmd -t stm32h723xx --write 0xE000ED28 0xFFFFFFFF
```

### 5.2 排查ISR不触发

```bash
# 检查TIM1状态
pyocd cmd -t stm32h723xx --read 0x40010010  # TIM1_SR (UIF=bit0应为1)
pyocd cmd -t stm32h723xx --read 0x4001000C  # TIM1_DIER (UIE=bit0应为1)
pyocd cmd -t stm32h723xx --read 0x40010024  # TIM1_CNT (应递增)

# 检查NVIC
pyocd cmd -t stm32h723xx --read 0xE000E100  # NVIC_ISER0 (bit25应为1)

# 检查VTOR
pyocd cmd -t stm32h723xx --read 0xE000ED08  # 应为0x08000000
```

### 5.3 性能验证

```bash
# 读取抖动统计
pyocd commander -t stm32h723xx -c "read32 0x20000008 4; read32 0x20000028 4; exit"

# PERIOD_MIN/MAX: 54400 = 100μs @136MHz (TIM1时钟)
# EXEC_MIN/MAX: ~500-2000 cycles (取决于路由数量)
```

## 七、坐标系

### 7.1 内存映射

```
0x00000000 - ITCM    (64KB, 指令)   ← 向量表在此
0x20000000 - DTCM    (128KB, 数据)  ← WIRE_MAP在此
0x20000300 - WIRE_MAP[1024]
0x20001700 - ROUTE_TABLE[1024]
0x20005700 - PARAM_TABLE[512]
0x20007700 - STATE_TABLE[256]
0x08000000 - FLASH   (1MB)
0x40000000 - 外设
0x40010000 - TIM1
0x40004400 - USART2
0xE0000000 - Cortex-M7 内部外设
```

### 7.2 TIM1寄存器

```
TIM1_BASE = 0x40010000
TIM1_CR1  = +0x00  (CEN=bit0)
TIM1_CR2  = +0x04  (MMS=bits[6:4])
TIM1_DIER = +0x0C  (UIE=bit0, UDE=bit9)
TIM1_SR   = +0x10  (UIF=bit0)
TIM1_ARR  = +0x2C  (自动重载, 13599 for 100μs)
TIM1_CCR1 = +0x34  (CH1比较值)
TIM1_CCR2 = +0x38
TIM1_CCR3 = +0x3C
TIM1_CCR4 = +0x40
TIM1_BDTR = +0x44  (MOE=bit15)
```

## 八、AI协作调试规范

> 当与AI协作修改代码时，遵循此规范可避免"改A忘B"的依赖缺失问题

### 8.1 修改代码前的AI提示模板

```
在修改代码前，请执行以下检查：
1. 阅读你要修改的函数/模块，列出它直接引用的所有外部文件（#include、.inc、外部函数调用）
2. 确认这些文件在当前工程目录是否存在（用find或ls检查）
3. 如果不存在，先创建/获取这些文件，再开始修改
4. 修改完成后，对比修改前后文件列表，确认没有遗漏依赖
```

### 8.2 常见依赖缺失场景

| 症状 | 缺失依赖 | 预防 |
|---|---|---|
| `fatal error: sin_lut.inc: No such file` | 外部.inc文件不存在 | 修改前检查所有#include |
| `undefined reference to 'xxx'` | 链接时缺少.c文件 | 添加所有源文件到编译命令 |
| `BusFault on write to 0x42xxxxxx` | GPIO基址错误（用了M4的bit-band） | 确认H7无bit-band，基址=0x58xxxxxx |
| `HardFault on interrupt` | VTOR未设置 | 启动文件中设置SCB_VTOR |
| `ADC_DR always 0` | 时钟/触发源未配 | 检查RCC_AHB1ENR和TIM1_CR2 |

### 8.3 AI问题分类处理

**AI问"要创建文件还是注释代码"时：**

```
先检查工程根目录和子目录：
1. 找是否已有同名或类似文件（如sin_table.inc、lut.inc）
2. 如果有→告诉我路径
3. 如果没有→生成所需文件（如4096点sin查找表）
4. 不要提议"注释掉"关键功能代码
```
