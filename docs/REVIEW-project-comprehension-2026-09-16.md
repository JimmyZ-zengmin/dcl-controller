## 1. 整体结构（一句话版，四层在代码里的对应）

```
① 引擎核心   engine.c   —— 扫描体 DEFINE_ENGINE_SCAN ×2 (FLASH/ITCM 同源码双实例) +
                          桶调度 engine_tick + 拍首 force + 顺序域 engine_seq_tick
② 外设能力   di.c / adc.c / hil.c / do.c / step.c / rtc.c / sd.c / as5600.c / i2c_sm.c
③ DCL 程序   SHM 里的 ROUTE/PARAM/STATE 三张表 —— **数据**，由 0x10/0x45-0x47 下发
④ 程序工程   tools/dclc.py + manifest + SD 持久化(prog_store.c)
```
**主循环**（`main.c:4046-4495`）= **服务型 + `wfi` 睡眠**：协议轮询 / 落盘 / SD 日志 / 免串口钩子 /
镜像发布 / 栈哨兵巡检，末尾 `wfi` 等下一拍唤醒。
**ISR**（`main.c:913-1571`）= ①入口 → 输入段(`di_poll`/`adc_poll`) → **引擎扫描** → 顺序域 →
通信域 → 输出段(`hil_out_poll`/`do_poll`) → 喂狗 → ⑦出口。

## 2. ★★ 程序面（③层）到底能看见、能做什么 —— **用 file:line 说话**

| 事实 | 出处 |
|---|---|
| 一条路由 = `src_type/src_index → op → dst_type/dst_channel`（+param/state/wire2/actuator/period）| `engine.c:245-299`（扫描宏）|
| 源只有 4 种：`SRC_SENSOR` / `SRC_WIRE` / `SRC_CONST` / `SRC_HMI` | `engine.c:205-223` |
| 原语白名单 = **19 个 `OP_*`**，部署期逐条校验 | `engine.c:844-850` |
| 目标只有 `DST_WIRE`；另外 `actuator_idx` 直驱 `ACTUATOR_STATUS[]` | `engine.c:842` / `:293-294` |
| ★ **`SRC_HMI` 被 deploy 期显式拒绝**，理由原文："未实现的能力必须在**下载期**失败，而不是运行时静默" | `engine.c:836-839` |

### ⇒ 由这四条推出的硬结论
**③层没有任何机制"发起一次 I2C 事务"** —— 它只能读槽、算原语、写槽。
所以契约 §3.2-C 那句"有了 C 通用事务 op，'接一个新器件' = **写一段程序**"——
**用一条 raw 事务命令兑现不了**（该结论已在契约 §3.7.1 定案，**本节用源码再确认一次**）。

**而器件能被程序用的真实形态就是 `as5600` 现在这样**：驱动读寄存器 → 写 `SENSOR[0]/[1]`
（`as5600.c:44-47`）⇒ 程序写 `SENSOR x FROM sensor[0]` 即可用。

## 3. 宿主↔设备面：既有的三种"范式"（G6-4 应当照抄，而不是发明）

### 范式 1 ★★ "上位机置标志 → 主循环服务"（**6 处**）
`g_persist_req` · `g_persist_auto` · `g_cmd_req`（接**真实** `proto_dispatch` 路径）·
`g_reinit` · `g_icache_req` · `sd_cfg_take(N)`（14 个钩子，含故障注入 `[13]`/`[14]`）
—— 均在 `main.c` 主循环里被消费。⇒ **新增一个"配置面"不需要新命令码**，这个范式就够了。

### 范式 2 ★★ 小注册表 + **两个观测量**（登记数 vs 实际执行数）
`engine.c:1109-1121`：`s_out_safe[ENG_MAX_OUT_SURFACES]` + `s_out_safe_n` +
`eng_output_surface_count()`，另有 `g_safe_surfaces_ran`。
理由（注释原文）：**要能区分"没登记"与"登记了没跑"**。
⇒ **设备绑定表应当照抄**：定长表 + `登记数` + `实际执行数`。

### 范式 3 ★★ "能力缺失 ⇒ 上传期拒绝"（`SRC_HMI` 先例）
见 §2 最后一行。⇒ 绑定表里出现固件不认识的能力/设备 ⇒ **拒绝下发**，而不是接受后静默不动。

### 范式 4 ★★★ **`bb_map_bind()` —— 这就是"绑定表"的既有形态**（`blackbox.c:161-193`）

黑匣子早就有一张 **60 槽的映射表**，形态与我们需要的设备绑定表**几乎一致**：

| 要素 | `bb_map_bind` 的做法 | 设备绑定表应照抄 |
|---|---|---|
| **条目编码** | `u32 = seg << 16 \| idx`（**段 + 索引**）| `u32 = dev << 24 \| addr7 << 16 \| reg << 8 \| len`（同为打包 u32）|
| **解析时机** | init 时**一次性**解析成源指针（`s_map_p[]`），不在拍内查表 —— 理由原文："一次查表+分支比一次取数贵" | 同样：init/下发时解析成"待轮询的设备描述" |
| **非法条目** | 落到 `s_map_zero` **兜底**（不是静默用垃圾指针）| 落"不绑定"，并计数 |
| **段内范围校验** | 每段 `idx < 64/128/…` 逐条核 | 每字段核（addr7 ≤ 0x7F、len ≤ 8、op 合法）|
| **布局一致性判据** | ★ **`bb_map_sum()` FNV-1a，固件与 PC 同一算法** —— "用来判**表头和固件是不是同一份映射**" | ★ **照抄**：设备表的校验和 ⇒ 上位机与固件对"布局是否一致"有机器判据 |
| **自检** | `默认表 60 槽全部有效 (0 个空槽)` —— 数**有效槽**（能失败）| 同样输出"有效槽数/总槽数" |
| **偏移来源** | `__builtin_offsetof` + `_Static_assert`，**不手写数字** | 同 |
| **可配置性** | **静态**（编译期表，`s_bb_map_def`）| ★ **本项是唯一的差异**：设备表要**上位机可写**（走 `0x21/0x23`）|

⇒ **结论：G6-4 不是"新发明一个机制"，而是"把 `bb_map_bind` 的形态用到一个新的解析目标上"**
（它的解析目标是 SHM 指针；设备表的解析目标是"设备寄存器轮询"）。
**这才是最小改动、最符合本项目既有基因的落法。**



| | A. 新增协议命令 `0x4B DEV_BIND` | **B. SHM 绑定表 + 复用现成 `0x21/0x23` 下发** |
|---|---|---|
| 对外接口面 | **新增命令码 + 新能力位 + 新宏** | **不加命令码**（SHM 写路径已在 `eng_valid_addr` 放行：`engine.c:1019-1029`）|
| 与既有范式 | 需新写一条分发 | 完全落在范式 1（配置面）+ 范式 2（表 + 两个观测量）|
| 缺能力时的行为 | 命令返回 NAK | 照范式 3：**下发期校验不通过就拒绝写入** |
| 风险 | 动 transport 协议段（该项目对协议"逐字不动"有强纪律）| 需在 `0x4A DEVICE_DESC`/manifest 里**公布表地址与布局**，否则上位机靠硬编码 |

**⇒ 推荐 B**，理由：**"对外接口面变更最小"** 是本项目的一条硬纪律（`transport.h` 开头写着
"协议一变，上位机脚本全部失效"）；而 B 的语义变更（某个 SHM 区有特殊含义）只需**登记 + 文档**，
不动任何线上格式。
**B 的三件必做**：① 表地址/布局进 `0x4A DEVICE_DESC` 与 `0x64 SYS_MANIFEST`；
② 下发期校验（能力位/参数范围）——照 `SRC_HMI`；③ 登记数/执行数两个观测量——照输出面注册表。
★ 并且**形态照 §3 范式 4（`bb_map_bind`）**：打包 u32 条目 + 一次性解析 + 兜底 + 段内范围校验
+ **与 PC 共用的表校验和** + 有效槽计数。**这是本项最重要的设计依据。**

★ 注：`0x45-0x4A` 那族之所以要新命令码，是因为它们要传 **6150 字节的程序包**（必须事务式分片）；
而一张 8 槽的绑定表只有 **几十字节** ⇒ `0x21/0x23` 完全够用。**这是"要不要新命令"的判据**。

## 6. 结论：GAP-6 的两条结论**不变**，但**落法更硬**

- **G6-4**：方向不变（**数据驱动的具名设备绑定**），落法由 A 改荐 **B**，且有三处现成范式可照抄。
- **G6-5**：仍降级（as5600 阻塞无危害；且 §3.6.1 已证明它不在 §3.6 的适用面内）。
- 新增一条判据：**"要不要新命令码"看载荷大小与是否需要事务式**（见 §4 末注）。
