# 修复报告 R1 — 停机安全态在真实物理输出上失守

日期: 2026-09-11 · 项目: `9.10 H723newest`
来源: `docs/audit/REVIEW-MIGRATION-FIDELITY.md` **一级 #1**
状态: **已修 + 已上板对照实证 + 已跑全量回归**

---

## 0. 一句话

范本里被定为 **P1** 的不变量「**停机 = 进安全态**」，在迁移线上以**新形态**失守：
H723 新增了一个真实物理输出面（HIL 的 PWM `TIM3_CCR1` / PA6），
而安全态还停在 S3 那套"清 GPIO 位图"的模型上 ⇒
**STOP 之后 PWM 保持最后占空比不动，执行器继续动作。**
本次把安全态的**契约**从"清某个寄存器"改成"覆盖全部已注册物理输出面"（结构性对策），
并用一个**能失败的对照构建**证明新判据不是空的。

---

## 1. 缺陷现场（可逐条读代码核对）

| 位置 | 事实 |
|---|---|
| `main.c` 主循环 | `hil_tick()` **无条件**每 10ms 跑（不在 `gate && RUN` 门内） |
| `hil.c` 输出臂 | 读 `WIRE[20]` → 算占空比 → **写 `TIM3_CCR1`（真实 PWM，PA6）** + 回写 `OFF_HIL_DUTY` 镜像 |
| `main.c` `h_stop_w1` | STOP 只把 `ENGINE_RUN=0` + 调 `eng_outputs_safe()`；**不碰 TIM3** |
| `engine.c` `eng_outputs_safe` | GPIO 清位已降级为"只观测"（H723 是 11 port × 16 pin = 176 位，u32 掩码不成立）⇒ `OFF_CTRL_GPIO_MASK` 恒 0、那段代码**不可达** |

**因果链**：STOP ⇒ 引擎停扫 ⇒ `WIRE[20]` 冻结在最后值 ⇒ `hil_tick` 仍无条件回写它
⇒ **PWM 保持最后占空比，永不归零**。

### 为什么回归没抓到

范本的 P1 判据（T23）读的是 **ESP32 的 GPIO 寄存器 `0x60004004`**，
在 H723 上被标为 N/A ⇒ **新输出面根本没有对应的停机安全判据**。
这不是"某人漏改一行"，是**契约形状有洞**：契约写"清某个寄存器"，
于是每新增一个输出面就漏一个。

## 2. 修法（结构性，不是补一行）

| # | 文件 | 改动 |
|---|---|---|
| ① | `engine.h` / `engine.c` | 新增**物理输出面注册表**：`eng_register_output_surface()` / `eng_output_surface_count()`。`eng_outputs_safe()` 末尾遍历调用全部已注册面（容量 `ENG_MAX_OUT_SURFACES=4`，当前 1 个）。**契约改为"覆盖全部已注册物理面"** |
| ② | `hil.c` / `hil.h` | 新增 `hil_outputs_safe()`：`TIM3_CCR1 = 0` **并回写 `OFF_HIL_DUTY` 镜像**（只清寄存器不回写 ⇒ 安全态读不出来，就成了不可核对的宣称） |
| ③ | `hil.c` `hil_tick()` | 输出臂加 **`ENGINE_RUN` 门控**：未运行就把 u 压到 0。★ 与 ① 并存的原因：STOP 的即时清零只覆盖"走了 0x12 命令"这一条路径；门控让安全态成为**持续成立的性质**（任何遗留非零占空比都会在 ≤10ms 内被纠回）。**反馈眼 ADC 不受门控**——停机时仍要能读现场值 |
| ④ | `main.c` `h_reset_w1` | 也调 `eng_outputs_safe()`。★ `cold_start_reset()` 整段 memset 清的是 **SHM**，而 **`TIM3_CCR1` 不在 SHM 里** —— "变量归零 ≠ 物理输出归零"的标本（见 §4 的诚实标注） |
| ⑤ | `main.c` | 新增可观测：`g_out_surfaces`（0x38 尾部 **byte 38**，响应长度 38 → 39）+ `g_safe_surfaces_ran`。★ 为什么两个都要：**登记数为 0 时 duty 恰好也是 0**（没人写它）⇒ "没登记"与"已进安全态"在读数上完全一样，必须要有一个独立的量把两者分开 |
| ⑥ | `main.c` 初始化 | `hil_init()` **之后**注册（先配硬件、再登记安全态，避免"已登记但硬件没配"的窗口） |

### A/B 对照开关 `DCL_HIL_SAFE`（默认 1）

* `1` = 交付行为（注册 + 门控）
* `0` = **改前行为**（不注册 + 不门控）—— **只为对照存在**

**静态验证（无需上板）**：`HIL_SAFE=0` 时 `eng_register_output_surface` 被 `--gc-sections`
整个回收（`nm` 计数 0），交付档为 1；两份 `dcl_h723.bin` 不同（33 308 vs 33 316 B）。

## 3. ★ 能失败的对照（本次的核心证据）

新判据 **H-2**（`tools/h723_w5.py`，**零接线**，读 `TIM3_CCR1` 镜像）在**两份构建上各跑一次**，
方法与脚本完全相同，只有 `DCL_HIL_SAFE` 不同：

| 判据 | 对照档 `HIL_SAFE=0` | 交付档 `HIL_SAFE=1` |
|---|---|---|
| 板上构建核对 `st[38]` | 0 ✓（确认刷的是对照档） | 1 ✓（确认刷的是交付档） |
| **H-2a** 阳性对照：RUN 且 `WIRE[20]=1024` ⇒ 占空比非零 | PASS `duty=1000` | PASS `duty=1000` |
| **H-2b** ★STOP 后归零（两次相隔 150ms） | **FAIL** `duty=1000, 再等150ms=1000` | **PASS** `duty=0, 再等150ms=0` |
| **H-2c** 重新 START ⇒ 回到非零（排除 PWM 永久坏） | PASS `duty=1000` | PASS `duty=1000` |
| **H-2d** ★输出面登记数 ≥1 | **FAIL** `registered=0` | **PASS** `registered=1` |
| 合计 | **16 PASS / 2 FAIL / 0 SKIP** | **18 PASS / 0 FAIL / 0 SKIP** |

* **H-2a 是必须有的阳性对照**：没有它，"STOP 后 duty=0" 会被 "duty 恒 0"（PWM 没配好、
  或输出面根本没登记）通过 —— 那就是一个空判据。
* **H-2b 的"两次相隔 150ms"**：要证的是"**持续**为 0"，不是碰巧某一拍读到 0。
* 刷写后**先核对 `st[38]`** 再跑判据（"板上跑的到底是哪个构建"必须先确认 ——
  本项目有过"把自检版当交付固件读回一轮数据"的事故）。
* 判据为什么用镜像而不是示波器：镜像是固件在**写 `TIM3_CCR1` 的同一处**回写的同一个数，
  而"镜像 == 按公式算出的计数值"这一点由既有 H-0 独立把着。有 LA 时夹 PA6 可作二阶证据。

### 顺带（HIL 跳线已接，物理回环一并通过）

`H-1a` 满幅 3.300V / 零幅 0.001V（轨道判据）；
`H-1b` u=512 → 1.650V（对照档）/ 1.857V（交付档），均在 [1.2, 2.1] 窗内。
**两次读数不同是正常的**：无 RC 滤波时 50% 占空比走"16 次跨周期平均"，
受采样相位影响（判据已按此设计成区间，不是定值）。

## 4. ★ 诚实标注：RESET 路径**不具备判别力**（不记分）

审查建议里写的是 "STOP/**RESET** ⇒ `TIM3_CCR1 = 0`"。实际实测（两档各一次）：

```
对照档 HIL_SAFE=0:   RUN 后 = 1000   →   RESET 后 = 0
交付档 HIL_SAFE=1:   RUN 后 = 1000   →   RESET 后 = 0
```

**两档同值 ⇒ 这条判据无法区分改前改后，故不作为判据记分**（本项目纪律：
"不能失败的判据要显式标注，不假装有用"）。

**机制**：`h_reset_w1` 走 `cold_start_reset()` 整段 memset ⇒ **`WIRE[20]` 也被清零**
⇒ 即使输出臂没有 RUN 门控，它算出的 u 也只是 0 ⇒ 物理输出**侥幸**归零。

⇒ 结论分两层：
* 真正可被利用的洞**只在 STOP 那条路径** —— `h_stop_w1` **刻意不清 `WIRE`**
  （"停机时当前值必须是可读的现场信息"），那正是 H-2b 抓到的。
* 本次给 `h_reset_w1` 补的 `eng_outputs_safe()` 属**纵深防御**（把"侥幸安全"改成
  "显式安全"，不再依赖 `WIRE` 恰好为 0），但它**无法被黑盒判据证实**，故只记录不记分。

## 6. 本次顺带发现的两个工具/环境问题（与本修复无关，但会误导后来人）

1. **`build/tmp` 间歇性 Permission denied**（本次构建三次被打断）：
   `cc1.exe: fatal error: can't open '...\build\tmp\ccXXXXXX.s' for writing: Permission denied`
   —— 随机文件、随机临时文件名、**重跑即收敛**；失败文件里包含本次**全程未改动**的
   `clock.c` / `macro.c`。症状极像"刚改坏了代码"，实际与代码无关（疑似实时扫描锁新建文件）。
   **处置：先原样重跑一次再判断。**
2. **`find_port()` 会在 CH343 在场时认错口**：它只按 `"CH340" in d or "1A86" in d` 匹配，
   而 **CH343 也是 VID `1A86`**（`h723_modbus.py:91-99`）。本机同时插着
   CH340(COM14，H723 协议口) 与 CH343(COM7，ESP32-S3) ⇒ 谁先被枚举谁被选中。
   **处置：跑套件一律显式 `--port COM14`**（本次全部显式传参）。
