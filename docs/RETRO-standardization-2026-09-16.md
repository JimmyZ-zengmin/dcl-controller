## 1. 三条不可协商要求（PLAN §1）

| # | 要求 | 判定 | 证据（可复跑） |
|---|---|---|---|
| **R1** | 程序必须能走通信上传，**且上传后必须正确** | ✅ **达成** | 链路：`.dcl` → 编译 → `0x45/46/47` 上传 → SD A/B → 上电自动装载（不碰 flash）。实测 `上传→复位` ⇒ `boot_loaded=1`、`0x38 n_routes=7 applied=1`。**"不能漏错"五道闸全部落地且各有一条判据**（`REF` §7）：① 帧 CRC16 ② 清单 CRC32+total_len ③ 写后回读 memcmp ④ A/B + 单调 seq ⑤ **装载前重跑上传时同一套静态校验**（`prog_validate()`，上传与装载调**同一个函数**）|
| **R2** | 核心与程序**物理隔离**（核心烧录 / 程序通信+持久介质） | ✅ **达成** | 程序区在 **SD 卡尾 A/B 两区**，代码区在片上 flash；`0x49 PROG_ERASE` 可证明"擦程序不影响代码"（实测 `ab_valid 3→0`、`seq A/B 3/4→0/0`、`生效=无`）。⇒ **"改一个程序"不再等于"换一台机器"** |
| **R3** | 核心与程序能**互相确认版本与能力** | ✅ **达成** | 程序清单带 `min_fw` / `req_caps`（u32），**两个时点都校验**：上传期 `main.c:2614/2617`（`PROG_RC_MINF` 拒绝 + `req_caps & ~DCL_CAP_H723_IMPL` 拒绝）；装载期 `prog_store.c:322`。核心侧自述走 `0x01 GET_VERSION`（fw+caps）+ `0x4A DEVICE_DESC`（fw+caps+6 条具名设备）|

★ **R3 的落实方式值得单说**：它把"版本错配"从**运行期以'行为不对'暴露**变成了**上传期明确拒绝** ——
这正是 R3 存在的全部理由。

## 5. ★ 元层面：这一轮真正证明了什么、以及暴露了什么

### 5.1 证明了"先契据后代码 + 能失败的判据"这套办法**真的抓得到东西**
- 本轮（G6-4 落地）**挖出并修掉 6 条真缺陷**，全部属"**无报错、只有值是错的**"族：
  在飞换表用错 lane / 事务结果归属不明 / 令牌必要但不充分 / 先占门后验参（引用计数泄漏）/
  **延迟释放丢释放（`refs` 泄漏 61 ⇒ AS5600 永久饿死）** / 一个槽两个语义。
- ★★ **抓到它们的主力是"为可解释性加的观测"**：`refs`、`skip_n`、`done_req`、`per-cmd 计数`。
  **本项目的经验已可下结论：为可解释性加的计数器，回报率高于任何一次"我觉得没问题"的评审。**
- ★ **一处修复消掉三个看起来无关的症状**（`refs` 泄漏 / 跑测顺序依赖 / `dev_bind` 只能跑到 53-1-2）
  ⇒ **"症状像三个问题，实际是一个"** 是本项目的高频形态。

### 5.2 暴露的**结构性缺口**（比上面 4 条挂账更值得处理）
1. ★★★ **"契据 vs 实现"的对账目前全靠人工审计**。两轮独立审计共发现 **5 处**契据与实现不一致
   （§3.8.5 未落地 / 码2"不回 done_seq"与"拒绝也回 done_seq"字面冲突 / §3.7 未同步令牌 /
   §3.8.3 未提接受时也写 `reject=0` / 工具侧 `expect_len` 只说不做）。
   ⇒ 建议：像 `dcl_static_check.py` 那样，**把契据里可机检的断言做成闸门**（例如"契据声称存在的
   SHM 字段名必须在 `engine.h` 里出现且被 `_Static_assert` 守住"）。
2. ★★ **提交信息/注释仍会与实现漂移**（本轮 1 例：提交信息写"连读两遍"，实现是连读 3 次 + magic 旁证）。
   ⇒ 这条已入 memory §九（写提交信息前先看 `git diff --cached`）。
3. ★★ **"板子是独占资源"这条纪律我违反了**，代价是一个错误在**三个地方以三种面貌**出现
   （一次串帧假故障、G6-2 顺序依赖被误读、一次 `SENSOR[15]=7.5` 假命中）。
   ⇒ 已入 memory §九；**并行 worker 不得同时访问同一串口**。
4. ★ **归因判据与回归判据没分开**：一次"当前固件 `refs` 增量 +0"被用来归因**历史缺陷**，
   得出与真因相反的结论。⇒ 也入 memory §九。

### 5.3 达成度自评（诚实版）
- **设计目标（R1–R3 + 四层 + 持久化 + 能力边界）：达成**，且每条都有可复跑的判据，不是"觉得可以了"。
- **纪律（PLAN §0 四条）：3 条完全做到，1 条（每刀带对照）有 1 处未做到**（`0x4A` 尾块）。
- **工程质量：判据体系比改革前强得多**（4 道构建闸门 + 10 种变异对照 + 每条判据带失败路径），
  但**"一致性"仍靠人**（§5.2 第 1 条）—— 这是下一步最该投入的地方。
