## 1. 一句话现状

**MCU 侧的脉冲是真的在输出的**（引脚实测在 0/3.3 V 之间翻转，见 §2 E4），
但**驱动器没有把这个脉冲变成步数**。因此问题在"PA6 之后"的某个环节，
或者在一个"看起来没在跑脉冲"的代码路径上（§4 C1）。

**先前的两次结论都已作废**，理由见 §2 E1–E3。**不要沿用"线断/插错端子"这个方向。**

## 2. 已确证的事实 / 已排除的假设

### E1 ★ 推挽输出不可能把引脚抬到 VDD 以上 —— 这是本轮唯一没被推翻的物理约束

现场读数：`PA6(u9 pin19) = 0.116 V`、`TB6600 PUL− = 4.5 V`、`PUL+ = 5 V`、
`DIR− = 3.4 V`、`ENA− = 3.4 V`、三个 `+` 端都是 5 V。

`4.5 V > 3.3 V(VDD)` ⇒ **那一刻 MCU 没有在驱动 PA6**（引脚是高阻），
4.5 V 是外部经"驱动器内部电阻 + 光耦 LED"把它拉上去的。
⇒ **`PUL− = 4.5 V` 不能作为"断线"的证据。**（前一版报告据它下了"线断"的结论，**错**。）

### E2 ★ 引脚在 AF 模式下、通道关断时是**高阻**（实测）

用芯片自己读 `IDR`（引脚**真实**电平，与谁在驱动它无关）：

| 状态 | `GPIOA_MODER[PA6]` | `TIM3_CCER.CC1E` | **`GPIOA_IDR` bit6** | 判读 |
|---|---|---|---|---|
| `probe high` | 1（GPIO 输出） | 0 | **1** | 我们在驱动 3.3 V ✓ |
| `probe low` | 1（GPIO 输出） | 0 | **0** | 我们在驱动 0 V ✓ |
| `probe af`（TIM3） | 2（AF） | 0 | **1** | ★ **我们没在驱动 ⇒ 高阻** |

⇒ **"无脉冲"时 `PUL−` 的电平完全由外部上拉决定，与被测的脉冲通路无关。**
这就是为什么"空闲态量电压"这条路一直把人带偏。

★ 复现：`python tools/h723_stepper_test.py probe high|low|af`

### E3 ★ 缓存与实时寄存器是两个量（这是 C1 的观测盲区）

`op=19` 原来报的 `ARR`/`CCR1` 是 **`step.c` 自己缓存的 `g_step_arr` / `g_step_ccr1`**，
**不是硬件寄存器的实时值**。任何别处改 `TIM3_CCR1` 都不会反映到那个读数上。
⇒ 已在应答尾部追加**实时** `TIM3_CCMR1` / `TIM3_CCR1` / `TIM3_ARR`（见 §5）。
★ 本项目的已知族："**同一个量两处存放 ⇒ 只改一处就静默失效**"。

### E4 ★ 脉冲确实被输出到了 PA6（实测，本轮最有价值的一条）

起 500 Hz 脉冲时，异步采样 `GPIOA_IDR` bit6：**0 出现 38 次 / 1 出现 49 次**。
（对照组 CC1E=0：59 次全是 1。）

⇒ **AF2 / TIM3_CH1 通路是接在 PA6 上的，引脚真的在翻转。**
⇒ "`MODER=AF` + `AFRL=2` + `CNT` 在跑 + `CC1E=1`"这四件套**这次恰好是对的**，
但请注意它**在原理上没有证明力** —— 能证明"引脚在动"的只有 `IDR`。

★ 复现：`python tools/h723_stepper_test.py idrwatch 500 1.5`

### E5 已排除：AS5600 / 编码器链

`raw` 长期稳定、`ok_n` 增长、`err_n = 0`、`NAK = 0`，转轴时能跟满一圈（跨度 4092/4096）。
⇒ 与"电机不转"无关。

### E6 已排除：上电安全态

`CC1E = 0`、`GPIO_MASK = 0x0F00`、`PE8~PE11 = 1`（IDR 与 ODR 都是 1）
⇒ 上电不会自己走。★ 注意此判据用的是 **`IDR`（引脚实际电平）**，不是意图变量。

### E7 已排除：步进限时逻辑本身

`step_tick` 的首次对齐（`s_sync`）与 `dt` 钳位已修；实测请求 3.00 s → 实际 3.48 s 停止。

### E8 已排除：`op=19` 查询有副作用

`sub=0` 已改为**纯查询（零副作用）**，停止挪到 `sub=6`。
（此前 `sub=0` 是"停止"，导致每次查询都在关脉冲 ⇒ 结论全部作废。已修。）

### E9 已排除：应答缓冲区栈越界（本处唯一一处）

`op=19` 原声明 `uint8_t r[40]` 却写到 `r+64` 并 `ack(r,68)` ⇒ **越界 28 字节**（已修）。
已逐块核对 `main.c` 中所有 `uint8_t r[N]` + `put32(r+off)` 模式，**只此一处**。

## 3. 未定案的疑点（**审计清单，按优先级**）

### U1 ★★★ 脉冲到底有没有被 `hil_outputs_safe()` 清掉 —— 见 §4 C1

这是唯一一个**能完全解释"寄存器看着对、轴不动"**的代码路径，且**改动极小、随时可能发生**。
判据：

- `python tools/h723_stepper_test.py pulse 500 20000` → 记录 `CC1E` 与**实时** `CCR1`；
- 再触发一次引擎 STOP / 任意 `eng_outputs_safe()` 路径；
- 再读：若 **`CC1E=1` 而实时 `CCR1=0`** ⇒ 命中。
- ★ 只看缓存值（`g_step_ccr1`）**永远查不出来**。

### U2 ★★★ 3.3 V 高电平能不能真正关断 5 V 光耦

共阳接法靠 MCU 输出**高**来关断。光耦链是 `+5 V → R(驱动器内部限流) → LED → PUL−`：

| 内部 R | 3.3 V 高时链上电压 | LED | 后果 |
|---|---|---|---|
| ≈4.7 kΩ | 1.7 V | 基本不导通 | ✅ 正常计数 |
| ≈300~500 Ω | 1.7 V | **仍有数 mA** | ✗ 驱动器看到"一直导通" ⇒ **不计数** |

**这是与 E4 完全兼容的**：引脚确实在翻转，但驱动器分辨不出来。
判据（任选其一）：

1. **电流法**（最直接）：万用表 mA 档串进 `PUL− ↔ PA6` 回路，
   `probe low` 时读到的电流 ⇒ 就是 LED 导通电流；再 `probe high` 读一次。
   **两次电流差 ≈ 0 ⇒ LED 在 3.3 V 仍导通 ⇒ 命中。**
2. **器件法**：查 TB6600 板上 `PUL+` 到光耦之间的贴片电阻阻值。
3. **推测法**（旁证）：`DIR−` 在 MCU 驱动 3.3 V 时读 **3.4 V** —— 与"LED 在 3.3 V 仍导通"
   **不矛盾也不证实**（推挽输出会压住节点电压，看不出电流）。

**若命中，修法是开漏**（`0x39 op=19 sub=10 arg=1`，即 `GPIOA_OTYPER` bit6=1）：
低 = 灌电流点亮 LED；高 = **高阻**，由驱动器内部电阻把 LED 彻底关掉。
★ **前提：PA6 必须是 5 V 容忍（FT）脚 —— 这条尚未查证数据手册（见 U5）。**

### U3 ★★ `PA6 → PUL−` 这条通路本身的判据（尚未取到）

只有在 **PA6 被驱动**的状态下量的数才有意义：

```
python tools/h723_stepper_test.py probe high   → 量 PUL−（此时 PA6 与 DIR−/ENA− 形态完全相同）
python tools/h723_stepper_test.py probe low    → 量 PUL−
```

| PA6 档 | `PUL−` 预期 | 结论 |
|---|---|---|
| `high`（3.3 V） | **≈3.4 V**（与 `DIR−` 相同） | ✅ 通路好 |
| `low`（0 V） | **≈0 V** | ✅ 通路好 |
| 任一档 | 恒 ≈4.5 V | ✗ 通路断/插错端子 |
| 任一档 | 恒 ≈0 V | ✗ `PUL−` 被短到 GND |

★ **不要用 `probe af` 档去量**（那是高阻，见 E2）。

### U4 ★★ ENA 的有效极性从未实测

`g_step_ena_pol` 默认 0（"拉低使能"），当前 `ENA=0` ⇒ 按此假设驱动器是**失能**的。
**若实际极性相反，则现在驱动器一直是使能的。** 两种情形都必须先定案，否则后续实验结论不可用。

判据：上电安全态（`ENA` 光耦不导通）下用手转电机轴 ——
**转得动 = 失能 / 锁死 = 使能**；再 `enapol 1` 复测一次。

### U5 ★ 数据手册层面的三处未核实

1. **`PA6` 是否 FT（5 V 容忍）** —— 决定开漏方案能不能用（U2 的修法依赖它）。
   旁证：实测 PA6 在 Hi-Z 时被外部拉到 4.5 V 而 `IDR` 读数正确、无钳位迹象 ⇒ 倾向 FT，但**未查手册**。
2. **`PA6 = TIM3_CH1` 是否确为 AF2** —— E4 已从行为上证明通路通，但没见过手册原文；
   且 `docs/HARDWARE-PINOUT.md` 记录过本表"曾从一张 PNG 里读错一个脚"，来源可信度需要复核。
3. **`PA6` 的网络名同时是 `DCMI_PIXCLK`**，板上**有摄像头座** ⇒ 该脚可能有额外器件
   （上下拉/ESD/串联件）。若 U3 出现"`probe` 两档都不跟随"，第一嫌疑是它。

### U6 ★ 驱动器侧尚未核对的三件事

- **拨码实际位置**：细分应为 `S1=OFF S2=ON S3=OFF`（8 细分 = 1600 脉冲/圈）、
  电流应为 `S4=ON S5=ON S6=OFF`（1.5 A 档）。**以电机铭牌为准，绝不超过。**
- **电机相线**：`A+ / A− / B+ / B−` 是否与线圈对应（万用表量相间电阻；
  两组线圈各自导通、组间不导通）。
- **24 V 是否真到位**：`TB6600 VCC ↔ GND` 之间实测电压。

## 4. 代码级可疑点（审计重点）

> 全部为**静态可核**项：不需要跑板子，读代码 + 数偏移即可判定。

### ★★★ C1 `hil_outputs_safe()` 没有 `g_step_owns_tim3` 门 —— 同一个语义守了一处、漏了一处

```
src/hil.c:106   void hil_out_apply(...)  { ... if (g_step_owns_tim3) { return; } ... }   ← 有门 ✓
src/hil.c:167   void hil_outputs_safe(void) { ... TIM_CCR1(TIM3) = 0u;  ... }           ← 无门 ✗
```

- 两条路径都会写 `TIM3_CCR1`，**只有每拍输出臂做了让路**。
- `hil_outputs_safe` 是通过 `eng_register_output_surface(hil_outputs_safe)`
  （`src/main.c:3447`）注册进"物理输出面"的，**任何引擎 STOP / RESET / `eng_outputs_safe()` 都会调它**。
- **后果**：若在脉冲运行期间命中：
  - `TIM_CCER.CC1E` 仍为 1（`step.c` 不知道这事），
  - `TIM_CCR1 = 0` ⇒ PWM 模式 1 下 `CNT < CCR1` 永不成立 ⇒ **输出恒为低**，
  - ⇒ **光耦持续导通** ⇒ 驱动器收不到任何边沿 ⇒ **不计数、轴不动**。
- ★ **观测盲区**：`op=19` 原来只报缓存 `g_step_ccr1`，这个故障在读数上**完全看不见**。
  本轮已补实时寄存器回读（§5），请优先用它复核。

**这一条与本项目的已知族完全同型**："一个语义两处存放，只改了一处 ⇒ 静默失效"
（历史同类：定时器 DMA 的路由 + 门控分开存放；`MB_MAX_FRAME` 一处常量两个语义）。

### ★★ C2 `DCL_DO_LATCH=0` 时 `do_latch_init()` 仍被无条件调用

```
src/do.h:46        #define DCL_DO_LATCH 0            ← A 档: CPU 直写 BSRR
src/do.c:90,191,211   #if DCL_DO_LATCH ... #endif   ← do_init / do_poll / do_outputs_safe 都做了分档
src/do.c:98-178       void do_latch_init(void) { ... }   ← ★ **没有** #if，也没有早退
src/main.c:3458       do_latch_init();              ← 无条件调用
```

- ⇒ A 档下 **MDMA ch0 + DMA2 S0 + DMAMUX1 仍然全部使能**，
  每拍把 `OFF_DO_SHADOW`（A 档下**从没被任何代码写过**，恒 0）锁存进 `GPIOE_ODR`。
- 该链的尺寸/地址配置是 **byte 尺寸 + 目的地址固定** ⇒ 只写 `ODR` 的**第 0 字节**。
- ⇒ **`PE0..PE7` 被每 100 µs 覆写成 0**（`do_poll` 的 `BSRR` 置位在 ≤100 µs 内被打回）；
  `PE8..PE15` 不受影响（在 ODR 高字节）。
- ⇒ **本轮不影响步进**（步进用 PE8/PE9），但 **DO 通道 0..7 实际不可用**；
  且这是"**同一个开关两档行为不一致**"的隐患。
- 另注：同一寄存器的两个写手（CPU 写 `BSRR` / MDMA 写 `ODR`）在**同一拍**竞争，
  谁后落谁赢 —— 属**随机性**故障，不是确定性故障。

### ★★ C3 `step.c` 从不写 `TIM_CCMR1` —— 隐含依赖 `hil_init`

`step_init()`（`src/step.c:53-60`）只写了 `PSC / ARR / CCR1 / CCER / CR1 / EGR`，
**通道模式（PWM1 + OC1PE）完全依赖 `hil_init()` 在 `src/hil.c:67` 那一行**。

- ⇒ 若 `hil_init` 被跳过、被开关关掉或改动，`OC1M = 000`（冻结模式）⇒
  输出不跟随比较值 ⇒ **永远不产生脉冲**，而 `CCER / ARR / CCR1 / CNT` 读回**全部"正常"**。
- ⇒ 建议 `step_init` 自己幂等地写一次 `CCMR1`，去掉这个隐含顺序依赖。
- ★ 这是"**该写而没写**"型缺陷（本项目已知族，见用户级记忆里的 ADC `PCSEL` 事故）。

### ★★ C4 限时截止里 `0` 同时表示"不限时"和"已到期"

```
src/step.c:103   g_step_deadline_tick = ms;      /* 存"剩余毫秒"; 0 = 不限时 */
src/step.c:138   if (g_step_deadline_tick == 0u) { return; }   /* ← 到期后被置 0, 也走这里 */
```

- ⇒ **限时是一次性的**：到期 ⇒ 置 0 ⇒ 之后任何 `step_set_rate(hz)`（未重新武装）
  **无限跑**，保护静默消失。
- ⇒ 建议拆成两个量：`deadline_armed`(bool) + `deadline_tick`(u32)。**不要用一个值表两个语义。**

### ★ C5 `g_step_owns_tim3` 是"单向声明"

`src/step.c:14` 硬编码为 1，**没有任何路径能把它设回 0**。
将来若要恢复 HIL 使用 TIM3，没有回收协议。属设计债，记一笔。

### ★ C6 `step_set_rate()` 在改频率时会开出一个"高阻窗口"

`src/step.c:77-82`：先清 `CC1E` ⇒ 改 `ARR/CCR1` ⇒ 再置 `CC1E`。
清了 `CC1E` 之后引脚**是高阻**（E2 已证），高阻期间电平由外部上拉决定。
频繁改频率 ⇒ 反复出现不确定电平窗口。对当前 500 Hz 应用无影响，但属可改进项。

### ★ C7 `hil_init` 把 `PA6` 设成最高速输出档（`OSPEEDR |= 3<<12`）

`src/hil.c:57`。500 Hz 完全不需要最高速档，边沿越快 EMI 越差。可降档。

## 5. 仪器与复现方法

### 5.1 `0x39 op=19` 命令族（步进控制 + 诊断）

| sub | 参数 | 作用 | 副作用 |
|---|---|---|---|
| 0 | — | **只查询** | 无（★ 曾经是"停止"，已修） |
| 1 | Hz | 起/停脉冲（0 = 停） | 改 `TIM3` |
| 2 | 0/1 | 方向 | 改 `PE8` |
| 3 | 0/1 | 使能 | 改 `PE9` |
| 4 | ms | 限时（0 = 不限） | 见 C4 |
| 5 | 0/1 | ENA 有效极性 | 改 `PE9` |
| 6 | — | 停止 + 失能（安全态） | 停脉冲 |
| **7** | — | **PA6 → GPIO 输出 0 V** | 停脉冲 + 改 `GPIOA` |
| **8** | — | **PA6 → GPIO 输出 3.3 V** | 停脉冲 + 改 `GPIOA` |
| **9** | — | **PA6 → 还原 TIM3_CH1（AF2）** | 停脉冲 + 改 `GPIOA` |
| **10** | 0/1 | **PA6 输出类型：推挽 / 开漏**（U2 的修法） | 改 `GPIOA_OTYPER` |

### 5.2 应答布局（**96 字节**，本轮扩过，尾部为新增）

| 偏移 | 内容 |
|---|---|
| 0 / 4 / 8 / 12 | 实际频率 / 方向 / 使能 / 剩余限时 ms |
| 16 / 20 / 24 | `TIM3_CCER` / **缓存** `ARR` / **缓存** `CCR1` |
| 28 / 32 / 36 | `GPIO_MASK` / AS5600 raw / `step_stop_n` |
| 40 / 44 / 48 | `GPIOE_ODR` / `GPIOE_MODER` / ENA 极性 |
| 52 / 56 / 60 | `TIM3_CNT` / `GPIOA_MODER` / `GPIOA_AFRL` |
| 64 | `g_step_dt_max` |
| 68 / 72 | `GPIOA_ODR` / `GPIOA_OTYPER` |
| **76 / 80** | **`GPIOA_IDR`**（PA6 = bit6） / **`GPIOE_IDR`**（PE8..11 = bit8..11） |
| **84 / 88 / 92** | **实时 `TIM3_CCMR1` / `TIM3_CCR1` / `TIM3_ARR`** |

★ 68/76/80/84 是**本轮新增**：`IDR` 判"高阻 vs 被驱动"，实时寄存器判 C1。

### 5.4 手动读（不依赖上位机）

```c
/* 判"脉冲有没有被清掉": CC1E 与实时 CCR1 必须同时看 */
TIM3_CCER  @ 0x40000420     /* bit0 = CC1E: 1 = 通道开 */
TIM3_CCR1  @ 0x40000434     /* ★ 实时, 不是 step.c 的缓存 */
TIM3_ARR   @ 0x4000042C
TIM3_CCMR1 @ 0x40000418     /* OC1M[6:4] 必须 = 110b (PWM1) */
GPIOA_IDR  @ 0x58020010     /* bit6 = PA6 的真实电平 */
GPIOA_ODR  @ 0x58020014     /* bit6 = 我们"以为"的输出 */
GPIOE_ODR  @ 0x58021014
```

## 6. 建议的审计顺序（最少来回）

1. **C1**（读代码即可定案：`hil_outputs_safe` 是不是真没门）+ 抓一次 `CC1E=1 而实时 CCR1=0` 的现场。
2. **U3**（`probe high` / `probe low` 两档量 `PUL−`）—— 把"通路"这件事一次性定死。
3. **U4**（手转轴判 ENA 极性）—— 不然后面所有"轴不动"的结论都不可用。
4. **U2**（mA 档量 PUL 回路电流）—— 决定要不要上开漏。
5. **U6**（拨码 / 相线 / 24 V）—— 纯硬件旁证。
6. C2 / C3 / C4 是**独立缺陷**，不阻塞上面，但都该修。
