# E-P 转变代价 `k` 跟什么有关？（2026-09-18）

> 起因：E-L 测出**全局** `k` 不是常数（每转变 8.50 → 5.56 TB，严格交替 1.29），
> 而 `docs/exp-TCM-cycles` §A2.3 当年测得 `k` **随 op 对而变**
> （`DIRECT+PID = 10.0 cyc`、`LPF+PID = 5.50 cyc`）。
> ⇒ 两者**共线**（本轮设计里"op 对"与"块大小"同时变）⇒ 本步**把每拍条数钉死**，只改 op 对。
> 工具：`tools/exp_ep_op_pair_k.py` · 分析 `.tmpctl/ep_analyze.py`。

---

## 1. 设计

**n=128、div0、两种 op 各 64 条**，只用 4 种排列（block = 64 / 16 / 4 / 1）
⇒ 转变数 1 / 7 / 31 / 127，而**每条 op 的总数恒为 64**
⇒ `Σ_ops` 那一项**恒定** ⇒ 增量只能来自转变。

`k_ab` 用 **block=64/16/4 三点**拟合，**block=1 留点检验**（不参与拟合）。

---

## 2. ★★★ 结果：`k_ab` 是**成本差**的严格函数

| op 对 | 成本差 (TB/条) | `k_ab` (cyc/转变) | block=1 每转变 (TB) |
|---|---|---|---|
| DIRECT+PID | 34.51 | **11.03** | 1.692 |
| LPF+PID | 14.49 | **5.03** | 2.667 |
| DIRECT+CMP | 8.00 | **11.03** | 1.565 |
| NOT+OR | 0.49 | **4.97** | 2.549 |
| LPF+MUX | 0.00 | **4.97** | 2.510 |
| RATE+SR | **−4.08** | **−3.20** | 3.253 |

### 2.1 拟合：**R² = 1.0000，残差 0.00 cyc**

```
k_ab(TB) = 0.000 + 1.0000 × 成本差(TB)        R² = 1.0000
换成 cyc : k_ab(cyc) = 2 × 成本差(TB)
```

★★ **六对全部零残差。** 这不是"相关"，是**恒等式**。

### 2.2 ★★ 这直接解释了 E-L 与 §A2.3 的"矛盾"

`k_ab ≈ Δc`（便宜 op 更便宜、贵 op 更贵）：

```
每周期总成本 = Σ_ops(m_op × 该 op 条数) + Δc × 转变数
```

在 block=1（**严格交替**）下：若两 op **条数相等、交替出现**，
则**多出的贵 op 被等量的便宜 op 抵消** ⇒ `Σ_ops` 项与"半半分明"相同，
而转变项又**恰好等于**那个"抵消掉的差" ⇒ **净效果 ≈ 0**！

⇒ **E-L 里 block=1 那个"离群"（1.29 TB/转变）不是反常，而是这条恒等式的推论。**

★ 也就是说：**E-L 的"每转变成本随块变小而下降"这个描述，其真正原因是
`k_ab ∝ 成本差`**，而不是"块大小本身有效应"。

### 2.3 为什么 §A2.3 当年以为 `k` 是"op 对常数"

它只测了 **2 对**（DIRECT+PID、LPF+PID），**两对的成本差都很大**（34.5 / 14.5）
⇒ 在那个区间里 `k` 看起来像"每对一个数"。
**本步测了 6 对（含成本差 ≈ 0 与负值）才看出它是成本差的函数。**

⇒ **"两三个点看不出函数形状"** —— 这是本步最有价值的教训。

---

## 3. block=1（严格交替）：**另一个 regime**，与成本差几乎无关

对 block=1 那一列拟合：

```
每转变(TB) = 2.631 − 0.0290 × 成本差        R² = 0.418
残差最大 1.67 cyc
```

⇒ **严格交替下，每转变成本几乎是常数（2.5 ~ 3.3 TB），与成本差无关（斜率 ≈ 0）。**
⇒ 这是**另一个机制**（可预测的分支/取指模式 ⇒ 流水线重叠），
与 block≥2 的"成本差"机制**不是同一个**。

★ 与 `exp-TCM-cycles` §A2.6 当年的记录一致：
> "唯一的离群是 **bs=1（严格交替）**：那是**分支预测器能完美学习的周期模式**，所以它反而便宜。"

**⇒ 三个独立实验（§A2.6 / E-L / E-P）都指向同一个机制。**

---

## 4. ★★ 对门（`OP_TRANS_COST = 25`）的判定：**不改**

| | 值 |
|---|---|
| 门用的常量 | **25 cyc/转变** |
| 实测最大 `k_ab` | **11.03 cyc/转变** |
| 余量 | **2.27×** |

⇒ **25 仍是保守上界** ⇒ **门的常量不需要改。**

### 4.1 已知的松处（登记）

- **严格交替**那一类：实测每转变 2.5~3.3 TB（5~6.5 cyc），
  而门按 25 cyc 计 ⇒ 127 次转变被算成 **3175 cyc**，实测只有 **826 cyc**
  ⇒ **过估 3.8×**
- 这是"界成立但不紧"的又一实例，与 E-A…E-L 的结论一致

### 4.2 若将来要收紧，**不要按 op 对建表**

| 方案 | 项数 | 依据 |
|---|---|---|
| 按 `(op_i, op_j)` 建表 | **19×19 = 361** | ❌ 本步证明它不是 op 对属性 |
| 按**成本差**分档/线性式 | **1 个式子**（`k ≈ Δc`） | ✅ R² = 1.0000 |

★ **`k ≈ Δc` 是一条恒等式，而不是一张表** —— 收紧时应沿这个式子做，
  并且它能**在部署期零成本算出**（`Δc` 从 `engine_op_cost()` 两张表直接取）。
★ 但要保留"严格交替"那个 regime 的保守处理（那一类 `k` 与 `Δc` 无关）。

## 6. 一个方法论收获（值得单独记）

> **"三个点看不出函数形状"** —— §A2.3 用 2 个 op 对得出"`k` 是 op 对常数"，
> 而本步用 6 对（含 `Δc ≈ 0` 与负值）才看出它其实是 `Δc` 的线性函数。
>
> ⇒ **当你想断言"某个量是 A 的函数"时，必须让 A 的取值覆盖它的整个范围，
> 包括零与负号。** 只在正区间取样，会把"线性关系"误读成"分类属性"。
>
> ★ 这与 §5.60（分组拟合掩盖自变量范围）是**同一族的第四次**：
> 前三次是"分组"与"代理变量"，这次是"**取样区间没覆盖零/负**"。
