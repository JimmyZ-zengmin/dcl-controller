# 异常路径与长稳覆盖 — 故障台账 + 注入/长稳套件（2026-09-13）

> 起因：整体评估（`ASSESS-PLC-readiness-2026-09-13.md` §3-②）指出
> **"异常路径与长稳几乎零覆盖"才是成熟度的门槛**，并给出实证 ——
> 一个 115200 连续帧下**几乎必然触发**的缺陷（ORE 未清 → 接收自锁死）存活了整条开发周期，
> 表现为"偶发"、本质是"必然"，靠 4 轮外部审计 + 一整天排查才定位。
> 用户定调：**"要出问题了问题自己出来，而不是找半天。设计要符合架构规律。"**

---

## 0. 设计原理（先讲规律，再讲代码）

两条规律决定了整个设计：

**规律一：现场自己留案底，胜过事后拼现场。**
485 那次事故的真正代价不是缺陷，是**找它的成本**。原因是异常发生时**现场没有任何案底** ——
手里只有"当前状态"，只能靠观测面**反推**过去发生了什么。

**规律二：判据必须能失败，且归因要分层。**
"注入 → 看有没有报错"是空判据 —— 一个"任何输入都记一笔故障"的坏固件也能全绿。

⇒ 落地为两层：
- **固件侧 `FaultLedger`**：首例（冻结现场）+ 末例 + 分类计数 + **自洽式**；
- **PC 侧 `fault_suite.py`**：单一入口，注入矩阵 + 长稳，每条注入必须同时证明
  (a) 预期分类**涨了** (b) 注入后**链路仍可用** (c) 台账**自洽**，
  再加一条**反向判据** (d) **不该涨的分类不许涨**（防噪声）。

## 1. 固件侧：统一故障台账（`src/faultlog.h`）

| 设计点 | 内容 |
|---|---|
| 位置 | SHM `0x7020`（原先未分配的空闲尾区，4064B），**不新增协议命令** —— 用已有 `0x22 READ_BURST` 读 |
| 内容 | `magic("FLOG")` + `total` + **24 类计数** + **首例**(code/tick/ctx0/ctx1) + **末例** |
| ★ 为什么记首例 | 第一条异常发生时状态**还没被后续污染** —— 那才是真现场（同汽车 ECU 的 freeze-frame） |
| 登记 | `fault_init()` 由 **`cold_start_reset()`** 调用（冻结平台纪律：新域必须登记到单一入口） |
| 布局 | 补 `_Static_assert`（结构体必须恰 136B；台账区必须接在 BB_SNAP 之后、不越 SHM 末尾） |
| ★ 自洽式 | `total == Σcats` + `magic` 正确 —— **唯一能失败的判据**，同时守住"部分写入 / 重入 / 布局漂移" |
| 登记点 | 通信域 6 处（ORE / CRC / 短帧 / 缓冲满 / 异常响应 / 组装越界）、ISR 2 处（超预算 / 零成本）、
护栏、协议 NAK（挂在**唯一拒绝出口** `nak()` 上，一处覆盖全部）、时基 |

★ 其中 **"RX 缓冲被填满"** 是本轮**新加的观测量**：此前那次"帧间零间隔"实验里
板子收到 34739 字节却只结算出 1 帧，而**没有任何量指出"缓冲满了"**。现在它报得出来（实测 288 次）。

## 2. 台账上线第一次运行就抓到了东西（这是本设计最有说服力的证据）

**第 1 次**（上电后）：
```
total = 20377   sane = OK
first = code 7 (ISR_OVER), tick 991, c0 = 0xFDA2A4E4 = 4,253,398,244 周期
```
`c0` 是 42.5 亿周期（≈10.6 秒 @400MHz）—— **不是真超预算，是 DWT 断钟后的跨纪元相减**（调试器伪影）。
⇒ **首例记录的价值在此**：一眼分辨真假，不用猜。

**第 2 次**：
```
cats[7]  ISR_OVER  = 1
cats[8]  SCAN_DIV0 = 184043    ← 185034 拍里 184043 拍在报"扫描恰好 0 周期"
```
扫描不可能 0 周期 ⇒ **`DWT_CYCCNT` 根本没在走**（调试器会话会静默停它）。
后果极隐蔽：**`eng_cyc_*` / `isr_cyc_*` / `pmin/pmax` 这些 DWT 计时统计全部静默变垃圾**，
现象只是"数字是 0"，不报任何错。这正是本项目记录过的最贵的一类事故 ——
**以前要靠人排查，现在固件自己说了出来。**

### 随之做的两件修正
1. **新增 `FAULT_TIMEBASE`（分类 14）**：主循环检测"CYCCNT 连续 100 轮不推进" ⇒ 记一笔。
   ★ 只判"**完全不推进**"（delta==0）而**不判"跨度很大"** —— 擦 flash 造成的几十 ms 跨度是
   **已知合理**窗口，判它只会制造噪声（噪声淹没真警告 = 本项目最恨的失效模式）。
2. **给 ISR 的"零成本"记录加闸门**（`g_timebase_dead`）：时基已死时 `d==0` **不携带任何信息**，
   既不计数也不记账。否则会出现"185034 拍里 184043 拍都在报"，**既是噪声又是每拍写台账的性能隐患**。

**修正前后实测对照**：

| 量 | 闸门前 | 闸门后 |
|---|---|---|
| `SCAN_DIV0` | **184043** | **101**（只在"时基还没判死"的前 ~100 拍） |
| `TIMEBASE` | 不存在 | **3158**（≈每 3s +334，与"每 100 轮报一次"设计一致） |
| 首例 | ISR_OVER（调试器伪影） | SCAN_DIV0 @ tick 1028（最早那个信号） |

**复位后**（`dwt_enable()` 重跑、时基恢复）：`total 0 → 0（3 秒内 +0）`，`magic=FLOG`，`sane=OK`
⇒ **零故障**，干净基线 ✓ 机制端到端成立。

## 3. PC 侧：`tools/fault_suite.py`（单一入口）

```
--show            打台账: 分类计数 + 首例/末例 + 自洽判定 + **已知外部条件的归类**
--inject          故障注入矩阵（9 条）
--soak MINUTES    长稳: 混合流量跑 N 分钟, 每 10s 采样, 事后断言不变量
```
退出码可直接当门（0 = 全 PASS）。
★ 只走协议口（`0x22` 读 SHM），**不开调试器**；台账地址**从 `.map` 读 `g_shm`**
（不硬编码 —— 本轮加一个全局就把 `0x200084A0` 挪成了 `0x200084C0`，
硬编码版本读出了"magic=0 的假故障"，白查一轮）。

## 4. ★ 我自己这套判据里修掉的两个 bug（同族，值得单列）

**① "末态必须 IDLE"是瞬态判据。**
长稳每 5ms 发一条，采样瞬间状态机本来就可能正在收（`state=1` = `MB_ST_RX`）。
⇒ 报出的"锁死"是假的。**"锁死"的定义是"有界时间内回不到 IDLE"** ⇒ 改为**静默 0.4s 后再判**。

**② 应答覆盖的恒等式推错了。**
第一版写 `Δftx ≈ Δfrx − 非法注入数` —— 但**非法地址帧是会回异常响应的**，它照样 `frames_tx++`；
而**CRC 失败的帧才是不回响应的那种**。
⇒ 正确恒等式从固件语义推出：**`Δftx ≈ Δfrx − Δerr_crc − Δ(非本站帧)`**。
改完后：`22258 − 1068 = 21190` = 实测 Δftx ⇒ **缺口 0，分毫不差**。

⇒ 两次都是"**我的实验/判据不合法**"而不是被测对象有缺陷。
归因顺序仍是：**① 我发的帧合法吗 ② 节奏合法吗 ③ 判据的恒等式成立吗 ④ 才是我/对方的缺陷。**

## 5. 还差什么（诚实边界）

- **长稳只跑了 2 分钟**（演示）。要出结论应跑 **≥8 小时**（`--soak 480`），
  并可挂到定时任务上每天跑一次。
- **没有真实看门狗**：台账能**记录**异常，但异常若导致程序跑飞，**没有自恢复**。
  ⇒ 这与整体评估的 ① 是同一条（PLC 的可靠性身份），仍待做。
- **I/O 侧的错误注入还没有**：当前注入矩阵只覆盖通信域与协议层；
  I/O 侧（断线 / 超量程 / 越界 / 强制越界）应补同类矩阵。
- **`SCAN_DIV0` 的 101 次**：那是"时基还没被判死"的窗口期内的真实误报。
  可以再收窄（例如启动后先做一次时基活性判定再允许该记录），本轮未做。
