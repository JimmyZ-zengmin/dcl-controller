## 1. div0 容量：实测（不再用预估）

**定义**（`MIGRATE-H723.md` §9.3）: 一拍内能跑完多少条"每拍执行"(div0) 的路由。
当时的预估是 550MHz + ~190 cyc/条 ⇒ ~290 条。

### 实测方法（三点定标 + 仿射拟合）

同一张表（profile 0 = 全 DIRECT）、`scan_mode=0`（全表扫 = div0 口径）、
`engine_sel=1`（ITCM），扫 `g_n_routes = 0/32/64/96/128`，每点读扫描段 DWT 成本：

| n | 扫描 cyc (min) | 扫描 cyc (max) | 极差 |
|---|---|---|---|
| 0 | 56 | 83 | 27 |
| 32 | 1885 | 1926 | 41 |
| 64 | 3644 | 3685 | 41 |
| 96 | 5402 | 5443 | 41 |
| 128 | 7147 | 7206 | 59 |

**仿射拟合**（n ≥ 32 的 4 点）: `cyc(n) = 124.5 + 54.99·n`，最大残差 5.3 cyc。
**两点法交叉校验** c = 54.53；**与成本表 DIRECT 项 56 一致**（±10% 内）；
与 `h723_op_sweep.py` 的 56.02 也一致 ⇒ **三套独立测量互相印证**。

★ 判据口径修正（第一版写错了，记录在此）：第一版要求"每点 `min == max`"。
实测**每点极差都是 27~59 cyc，连 n=0（一条路由都不跑）也一样** ⇒ 那是**固定的测量包络**
（DWT 读 + 调用/返回 + 分档前导），**与条数无关**。正确且能失败的判据是
**"极差不随条数增长"**：拟合斜率实测 **0.263 cyc/条**（≪ 1）。
若每条的获取时序不确定，斜率会接近 c 本身（55 cyc/条）—— 那才是真失效。

### 容量台账

| 上限 | 值与来源 |
|---|---|
| **表上限** | **128 条** — `MAX_ROUTES`（硬上限） |
| **门上限** | **471 条** — `(26000 − 124.5) / 54.99`（`EXEC_DEPLOY_BUDGET`，策略上限） |
| **拍长上限** | **725 条** — `(40000 − 124.5) / 54.99`（物理上限） |
| 最坏情况实测 | **128 条全 PID = 17970 cyc = 拍长的 44.9%** |

**两条结论（都可复跑）**:
1. **目标 ~290 条达成**：门上限 471 条 ≥ 290。而且这个预估偏保守 ——
   它按 550MHz 与 ~190 cyc/条 算，而本平台实跑 400MHz 且实测 **54.99 cyc/条**（快 3.5×）。
2. ★ **当前瓶颈是表尺寸（128），不是时间（471/725）** ⇒
   若要扩容，**改 `MAX_ROUTES` + 表区即可，时序上有 3.7 倍余量**。
   这把 `MIGRATE-H723.md` §4.2 那句"内存不再是瓶颈、时间只能跑 ~290 条"
   从**预估**变成了**实测**（且时间比预估宽得多）。

## 2. 协议层使能下的拍周期（能测的那一半）

| 状态 | 周期上界 pmax | 说明 |
|---|---|---|
| 协议空闲 | **40006 cyc** | 标称 40000 + 测量量化 |
| PC 连续发帧（`0x22` 满速） | **40006 cyc** | **Δ = 0 cyc** |

**判据（能失败）**: `pmax ≤ 40012` 且使能后 `Δ ≤ 100 cyc（0.25%）`。
`pmax` 语义 = "周期上界"，**任何整拍丢失或被拖长都会抬高它**（量级是成百上千 cyc）。
USART1 中断优先级低于拍（设计如此），实测 Δ=0 ⇒ **设计意图被实测确认**。
（前一轮曾测到 Δ=+7 cyc = 17.5 ns；再跑一轮为 0 ⇒ 属总线竞争/量化噪声。）

## 3. ★ 拒答的那一半：拍抖动极差**不发表**

`g_per_cyc_min` 在**每一段**窗口里都远低于标称 40000（实测 5999 / 17233 / 16743 /
18229 / 9189 / 30121 —— 连做三段窗口、空闲与使能都一样），而 `pmax` 恒为 40004±8。

**排除的两个机制**（这一步比数字本身重要）:
- 若小样本来自"某拍晚进入"，p 的和守恒 ⇒ 必然存在一个**等量偏大**的样本，
  但 `pmax` 只有 40006 ⇒ **不成立**；
- 若来自 `CYCCNT` 回绕，会被负增量保护计入 `g_per_glitch_n`，实测 **glitch = 0** ⇒ **不成立**。

⇒ 剩下的最可能机制：**调试暂停冻结 `DWT_CYCCNT` 而 TIM2 继续计数** ——
恢复后的第一拍会把"暂停残余"算成一个偏小的周期。
`pmin` 在"经 pyocd 会话测量"的条件下**不可信**。

### ★ 顺带修掉的真缺陷（本轮）

`TIM2_IRQHandler` 消费 `g_stat_reset` 时只调 `stats_reset()`，而后者**刻意保留 `g_per_prev`**
——"暂停 → 复位统计 → 恢复"这条路径上，恢复后的第一拍 `p = t0 − g_per_prev(暂停前的值)`
= 一个任意的正小数（实测 **5999 cyc = 15 μs**），被折进 `min` ⇒ **`pmin` 恒被污染**。
修：该分支同时 `g_per_prev = 0`（丢弃一个样本 ≤100μs，换来 pmin 不再撒谎）。
pmin 从 5999 改善到 ~17k+，但**另一条路径仍在** ⇒ 所以仍然不发表抖动数字。

★ 为什么 `stats_reset()` 保留 `g_per_prev` 本身是对的、这里却必须清：
保留是为了"**轮内** 0x13 RESET 后第一个样本仍有效"（那时钟没断，相减有意义）；
而调试暂停**把钟断了** —— 断过的两个读数相减没有物理意义。
这与今天早些时候修的"跨纪元样本污染"是**同一条**：**钟一旦不连续，基准就必须作废**。

### ★★ 由此引出的一个未决项（不挑一个信）

历史文档（`docs/STATUS-2026-09-11.md` §2）记着 **"拍抖动 极差 0 cyc（min=max=40000）"** ——
那是 **LA 外部测**的口径。本轮**内部量**与它矛盾。
**两套测量给出矛盾结论时，不能挑一个信。** 已列为未决项，复验路径二选一：
① LA 外部实测（本轮 Saleae MCP 只列出**仿真设备**，无物理分析仪 ⇒ 硬件阻塞）；
② 片内**抖动直方图**（需要一个新固件仪器：把 p 分桶计数，而不是只记 min/max ——
   min/max 的语义天生会被单个异常样本毁掉）。
