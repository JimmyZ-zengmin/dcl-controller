# H723 实测频率天花板 ≈465MHz — LA 外部证据

日期: 2026-09-10 · 板: 鹿小班 LXB723ZG-P1 (STM32H723ZGT6, Rev Z, REV_ID 0x1001)
仪器: Saleae Logic2 (Logic 8, 设备 F397589430559C0B), CH4 ← PA8, GND 共地

---

## 1. 结论

| CPU (SYSCLK) | HCLK | 结果 | LA 实测 |
|---|---|---|---|
| **450MHz** (N=90) | 225MHz | ✅ 完整运行 | 拍周期 **99.9976us** → 反推 CPU **450.01MHz**（偏差 +0.002%）|
| **460MHz** (N=92) | 230MHz | ✅ 完整运行 | 拍周期 99.9934us → 460.03MHz（+0.007%）|
| 470MHz (N=94) | 235MHz | ❌ 不运行 | PA8 无输出（2 秒窗口内 1~6 个跳变）|
| 480 / 500 / 520 / 550MHz | — | ❌ 不运行 | PA8 无输出 |
| 500MHz + HCLK **仅 125MHz** (HPRE=/4) | 125MHz | ❌ 不运行 | → **排除总线带宽** |

**本板实测天花板 ≈ 465MHz**，远低于数据手册标称的 550MHz。

---

## 2. 为什么这是"外部证据"而不是固件自报

固件里 TIM2 的 `ARR = (TIMxCLK/1e6)×100`，而 `TIMxCLK` 由**假定的**频率宏推导。
所以 PA8 的**实际周期与假定值成反比**，LA 测出周期即可反推真实 CPU：

```
cpu_actual = cpu_assumed × 100us / period_measured
```

450MHz 时测到 99.9976us ⇒ 反推 450.01MHz ⇒ **HSE 25MHz / PLL 分频 / VOS 全部正确**。
即：同一份代码在 450MHz 上是**精确正确**的，所以 470MHz 的失败**不是配置错误**。

## 3. 抖动（16MHz 采样，LA 量化 62.5ns）

```
半周期 min / max : 99.9375 / 100.0000 us
极差             : 63 ns  = 恰好 1 个采样点
分布             : 100.0000us × 5098 (95.92%) / 99.9375us × 212 (3.99%)
```

96%/4% 的两值分布正是**量化效应**（真实半周期 = 1599.96 个采样点，
所以 4% 落在 1599、96% 落在 1600）。
⇒ **真实抖动低于 LA 分辨率（62.5ns）** —— 拍是硬的。

## 4. 已排除的原因（全部实测，不是推理）

| 假设 | 实验 | 结论 |
|---|---|---|
| 晶振频率错 | 450MHz 反推 450.01MHz | ✗ HSE 确为 25.000MHz |
| PLL 分频错 | 同上，误差 0.002% | ✗ 分频正确 |
| FLASH 等待态 | WS = 3 / 7 / 15 三档 | ✗ 结果完全相同 |
| 总线(HCLK)带宽 | 500MHz CPU + HCLK 仅 125MHz | ✗ 仍然失败 |
| VOS 电压档写入 | 写 Scale0 vs 保持复位默认档 | ✗ 结果相同 |
| PLL 输入频率 | 复刻板商原配 M=10/N=220/RGE=1（2.5MHz 输入）| ✗ 同样失败 |
| CPUFREQ_BOOST | 只影响 >520MHz | ✗ 解释不了 470MHz 就挂 |
| DIVP1EN 等输出使能位 | 已修（修前连 100MHz 都切不过去）| ✓ 已修 |

## 5. 剩余最可疑（下一步验证方向）

1. **VCORE 实际电压未达 VOS0 水平** — `PWR_D3CR.VOS` 读回 0b00 且 `VOSRDY=1`，
   但"寄存器写进去了"不等于"电压真的升上去了"（本项目在 H743 的逐级切换上踩过同类坑）。
2. **板级供电 / VCAP 不足** — AN5419 Rev3 p7 要求 VCAP 外接 **2.2uF, ESR<100mΩ**；
   原理图文本里出现 `4.7uF ×2`，需确认是否为 VCAP 且 ESR 是否达标。

**验证手段**：万用表 / 示波器量 VCAP 引脚电压（VOS0 时约 1.3V 档）。
> ⚠ 本项目所用 Saleae **Logic 8 没有模拟输入**（`get_devices` 只返回
> `deviceType: "Logic"`），**测不了电压**，必须用外部万用表/示波器。

## 7. 对迁移策略的含义

- **450MHz 已足够落地**：45000 cyc/拍（ESP32-S3 是 24000，×1.9）、
  定时器 4.0ns 分辨率（S3 是 12.5ns）、DTCM 确定性内存、16 位 ADC、以太网 MAC ——
  迁移的**核心收益已经全部拿到**，不依赖 550MHz。
- **550MHz 留给自绘 PCB**：那时 VCAP / 供电 / 去耦由我们控制，
  再决定是否启用 CPUFREQ_BOOST（代价是 TCM 失去 ECC）。
- ⚠ **尚需一次"满载"验证**：本次 450MHz 是在 `wfi` 低功耗主循环下测的；
  迁移后引擎满负荷运行时电流更高，需重测确认该点仍稳定。

## 8. 方法论教训（重要，已写入 skill）

1. **SWD 在 CPU 跑不住时会失步/读回全 0** → 会把"芯片活着"误判成"挂了"。
   本项目曾据此得出"300~340MHz 断崖"的**错误结论**；固件 + LA 实测是 450MHz 正常。
   ⇒ 频率类结论必须用外部仪器证据。
2. **pyocd 自带的 `reset halt` 会清掉运行态寄存器** —— 若读"运行态"前刚 reset，
   读到的 RCC 是复位默认值，结论会完全失真。
