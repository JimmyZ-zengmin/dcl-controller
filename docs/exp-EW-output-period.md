# exp-EW —— 3.1 `OUTPUT ... PERIOD=`：让 ③ 层真的能把路由放到 div1/div2

> 一句话：把"下游整条链必须同档或更慢"这条规则**在最后一级接上**（原来 `OUTPUT` 收不下 `PERIOD=`），
> 并且顺手拆掉一个**写在编译器里的假承诺** —— `PERIOD=10ms` 在 100 µs 档上从来达不到
> （引擎的 div2 是 **64 拍 = 6.4 ms**，phase 字段只有 6 位）。现在三档周期**全部由 `src/` 派生**。

- 工具：`tools/exp_ew_output_period.py` —— **18 项判定 / 0 FAIL / 0 SKIP**
- 改动：`tools/dclc.py`（纯主机侧；**固件一行未动**，交付档指纹 `6daa7e65…` 不变）
- 前置：`docs/exp-EV-gate-phase-dependency.md`（相位归固件 ⇒ `PERIOD=` 只能承诺 **div 档**）

---

## ① 缺陷一：`OUTPUT` 收不下 `PERIOD=`（一条规则在末级断掉）

`PERIOD=` 后缀原来只在**第二遍**里剥掉，而**第一遍**（`OUTPUT` 固定槽预检）拿的是
**没剥后缀**的原文 ⇒ `fullmatch` 直接判"语法错误 OUTPUT"。

```python
# 第一遍（原来）: body 里还带着 " PERIOD=1ms" ⇒ fullmatch 失败
m = re.fullmatch(r'(\S+)\s+TO\s+wire\[(\d+)\]\s+FROM\s+(\S+)', body)
```

⇒ `PERIOD=` 对 `OUTPUT` **不可表达**。而固件的跨档速率检查
（`src/main.c:1900` `if (pdiv >= 0 && pdiv < cdiv) return "rate mismatch";`）是**程序级**的：
一条链只要有一级降档，**下游每一级都得同档或更慢** —— 于是 `OUTPUT` 卡住了整条链，
错误提示里甚至专门写了一句让人绕开它（"让最后一级留在快档通常最省事"）。

**处方**：新增 `split_period()` **预扫**，两个 pass 共用**同一份**已剥后缀的语句表。
⇒ 顺带消掉"同一个语义两处解析"这个隐患。`OUTPUT` 现在自动继承该语句的档位。

## ② 缺陷二（★ 比第一条值钱）：`PERIOD=10ms` 是假的

编译器的档位表原来是写死的：

```python
PERIOD_DIV = {0.0001: 0, 0.001: 1, 0.01: 2}      # 即 "div2 = 10ms"
```

而引擎真实的 div2 周期 = `BUCKET_DIV2_PHASES_USED × 拍长` = **64 × 100 µs = 6.4 ms**
（phase 只有 6 位，装不下 100 个相位；固件自己的注释就写着"10ms 从来达不到"）。
⇒ 编译器在承诺一个**引擎给不出的周期**，而且**没有任何东西会响**。

**处方**：三档周期**全部由 `src/` 派生**（`engine_timeline()`，与固件
`DT_FAST/DT_MID/DT_SLOW` 走**同一条规则**：`1 拍 / 10 拍 / 64 拍`）；读不到就**响亮退出**，
绝不退回写死的旧值。`10ms` 只作为**能力位标称值 `DIV2_NOMINAL_US` 的别名**被收下，
**并在编译输出里报出真实周期**：

```
  ! PERIOD=10ms 是能力位的**标称值**; 本档真实周期 = 6.4ms (div2 = 64 拍 x 100uS;
    phase 只有 6 位 ⇒ 标称的 10ms 达不到)
```

不存在的档（如 `5ms`）**被拒**，且报错里列出三档真实值。

## ③ 判据

| # | 判据 | 凭什么能失败 |
|---|---|---|
| W1 | 整链同档时 `OUTPUT ... PERIOD=1ms` **编得过** | 改动前这里是"语法错误"——本项的存在性证明 |
| W2 | ★ dclc 的三档 == 固件 `DT_FAST/DT_MID/DT_SLOW`（两边**各自**从 `src/` 派生后比对） | 两边任一改动/解析退化立刻不等（不是自我引用） |
| W3 | div0/div1/div2 三个程序的 **period 字节低 2 位 = 0/1/2** | 档位真的落进路由表，而不只是打印好看 |
| W4 | ★ `PERIOD=10ms` 收下 + **输出里报出 6.4ms** + period 字节 = 2 | 若哪天把别名当真实值（回到旧的谎），W4b 立刻 FAIL |
| W5 | 负对照：`PERIOD=5ms` 被拒且列出三档真实值 | 防"档位表见谁都收" |
| W6 | 负对照：SEQ 块内 `PERIOD=` 被拒 | 逐步档位不存在；默默剥掉就是"设了就算" |
| W7 | 22 个 `examples/*.dcl` 全部仍编过（含 7 个写着 `PERIOD=10ms`） | 别名与真实值**都**要能编过，否则就是破坏兼容 |
| W8 | ★★ **在板**：三档程序各自部署后 `OFF_TICK_STATS` 的增量**只落在自己那一档**、速率相符 | 若 `PERIOD=` 被忽略，三档全落 div0 ⇒ 三条全 FAIL |
| W9 | 负对照：本档跑的时候**他档增量恒 0** | "只落自己档"不能恒真 |

**在板实测**（`OFF_TICK_STATS` = 各档累计执行的路由条次；程序 = 2 条路由）：

| 档 | Δ拍 | Δcnt0 / Δcnt1 / Δcnt2 | 速率（期望） | 偏差 |
|---|---|---|---|---|
| div0 | 6083 | **12166** / 0 / 0 | 2.0000（2/拍） | **+0.0%** |
| div1 | 6106 | 0 / **1222** / 0 | 0.2000（2/10 拍） | **+0.1%** |
| div2 | 6198 | 0 / 0 / **194** | 0.03125（2/64 拍） | **+0.2%** |

⇒ "能把路由放到 div1/div2"这句话现在是**行为判据**，不是结构推断。

## ④ 诚实标注

- `PERIOD=` 承诺的是 **div 档（速率）**，**不是相位**。相位由固件
  `engine_stage_program` 轮转分配、载荷里的 phase 位被覆写 —— 见 `docs/exp-EV`。
  这条已写进 `dclc` 的文档头与 `RouteEntry_t.period` 注释两侧。
- 本项**没动固件**：交付档指纹 `6daa7e65a778ac308267785104426f17` 逐字节不变。
- 三档周期是**拍长的函数**（100 µs 档 6.4 ms；200 µs 档 10 ms）。dclc 支持
  `DCL_TICK_US` 环境变量覆盖，与 E-Q/E-R/E-S 的期望值来源同款。
- `OFF_TICK_STATS` 是**累计条次**（不是拍数），所以它同时是"分档真的按档跑"的
  独立证据 —— 这正是它当初被加进来的理由（`engine.h:314`）。
