## 2. 核心命题（要证明的一句话）

> **把"反馈"从主循环搬进拍内之后，闭环带宽能从 ~80 Hz 提到 ≥1 kHz；
> 并在同一判据下，把"PC 在环的 87 ms 死时间"换成"片内的 ≤1 ms"，跟随误差从 ±25.9° 降到 ~残余量级。**

**为什么只差"搬发起"一件事**（源码已核实）：
| 环节 | 现状 | 位置 |
|---|---|---|
| I2C 状态机**推进** | **已在拍内**（`i2c_sm_tick()` 在 ISR 最尾，每拍一相位）| ✓ |
| **发起**（谁下 `i2c_sm_request`）| ★ **在主循环** ⇒ 发起率 ≤ 主循环频率（163 Hz）| ✗ **唯一瓶颈** |
| 取结果 | 主循环（`dev_bind_service` / `as5600`）| ✓ 不需要快 |

## 3. 阶段划分（每阶段：目标 · 判据 · 脚本 · **止损条件**）

### 阶段 0 ★关键路径：**把"发起"搬进拍内**

- **做什么**：在拍 ISR 里按"每 N 拍"发起 `i2c_sm_request`（读 AS5600 raw），
  结果由 `i2c_sm_take_result()` 在**拍内或主循环**取；N 可配（`op=19 sub=20` 已有）
- **判据（能失败）**：
  1. ★ **`g_as_ok_n` 增量 ÷ 时间 ≥ 1000 Hz**（现在 163）
  2. `err_n == 0`、`skip_bus_n == 0`（信道干净）
  3. ★ **ISR 预算**：`0x38` 的 `isr_overrun == 0`（`i2c_sm` 一相位 ≈9000 cyc，而拍预算 32000）
  4. **全量回归零新失败**（动 ISR ⇒ 必经）
- **脚本**：`build/_asrate.py`（已存在）+ `tools/h723_full_regress.sh`
- **★ 止损**：若 ①做不到（例如拍预算不够）⇒ **闭环带宽上限就是 ~80 Hz，×6 就是我们的天花板** ⇒
  **立即停止"提带宽"这条线**，转向"用现有带宽把确定性/可靠性做实"。

### 阶段 1：**用同一判据做 A/B（证明收益）**

- **公平条件（写进脚本注释，不满足即判无效）**：两侧同增益/同误差带/同限幅/同目标/同采样；
  **唯一变量 = 环路在哪**
- **臂 A（PC 在环）**：读 `0x39 op=18`（**阻塞路径 = 实时**，`longrun/roundtrip` 一直用它）
- **臂 B（片内）**：读 `sensor[]`（阶段 0 后的反馈率）
- **判据（能失败）**：
  1. **上升时间之差 ≈ 死时间之差**（预测：阶段 0 前 ~87−6 ms；阶段 0 后 ~87−1 ms）
  2. ★ **低频跟随误差**：`track sine 0.2 Hz` 下"纯滞后项"应**从 23.5° 掉到 ≤0.5°**（ω×死时间）
  3. 残余项两侧同量级（控不住的就是控不住 —— 这句本身是反空判据）
- **脚本**：`build/_ab_step_response.py`（已有骨架，**要按上表改**：PC 臂换阻塞路径）

## 4.1 ★★ 收口判断（2026-09-17，阶段 0–3 全过之后）

**① "闭环带宽"这条线就此收住，不再投入。**
  搬进拍内之后带宽从 ~80 Hz 提到 **~1 kHz**，而**新的上限是编码器回填率**（`sub=20` 的周期），
  不是算力。要继续推，得换**更快的反馈通道**（SPI/ABZ 增量编码器、或片上比较器硬件捕获），
  那是**换器件**的事，不是"再写点 DSP"。⇒ **投入产出比最好的方向不在这里。**
  ★ 附带证据：PC 侧差分测速在本装置上**根本不可用**（§5.27 的采样拍频）——
  这条也说明"反馈通路"才是真瓶颈，而不是环频。

**② 最值得对外讲的是"确定性"，不是"带宽"。**
  可复现的数字：拍基 **99.95 µs**（−0.05%）、DO 直写 σ = **3.6 ns**、
  频率量化 **1 µs 可预测**（`rate_actual` 7/7 命中）、1~60 kHz **跟随线性度 ≤0.5%**、
  突加拐点 **16500~16750 Hz**（619~628 rpm，可复现）。
  ⇒ 这些是**工程可依赖**的量：**你知道它会怎么动**。

**③ 产品级证据是"失步自动检测"**，因为它把**现场抱怨**变成了**确定性行为**：
  1.17 s 触发 / 降额 0.25 / 轴恢复 99.2% —— 而且整条逻辑在 **③ 层程序**里（算法不改固件）。
  ★ 建议对外材料以它为主线，带宽表只作为工程附录。

**④ 下一步真正该投的不是功能，是"让工具自己会出错"**（本轮 7 个错里没有一个是工程判断错，
  全在**工具与测量层**）：
  - `dclc` 的跨档速率检查✅、保留槽跳过✅、输入槽预扫✅；**待补：`LUT` 暴露**（§5.25）
  - **`MEMORY.md` 拆分**（46 KB → 22 KB，前 15 KB 自足）—— 防的正是"注入被静默截断"
