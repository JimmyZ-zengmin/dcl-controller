## 2. 核心命题（要证明的一句话）

> **把"反馈"从主循环搬进拍内之后，闭环带宽能从 ~80 Hz 提到 ≥1 kHz；
> 并在同一判据下，把"PC 在环的 87 ms 死时间"换成"片内的 ≤1 ms"，跟随误差从 ±25.9° 降到 ~残余量级。**

**为什么只差"搬发起"一件事**（源码已核实）：
| 环节 | 现状 | 位置 |
|---|---|---|
| I2C 状态机**推进** | **已在拍内**（`i2c_sm_tick()` 在 ISR 最尾，每拍一相位）| ✓ |
| **发起**（谁下 `i2c_sm_request`）| ★ **在主循环** ⇒ 发起率 ≤ 主循环频率（163 Hz）| ✗ **唯一瓶颈** |
| 取结果 | 主循环（`dev_bind_service` / `as5600`）| ✓ 不需要快 |

## 3. 阶段划分（每阶段：目标 · 判据 · 脚本 · **止损条件**）

### 阶段 0 ★关键路径：**把"发起"搬进拍内**

- **做什么**：在拍 ISR 里按"每 N 拍"发起 `i2c_sm_request`（读 AS5600 raw），
  结果由 `i2c_sm_take_result()` 在**拍内或主循环**取；N 可配（`op=19 sub=20` 已有）
- **判据（能失败）**：
  1. ★ **`g_as_ok_n` 增量 ÷ 时间 ≥ 1000 Hz**（现在 163）
  2. `err_n == 0`、`skip_bus_n == 0`（信道干净）
  3. ★ **ISR 预算**：`0x38` 的 `isr_overrun == 0`（`i2c_sm` 一相位 ≈9000 cyc，而拍预算 32000）
  4. **全量回归零新失败**（动 ISR ⇒ 必经）
- **脚本**：`build/_asrate.py`（已存在）+ `tools/h723_full_regress.sh`
- **★ 止损**：若 ①做不到（例如拍预算不够）⇒ **闭环带宽上限就是 ~80 Hz，×6 就是我们的天花板** ⇒
  **立即停止"提带宽"这条线**，转向"用现有带宽把确定性/可靠性做实"。

### 阶段 1：**用同一判据做 A/B（证明收益）**

- **公平条件（写进脚本注释，不满足即判无效）**：两侧同增益/同误差带/同限幅/同目标/同采样；
  **唯一变量 = 环路在哪**
- **臂 A（PC 在环）**：读 `0x39 op=18`（**阻塞路径 = 实时**，`longrun/roundtrip` 一直用它）
- **臂 B（片内）**：读 `sensor[]`（阶段 0 后的反馈率）

#### 1-1 判据 1：阶跃响应上升时间 —— ✅ **已测，但预测被证伪（2026-09-18）**

- **判据**：上升时间之差 ≈ 死时间之差（预测 ~80 ms 量级）
- **实测**：PC 在环 **2.115 s** vs 片内 **0.635 s** = **3.3×**（两侧 ±2.5% 可复现）
- ★★★ **机制更正（这是本阶段最重要的一次自我纠正）**：差异主因**不是"纯滞后"**，而是
  **PC 控制周期 ≈110 ms（读 1 + 写 2 = 3 条命令 × ~36 ms）+ `HZ_LO=60` 地板**
  ⇒ 一周期就走 60×0.11 = 6.6 步 = **1.5°**，**一步跨过 ±0.5° 误差带 ⇒ 极限环振荡** ⇒ 收敛慢；
  片内 100 µs/拍 ⇒ 一周期 0.006° ⇒ 无过冲。
  ⇒ **"死时间"这个词在闭环语境下是错的**，正确说法是"**控制周期 ⇒ 极限环**"。
- **脚本**：`build/_ab_step_response.py`

#### 1-2 判据 2：低频跟随的"纯滞后项" —— ❌ **未实测**（下面 2026-09-18 重新分解）

★★★ **重新分解（先想清再跑，否则又是一条建在错模型上的判据）**

`track sine` 与"阶跃响应"量的是**两个不同的机制**，不能互相套用：

| | 阶跃响应 A/B（判据 1）| `track sine` 跟随（判据 2）|
|---|---|---|
| 环路 | **闭环**（写 rate ← 读角度）| **开环 / 前馈**（只按自己的钟下发 rate）|
| PC 臂误差来源 | 控制周期 110 ms + `HZ_LO=60` ⇒ **极限环** | **命令通路运输滞后 87 ms** ⇒ 位置滞后 = ω×87 ms |
| 片内臂 | 100 µs 决策 ⇒ 无过冲 | 100 µs 生成 ⇒ 滞后 ≈ **0.1 ms** |
| 判据 | 上升时间之差 | **拟合出的等效滞后** |

⇒ ★ **判据 2 的"纯滞后项"分解仍然成立**：它量的是**开环前馈**，而开环前馈的误差**就是**运输滞后，
**与判据 1 的极限环无关**。所以判据 1 的机制更正**不动判据 2**。

**滞后项的算式（已追溯到出处，不是相位公式）**：
```
滞后项 = 峰值角速度 × 等效滞后 = (amp × K) × lag = 1200 Hz × 0.225 °/s/Hz × 0.087 s = 270 × 0.087 = 23.5°
```
（`docs/audit/h723_stepper_motion.py` 的 `track`：`err ≈ −lag·ω` 最小二乘拟合，`lag` 单位 s。）

★★★ **判据 3 必须替换 —— 原设计会把好消息判成坏消息**

- 原判据 3 = "残余项两侧同量级"，前提是"残余 = 采样/量化/电机 ⇒ 两侧相同"。
- 但 `track sine` 是**开环前馈** ⇒ 残余里**额外含"速度命令的阶梯量化"**（PC 每 ~80 ms 跳一档，
  片内每 100 µs 一档）⇒ **PC 臂残余必然 ≥ 片内臂** ⇒ "同量级"会**因为"片内更好"而失败**。
- ⇒ 换成两条**能失败且方向正确**的：

| 代号 | 判据（能失败）| 不过怎么办 |
|---|---|---|
| **P1** 主判据 | 片内臂拟合出的**等效滞后 lag_B ≤ 5 ms**（基线 87 ms）⇒ 滞后项 ≤ 1.35° | 若 lag_B > 20 ms ⇒ **"波形生成位置"不是收益来源** ⇒ **停止该叙事，不许找理由** |
| **P2** ★正对照（必须过）| 给 PC 臂**人为加 300 ms 延时**，拟合滞后**必须相应涨 ~300 ms** | 不涨 ⇒ **判据无效 ⇒ 判 SKIP**（§5.23：期望为 0/小 必假绿）|
| **R** 噪声底闸门 | 同一采样链 + 同一拟合器，轴**静止**时量残余 ⇒ 得底噪 `N`。片内残余 ≤ 1.5N ⇒ "到底噪"；**> 3N ⇒ 有未解释机制 ⇒ 判 SKIP** | 不许把"没解释的数"当收益 |

**公平性条件（不满足即判无效）**：★ 因为 DCL **没有 `sin`**，片内只能下发**阶梯表**
⇒ **PC 臂必须用同一张阶梯表**（套件新增 `track stair6`），否则波形/谐波不同 ⇒ 残余不可比、A/B 不成立。
其余：同段长 / 同幅度与直流偏置 / 同 f / 同时长(≥3 周期) / 同一采样脚本，**唯一变量 = 波形在哪生成**。

**★ 预测（跑之前写下来）→ 实测（2026-09-18）**

| 臂 | 预测 | 实测 |
|---|---|---|
| PC 在环（stair6 + 斜坡）| lag ≈ 87 ms | **133.9 ms**（被斜坡限速暂态污染，见下）|
| 片内（stair6 + 斜坡）| lag ∈ [0.1, 2] ms | **121.6 ms** |
| 正对照（PC + 300 ms）| lag ≈ 387 ms | **395.2 ms** ✅ 正对照通过 |

**★★★ 首跑正对照 FAIL ⇒ 判据判 SKIP。它当场抓出三个"测量层"的真 bug（这是本判据最有价值的一次作用）：**

| # | 问题 | 证据 | 修法 |
|---|---|---|---|
| ① | **延时被烘进参考**：A+ 臂把"延时后的命令"也记进参考序列 | A+=28.05 vs A=29.44 ms，**纹丝不动** | 参考一律记**意图** |
| ② | **时间戳口径**：取在写之前 ⇒ 拟合量 = τ − 环内读+写(72 ms)，与历史 87 ms 不可比 | A=29.4 ms | 时间戳改到**读之后**（与套件同口径）|
| ③ | **参考边沿被 12.5 Hz 采样抖掉**：`ω` 瞬跳 ⇒ ±40 ms 抖动 × Δv ⇒ 假残余 6.8° | B 残余 5.04°/15.38° ≫ A 的 0.75°/2.92° | 两侧同开斜坡 ⇒ `ω` 连续 |

**★★ 但真正的坑是第 ④ 个（波形本身）**：修完 ①②③ 后 A=133.9 / B=121.6 / **差仅 12.3 ms**。
残余峰峰 **36.6°** ≈ 滞后项 **36.2°** ⇒ 误差被**斜坡限速暂态**主导：
6 级阶梯每次跳变 Δv=1200 Hz、斜坡 3000 Hz/s ⇒ 爬升 400 ms ⇒ **暂态面积 ½·Δv·t = 54°**，
而它**不是延时形状**（限速器的非线性响应）⇒ LSQ 报出的是**混合值**，差值被两个大数的共模部分吃掉。

#### 1-3 判据 2 定案（v2：三角波 + 边沿穿越估计量）—— ★ 结论**推翻了 87 ms 的归因**

**v2 设计**：请求只给 **HI/LO 两档**，让**斜坡自己画三角波**（Δv=1200 @480 Hz/s ⇒ 爬升 2.5 s，
周期 2×2500 ms = **5000 ms 整**）⇒ **无限速暂态**；估计量换成**上升边沿的中点穿越时刻**
（形状无关、免疫共模斜坡滞后、**逐边沿一个样本 ⇒ 有真实误差棒**）。
脚本 `tools/h723_stage1_ab_sine.py` · 片内程序 `examples/h723_step_traj_tri_5s.dcl`

**实测（n=8 边沿）**

| 臂 | delay | sd |
|---|---|---|
| **A** PC 在环 | **+15.1 ms** | **4.3 ms** |
| **A+** 正对照（注入 300 ms）| **+335.4 ms** | 2.3 ms ⇒ **增量 +320 ms ✅ P2 通过** |
| **B** 片内 | **+23.8 ms** | 24.2 ms |

**P1 FAIL：`delay_A − delay_B = −9 ms`**（片内不比 PC 慢也不快，落在噪声里）。

★★★ **这个负结果的价值 = 它证明"87 ms"的归因错了。** 重新分解历史那个 87 ms：

| 组成 | 量级 | 是不是"生成位置"能消掉的 |
|---|---|---|
| **零阶保持**（PC 环 12.5 Hz ⇒ T/2）| **~40 ms** | ✅ 是 —— ★ **这才是主项** |
| **读延时**（套件时间戳取在**读之后**）| ~36 ms | ❌ 不是 —— 纯**测量口径** |
| **命令传输/受理** | **~15 ms** | ✅ 是（本次**首次单独测出**）|
| 合计 | ≈ 91 ms ≈ 实测 87 ms ✓ | |

⇒ ★★ **判据 2 原来的"23.5°"是把整个 87 ms 都当成传输延迟**（270 °/s × 0.087 = 23.5°）；
正确的可消项只有 **ZOH 40 ms + 传输 15 ms = 55 ms ⇒ 滞后项 ≈ 14.9°**。

★★★ **而 v2 这个波形根本量不到 ZOH 项**：方波跳变是**离散事件**，PC 每 80 ms 更新一次也来得及
⇒ ZOH 不适用 ⇒ 量到的只剩传输项（15 ms），而 B 臂的边沿检测 sd=24 ms **大于 15 ms 信号**
⇒ 本条设计**对"传输项"判别力不足，且传输项本来就不是主项**。

**⇒ 判据 2 的**正确**形式（v3，待做）**：A/B 必须用**需要连续更新**的轨迹（**连续正弦**，即历史 `track sine`），
因为只有"PC 必须在 12.5 Hz 下持续重算轨迹"才暴露 ZOH。
- 正确预测：`lag_A − lag_B ≈ 55 ms`（ZOH 40 + 传输 15）⇒ 滞后项 ≈ **14.9°**
- 片内臂要能产生**可比**的连续波形 —— 这是 v3 的真难点（DCL 无 `sin`；6 级阶梯 + 斜坡会被限速，
  爬不上去）。**出路**：把 `LUT` 原语暴露给 `dclc`（§5.25 的待补项），或在 ③ 层写累加式三角波。

**★ 本次已确证的独立结论（可直接引用）**：
- **PC→引擎 的单次命令受理+传输滞后 = 15.1 ± 4.3 ms**（边沿法，n=8，正对照 +320 ms 验证过估计量）
- ⇒ 这**同时否掉了**"PC 命令通路 87 ms"这个被引用了两天的说法；87 ms 里只有 **~15 ms** 属于传输。

2. ★★★ **"期望为 0/小"的判据必然是假绿**：第一版没有正对照，而"轴完全不动"时 R 判据
   `0 < 阈值` **照样通过**。加上正对照后，它**当场抓出测速器偏高 3.2 倍**的真 bug

## 4.1 ★★ 收口判断（2026-09-17，阶段 0–3 全过之后）

**① "闭环带宽"这条线就此收住，不再投入。**
  搬进拍内之后带宽从 ~80 Hz 提到 **~1 kHz**，而**新的上限是编码器回填率**（`sub=20` 的周期），
  不是算力。要继续推，得换**更快的反馈通道**（SPI/ABZ 增量编码器、或片上比较器硬件捕获），
  那是**换器件**的事，不是"再写点 DSP"。⇒ **投入产出比最好的方向不在这里。**
  ★ 附带证据：PC 侧差分测速在本装置上**根本不可用**（§5.27 的采样拍频）——
  这条也说明"反馈通路"才是真瓶颈，而不是环频。

**② 最值得对外讲的是"确定性"，不是"带宽"。**
  可复现的数字：拍基 **99.95 µs**（−0.05%）、DO 直写 σ = **3.6 ns**、
  频率量化 **1 µs 可预测**（`rate_actual` 7/7 命中）、1~60 kHz **跟随线性度 ≤0.5%**、
  突加拐点 **16500~16750 Hz**（619~628 rpm，可复现）。
  ⇒ 这些是**工程可依赖**的量：**你知道它会怎么动**。

**③ 产品级证据是"失步自动检测"**，因为它把**现场抱怨**变成了**确定性行为**：
  1.17 s 触发 / 降额 0.25 / 轴恢复 99.2% —— 而且整条逻辑在 **③ 层程序**里（算法不改固件）。
  ★ 建议对外材料以它为主线，带宽表只作为工程附录。

**④ 下一步真正该投的不是功能，是"让工具自己会出错"**（本轮 7 个错里没有一个是工程判断错，
  全在**工具与测量层**）：
