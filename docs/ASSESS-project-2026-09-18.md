## §1 它到底在做什么

**三层说法，越往里越接近真相：**

| 层 | 说法 |
|---|---|
| **对外一句** | 一个用「静态路由表」替代「程序」的裸机确定性控制运行时（STM32H723 / Cortex-M7） |
| **实际建出来的** | **两件作品**：① 100 µs 硬拍驱动的表驱动运行时；② 一套**测量与验证机器**（109 个工具 + 契据机检 + 6 道构建闸门 + 747 KB 记忆） |
| **真正在卖的** | 不是"控制性能"，是 **「确定性 + 逻辑可热更」这个结构本身** |

★ **最容易被忽略的事实**：**9 天的力气绝大部分花在第 ② 件上。**
README 的主体不是功能清单，是**证据表**。这不是跑题 —— 因为第 ① 件的卖点（"编译期可算的确定性"）**只能靠第 ② 件证明**。

## §2 核心思想

**一句话**：**把控制逻辑从「代码」降级为「数据」，从而让时间行为成为编译期可判定的属性。**

| # | 支柱 | 换来了什么 |
|---|---|---|
| 1 | **静态数据流替换控制流**：没有 `while(1)` 控制大循环，每拍按拓扑序扫一张编译期生成的表（`源→原语→目标`） | **无隐藏分支 ⇒ WCET 可算** |
| 2 | **硬拍 + 零等待 TCM**：TIM2 每 100 µs 硬中断；热代码全在 ITCM | **确定性是结构给的，不是调优出来的** |
| 3 | **逻辑与硬件解耦**：程序里出现引脚号/总线地址 ⇒ **编译错误**（rc=2） | 逻辑成了**可校验、可拒绝、可热更**的数据 |
| 4 | ★ **判据必须能失败**（非技术，但同等核心） | 唯一能**抓住自己说谎**的东西；已做成机器（`--selftest`/变异体/反向判据/SKIP 语义） |

**与 PLC 的真正分界**：PLC 也分离逻辑与扫描周期，但它靠**把周期拉长到 ms 级来"藏住"抖动**。
本项目的赌注是 **不藏**：周期压到 100 µs，同时让每拍成本**编译期可算**。

**一句话概括它的世界观**：**确定性不是调出来的，是把不确定性逐个从路径上移除后剩下的东西。**
（五个根机制与它们移除的东西 ⇒ 见 `ARCH-GUARANTEE-MAP.md` §0）

## §3 架构设计

### 四层 + 判层表（强制）

| 层 | 是什么 | 改它的代价 |
|---|---|---|
| **① 引擎核心** | 硬拍驱动 + 路由表扫描 + 19 原语（烧进 flash） | = 换固件，必走 A/B + 全套回归 |
| **② 外设能力** | 通用事务 op（I2C/SPI/UART）+ **具名设备绑定表** | 随核心版本化 + 能力位 |
| **③ DCL 程序** | 逻辑/连续/顺序（**怎么算**都在这） | **上传即可，不碰固件** |
| **④ 程序工程** | 上位机侧 `.dcl` + 清单 + 产物 | — |

**判层表**：怎么算 ⇒ ③｜和外设怎么说话 ⇒ ②（**不是写新驱动**）｜需要新的每拍行为/实时保证 ⇒ ①｜
只是给上位机看的量 ⇒ **SHM + `obs_anchor()`**（不是加协议 op）。

### 数据面 / 执行面

- **数据面**：一切数据在 SHM（DTCM 32 KB）；**每个槽单一写者**；不加锁 —— 通信就是"写我自己的槽"。
  布局以 **`src/engine.h` 为唯一权威**（文档里有**三套互相打架的表**，这是踩过的坑）。
- **执行面**：每拍 ISR = 读时基 → **热重载检查（STAGING→ACTIVE 原子切换）** → HEARTBEAT → Force 覆写 →
  扫描分派（三档 div0/1/2 + 桶表）→ 顺序域 → Modbus → 统计。
- **三个结构性保证**：① 热重载**本拍生效**（不出现"已受理但还用旧表"）；
  ② **状态表先全清再拷**（新程序绝不继承旧积分残留）；③ `STOP/RESET` 走**输出面注册表**逐面归零。

> 每条效果**到底靠什么机制保证**、以及**哪些"曾经的机制"已被推翻** ⇒ 全部见 `ARCH-GUARANTEE-MAP.md`。

## §4 目前实现效果

### ✅ 已实测成立（可复跑）

| 项 | 数字 |
|---|---|
| 拍基 | **99.95 µs**（−0.05%） |
| 输出抖动 σ | **3.6 ns**（CPU 直写档，量的是**引脚本身**） |
| 拍周期跨度 | **90 ns** |
| ITCM vs FLASH（单路由） | **56 cyc vs 203.6 cyc** |
| 分档调度收益 | **2.59×** |
| 热重载代价 / 延迟 | **3.6 µs** / `reload_lat = 1 拍` |
| 执行频率 | **10 kHz**（PC 在环 13.5 Hz；命令通路 26.3 命令/s） |
| 失速边界 | 突加 **16500~16750 Hz = 619~628 rpm**；转动中突跳 31 kHz 正常；**斜坡 ≥50000 Hz** |
| **失步自检 + 恢复**（**③ 层程序，不改固件**） | **1.17 s 触发 / 降额 0.25 / 轴恢复 99.2%** |
| 频率可预测 | `rate_actual = 1e6/floor(1e6/f)`，**7/7** |
| 程序全链 | `.dcl → 编译 → 上传 → SD A/B → 上电自动装载` **全通，不碰 flash** |
| 纪律机器化 | 6 道构建闸门 + 契据机检（A12/B7/C11/D43/E10）+ ③层静态判据 rc=2 |

### ⚠️ 部分成立 / **比宣传弱**

| 项 | 真相 |
|---|---|
| **"闭环跑片内 ⇒ 性能提升"** | 阶跃 **0.635 s vs 2.115 s = 3.3×**，机制**更正为"控制周期 ⇒ 极限环"**（不是"快"）；**纯滞后项判据 FAIL（`A−B = −9 ms`）⇒ 跟踪滞后上无收益** |
| **"闭环带宽大提升"** | 10 kHz 是**执行频率**；带宽上限 = **反馈更新率**（AS5600 阻塞 163 Hz / 拍内 ~1 kHz）⇒ 真实对比 **×6 / ×40**，不是 ×700。**已收线**：要推得换反馈器件 |
| **"每拍成本编译期可算"** | 模型与门都在，但**预算门从未触发**（128×145=18560 ≪ 26000）⇒ 项目自陈"**不能相信一个从未触发过的判据**"；成本表还被查出**系统性偏低 +5~6 cyc/条** |

### ❌ 已推翻 / 已按设计降级

| 曾宣称 | 真值 |
|---|---|
| **"输出由硬件定时器锚定"** | **MDMA 自循环**（`TSEL` 扫 0…15 全部照常工作）⇒ 引脚时刻 = **CPU 最后写影子 + 0.12 µs**；且 1 档比 0 档**差 15 倍**（54~60 ns vs 3.6 ns） |
| 内部 flash 掉电保持 | 擦 128 KB 时 ISR 卡死 **210.6 ms** ⇒ 看门狗复位 ⇒ **降级，持久化一律走 SD** |
| DO 全通道原子锁存 | 锁存只覆盖 `ODR` 低字节 ⇒ **16 路只通 8 路**；默认档已改 CPU 直写 |
| 上一代"抖动 <10 ns" | **设计目标被写成实测结果** ⇒ 已留案并标作废 |

### ❌ 明确没做

多轴（三个真阻塞：AS5600 地址固定 `0x36` / 台架没有第二驱动器 / **ITCM 64/64 KB 已满**）·
电流环（TB6600 只有 PUL/DIR/ENA ⇒ **硬件缺**）· 轨迹形状验收（判 **SKIP**）· 长稳（只跑过 2 分钟）。

## §5 设计意图 ⇄ 实现效果

| 设计承诺 | 实测 | 判定 |
|---|---|---|
| 静态表 ⇒ **编译期可算的 WCET** | 有模型有门，但**门从未触发** | ⚠️ **未压力验证** |
| 硬拍 ⇒ **确定性** | σ 3.6 ns、跨度 90 ns，**且与负载无关** | ✅ **成立（最硬的一条）** |
| 逻辑=数据 ⇒ **热更 ≤1 拍** | 全链通，`reload_lat = 1` | ✅ **成立（真本事）** |
| 判层 ⇒ **程序不得碰硬件** | 编译期 **rc=2 拒绝**，已进 `dclc` + `build.sh` | ✅ **成立（纪律做成了机器）** |
| **输出硬件锚定** | MDMA 自循环 | ❌ **已推翻** |
| 片内闭环 ⇒ **控制性能** | 阶跃 3.3×；**滞后无收益** | ⚠️ **部分，且弱于宣传** |
| 片内 ⇒ **高带宽** | 上限是**传感器**不是算力 | ⚠️ **已收线** |

**净判断**：
> **"确定性"与"逻辑可热更"两条是真的、且是结构给的；
> "因此控制性能更好"只拿到 3.3× 的阶跃改善，机理还是"控制周期消除极限环"，不是"快"。**

## §6 上层问题（按严重度）

**1. ★ 两个命题被绑在一起卖，但它们已被测量解耦。**
"确定性（×700 执行频率）"与"控制更好（3.3×、滞后无收益）"在叙事里是一件事，在数据里是两件事。
⇒ **项目需要选一个当主语。** 现状是 README 用前者撑场面、用后者（部分地）收场。

**2. ★ 瓶颈已经移出运行时。**
带宽上限 = 反馈更新率（AS5600 ~1 kHz）。⇒ **继续打磨运行时确定性，对"控制"的边际收益已很低**；
杠杆在**传感器 / 驱动器 / 电流环** —— 而这三个是采购或硬件问题。

**3. ★ 证据基础是"单轴步进台架"，而定位是"通用确定性控制"。**
全部实证都在一条轴 + 一块板子上。这不是缺陷，但**是定位与证据的错配**：
"通用运行时"的宣称，证据是"单轴运动台架"。

**4. ★ ③ 层表达力是整条故事里最弱的一环。**
"一次烧录、逻辑反复下发"的价值取决于**能写出多复杂的逻辑**。现状：无 `ABS`/`MOD`（用 `MAX` 凑最短弧）·
`THR=` 只认字面量 · `CONST` 不认科学计数法 · **引擎有 `LUT` 而编译器未暴露** · `OUTPUT` 不接受 `PERIOD=`。
⇒ **运行时很硬，程序语言很薄。**

**5. ★★ 文档层没有闸门 —— 这是 2026-09-18 复核暴露最系统的问题。**
有"契据 ⇄ 代码"的机检（F 类），但**没有"文档 ⇄ 文档"的检查**。实测后果：
- `2026-09-11.md` **L15–17 把虚空地址当"硬件锚定"推荐**，而同一文件 L1292 已推翻它
- 两份日志的**文件顶部区块都非时序**；`2026-09-12.md` 有一节**逐字重复 3 次**
- 日报里**三个数字在原始记录中查无出处**
- 契据/README/GAP 表曾**同时 6 处过期状态**

⇒ "宣称必须等于实现"目前**只覆盖代码，没覆盖文档**，而文档正是继承者唯一能读到的东西。

**6. ★★ 记忆继承是存在性风险，不是运维问题。**
继承链实测 **约 5000:1**，且**损失偏斜**：**"被推翻的结论"在日报那一代就丢了**
（09-12 的六次误判链整段不在日报里；`ARCH-H723.md` 737 行、W3/W4 交付也没记）。
⇒ 而**这个项目的竞争力恰恰在判例里，不在规约里**。
⇒ 已处置：另立 `RETRACTIONS.md`。但根本矛盾仍在：**价值载体（判例）与存储形态（长文档、只出现一次）天然不匹配。**

**7. 验证债清单（项目自己已登记）**：判据 2 = 负结果 · 判据 3 = 判据本身被替换 · `w2_probe` **自身非确定** ·
`persist` 基线 7/19 · 大 deploy 偶发静默（触发未定）· `3.26×A` 毛刺机制未知 · 轨迹形状 SKIP ·
长稳未做 · 内部 flash 持久化已降级。

**8. 定位问题（最上层的那个）**：它究竟是
 **(a) 一个通用确定性控制运行时**（那运动台架只是 demo，需要更多品类的 demo 来证），还是
 **(b) 一台"证明闭环可以搬进片内程序面"的参考实现**（那证据已经够了，该收口）？
README 的措辞在 (a)/(b) 间摆动 —— 而 **9 天的资源分配更像 (b) 的做法（把一条线挖到负结果）**。

## §7 判断与建议

> **一句话**：这是一个**"结构上真的做到了确定性"**的运行时，配着一套**"真的能抓住自己说谎"**的测量纪律；
> 它最硬的成果是**确定性与逻辑热更本身**，最诚实的成果是**那张撤回台账**，
> 而它**尚未证明**的是「**所以控制更好**」。

**建议的方向（按性价比）**：

1. **别再加固运行时**（瓶颈已移出）。把力气投到 **③ 层表达力**（补 `LUT` 暴露 / `ABS`·`MOD` / `PERIOD=`）
   —— 它是"通用"这个宣称的唯一兑现路径，且**不需要采购**。
2. **给"文档 ⇄ 文档"加闸门**。这是本次复核花最小代价暴露的最大系统性风险：
   一份**跨文档否定式断言**检查（"某文档说没有 X，而 `examples/` 里有 X 的例程"）就能覆盖一部分。
3. **选一个主语**（§6.1）：要么对外主打"确定性 + 可热更的运行时"（把运动当 demo），
   要么主打"闭环下沉到片内"（把运行时当手段）。**两者都能成立，但不能同时当标题。**
4. **把"从未触发过的门"触发一次**（超载实验）。这是 G3 那条核心命题唯一的缺口。
5. **记忆继承的机制闭环**（§6.6）：`RETRACTIONS.md` 只是补丁；需要一个**机制**保证"撤回"必然进台账。

**明确不建议做的**：在拿到更好的反馈器件（或第二轴）之前继续深挖运动品质 ——
那会不断撞到"测量口径"而不是"系统能力"的墙（已发生三次：`87 ms`、`被砍 47%`、`3.26×A`）。
