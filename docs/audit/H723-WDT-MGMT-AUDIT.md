# H723 看门狗 + 非侵入通信管理系统 —— 功能审计

- 审计对象：`ea1294b`（已推 `H723PLC`）
- 范围：`src/wdt.h`(283) · `src/faultlog.h`(159) · `src/manifest.h`(136) · `main.c` 的 ISR 喂狗/停滞段 ·
  `tools/mgmt.py` · `docs/VALIDATE-watchdog.md` · `docs/RUNBOOK-diagnostics.md`
- 实测：`mgmt.py --health / --boot / --manifest / --read FAULTLOG`（走协议口，未用调试器）
- 日期：2026-09-13

---

## 0. 结论先行

**这不是"加了个看门狗"，是把"排障"从人的技能变成了系统的能力。** 设计水准明显高于工程平均——
三个判断（判据必须能失败 / 观测不得改变被测对象 / 首例 freeze-frame）都是**踩过坑才写得出来的**，
不是抄来的。

**但它有一个哲学上的缺口**：你们把"喂狗点"定义得很清楚（拍 ISR），也把"喂狗点之外谁负责"往前推了一步
（故障台账）——**然而台账的读取本身也依赖主循环**。所以：

> **这套系统已经能让"下一次 ORE"自己浮出来，但还不能让"主循环死了"自己浮出来。**

---

## 1. 做对了什么（三条，附证据）

### ① "判据必须能失败"被**系统性地**落地（最难得）

这不是一句口号，是贯穿全部六处：

| 位置 | 反例机制 |
|---|---|
| **对照构建** | `WDT_START_FIRST` / `WDT_FEED_GATE` / `WDT_PR_VALUE` 三个开关，**每个恰好对应一个被测变量** |
| **同步等待** | `sync_expired` 与 `wait_cyc` **分开记** —— 只看大数时"等到了"与"跑满了"长得一样，那是空判据 |
| **台账自洽** | `total == Σcats`（能失败 ⇒ 守住部分写入/重入/布局漂移） |
| **复位归因** | 否掉"原因位恰好 1 位"（RM0468 **Table 52**：单事件置多位）⇒ 改按十种签名对表 |
| **期望值来源** | `PR/RLR` 期望**由固件自报**（`WDT_STAT[24][25]`）—— 工具原先把 `PR=4/RLR=99` 写死在身上，换档即假报警 |
| **负向路径** | `wdt_start()` 保留 `WDT_START_FIRST=0` 分支，**唯一目的是"用同一套测量方法打出坏的那一半"** |

**特别是 §3 的 A/B 矩阵**：#1（先配后启动）与 #3（先启动）之间差着"顺序 + 预算"两个变量，
**单独看判不出**；补上 #2（只退回顺序、预算给足 302ms）仍 `rc=−2` ⇒ **干净地排除了预算这个变量**。
这个对照设计是对的，不是"凑一个能过的数"。

### ② 铁律 0（观测不得改变被测对象）成了**架构约束**，不是口号

- **用"关闸"而不是 `__disable_irq()`** —— 理由写得准：*"只让 ISR 少做一件它在这个瞬间本就不该做的事
  （没有看门狗可喂时去写它的 KR 本来就无意义），拍照走、其余工作照做"*。这是**真理解自己系统**才写得出的话。
- **关闸的存在理由引了 RM0468 §50.3.6 逐字**（写 KR 的其它值会打断解锁序列，**包括喂狗用的 0xAAAA**）
  —— 并且**没有**把它当成根因（#3 的对照证明关闸不是根因），而是"关闸保留为硬化措施，注释注明未被证明是成因"。
  **能区分"机制上真实"与"本次是不是成因"**，这个分寸感很值钱。
- **运行期只走协议**：IWDG 武装后任何 ≥200ms 的 pyocd HALT 都会复位板子 ⇒ pyocd 只用于烧录 + 烧录前预写 `SD_CFG`，
  且收尾必须 `go`。
- **台账复用已有读路径**（`0x22 READ_BURST`），**不新增协议命令** —— "少一条命令少一处要同步的东西"。

### ③ 首例 freeze-frame —— 这条设计判断是本次最值钱的一条

`faultlog.h` 开篇把 485 事故的真正代价定为 **"找它的成本，而不是缺陷本身"**，并给出架构回答：
**记首例**（第一条异常时系统还没被后续污染，那才是真现场），类比汽车 ECU 的 freeze-frame。

**证据**：注释里直接写了 —— *"本次 ORE 排查里，若有首例记录，第一眼就能看到 `ORE=1 且 RXNE=0` 那一刻的
ISR/rx_len，而不是几小时后去猜。"* 而 `mgmt.py --boot` 确实把"上一轮台账首例/末例"带了出来（实测可读）。

**这条如果早三天存在，那次 4 轮审计 + 一整天的排查可以直接缩短到一次读数。**

## 2. 结构性缺口（P1）：主循环失活 —— 既不自愈、也不可实时读

`wdt.h` 的喂狗契约定在**拍 ISR**，主循环**故意不纳入**。这个取舍本身是对的
（T26 实测 sector erase 让主循环阻塞 ~816ms，纳入必然"每次刷盘都误复位"）。**但它留下这个表：**

| 保护对象 | 谁在保 | 主循环卡死时 |
|---|---|---|
| CPU + TIM2 + 拍 ISR | **IWDG**（喂狗点在 ISR） | 照常 → **不复位** |
| 主循环活性 | **只记录**（ISR 判 `g_loop_hb` ≥1.2s 不动 → `FAULT_LOOP_STALL`） | 留痕，**复位不触发** |
| 对外通信（`proto_poll` / 管理面） | 无 —— 全在主循环里 | **全断** |

**后果**：主循环一死 = **不复位 + 读不到 = 变砖，只能人工断电**。

要精确：**"事后归因"是有的** —— `fault_record()` 可被 ISR 调用，`BOOT_AXI[6..]` 带上"上一轮台账 total + 首末例"，
且 AXI 跨复位不丢，复位后 `mgmt.py --boot` 能看到"上一轮停在 stage=7 / 最后拍 345434"。
**缺的是"实时可观测"与"自愈"** —— 你**在它死的那一刻读不到**，也**等不到它自己恢复**。
而"非侵入通信管理系统"的全部意义恰恰是实时观测 —— **这两件事撞在一起了**。

### 改进（两件都要，缺一不可）

**① 让 ISR 里已有的停滞计数**触发主动复位**（`main.c:656` 那一段）

```c
} else if (++s_hb_stall >= 12000u) {
    s_hb_stall = 0;
    fault_record(g_shm, FAULT_LOOP_STALL, g_tick_count, g_loop_hb, g_stage);  /* 先留痕 */
#if DCL_LOOP_WDT_RESET
    eng_outputs_safe(g_shm);        /* ★ 复位前先进安全态 —— 复位只是"停止驱动" */
    NVIC_SystemReset();
#endif
}
```

**两个必须先想清楚的：**
- **阈值约束**：现在 1.2s 是对着 816ms 留的余量，**但 `sd_log_poll()` 的最坏耗时你们测过吗**？
  若它也超 1.2s，正确做法是**刷盘期间暂停这条判据**（有窗口语义），**不是把阈值调大** ——
  调大只会让"真卡死"也检测不到。
- **这是个语义决策，要写进宣称**：对 PLC，「**复位进安全态**」优于「**失联但保持输出**」。
  后者是更危险的失效模式（操作工以为机器还在受控）。答案应该是"复位"，但要**显式说出来**，不能默认。

**② 最小心跳下沉到 ISR**（保住实时可观测性）

ISR 用串口 TXE **非阻塞**发 2~3 字节"ISR 活着"帧，不经主循环。
这样主循环死了，上位机仍能区分「**整机死**」与「**主循环死**」——**这两件事的处置完全不同**。
（不要在 ISR 里等 TXE；要么非阻塞丢帧，要么只在停滞时发一次。）

**③ 两级看门狗：在 H7 上不成立，别再想**
H7 只有一个 IWDG；想用 WWDG 保主循环，但它走 APB(PCLK 100MHz)、窗口语义、**超时上限只有几十 ms**，
装不下"主循环可能合法阻塞 816ms"的现实。

## 3. 判据完整性（P1）：`-DDCL_WDT=0` 负向对照还没做

你们 §7 自己列为"未做"，我确认它是**最后一块拼图**：

正向证明了"注入挂死 → ≤200ms 复位 → `--boot` 说得出 IWDG1"。**但它没排除"注入动作本身导致了复位"**
—— 若 `SD_CFG[13]` 那条注入路径碰巧触发了别的异常，**读数会长得一模一样**。
**开关和注入手法都是现成的**，成本很低，建议先补。

---

## 4. 自描述的下一步（P2）：只描述到"区"，没描述到"字段"

`manifest.h` 的 `/proc` 式思路是对的，**消灭了"PC 端硬编码地址"这一整类缺陷**
（实测印证：`g_shm` 一天内挪了三次 `0x200084A0 → 0x200084C0 → 0x20008560`，工具却零改动）。

**但"字段语义"目前有两份副本**：
- `manifest.h` 的注释里（如 `WDT_STAT[0..25]` 的完整字段表）
- `mgmt.py` 的解析代码里（按硬编码偏移解）

**⇒ 这正是 `PR=4/RLR=99` 写死那类漂移的下一个发生地** —— 加一个字段忘了同步，
工具会**静默读错位**（而它现在完全没有防护）。

**建议**：`kind=MF_K_STRUCT` 的条目，让目录**再自报一层字段描述符**
（字段名 + 偏移 + 宽度 + 语义），或退一步——固件自报一个字段名表供 PC 打印。
做不到全自动也行：**至少让 `mgmt.py` 的偏移解析与 `manifest.h` 的注释有一个"对账判据"**
（比如固件自报 `WDT_STAT` 的字段数 + 一个 FNV 校验和，PC 侧对账——你们在 `BB_DIAG[37]` 已经用过这招）。

## 5. 其他（P2/P3）

| 级 | 项 | 说明 |
|---|---|---|
| **P2** | `fault_record` 的首例哨兵用 `FAULT_NONE(0)` | 判据是 `f_code == FAULT_NONE` ⇒ 若有人传 `code=0`（bug），**首例会被反复覆盖**。你们已注意到"不能用 `total==1`"（因为 total 可能不涨）✓，但没走到最后一步：**用一个独立的 `f_first_valid` 位**，别让哨兵落在合法值域内。 |
| **P3** | `--read <struct>` 先打 34 字原始 dump 再判读 | 噪声大；加个 `--raw` 开关把 dump 变成可选 |
| **P3** | `SD_CFG` 列在只读目录 | 暴露魔数 `0xF00DBEEF`（暴露"如何触发调试钩子"）；**写被拒是对的** ✓，仅记录信息暴露面 |
| **P3** | `WDT_STAT[23]` 的语义方向 | `1 = 跑满预算(=啥也没等到)` —— 命名是反的（读的人容易当成"成功"）；建议改名 `sync_expired` 或把 1/0 语义写进 manifest 的字段注释 |

## 6. 建议顺序

1. **P1 主循环失活** —— 先决定"复位还是不复位"（这是语义决策，不是技术决策），再落 ①；② 作为配套
2. **P1 负向对照** `-DDCL_WDT=0` —— 成本最低、补齐最后一块判据
3. **P2 字段级自描述** —— 不阻塞，但它决定"下一批诊断区能不能不加维护成本地扩"
4. **P2/P3 其余** —— 随功能走

## 7. 一句话评价

**这套东西的价值不在"看门狗会把板子复位"**（那是 IWDG 的出厂功能），
**而在"它把每一次异常都变成了可读的证据"**：首例 freeze-frame、字节级观测面、自洽式校验、
复位签名对表、期望值由固件自报 —— 这些加起来，才让"下一次 ORE"不必再花一天。

**但它还没回答那个问题**：*喂狗点之外的东西死了，谁负责？*
—— 这是这套系统**唯一不能自愈的失效模式**，也是它作为"管理系统"目前最大的一处留白。
