### ★★★ 声明的时间量 = 跑出来的（2026-09-18 新增，G10）

**可以依赖**：你在程序里写的**时间量**就是那段真实时间。判据里**不出现实现细节**，只问"声明的物理量实现了吗"。

| 你写的 | 实测（三档 div0/div1/div2 都验过） | 判据 |
|---|---|---|
| `LPF τ = 2.0 s` | τ_eff = 2.0000 ~ 2.0057 s | `tools/exp_eq_dt_semantics.py` |
| `PID Ki = 1.0 /s`（err=1） | 积分速率 = 0.99970 ~ 1.00145 /s（**精度 0.01~0.08%**） | 同上 |
| `TIMER PT = 3/5/7 s` | 翻转时刻 = 声明秒（div2 与 div0 **同拍配对差 0 拍**） | 同上 |
| `SEQ 超时 = 2/4/6 s`（含**阈值+超时同时使能**） | 阈值路径在拉起后 ~50 ms 推进；超时路径在声明值 ±0.3 s | 同上 |
| `op=19 sub=4 限时 = L ms` | 流逝率 **999.7~1000.1 ms/s**（**静默与持续读两种宿主条件都测**） | `tools/exp_er_motion_time.py` |
| `sub=17 斜坡 = S Hz/s` | 爬升时长 = ΔHz/S（实测 −0.19%） | 同上 |
| `sub=15 走 N 步 @ f Hz` | 时长 = N/f（固件拍号直读：**0.9916 s vs 1.0000 s**） | `tools/exp_es_step_duration.py` |
| 拍长（`-DDCL_TICK_US=`） | **一个旋钮**：dt 三档 / div2 相位数 / 门的除数 / step 的拍↔秒换算全部自动跟随；200 µs 档下上述判据**全部仍成立** | `docs/exp-EU-tick-and-cost.md` |

★ **边界（会限制上表的适用范围）**：
- **`RATE`/`PID-D` 的 div0 在 100 µs 档曾被认为"结构性不可测"——那个说法是错的**（理由写反了），
  现已补判据并实测通过（`(9000,11000] ∋ 10000`）。★ 这条留在这里作**教训**：**SKIP 的理由也要能被推翻**。
- **秒级绝对量只到 ~0.1%**（"声明↔拍"与"拍↔上位机墙钟"各 ~0.1%）；更强的溯源需外部时基。
- 「走 N 步」的**过冲**界是"**本次停脉冲前主循环的最大间隔**"（可读 `g_loop_gap_max`），
  **不是**"1 圈 0.37 ms"（后者是名义值，实测被打破 189~282 倍）。
  设计规则：要求过冲 ≤ k 步 ⇒ **`f ≤ k / 主循环最大间隔`**。
- 运动域的上述结论**与机械无关**（脉冲由 TIM3 硬件发、TIM4 硬件数）；
  **本装置在那些测试里未使能驱动器**（轴不动，不影响时间判据）。
## 3. 明确**不要依赖**的（禁区，逐条有据）

| 不要依赖 | 为什么（不是"没做"，是"做不了或反着来"）|
|---|---|
| **`0x10 DEPLOY` 单帧传大程序（>2 KB）** | 曾经偶发"协议静默"。**根因已修**（帧组装超时 + 接收环 4096），但**上游"主循环会停顿数十~数百 ms"（`sd_log_poll` 等）没治** ⇒ 仍可能丢字节。**大程序请走分片路径 `0x45/0x46/0x47`**（本来就为分片设计，且顺带持久化）|
| **内部 flash 掉电保持** | 已按设计降级（擦 flash 会让拍 ISR 卡死 ⇒ 看门狗复位）。**持久化一律走 SD** |
| **"发请求即得值"** | 事务**跨拍**（≈6~8 拍）⇒ 必须用**就绪门**（`done_seq == req_seq` / `IX_DONE_SEQ`）|
| **引脚号 / 总线地址写进程序** | 契约 §3.1 红线：程序只能写 `sensor[i]/wire[j]/actuator[k]`；`tools/dcl_static_check.py` 会在编译期**拒绝** |
| **用"等值"判能力字或应答长度** | 能力字随版本增长（`0x0DF7 → … → 0x7DF7`），应答只**追加**不缩短。判据用 **必备位掩码** 与 **`>= N`** |
| **`0x39 op=7`（重新校时）** | **交付固件里不存在** ⇒ 时基死在协议面上**无法自证**（影响已因换用 TIM5 降低，但缺口仍在）|
| **`DB_RC_DST(6)` / `DB_RC_NOSEQ(8)` 当作"已验证的拒绝路径"** | 是**死码**（编码层不可达 / 入口即返回）。已由 `claims` 闸门**显式登记为 uncovered** —— 不得据此声称"这两条测过"|
| ★★★ **复位默认的 ENA 极性** | `enapol` 默认 **0**，与实机接线**相反** ⇒ `ena(1)` 实际是**失能**；而 `ena(0)` / `step_stop_safe()` / `step_init` 的"上电安全态"实际是**通电**（**三处同时反相**，见 `RELEASE` §6.1）。**要动电机必须先置 `enapol=1` 并回读 `PE9==1`** —— 只看 `ena`（逻辑位）会被骗 |
| **依赖动态内存 / 内存池** | 本平台**全静态**（内存宪法公理⑤ · 不变量 **M6**）：`C_other`/`C_scan` 之所以是常数，前提是"**每拍访问的内存集合编译期封闭**" ⇒ 引入分配器会让 `di(t)` 不再可算。判据: `src/` 里 `malloc/free` 出现次数 == 0（C12） |
| **依赖内存隔离 / MPU 分区** | ③层程序由"构建期静态判据 + 部署期校验 + 单写者公理"三重管；威胁模型里**没有不可信程序** ⇒ 暂不上 MPU（它带来的是故障路径成本）。★ 这与"多轴/多实例"是两个不同的缺口，不要混为一谈 |
| **在程序或工具里写固定地址 / 依赖内存地图** | 程序只引用**符号**（信号名 / `sensor[i]` / `wire[j]`）；固定地址的**唯一权威源**是 `src/memmap.h`（不变量 **M1 地址唯一**），`tools/hardcode_audit.py` 机械执行归属（**M5**：引用者必须在区的 `refs` 白名单内）。容量超限给出**可执行报错**（含"板上限 N"+ 三条修法）；账本 `python tools/mem_report.py` |
| **把 `0x39 op=19`（步进/引脚探针）当架构能力** | 它是**定位脚手架**：未进 SHM、无 `obs_anchor()` 登记、**不占能力位**、③层程序**不得依赖**它。（审计/上机排查可以用，产品代码不要用）|

## 4. 使用入口（贴墙用）

| 场景 | 命令 / op |
|---|---|
| 板子还活着吗 | `0x01`（返回 `fw` + 能力字）；或 `python tools/h723_proto.py` |
| 认口（**必须掩码**）| `(cap & 0x0DF7) == 0x0DF7`；本版 cap = **`0x7DF7`** |
| 接一个新器件 | 写 `DB_ENTRIES[8]` → FNV-1a(按 32 位字) → `DB_CRC` → `DB_PERIOD` → **最后**递增 `DB_REQ_SEQ` |
| 每次提交前 | **先读回 `DB_REQ_SEQ` 当基准**（`0x13 RESET` 会归 0；不要自己维护计数器）|
| 上传大程序 | `0x45 BEGIN` → `0x46 DATA`（分片）→ `0x47 COMMIT` → `0x48 STATUS` |
| 开帧归属 | `0x05 FRAME_MODE [1]`（★ 它的应答**永远用 v1**）→ 之后用 v2 帧 |
| 重放"开机装载" | `0x39 op=23`（程序 + 绑定表；**不能替代真断电那一次**）|
| 读设备侧帧模式 / 组装超时计数 | `0x39 op=24` / `op=25` |
| ★★★ **驱动电机前（尤其每次复位/上电后）** | `0x39 op=19 sub=5 arg=1`（`enapol=1`）→ **回读断言 `PE9==1`**。**不要只看 `ena`**（逻辑位 ≠ 引脚实读）。审计脚本已内建 `ensure_enabled()` |
| **某个工具报"无应答 / 一直 TIMEOUT"** | ① 先 `python tools/h723_frame_attrib_test.py --reset-mode`（可能是设备被留在 v2）② 仍不回：**静置 ~60 s**（历史上会自愈）③ 再不行 `pyocd reset` |
| 一键全量回归 | `bash tools/h723_full_regress.sh`（末尾自动探活）|

## 6. 判据纪律（本系统"能信"的根据）

1. **每条判据都能失败**，并且配了对照：变异体（注入固件缺陷看判据是否变红）· 反空判据 · 逐字节比对。
2. **"覆盖不到"要判 SKIP，不是 PASS**；闸门"覆盖不足"判**无效**，不是"干净"。
3. **未覆盖项必须显式声明**（`--allow-uncovered <理由>`）—— 不允许沉默地留着。
4. 数字都追得到命令：`docs/RELEASE-v2.1.0.md` §8。

## 7. 兼容承诺（改了就是破坏性变更）

| 保证 | 说明 |
|---|---|
| **v1 帧一字不改** | v2 只在协商后启用；未协商 ⇒ 与老上位机**逐字节相同** |
| **应答只追加、不缩短** | 例：`0x48` 从 96 → 104 B，前面 96 B 未动 ⇒ 判据请写 `>= N` |
| **能力字只增位** | 已有位的语义不变；判据用掩码 |
| **老程序包行为不变** | 无绑定段的老包 ⇒ 不恢复绑定，其余逐字节相同 |
| **反向不承诺** | 新包 + 老固件**不保证可用**（老固件不认识新字段）|
