## 三、待定问题

### 问题1：核心0自己做memcpy是否违反"不等待"原则

**场景**：核心0 ISR检测到reload_flag，需要从暂存区拷贝2KB到活动区。

**分析**：2KB memcpy在240MHz下约10μs。ISR上限100μs，多花10μs不影响。且memcpy是纯SRAM操作，不访问总线。可接受的"一次性代价"。

**倾向**：可行，不算违反。但需要在ISR执行时间预算中计入。

---

### 问题2：程序slot的版本管理 → 已定

**结论**：最简单的方式。NVS存多个program_N，一个active变量指向当前用的。
```
NVS:
  "program_0" = {路由表, 参数}
  "program_1" = {路由表, 参数}
  "active"    = 1     ← 当前跑的是 program_1
```
核心0启动→读active→加载对应program。切换时改active值。

### 问题7：PC编译器形态 → 已定

**结论**：一期做CLI工具(Python)，后续加IDE。
```
PC端: lf-compile my_program.lf → route_table.bin + params.bin
       ↓ 通过MQTT或串口发送到ESP32
ESP32: 核心1接收 → 存NVS → 写暂存区 → reload_flag → 核心0运行
```

---

### 问题3：离线期间的参数修改

**场景**：WiFi断了，用户在App上改了目标温度。

**倾向**：离线改不了是合理的。核心0按最后一次参数继续运行。

---

### 问题4：核心1写参数的原子性

**场景**：核心1正在写PARAM_TABLE[3]的四个float，ISR同时读到。

**倾向**：不管。float单次写入原子。最差一个周期值混合，下周期稳定。

---

### 问题5：PID自整定

**倾向**：一期不做。手动调参。

---

### 问题6：传感器故障检测

**倾向**：核心0不检测，核心1通过读Sensor_Map判断。
