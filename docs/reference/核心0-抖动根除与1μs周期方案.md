## 一、抖动根除：计算与输出解耦

### 1.1 问题的本质

```
当前ESP32-S3架构:

  定时器触发 ─?─ ISR入口(抖) ─?─ 计算(定) ─?─ 写PWM寄存器(立即生效)
       ↑                          ↑              ↑
  0抖动硬件                  462ns抖动      输出跟着抖
```

**根因：计算完成时刻 = 输出生效时刻。** ISR入口的抖动直接传导到了硬件输出。消除这个传导链条，就消除了抖动。

### 1.2 解耦原理

```
解耦后架构:

  定时器触发 → ISR入口(抖) → 计算(定) → 写影子寄存器(无timing要求)
                          
  定时器硬件事件 → 影子→真实寄存器(硬件时钟, 0抖动!) → 输出
```

**计算可以在任何时刻完成，输出由硬件定时器在精确时刻触发锁存。** 计算侧的抖动不再影响输出侧。抖动没有被"消除"——它变得无关紧要了。

### 1.3 ESP32-S3实现：外挂74LVC574

ESP32-S3的LEDC/MCPWM没有硬件影子寄存器。通过外挂一片八位D触发器实现等效功能。

```
电路:

  ESP32 GPIO[0..5] ──→ 74LVC574 D[0..5] ──→ Q[0..5] ──→ GaN半桥6路PWM
                            ↑
  ESP32 GPTimer Compare ──→ CLK (上升沿触发)
  
工作流程:

  周期N内:
    ISR算完FOC → GPIO输出寄存器写入新占空比值 (6个, ~30ns)
    这些值在574的D输入端等待, Q输出保持旧值
    
  周期N+1 边界时刻:
    GPTimer Compare在精确时刻触发 → CLK上升沿
    574在3.5ns内锁存 D→Q → 6路PWM同时更新
    → 输出时刻由GPTimer Compare决定, 0抖动 (仅受晶振精度影响)
```

| 参数 | 值 |
|------|-----|
| 芯片 | 74LVC574 (8位D触发器, SOIC-20/TSSOP-20) |
| 供电 | 3.3V |
| 传播延迟 | 3.5ns |
| 输出驱动 | 24mA/引脚 |
| 价格 | ¥2-3 |
| 额外PCB面积 | ~20mm² |

### 1.4 H723实现：内置TIM1影子寄存器

H723的TIM1高级定时器自带硬件影子寄存器，无需外挂芯片。

```
TIM1配置:

  TIM_OC1PreloadConfig(TIM1, TIM_OCPreload_Enable);
  
工作流程:

  ISR写 CCR1 → 值进影子寄存器 (不影响当前PWM)
  TIM1溢出(UEV事件) → 影子自动加载到真实CCR1 → PWM更新
  延迟: 1个TIM1时钟周期 = 3.6ns
  抖动: 0 (硬件自动完成)
```

| | ESP32-S3 + 74LVC574 | H723 TIM1 |
|---|---|---|
| 实现方式 | 外挂D触发器 | 内置影子寄存器 |
| 额外硬件 | ¥3 + PCB | ¥0 |
| 锁存延迟 | 3.5ns | 3.6ns |
| 抖动 | <0.5ns | <0.5ns |

### 1.5 根除后的效果

```
之前 (ESP32-S3, 直接写LEDC):
  输出抖动: 462ns p-p (等于ISR入口抖动)

之后 (ESP32-S3 + 74LVC574 或 H723 TIM1):
  输出抖动: <0.5ns (仅受晶振精度和锁存延迟变化影响)
  改善倍数: ~1000x
  
  周期波动(测量值): 仍然存在462ns p-p (CCOUNT测量t0点不变)
  输出确定性:     <0.5ns (物理输出, 和测量值解耦)
```

**关键认知：周期测量抖动 ≠ 输出抖动。** 测量值(CCOUNT t0)反映的是ISR入口时刻的变化，
但输出时刻由硬件锁存决定，与入口时刻无关。

## 二、控制周期降低到1μs

### 2.1 加速路线图

```
基准 (ESP32-S3, DRAM, 手写C):
  29条混合路由: 3,500 cyc @240MHz = 14.6μs
  5条PID链:   ~800 cyc = 3.3μs

第1级 — H723 TCM + 双发射 (换芯片即有):
  29条混合路由: 2,600 cyc @550MHz = 4.7μs
  5条PID链:   ~450 cyc = 0.82μs ✅ 已破1μs

第2级 — CMSIS-DSP加速 (换函数实现):
  29条混合路由: 1,200 cyc @550MHz = 2.2μs
  5条PID链:   ~150 cyc = 0.27μs
  22条混合路由: ~530 cyc = 0.96μs ✅ 1μs跑22条

第3级 — 汇编重写热原语 (进一步压榨):
  22条混合路由: ~380 cyc = 0.69μs
  最大容量@1μs: ~35条路由
```

### 2.2 CMSIS-DSP 加速原理

CMSIS-DSP是ARM官方免费提供的DSP函数库，针对Cortex-M7流水线做了汇编级优化。

核心加速来源：
1. **消除条件分支** — 积分限幅等用位运算替代if/else，消除分支预测失败（M7分支预测失败 = 12周期惩罚）
2. **双发射指令排布** — 整数和浮点指令交替排布，M7可同时发射两条
3. **预取数据** — 一次加载4个float值到寄存器，减少LOAD指令次数

```
例: PID原语加速

原实现(C语言, switch/case中):
  字面浮点运算 + if/else限幅 + 结构体访问
  → 200 cycles

CMSIS-DSP arm_pid_f32():
  DTCM零等待 + 双发射排布 + 位运算替代分支 + 批量加载
  → 35 cycles
  
加速比: 5.7x
```

关键原语加速预估：

| 原语 | 原实现 | CMSIS-DSP | 加速比 |
|------|--------|-----------|--------|
| PID | 200 cyc | 35 cyc | 5.7x |
| LPF | 130 cyc | 30 cyc (arm_biquad) | 4.3x |
| SCALE | 60 cyc | 15 cyc (arm_scale) | 4.0x |
| CLAMP | 50 cyc | 12 cyc (arm_clip) | 4.2x |
| SIN/COS | 150 cyc | 20 cyc (arm_sin_cos) | 7.5x |

### 2.3 1μs周期的路由容量预算

```
1μs = 550 cycles @550MHz

原语类型      数量    单价      小计
───────────────────────────────────
PID           2×      35 cyc    70 cyc
LPF           2×      30 cyc    60 cyc
CMP           3×      15 cyc    45 cyc
SCALE         2×      15 cyc    30 cyc
CLAMP         2×      12 cyc    24 cyc
ADD/SUB       3×      20 cyc    60 cyc
MUL           2×      20 cyc    40 cyc
AND/OR/NOT    2×      15 cyc    30 cyc
DIRECT        3×      10 cyc    30 cyc
MUX           2×      20 cyc    40 cyc
开关开销              20 cyc    20 cyc
───────────────────────────────────
总计          22条              449 cyc → 0.82μs
余量                             101 cyc → 18%
```

**22条CMSIS-DSP优化的混合原语，在1μs周期内执行完毕，占有82%时间预算。**

### 2.4 不同周期的能力边界

| ISR周期 | 可跑路由数 | 典型场景 |
|---------|-----------|---------|
| 1μs (1000kHz) | ~22条 | 单通道PID + 滤波 + 告警 + 通讯 |
| 2μs (500kHz) | ~44条 | 双通道PID + 前馈 + 诊断 |
| 5μs (200kHz) | ~110条 | 多回路控制 + 复杂逻辑 |
| 10μs (100kHz) | ~220条 | 全FOC + 位置环 + 速度环 + 诊断 |
| 50μs (20kHz) | — | 几乎所有程序都够用 |

### 2.5 周期与传感器带宽的匹配

控制周期降到1μs后，瓶颈从控制器转移到传感器：

| 传感器 | 读取延迟 | 1μs周期下能读到新值吗 |
|--------|---------|---------------------|
| AS5600 (I2C磁编码器) | ~500μs | ❌ 500个周期后才能读 |
| BISS-C编码器 | ~30μs | ❌ 30个周期 |
| ADC (5Msps) | 0.2μs | ✅ 每次都更新 |
| 模拟编码器 (Sin/Cos) | 零延迟 | ✅ 每次都更新 |
| 霍尔传感器 | <1μs | ✅ 每次都更新 |

**控制周期降到1μs后，必须配合高速ADC或模拟传感器才能发挥全部带宽。** 
对于编码器反馈的场景，电流环周期建议≥10μs，让编码器有时间送新数据。

## 四、总结

```
当前                    ESP32-S3 + 74LVC574        H723 + TIM1影子
──────────────────────────────────────────────────────────────────
抖动(输出)  462ns       <0.5ns                    <0.5ns
周期下限    ~15μs       ~15μs (ESP32算得慢)       1μs (22条路由)
CPU         240MHz      240MHz                     550MHz
RAM         共享DRAM    共享DRAM                    DTCM(零仲裁)
额外硬件    —           ¥3 (74LVC574)              无(内置)
改逻辑速度  4μs热切换   4μs热切换                  同架构移植
```

**根除抖动 = 解耦计算和输出。**
**降低周期 = H723 TCM + CMSIS-DSP加速。**
**两个问题独立解决，互不阻塞。**
