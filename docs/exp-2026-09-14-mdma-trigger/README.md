# 实验单元：MDMA 输出锁存链的触发源归因

- **日期**：2026-09-14
- **触发**：用户提出"在 ISR 内把输出后的任务推后 1~2 µs 给 MDMA 让路"，随后形成
  "新建 CPU 时间表 + MDMA 时间表，让两条时间线不互相干涉"的系统性要求
  （见 `docs/ARCH-TIMELINE-CPU-MDMA.md`）。
- **本实验要回答的问题**：把 MDMA 锁存的触发源从 `TIM2_UP` 换成 `TIM2_CC4`
  （把"表 B"整段移出拍边界），能不能降低引脚抖动？
- **一句话结论**：**不能 —— 而且原因不在方案本身**。实测发现
  **MDMA 通道根本不消费任何请求源（它在自循环）**，因此
  **输出引脚的边沿时刻由 CPU 写影子的时刻决定，硬件定时器对输出时刻没有贡献**。
  所谓"七级触发链"（`do.c` 的注释）不成立。

> ★★ **本目录只记录实验，不改变主线代码。**
> 实验期的固件改动（`src/main.c`、`src/regs.h`）**没有**进入版本库，只以
> `firmware-experiment.patch` 的形式留档（457 行）。仓库里的 `src/` 始终是
> **上一版稳定运行**的代码。要用本目录的仪器复现，先把 patch 打到工作区。

## 2. 顺带修掉的一个**空判据**（不修它，后面所有抖动数据都不可信）

**现象**：`g_ppat_wr_n` 涨到 101 万，而 `min/max/last/first` **全是 0**、五个分档计数**全是 0**。

**根因不是统计代码**（分档条件是穷尽的）——`tp = DWT_CYCCNT` **恒为 0**，
所以 `if (g_ppat_prev != 0u)` 这个门**永远进不去**。

真因是**本项目自己记录过**的陷阱（`src/modbus.c:79`、`src/faultlog.h:75`）：
**pyocd / 调试器会话退出时调试域断电 ⇒ `DWT_CTRL.CYCCNTENA` 被清 ⇒ CYCCNT 冻结在 0**，
而固件的 `dwt_enable()` 早在启动时跑过了，之后就没人再打开它。

⇒ 新增 `0x39 op=7`：重新 `dwt_enable()` + 清统计，并**返回两次 CYCCNT 读数**，
把"时基到底在不在走"变成**可失败的判据**。修复后分档立刻有数据（`0/20/3255/21/0`）。

> ★ 教训：**凡 DWT 派生的观测量，判据里必须含"时钟在走"这一条** ——
> 否则它是一个**永远通过的空判据**（看起来"这条路径很干净"，实际是"从没被走到"）。

## 3. 方案②第一次实现**静默失效**：一个绑定跨了两个寄存器

把 `DMAMUX1_C8` 从 22（`TIM2_UP`）改成 21（`TIM2_CH4`）**不够** ——
定时器的 DMA 请求还被 `TIMx_DIER` **逐位门控**：

| DIER 位 | 门控的请求 |
|---|---|
| `UDE` (bit8) | `TIM2_UP` → 请求号 22 |
| `CC4DE` (bit12) | `TIM2_CH4` → 请求号 21 |

而 `src/do.c:176` 只置了 `UDE` ⇒ **切到 CC4 之后那个请求根本不会产生**。
表现就是本项目最熟的一类故障：**寄存器写着我要的值、也读得回来，功能一动不动。**

修法：`trig_source_apply()` 必须**同时**改"路由（DMAMUX 请求号）"与"门控（DIER）"。
> 同族教训对照：以前是"**一个常量两用**"（请求上限 ≠ 响应上限），
> 这次是"**一个语义两处存放**"。

## 4. 结果一：修好之后，寄存器全绿，**引脚纹丝不动**

`0x39 op=6` 自证（sel=1）：`DMAMUX1_C8=21`、`DIER=UIE,CC4DE`、
`SR.CC4IF=1`（**CC4 事件确实在产生**）、`DMA2_S0_CR=0x5111(EN=1)`、`MDMA_CCR=1(EN=1)`。

**判据用的是形状判据**：锁存若真移到拍内 50 µs，`PE0 − PA8` 相位**必须**变成 ±50 µs。
这个判据不受噪声/量化影响。（若比 σ 这种幅度判据，就完全分不出来 —— 见 §7。）

完整数据见 `analysis.txt` 表 1：

| capture | 说明 | PE0 σ | PA8 σ | **PE0 − PA8** |
|---|---|---|---|---|
| `la_trig_up` | 旧：sel=0 `TIM2_UP` @16MS | 68.4 ns | 29.1 ns | **+132 ns** |
| `la_trig_cc4` | 旧：sel=1 CC4@50µs（DIER 没改 ⇒ 无效）@16MS | 73.7 ns | 26.7 ns | **+127 ns** |
| `la_UP_r1` | 新：sel=0 `TIM2_UP` @16MS（修好后基线） | 64.1 ns | 32.3 ns | **+120 ns** |
| `la_CC4_r1` | 新：sel=1 CC4@50µs（路由+门控都改对）@16MS | 69.3 ns | 31.6 ns | **+122 ns** |

⇒ **相位纹丝不动（±2 ns）⇒ 换请求源无效。**

## 5. 结果二：四个"否决性"实验 —— 链路根本不是注释写的那样

用 `op=8/9/10` 把每个环节**单独拆掉**，判据统一为"**锁存还在不在动**"
（`op=2` 会先用 `BSRR` 把 ODR 污染成 `0x7F`，所以"ODR 又回到影子值"就说明锁存活着）：

| # | 拆掉什么 | 锁存还活着吗 | 含义 |
|---|---|---|---|
| ① | `DMAMUX1_C8 = 0` + `DIER` 无任何 DMA 使能位 | **照常工作** | 触发不经过 DMAMUX / DIER |
| ② | `DMA2_S0_CR` 的 `EN` 清零（回读 `0x5000` 确认） | **照常工作** | 触发不经过 DMA2_S0 |
| ③ | `MDMA CTBR.TSEL` 扫遍 0…15 | **全部照常工作** | MDMA 不消费 TSEL |
| ④ | `MDMA_CH0_CCR` 的 `EN` 清零 | **停** | ✓ 写入者确实是 MDMA |

**⇒ MDMA 通道不消费任何请求源，它在自己循环。**
旁证：`MDMA_CH0_CBNDTR` 在多次读回中出现 4→2→1 的**递减**、`CISR` 的完成标志反复出现。

## 6. 结果三（决定性）：锁存时刻跟随的是「影子写入」

在 ISR 里对影子做**第二次写**（把 bit0 取反），扫"两次写之间的 NOP 轮数"：

| NOP 轮数 | 第二次写 | **PE0 − PA8 均值** |
|---|---|---|
| 0 | —（只写一次） | **+119.7 ns** |
| 800 | 写 | **+3347.1 ns** |
| 1600 | 写 | **+6324.1 ns** |
| 3200 | 写 | **+12282.0 ns** |
| **1600** | **★ 只空转、不写（对照）** | **+128.1 ns（不动）** |

**斜率 ≈ 3.9 ns/轮，线性。**
配套排除项：ISR / `do_poll` / `engine_scan_itcm` 地址全在 **ITCM**（0xE4 / 0x25E0 / 0xC94）
⇒ NOP 循环**零总线流量**，"刷 AXI 把 MDMA 饿住"的解释不成立；
而**纯空转对照相位不动**，进一步排除"ISR 位置/争抢"。

⇒ **锁存时刻 = CPU 最后一次写影子的时刻 + 0.12 µs。**
⇒ **输出引脚时刻由 CPU 决定；硬件定时器对输出时刻没有贡献。**

**副产品（解释"为什么每拍只有一个边沿"）**：`pat(T−1)^1` 与 `pat(T)` 的 bit0 **相同**
（因为 +1 会翻转 bit0），所以第一次锁存落进 ODR 时**不产生边沿**，边沿只出现在第二次锁存处。
⇒ 若不做这个位运算校验，很容易把"每拍两次锁存"误判成"每拍一次"。

## 7. ★ 方法学收获：**幅度判据不可复现，形状判据可复现**

`analysis.txt` 表 1 里 PE0 的 σ 在 8 个采集档之间是：
**52.5 / 60.8 / 64.1 / 68.4 / 69.3 / 69.3 / 73.7 / 91.4 ns**（跨度近 2 倍）。

⇒ **"σ 变了 X ns" 这种幅度判据，在 ~40 ns 的档间波动面前没有分辨力。**
（这也回过头说明：之前"方案① 关黑匣子无效（σ 只动 0.3 ns）"的结论虽然结论正确，
但**推理依据偏弱** —— 好在它的结论是"无变化"，无变化不需要分辨力。）
而 `PE0 − PA8` 相位在不同档之间稳定在 **±2 ns**。

⇒ **判据选择铁律：证明"一个事件被移动了"，用形状判据（整段平移）；
不要用幅度判据（σ/极差）。**

## 9. 结论与影响

1. **"计算与输出解耦、引脚输出时刻由硬件锚定"这条核心设计原则，当前并未达成。**
   引脚时刻 = CPU 写影子时刻。ISR 里任何让"写影子"变晚的因素（多做一个域、
   被总线拖慢、多一次 cache miss）都会**直接搬到引脚上**。
2. **抖动预算要重新分配**：PE0 σ ≈ 60 ns 里约 45 ns 来自这个"自由跑采样"环节
   （`PE0 − PA8` 延迟分布 = 125 ± 45 ns），CPU 侧只贡献约 26 ns。
3. **方案② / 让路 / 关黑匣子这些"分离两条时间线"的手段注定无效** ——
   因为两条时间线本来就没有通过"请求"相连。
4. **AXI 的一个大消费者可能就是 MDMA 自己**（自循环 ⇒ 每轮都要读 AXI 里的链表节点），
   这值得单独量一次带宽占用。

### 待办（下一步）

1. **让 MDMA 真正"一次请求搬一次"**（把通道从自循环改成一次触发一次搬运），
   再用**同一套判据**复测。成功标志：
   - `op=11` 双写时相位**不再跟随** NOP（回到 +0.12 µs 且不随 NOP 移动）；
   - PE0 σ 收敛到接近 PA8 的 ~26 ns（★ 需多次重复采集才能下这个结论，见 §7）。
2. 确认后决定交付配置：**"定时锚定"（输出滞后一拍、抖动小）** 还是
   **"CPU 直写"（无滞后、抖动大）**。
3. ★ 已知约束：MDMA 的 `CTCR/CTBR/CBNDTR/CSAR/CDAR/CLAR` **只在 `CCR.EN=0` 时可写**，
   否则**静默忽略**；且清 `EN` 后**不能只靠写 `CCR` 重新使能**，
   需完整重初始化或复位（本轮踩到：写 0 回读仍是 `0x20000`）。
