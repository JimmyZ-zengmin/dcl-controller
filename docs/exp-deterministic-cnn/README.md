# exp-deterministic-cnn —— 确定性推理时间 CNN（DT-CNN）

> 立：**2026-09-21** ｜ 状态：**P0（骨架就位，成本常数待标定）**
> 板卡：LXB723ZG-P1（STM32H723ZGT6，400 MHz，ITCM 64 KB / DTCM 128 KB）
> 基线：`v2.1.0`（cap `0x7DF7`）｜ 引擎契约：`docs/REF-program-contract.md`

---

## 0. 一句话命题

> **推理的完成时间是一个「承诺值」：无论拓扑与输入如何变化，推理一定在设计周期之内结束。**
> **那个周期由设计者定**（1 拍 / 1 ms / 10 ms / 100 ms / 1 s 都可以），
> **但一旦定下，就必须是可算、可证、可被闸门拦住的。**

### ★★ 2026-09-21 重构（charter 级，来自用户决定）

**本课题不再要求"一拍内完成"。** 前一版把推理锚定在单拍上 ⇒ 切片被引擎的门压到
**8,000 cyc/拍** ⇒ 结论是"网络只能 6,500 MAC"。**那是自我设限。**

把周期变成设计参数后，可用算力放大 **100 倍**：

| 承诺周期 | 拍数 | 切片总量（按 8,000 cyc/拍） | 可跑 MAC（int8 @0.5 cyc/MAC） |
|---|---|---|---|
| 1 拍 · 100 µs | 1 | 8,000 | 16 000 |
| **1 ms** | 10 | 80 000 | 160 000 |
| **10 ms** | 100 | 800 000 | **1.6 M** |
| **100 ms** | 1 000 | 8 M | 16 M |
| 1 s | 10 000 | 80 M | 160 M |

⇒ **10 ms 就是 LeNet 级；100 ms 相当宽裕。**
★ 而"承诺值"这件事**没有被放宽** —— 变大的只是周期，不是不确定性。

## 1. 这个命题与"在 MCU 上跑 AI"的区别

| | 行业常见做法（TFLM / STM32Cube.AI） | **本课题** |
|---|---|---|
| 跑得动吗 | 能 | 能 |
| 最坏执行时间 | **测出来**（事后统计 / profiler） | **算出来**（事前可证） |
| 超预算怎么办 | 运行期才发现，或**根本没有机制** | **部署期拒绝**（闸门） |
| 依赖 | 算子库 + **函数指针分派** + 动态 arena | 定长循环 + 静态缓冲 + **无间接跳转** |
| 可复现性 | 受 cache / 调度 / 算子实现影响 | 同输入同周期，**可回放** |

⇒ **目标不是"能跑 AI"，是"能证的 AI"。** 前者满街都是；后者是这个引擎唯一不可替代的东西。

★ **为什么这条值得单独立项**：若走 TFLM，`MicroInterpreter::Invoke()` 走**算子解析器的函数指针**、
且多个 kernel 含数据相关分支 ⇒ **本项目"成本可算"的根前提被拆掉**。
那不是"多一个功能"，是**把护城河填了再盖楼**。

## 2. 为什么这在架构上成立（核心论证）

本引擎的"每拍成本可算"来自一条性质：

> **无数据相关控制流**（无循环、无间接跳转、无递归、不可行路径已消除）

而一个**固定拓扑**的 CNN：

- 每层循环次数 = **编译期常量**
- 无早退（不允许 `if (conf > 0.9) break`）
- 无数据相关的索引/边界分支（padding 在编译期定死）
- ⇒ **同样没有数据相关控制流**

### ⇒ 同一个性质。这不是"破坏架构去跑 AI"，是**把既有性质扩展到新领域**。

★ **必须同时更正一处旧宣称**：`docs/ARCH-EXECTIME-COMPUTABILITY.md` 写着"四大难题全砍了
（循环边界 / 间接跳转 / 递归 / 不可行路径）"。本课题引入**定长循环** ⇒ 该句应改为
"**三个全砍；循环边界保留，但为编译期常量**"。**不更正就是制造假宣称。**

详细论证与陷阱清单见 [`THEORY.md`](THEORY.md)。

## 2.5 ★★★ 机制：**切碎，每拍一片** —— 控制环零扰动

承诺一个周期**不等于**"有一拍被推理占满"。

**后者会让那一拍的控制延迟** ⇒ 对运动控制器就是**抖动**，是致命的。
本课题是给运动控制用的，所以必须先排除它。

**正确形态 = 本项目已有的 `adc_poll` 模式**（`GAP-6 推论` 的同一件事）：

```
每拍做固定的一小片（如 2,000 MAC）  →  N 拍后完成  →  完成时刻 = N × 拍长
```

| 性质 | 为什么成立 |
|---|---|
| **每拍成本恒定** | 每片工作量固定 ⇒ 这就是可证性的来源 |
| **完成时间 = N × 拍长** | **固定**，且是承诺值 |
| **控制环不受影响** | 推理永远只用拍内剩余的那一份 |

★ **判据（能失败）**：切碎版 vs 整拍占用版对照 ⇒
**整拍占用版必须让 `emax` / `ov` 变差**。若两者一样，说明切碎没有意义（或测量不对）。

### 拍内预算的显式分配

一拍 40,000 cyc 是**两个使用者的共享池**，分配必须显式：

```
引擎扫描 ≤ EXEC_BUDGET_CYCLES    （默认 32,000 = 拍长 × 80%）
推理切片 ≤ DC_SLICE_CYC          （默认  8,000）
--------------------------------
合计     ≤ CLK_TICK_CYCLES       （= 40,000，编译期断言）
```

⇒ **想让推理拿更多，就得显式压低引擎的预算** —— 那是一个**可证的设计选择**，不是调参。
（提示：`-DDCL_TICK_US=200` 会把拍长变 80,000，两个使用者的池子一起变大。）

## 3. 输入信号：为什么用"跟随误差序列"而不是相电流

★ **这是本课题与常见"电机故障诊断 CNN"最大的差别，也是它能今天就开工的原因。**

| | 常见做法（电流特征分析 MCSA） | **本课题选的路** |
|---|---|---|
| 输入 | 相电流 I_q（需电流采样通路） | **跟随误差序列**（`AS5600 实测位置` − `指令积分位置`）|
| 本台架有吗 | ⛔ **没有**（TB6600 是 step/dir，无相电流输出；板面无分流/隔离放大/霍尔） | ✅ **有，且已有 10 kHz 拍内通路** |
| 覆盖的故障 | 电气类（缺相、绕组、供电） | **机械/运动类：失步、背隙、卡滞、磨损、谐振、负载突变** |
| 对本装置重要吗 | 中 | **★ 高** —— 步进系统的**主导故障就是机械的** |

**理由**：TB6600 开环电流 + 步进电机，`驱动器内部自己斩波`，本系统**没有 FOC、没有相电流环路**。
强行追相电流 = 先买硬件、先改驱动器 —— 那是**采购问题，不是研究问题**。

而跟随误差序列在这套系统里是**最富信息的一维时序量**：
- 10 kHz、每拍可得（拍内模式，反馈率实测 1002~1114 Hz；阻塞路 163 Hz）
- **失速检测已经在用它**（`examples/h723_step_stall_recover.dcl`，突加 18000 Hz ⇒ 1.17 s 触发）
- ⇒ **CNN 是这个已跑通用例的自然推广**，不是从零开始

★ **诚实边界**：跟随误差**看不到纯电气故障**（如驱动器过流保护动作前的电流畸变）。
本课题**不声称覆盖电流特征分析**。若将来上车电流通路，输入换成 `[跟随误差, I_q]` 双通道即可，
**拓扑与成本模型不用改**。

## 4. 三个待答问题（每个都带能失败的判据）

### Q1 —— 单条 `cycles/MAC` 是多少？（**P1，承重**）

**这是唯一一个我现在没有数的量。** 后面所有结论都挂在它上面。

| 项 | 内容 |
|---|---|
| 做什么 | 写固定拓扑卷积核（放 ITCM、定长循环、无分支），拍内跑，用协议面 `emax` 量 |
| 判据 ① | 预测 vs 实测**留点 ≤3%**（照本项目 E-K 的既有口径） |
| 判据 ② ★ | **两次不同输入给出同一个 `emax`** ⇒ 证明"数据无关"成立（这条不过，整个命题不成立） |
| 判据 ③ | **关掉 `FPSCR.FZ` 的对照档必须量出差异** ⇒ 证明那条断言不是空的 |
| 判据 ④ | 负对照：故意在 kernel 里插一条数据相关早退 ⇒ **判据 ② 必须变红** |
| 工具 | [`cost/measure_mac_cost.py`](cost/measure_mac_cost.py) |

**预估口径（待实测替换）**：f32 ≈ 4 cyc/MAC · int8+DSP(`SMLAD`) ≈ 0.5 cyc/MAC。
⇒ 15~20 kMAC 的网络：f32 ≈ 154~200 µs（**超一拍**）· int8 ≈ **19~25 µs（一拍内）**。
★ **⇒ int8 不是优化选项，是"能不能进一拍"的前提。**

### Q2 —— 最坏时间能不能在**编译期**就钉死？（**P2**）

| 项 | 内容 |
|---|---|
| 做什么 | 拓扑写成编译期常量 → `MAC 数`是常量 → `最坏周期 = Σ(层 MAC × cycles/MAC + 层开销)` |
| 判据 | 把切片改大到越界 ⇒ **构建必须失败**（变异对照，见 [`kernels/dcnn_topology.h`](kernels/dcnn_topology.h)）|
| 判据 | 注入一个"估小了"的常数 ⇒ 部署门**必须变红**（照 `OP_TRANS_COST` 的先例：纯可加不是上界） |

### Q3 —— 它真的能分辨故障吗？（**P3，应用**）

| 项 | 内容 |
|---|---|
| 做什么 | 在现有台架上采集 3 类窗口：正常往复 / 人为失步 / 人为增加负载 |
| 判据 ① | **阴性对照**：故障窗口必须被判为故障（★ 只做"正常→正常"是**假绿**——恒输出"正常"的常数模型也能过） |
| 判据 ② | **输入扰动 ⇒ 输出必须动**（防"推理被跳过 / 输入恒 0"伪装成"正常"）|
| 判据 ③ | 端到端时延 = 设计值 ±5%（读协议面 `emax`，**不用 DWT** —— 见下）|
| 判据 ④ | 同一段输入重放两次，**逐位相同的输出**（确定性推理的直接证据）|

## 5. 阶梯（从最简到复杂，每级都要能在板上跑）

| 级 | 内容 | 出口判据 |
|---|---|---|
| **L0** | 边界写死：切片 + 引擎预算 ≤ 拍长，**编译期断言** | 变异对照能让构建失败 |
| **L1** | ★★★ **切碎机制 —— 不用 CNN！** 一段工作量已知的假负载，每拍切一片 | ① 每拍增量**恒定** ② 完成时间 = N×拍长（实测 = 设计）<br>③ **整拍占用对照版必须让 `emax` 变差** |
| **L2** | 单个卷积层，定长循环、无分支、ITCM | Q1 四条判据全过 |
| **L3** | 全网络 + 按**承诺周期**切碎（周期是设计参数，不限于 1 拍） | 实测完成时间 = 承诺值；两组不同输入同耗时 |
| **L4** | 接进闸门（ITCM 闭包 + 部署门 `CNN_cost`） | 注入"估小了"的常数 ⇒ 门变红 |
| **L5** | 应用落地（见 §5.5） | 应用自己的判据 |

★ **L1 的顺序不能颠倒**：**先证明"固定周期承诺"这个机制成立，再谈网络。**
用假负载就能验，不需要任何 ML。

## 5.5 应用层：用 CNN 规划速度曲线 —— 换一个说法

### 不做：让 CNN 输出完整的 `v(t)` 曲线
梯形 / S 曲线本身是**解出来的数学**，CNN 不会更好。拿它去替代解析式只会更差更不可证。

### 要做：让 CNN **给曲线提供参数**

| 参数 | 今天怎么定 | CNN 该学什么 |
|---|---|---|
| **加速度上限** | 靠余量 / 反复试 | 受**惯量与机械共振**限制的那条线 |
| **匀速段速度** | 靠余量 / 反复试 | 受**共振区与失步边界**限制 |
| **减速起点** | 解析式（理想） | 受**摩擦 / 负载**影响的实际到位点 |

★ 这三个参数**今天要么靠人调、要么靠保守余量** ⇒ 直接对上「**电控调试占非标项目 40% 时间**」。

### ★★★ 更高价值的一条：**学习前馈（ILC）—— 它天然就是"固定周期推理"**

重复运动（产线上是绝大多数）⇒ **跟随误差曲线可重复** ⇒ 可以逐轮修正前馈。

```
第 k 轮：执行 → 记录 e_k(t)
轮  间：算修正量 Δu(t)  ← ★ 推理发生在两轮之间
第k+1轮：前馈 = 前馈 + Δu → e_{k+1}(t) 更小
```

| 为什么它是本课题的最佳落点 | |
|---|---|
| **周期天然固定** | 推理周期 = 运动周期（10 ms ~ 1 s）⇒ 完美对"固定周期承诺" |
| **指标客户看得见** | 直接改善**跟随误差**（不是内部指标） |
| **拍内零额外成本** | 修正量在轮间算；拍内只多一条前馈查表 |
| **修正量有存放处** | **LUT（256 点）** —— 顺带回答 `PLAN-completion` 里 LUT 归属那个待拍板问题 |

### 前提（必须先解决）
要"每轮的误差曲线"，就得采到**整段运动**。黑匣子运动时跨度只剩 ~0.4 s ⇒
`PLAN-expansion-headroom.md` §A2 已给方案：**DTCM 余 76 KB，另开一块秒级环**；
★ 与"**触发式抓取**"合用（只在运动窗口内记），跨度利用率最高。

## 6. 明确不做（附理由）

1. **不用 TFLM / Cube.AI 作为推理内核** —— 函数指针分派 + 数据相关分支 ⇒
   **拿不到"可证"，而那是本课题存在的全部理由**。（可以用它们**离线**训练与量化。）
2. **不准有数据相关的控制流**：无早退、无动态 padding、无"置信度够高就跳过"。
3. **不追相电流特征分析**（本节 §3 的边界）。
4. **不引 run-time 堆**：所有缓冲静态、住 DTCM（与本项目零 malloc 一致）。
5. **不改 `MAX_ROUTES`** —— 与本事无关；CNN **不走路由表**（实测：路由法 8,547 µs/次，
   且需 129,000 条路由，是上限的 1008 倍）。
6. ★★ **不让 CNN 直接输出控制量。** 推理的输出只能**参数化**下层，
   且**限幅必须住在下层（引擎的 `CLAMP` 原语里）**，不能住在被学的那一侧。
   ⇒ 理由有两条：① 可证性（学习组件的输出域不可枚举）② 安全。
   **若限幅也长在被学的那一侧，等于没有限幅** —— 这不只是理论：2026 世界机器人大会的
   「决策正确、执行失败」就是上层输出没有被下层兜住。
7. **不让推理占满任何一整拍**（那会制造控制抖动）—— 见 §2.5。

## 7. 测量纪律（复用本项目既有铁律）

- ★ **测前先断言时基活着**：`0x13 RESET` → `0x11 START` → 等 1 s → `pmin` 非 0。否则**拒答**。
- ★ **不用 DWT 做交付判据**：`pyocd` 会话会**静默停掉 `DWT_CYCCNT`**（本项目铁律 0）。
  交付档时基是 **TIM5**；一律读协议面 `0x38` 的 `emax`。
- ★ **不用大 deploy 传大程序**：走分片 `0x45/0x46/0x47`
  （`0x10` 单帧 >2 KB 有已知"丢字节"上游）。
- ★ **每个配置前 `0x13 RESET`**（`main.c:3617` 显式调 `stats_reset()`）⇒ `emax` 才干净。
- ★ **板子认口按能力字**，不认 COM 号。
