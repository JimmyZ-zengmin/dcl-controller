# E-L 混合 op 验证：**可加性不成立**，但上界成立（2026-09-18）

> 这是 E-K 留下的**唯一关键缺口**：E-K 验的是单 op 程序，只验了"每项常数对不对"，
> **没验 `Σ_ops` 的求和**。而"可加性"在本项目历史上失败过一次
> （`docs/exp-TCM-cycles` §A2.3 的 `k × 转变数`）。
> 工具：`tools/exp_el_mixed.py` · 分析 `.tmpctl/el_analyze.py`。

---

## 1. 设计（一次实验分离"求和"与"排列"）

固定 **n=128、div0**（每拍全跑），PID 与 DIRECT **各 64 条**，
**只改排列**以改变"相邻 op 不同的次数"：

```
block=128: 全 PID                 ⇒ 转变数 0
block= 64: 64×PID + 64×DIRECT     ⇒ 转变数 1
block= 32/16/8/4/2/1: 更细交错     ⇒ 转变数 3/7/15/31/63/127
```

★ **每种 op 的总条数恒为 64** ⇒ `Σ_ops` 那一项**恒定**
⇒ 任何随 block 变小的**增量**，就**只能**来自"邻接 op 改变"。

**纯可加预测** = `C + 64×64.00 + 64×29.50` = **6580 TB**（全部来自 E-K，本步不重新拟合）

---

## 2. ★★ 结果一：可加性**不成立**（但很小）

| block | 转变数 | 实测 di | 偏差（实测−纯可加）| 每转变 |
|---|---|---|---|---|
| 64 | 1 | 6588.9 | **+8.5** | 8.500 |
| 32 | 3 | 6600.5 | +20.1 | 6.700 |
| 16 | 7 | 6622.5 | +42.1 | 6.014 |
| 8 | 15 | 6666.6 | +86.2 | 5.747 |
| 4 | 31 | 6754.6 | +174.2 | 5.619 |
| 2 | 63 | 6930.6 | +350.2 | 5.559 |
| **1** | **127** | **6744.6** | **+164.2** | **1.293** ← ★ 离群 |

**噪声底 = 0.0 TB**（同一程序重复三次，极差 **0**）⇒ 上表每个偏差都是**真实的**。

**⇒ 纯可加系统性低估，最多 `+350.2 TB = 700 cyc（5.3%）`，且永不反向。**

★ **这一点对"门"是危险的**：纯可加**不是上界** ⇒
**会放行实际超预算的程序**。而本项目历史上前两代成本模型（标量 3.03、`min` 口径表）
**犯的正是同一个方向的错**（见 `RETRACTIONS.md` P24/P25）。

---

## 3. ★★ 结果二：转变项**存在，但不是常数**

### 3.1 block≥2 那 6 个点：**拟合到 0.9 cyc**

```
偏差 ≈ 3.4 + 5.506 × 转变数   (TB)
残差最大 0.4 TB = **0.9 cyc**
```

★★ **`k = 5.506 TB = 11.01 cyc/转变`** —— 与 §A2.3 当年独立测得的
**`k = 10.0 cyc`（DIRECT+PID）** 吻合到 **10%**。**跨实验复现。**

### 3.2 但 block=1（严格交替）**离群**

它 127 次转变，偏差却只有 **+164.2 TB**，比 block=2（63 次转变）**还便宜 186 TB**。

⇒ **每转变成本随块变小而下降**：`8.50 → 5.56`（降 35%），然后 block=1 掉到 **1.29**。

★ 与 §A2.6 当年记的**完全一致**：
> "唯一的离群是 **bs=1（严格交替）**：那是**分支预测器能完美学习的周期模式**，所以它反而便宜。"

**⇒ 同一个现象在两次独立实验里重现。这不是噪声，是机制。**

⇒ **不能用单一全局 `k`。**

---

## 4. ★★★ 结果三：但**上界可以做出来**，而且可以在部署期算

**目标**：找一个 per-transition 系数 `k`，使 `纯可加 + k × 转变数 ≥ 实测` **处处成立**。

⇒ **最小安全系数 `k* = 8.90 TB/转变 = 17.8 cyc/转变`**，7/7 点全部成立：

| block | 转变数 | 预测 | 实测 | |
|---|---|---|---|---|
| 64 | 1 | 6588.9 | 6588.9 | ✅ |
| 32 | 3 | 6606.7 | 6600.5 | ✅ |
| 16 | 7 | 6642.3 | 6622.5 | ✅ |
| 8 | 15 | 6713.5 | 6666.6 | ✅ |
| 4 | 31 | 6855.9 | 6754.6 | ✅ |
| 2 | 63 | 7140.7 | 6930.6 | ✅ |
| 1 | 127 | 7710.3 | 6744.6 | ✅ |

### 4.1 这给出一个**成立且可算**的上界

```
di ≤ C + Σ_ops ( m_op × 该 op 条数 ) + 17.8 cyc × (相邻 op 改变次数)
```

★ **"相邻 op 改变次数"可以在部署期从路由表直接数出来** —— **零运行期代价**。

### 4.2 但它**不紧**

`block=1` 时过估 **966 TB（1932 cyc）** —— 因为严格交替是分支预测器最擅长的模式，
而 `k*` 是按最坏形状（block=2）定的。

⇒ **结论与 E-A…E-K 一致，而且这次是在"程序形状"维度上：**
> **能给出成立的界，但界的松紧依赖程序形状。**

---

## 5. 对"可算"总账的影响

到此为止，模型的完整形态是：

```
di(t) = C_other(474, 与程序无关)
      + C_scan(随 op 略变, 574~596)
      + Σ_ops ( m_op × 该 op 本拍条数 )        ← m_op: 19 个跨构建稳定常数
      + 转变项（相邻 op 改变）                  ← ★ 非单调, 是"形状"的函数
```

| 项 | 状态 |
|---|---|
| `Σ_ops` **求和本身** | ✅ **成立**（block=64 偏差 +8.5 TB；噪声底 0）|
| `m_op` 19 个常数 | ✅ 跨两代固件复现 ≤0.6% · 跨 division 留点 3.1% |
| **转变项** | ◐ **存在、可算、但不单调** ⇒ 做成**上界**要 `k*=17.8 cyc`（偏松）|
| 纯可加做界 | ❌ **不安全**（低估最多 5.3%，且方向与历史两代错误相同）|

★ **可主张**：存在**成立且部署期可算**的上界（含转变项）。
★ **不可主张**：该上界"紧" —— 松紧是程序形状的函数。

## 6. 下一步建议

| # | 项 | 价值 |
|---|---|---|
| **1** ★ | **把转变项加进门的预算计算**（`engine_prog_budget`）| 纯可加**不安全**（低估 5.3%）。转变数在部署期一数即得，零运行期代价。**这是安全性修复，不是优化** |
| 2 | 把 `k*` 收紧：按"最大 run 长度"而不是全局常数 | 现在对严格交替过估 966 TB；若按形状分档可收紧 |
| 3 | 转变项是否依赖 **op 对**（§A2.3 说 `k` 随 op 对而变：DIRECT+PID 10.0 / LPF+PID 5.5）| 本步只测了一对。若是表，则需 `(op_i, op_j)` 表 |
| 4 | `C_scan` 的 op 依赖（574~596）| 模型里唯一的"非 19 项常数"部分 |
