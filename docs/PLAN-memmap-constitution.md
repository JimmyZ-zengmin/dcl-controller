> **本文件是"内存管理怎么做"的唯一权威源。**
> ★ 它**显式更正**（不改写历史，但必须作废）`docs/PLAN-memory-management.md`（审计稿）中的四处结论，
> 并**采纳它最有价值的两条**（"不是不够用，是没有主" · "没有账本"）。处置见 §0.2。

## 0. 结论先行

**内存管理在本项目里不是"分配容量"，是给"每拍必须发生的事"保证三种物理性质。**
⇒ 它要做成**放置的宪法（编译期的类型系统）**，不是分配器。

**公理⑤（放置公理）**
> 每块内存**恰有一种所有权**（链接器 拥有 **异或** 固定地址 拥有），
> 且**它的物理性质必须与使用它的代码对时间的假设一致**。

**五条不变量**（每条都有一条能失败的机器判据，见 §3）

| # | 不变量 | 一句话 |
|---|---|---|
| **M1** | 地址唯一 | 一个地址只有一个权威源；地图**不得有第二份** |
| **M2** | 所有权互斥 | 链接器拥有的段与固定地址拥有的区**不得相交**（`.axi_buf` 陷阱） |
| **M3** | 性质匹配 | HOT_CODE∈ITCM · HOT_DATA∈DTCM · DMA_BUF∈AXI —— 且 `vector` 钉在 ITCM 顶 |
| **M4** | 容量派生 | 一切尺寸/容量**由构建派生**，不得手抄；文档里的容量宣称与账本比对 |
| **M5** | 归属唯一 | 固定地址区**只能被它的 owner 模块引用**（不是"注释里写着"） |
| **M6** | 静态封闭 | **每拍访问的内存集合必须在编译期封闭**（禁动态分配 —— 它是成本模型可算的前提） |

**它漏掉的三条（已并入本方案）**：
1. ★★★ **"ITCM 已满"是假的** —— 实测 **14.3 KB / 64 KB = 22.4%**，而这句话写在 **6 份文档**里，
   并被 README §五当作**多轴的"三个真阻塞"之一**（`src/step.h:133` 还记着它**已经第二次**支撑错误结论了）。
2. ★★ **`.axi_buf` 是一个压在诊断区上的空段** —— 链接器 AXI 段起点 = `0x24000000` = `SD_DIAG/BB_DIAG/SD_CFG/BOOT_AXI` 的起点。
3. ★ **DTCM 有 71.8 KB 无名区**（`_shm_end` + 4.5 KB → `_estack`），而 `_Min_Stack_Size` 只有 4 KB。

## 1. 实测基线（一条命令复核）

```bash
arm-none-eabi-size -A build/dcl_h723        # 工具链路径从 cmake/arm-none-eabi.cmake 读
```

| 区 | 实测 | 上限 | 判读 |
|---|---|---|---|
| **ITCM** | `.itcm_text` 13.32 KB @0x0 + `.itcm_vectors` 1.00 KB @0xFC00 = **14.3 KB** | 64 KB | **22.4%**；`0x3544..0xFC00` 有 **49.7 KB 连续空闲** |
| **DTCM** | `.data` 140 B + `.bss` 20.0 KB + `SHM` 32 KB + `._user_heap_stack` 4.5 KB = **56.2 KB** | 128 KB | 有主部分 43.8%；**71.8 KB 无名**（栈向这里长） |
| **AXI** | 320 KB **全被固定地址占满**（diag 0x600 / gap 10.5 KB / latch 0x3000 / 环 240 KB / SD_STAGE 64 KB） | 320 KB | **链接器可用 0 字节**；真实空隙只有 512 B + 1.5 KB |
| **SHM** | 32 KB，其中 routes/params/states ×(active+staging) = **12 KB（37.5%）** | — | 不是天花板（DTCM 还空 71.8 KB） |
| **Flash** | `.text` 47.6 + `.rodata` 3.7 + `.scan_flash` 2.1 + vectors 0.65 ≈ **54 KB** | 1 MB | 5.4% |

**⇒ 这个平台不缺内存。缺的是：①"性质—用途"的匹配检查；②容量数字的自证。**

## 2. 宪法形态：**一类表 · 两类所有权 · 六个 class**

- **两类且只有两类所有权**
  - **链接器拥有**：`SHM` · `.itcm_text` · `.itcm_vectors` · `.bss/.data` · 栈
  - **固定地址拥有**：外设 · AXI 全部区段 · MDMA 锁存/链表节点 · 向量表位
- **`src/memmap.h`（唯一源）**：每行 `name / 起止 / class / owner / 上限 / 依据`
- **class**：`HOT_CODE` · `HOT_DATA` · `DMA_BUF` · `DIAG` · `STACK` · `FREE`
  ★ class 不是标签，是**判据的输入**（HOT_CODE 必须在 ITCM、HOT_DATA 必须在 DTCM、DMA_BUF 必须在 AXI）
- ★ 命名借 **AUTOSAR `MemMap.h`** 的成熟思路，但我们按**时间性质**分类（它按初始化/保持语义分类）——
  两个维度**正交**，将来可合成一张两维表

### 2.1 AXI 的最终裁定
**AXI = 100% 固定地址拥有。删除 `.axi_buf` 段与 `_axi_start/_axi_end` 符号**
（已核：**全仓除 `.ld` 外无任何引用**）。理由：真实空隙只有 512 B + 1.5 KB，
**链接器没有余地**；留一个空段就是留一个陷阱。
需要 AXI 大缓冲时的**正确做法**写进 `memmap.h`：先改地图 → 重跑账本 → 本文件备案。

## 3. 判据总表（**"能失败"是入场券：每条都必须配变异对照**）

| # | 守的不变量 | 判据 | 变异对照（证明了才算数） | 成本 |
|---|---|---|---|---|
| C0 | M1 | **唯一源**：`0x2400xxxx` 这类固定地址的**定义**只允许出现在 `src/memmap.h`（其它文件只能 include） | 在 `blackbox.h` 里再写一个 `#define … 0x2400xxxx` ⇒ 红 | 低 |
| C1 | M2 | 固定区两两不重叠；AXI 各区**恰好铺满** 320 KB（无缝） | 故意让两区重叠 `0x10` ⇒ **构建必须失败** | 低 |
| C2 | M2 | 链接器段与固定区不相交（删段后由 C1 覆盖；另加 `SHM ⊂ DTCM 且 ∩AXI=∅`） | 把 `SHM_SIZE` 改到越出 DTCM ⇒ 构建红 | 低 |
| C3 | M4 | `_shm_end − _shm_start == SHM_SIZE`（链接期）且 `SHM_SIZE == 区表之和` | 只改 `SHM_SIZE` 0x10 不同步区表 ⇒ 构建红 | 低 |
| C4 | M4 | `mem_report.py` 每次构建打印四区账；**超限/重叠/不一致 ⇒ 非零退出** | 手工改小一个上限 ⇒ 闸门红 | 中 |
| C5 | M4 | `--check-docs`：docs/README 里的容量宣称与账本比对 | 往 docs 写一个错的 ITCM 数字 ⇒ 红 | 中 |
| C6 | M3 | HOT_CODE：ISR 可达闭包全在 ITCM（`gate_isr_itcm.py` 已有：44 函数 / 437 字面量自证）**＋ 使用率上限（>80% 红，>60% 告警）** | 把一个 ISR 可达函数移出 ITCM ⇒ 红 | 低 |
| C7 | M3 | HOT_DATA：`shm_layout_ok()` 扩展 —— `[g_shm, g_shm+SHM_SIZE)` ∈ DTCM 且 ∩AXI=∅，并与 `0x38` 回报一致 | 变异构建把 `g_shm` 指到 AXI ⇒ **启动必须拒绝**（不是静默跑） | 中 |
| C8 | M3 | DMA_BUF：`prog_store`/`blackbox`/`sd` 的缓冲地址 ∈ 各自区（编译期常量比较） | 把 `PROG_PAY_ADDR` 改到环里 ⇒ 构建红（现有 `#if` 接到 `memmap.h`） | 低 |
| C9 | M5 | owner 规则：固定地址区只能被 owner 模块引用（`hardcode_audit.py`） | 往非 owner 模块加一个环地址 ⇒ 红 | 中 |
| C10 | M3/M4 | 栈与无名区：`STACK_HEADROOM` 显式命名 + 引导铺魔术字 + **运行期最深水位**；`_estack − (_shm_end+4.5KB) ≥ 8 KB` | 递归/大局部数组压栈 ⇒ **水位必须变大**；水位 > 上限 50% ⇒ 告警 | 中 |
| C11 | M4/M5 | 容量发布：`dclc` 解析出的容量 == `engine.h` 的 `#define`（离线判据，进 audit） | 改 `engine.h` 一处 ⇒ 判据必须红（而不是"编过了 → deploy NAK"） | 中 |
| C12 | M6 | **静态封闭**：`src/` 里 `malloc/calloc/realloc/free/aligned_alloc` 出现次数 **== 0** | 加一行 `malloc` ⇒ 构建红 | 低 |

## 5. 拍板（**我定的，不再回问**）

1. **公理⑤ + M1~M6 立为平台不变量**（与 `CORE-ENGINE.md` 的四公理八不变量并列）。
2. **A/B/C/D 现在做**；E **不批**，改挂 §6 的可判定触发条件。
3. **AXI 定为 100% 固定地址所有**，删 `.axi_buf` 与 `_axi_start/_axi_end`（已核无人引用）。
4. **不引入任何动态分配/池**（M6）。理由不是"碎片"，是**它会摧毁成本模型**：`C_other`/`C_scan` 是常数的前提是"每拍访问的内存集合编译期封闭"。
5. **不上 MPU**（等"要跑不可信程序"这个需求；写进 `SUPPORTED-SCOPE §3` 的"不是什么"，并给理由，不留"以后再说"）。
6. **不重排 SHM**（维持 `MEMORY-LAYOUT §5` 结论）。
7. **owner 从"注释"升级为"判据"**（C9）—— 今天"载荷缓冲撞进黑匣子环"那件事，用 C8/C9 在**构建期**就能抓住。
8. **文档里的容量数字必须被 C5 管住** —— "ITCM 已满"这类过期数字**永久消失**。
9. **用户面只出容量与可执行报错**，不出地图（C11）。用户不该知道 SHM/AXI/槽号。
10. **交付档指纹若变，必须同一次提交里同步 `h723_restore_delivery.sh` 的 `EXPECT_MD5`**（P32）。
11. **`docs/PLAN-memory-management.md` 等三份未提交文档不进 `dcl` 公开仓**，直到有人 review（草稿不发公开仓）。

## 6. 明确不做 + E 期的触发条件

**不做**：动态分配/池（M6）· 虚拟内存/GC · MPU 分区 · SHM 重排 · 把地图交付给用户。

**E 期触发条件（任一成立即启动，并先写收益证据）**
1. 出现**第一个因 SHM 容量被真实拒绝的程序**；
2. **ITCM 使用率 > 60%**（C6 的告警线）；
3. **路由/参数表访问占拍预算 > 5%**（成本模型里的可测量项）。

## 7. 做完之后怎么知道做完了

- **一条命令得到四区账**，且账本里的每个数字都**由构建派生**（无手抄）。
- **五条不变量各有 1~3 条判据，每条都有变异对照**（A/B/D 三期合计 ≥ 10 条）。
- **6 份文档里的"ITCM 已满"消失**，多轴阻塞从 3 条变 2 条（都是采购/接线）。
- **`build.sh` 从 6 道闸门变 7 道**，且新闸门**已被证明会红**。
- **用户侧**：程序超容量时拿到一句可执行的报错，而不是 deploy 期 NAK。

## 附：一句话

**把 TCM 从"注释里的地图"变成"编译期的类型系统"** ——
每块内存有名字、有拥有者、**有一种时间性质**；性质与用途是否匹配由**构建期判据**回答；
容量数字一律**派生**；用户只看到容量与可执行的报错。
