## 四、核心理论：火车模型与周期内通讯时间窗

### 4.1 火车模型（硬实时时间表）

引擎采用**严格规划的固定时间表**，而非尽力而为模型：

> 100μs周期是一个固定时刻表，各组件在规划的时间片内执行。
> 如果有组件超时（违约），计算结果不会被DMA搬走，而是跳到下一周期输出。
> 这不是一个"尽力而为"的模型，而是一个严格的时间表。

```
周期100μs时间表:
┌────────────────────────────────────────────────────────────────┐
│  0 cyc    ISR入口                                              │
│  0-400    路由扫描（~3μs）                                     │
│  400-600  ADC/传感器处理（~1.5μs）                             │
│  600-1800 ★ 通讯窗口（10μs）                                  │
│              ├─ ETH DMA描述符检查（100 cyc）                   │
│              ├─ 0xC0帧解析：READ/WRITE即时响应（300 cyc）      │
│              ├─ 监控数据打包入TX队列（200 cyc）                │
│              └─ LAN9252 SPI PDO读写（~400 cyc）                │
│  1800-2000 余量A（防扫描超限）                                 │
│  2000-13200 余量B（大片空闲，主循环做TCP协议栈/CANopen）       │
│  13200-13600 DMA搬SHADOW→ODR（硬件完成，零CPU，不可违约点）    │
│           ↑ CCR4 match (97.5μs) — 铁定触发，不等任何人         │
└────────────────────────────────────────────────────────────────┘
```

**违约的定义**：CCR4 match时SHADOW值未写完 → DMA搬走的是上一周期的旧值 → 该周期输出不准。

### 4.2 通讯窗口设计原则

| 原则 | 说明 |
|------|------|
| **硬截止时间** | 通讯窗口有固定结束时间（1800 cyc），超了就不处理，等下一周期 |
| **轻量操作** | 窗口内只做：DMA描述符检查、寄存器读写、帧入列（总~5μs） |
| **重负载外移** | TCP协议栈（ACK/重传/窗口管理）、大文件拼接→余量B/主循环 |
| **MAC自理** | 以太网电缆的位时序由MAC硬件完全处理，不消耗CPU |
| **双口并行** | DP83848与LAN9252在同一个窗口内处理，不翻倍 |

### 4.3 为什么不是2×10μs = 20μs？

因为LAN9252是**专用ASIC**，EtherCAT帧处理完全在ASIC内部完成：

```
网线来帧 → LAN9252硬件解析 → 提取PDO → 存到DPRAM → 转发下一站
                                     ↑
                              CPU只做: SPI读/写几个字节
                               (~3μs, 可配DMA完成)
```

所以两个网口在同一个10μs窗口内并行工作，总CPU开销~8μs。

### 4.4 吞吐量推算

| 操作 | 每周期占用 | CPU耗时 | 吞吐量 |
|------|-----------|---------|--------|
| 监控上行（20个float/周期） | ~80字节 | ~300 cyc (2.5μs) | **840KB/s** |
| READ命令响应（16个WIRE） | ~72字节 | ~300 cyc | 即时响应 |
| WRITE命令 | ~8字节 | ~100 cyc | 即时响应 |
| 烧录大文件（分片） | 不分片使用窗口 | 主循环拼接 | **<10ms/2640B** |

## 五、分层决策理由

### 5.1 第1层：工程以太网（PC↔H723 直连，无RPi中间层）

| 决策项 | 选择 | 理由 |
|---|---|---|
| **物理层** | 100Mbps RMII + DP83848 PHY | STM32H723内置MAC，DP83848 ¥8模块，100Mbps=12.5MB/s |
| **传输协议** | TCP/IP（lwIP裸机） | 可靠传输，与Web IDE天然集成，无RTOS依赖 |
| **应用协议** | 自定义0xC0帧（改进版） | 4字节MAGIC帧同步，增量改动，兼容现有验证 |

> **v3.0 关键变化**：去掉RPi CM4中间层，**电脑网线直连H723**。工程通道承载：
> - 烧录（TCP分段，~300μs完成2640B程序）
> - 实时监控（UDP推流，每周期~80字节 → 840KB/s）
> - 在线调参（TCP命令/响应，<200μs延迟）

**验证标准**：
- Web IDE在1秒内读取所有1024路WIRE值
- 烧录2640B程序总耗时 < 10ms（vs 当前pyocd ~2s）

---

### 5.2 第2层：EtherCAT主力现场总线（LAN9252 ASIC）

| 协议 | 定位 | 控制器 | 理由 |
|---|---|---|---|
| **EtherCAT** | 主推（必选） | LAN9252 (¥25) | 运动控制黄金标准，<100ns同步 |
| **CANopen** | 补充（已有） | FDCAN1 + TJA1050 | 低成本传统传感器/变频器 |
| **Modbus RTU** | 补充（规划） | USART2 + MAX485 | 变频器/仪表行业标配 |

> **决策依据**：
> - LAN9252是硬件EtherCAT从站控制器，所有EtherCAT帧处理在ASIC内部完成，CPU只需SPI读写PDO数据（~3μs/周期）
> - EtherCAT是唯一能让你的<7ns抖动真正发挥价值的协议
> - 两个网口（DP83848工程口 + LAN9252 EtherCAT口）在同一个100μs周期窗口内并行工作，CPU总开销~8μs

**验证标准**：通过EtherCAT控制4轴伺服做插补运动，同步误差<100ns。

---

### 5.3 第3层：OPC UA + MQTT并列主力

| 协议 | 用途 | 理由 |
|---|---|---|
| **OPC UA Server** | SCADA/MES对接 | 工业4.0标准，语义模型 |
| **MQTT** | 上云/IoT | 轻量，带宽友好，适合边缘到云 |

**验证标准**：OPC UA Client（如UAExpert）能读写所有变量；MQTT消息5ms内送达云端。

### 10.2 各方式详解

#### 方式1：接口直接IO

```
PLC → 光耦隔离 → 大功率驱动 → 接线端子 → 设备
```

| 信号类型 | 用途 | 适用设备 |
|---|---|---|
| 数字输出(DO) | 24V/0.5A | 电磁阀、指示灯、继电器 |
| 模拟输出(AO) | 4-20mA / 0-10V | 变频器、比例阀、调节阀 |
| 数字输入(DI) | 24V | 接近开关、按钮、限位开关 |
| 模拟输入(AI) | 4-20mA / 0-10V / PT100 | 温度/压力/流量传感器 |

#### 方式2：脉冲/运动控制

```
PLC → PUL/DIR → 步进/伺服驱动器 → 电机
```

| 信号类型 | 用途 | 适用设备 |
|---|---|---|
| PUL+DIR | 脉冲+方向控制 | 步进电机、伺服电机 |
| CW+CCW | 双脉冲控制 | 通用伺服 |
| PWM | 占空比控制 | 直流电机、加热器、比例阀 |
| 模拟量±10V | 速度/转矩指令 | 变频器、伺服驱动器 |

#### 方式3：工业以太网（高端控制核心）

```
PLC主站 ──确定性以太网──→ 分布式IO + 伺服 + 变频器
```

| 协议 | 周期 | 同步精度 | 适用场景 |
|---|---|---|---|
| EtherCAT | 125us-1ms | <100ns | 高速多轴、CNC、包装 |
| PROFINET IRT | 250us-1ms | <1us | 汽车制造、化工厂 |
| EtherNet/IP | 2-100ms | 通用CIP | 北美产线、罗克韦尔生态 |
| CC-Link IE TSN | 31.25us | <1us | 亚洲产线、三菱生态 |

> **结论**：EtherCAT + 你的<7ns抖动引擎 = 完美的性价比组合

#### 方式4：现场总线（工业领域的"普通话"）

```
PLC主站 ──串行总线──→ 远程IO + 变频器 + 仪表
```

| 协议 | 速率 | 拓扑 | 适用场景 |
|---|---|---|---|
| Modbus RTU | 115.2kbps | 总线型 | 最通用（变频器/仪表/传感器） |

| DeviceNet | 500kbps | 总线型 | 北美工业 |
| CC-Link | 10Mbps | 总线型 | 三菱生态 |

> **结论**：Modbus RTU是工业传感器的事实标准，必须支持

#### 方式5：IO-Link（智能传感器"USB"）

```
PLC主站 ──3线电缆(24V+Data)──→ 智能传感器（供电+通信+参数配置）
```

**不可替代的优势**：
- 一根3线电缆同时供电(24V)和通信(双向数字)
- 远程参数配置：PLC可以修改传感器量程/阈值
- 故障诊断：传感器脏污/老化/断线可知
- 即插即用：不同品牌传感器统一接口

> **结论**：IEC 61131-9标准，西门子主推，2026年爆发式增长

#### 方式6：无线工业


```
移动设备/旋转物体/危险环境 ←─无线─→ 控制系统

## 附录A：工程通道协议规范（0xC0帧 over TCP:502）

### A.1 帧格式

```
TCP 流上的帧定界:
[MAGIC:4B][LEN:4B][CMD:1B][PAYLOAD][CRC16:2B]

MAGIC = 0xC0C0C0C0 (帧同步标记，支持TCP丢同步后重同步)
LEN   = 1 + sizeof(PAYLOAD) (大端，最大65535)
CMD   = 命令码
PAYLOAD = 载荷 (0-65534字节)
CRC   = CRC16-CCITT(CMD + PAYLOAD) (大端)
```

| 改进项 | v2.0 (UART) | v3.0 (TCP) | 理由 |
|--------|------------|------------|------|
| MAGIC | 1字节 (0xC0) | **4字节** (0xC0C0C0C0) | TCP流可能丢同步，4字节可靠重同步 |
| LEN | 2字节 (65535) | **4字节** (4GB) | 预留未来 |
| CRC | 覆盖CMD+LEN+PAYLOAD | 同左 | 防御NIC/路由器内存错误 |

### A.2 命令集

| 命令 | 码 | 方向 | 窗口内执行？ | 说明 |
|------|---|------|-------------|------|
| DEPLOY | 0x10 | PC→H723 | ❌ 主循环拼接 | 烧录程序（分片发送） |
| START | 0x11 | PC→H723 | ✅ 轻量 | 启动引擎 |
| STOP | 0x12 | PC→H723 | ✅ 轻量 | 停止引擎 |
| RESET | 0x13 | PC→H723 | ✅ 轻量 | 复位引擎 |
| READ | 0x20 | PC→H723 | ✅ **窗口内** | 读WIRE[N:M]，即时响应 |
| WRITE | 0x21 | PC→H723 | ✅ **窗口内** | 写WIRE[N]=float，即时生效 |
| WRITE_BATCH | 0x22 | PC→H723 | ✅ **窗口内** | 批量写WIRE（调参用） |
| MONITOR | 0x30 | PC→H723 | ✅ 轻量 | 订阅监控信号列表 |

### A.3 监控推流格式

```
订阅阶段 (TCP命令通道):
PC → [0x30][count:2B][wire_idx0:2B][wire_idx1:2B]...
H723 ← [0x30][stream_id:1B][period_cycles:4B]

        每周期ISR窗口打包一次
        payload = 20个float (80字节) + header(4B)
        10kHz × 84B = 840KB/s
```
