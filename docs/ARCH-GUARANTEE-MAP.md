# ARCH-GUARANTEE-MAP —— 保障图谱：「效果 ← 靠什么保证」

> **这份文件回答一个问题**：本项目声称的每一个效果，**到底靠什么机制保证的**？
>
> **为什么需要它**：这个项目最贵的病是**"宣称 vs 实现"分不清**（`docs/claims.md` 就是为此而生）。
> 而日常叙述里混着三种东西：**① 设计意图**（想这么做）、**② 实际机制**（真的靠这个）、
> **③ 曾经的设计意图（已被推翻）**。三者混讲 ⇒ 下一个人会把②当成①去推，或把③当②去信。
> ⇒ 本图谱**逐条把三者分开**，每条都带**判据**（怎么知道它成立）和**反例**（什么会打破它）。
>
> ★ 读法：**效果 ⇒ 保证机制 ⇒ 载体 ⇒ 判据 ⇒ 状态**；★ = 影响面；`❌` = 该机制**已被推翻**。

---

## §0 一句话总纲

> **确定性不是调出来的，是把"不确定性"逐个从路径上移除后剩下的东西。**

本项目移除的不确定性只有**五类**，其余全部效果都是它们的组合：

| 根机制 | 移除的不确定性 |
|---|---|
| **R1 零等待 TCM**（ITCM 代码 + DTCM 数据） | cache miss / 总线仲裁 / 访问周期波动 |
| **R2 单一硬拍**（TIM2，无 RTOS 无调度器） | 调度抖动 / 优先级反转 / 上下文切换 |
| **R3 静态表**（无控制流、无循环、无动态分派） | 分支预测 / 数据相关的路径长度 / 不可枚举的 WCET |
| **R4 层间判据 + 闸门**（判层表 + 6 道闸门 + 契据机检） | 人的遗忘 / 文档漂移 / "配置全对但功能不可用" |

★ **R1–R3 是"让时间可预测"，R4 是"让人不把可预测性弄丢"。** 四者缺一，前三条的收益都会随时间衰减。

## §2 逐条展开（**重点看 `③ 已被推翻的替代方案` 一栏**）

### G1 —— **输出抖动 σ = 3.6 ns**

| | |
|---|---|
| **效果** | 拍内"算完 → 引脚真的翻转"的**抖动 σ 3.6 ns**（量的是**引脚本身**） |
| **① 实际保证** | **计算段与输出段是拍内两段**（扫描只写 `ACTUATOR/WIRE`；输出段才碰引脚）⇒ 输出**不会发生在计算中途** |
| | **CPU 直写 `BSRR`**（单次 32 位原子写，**非读-改-写**）|
| | **零等待 TCM**：输出段代码在 ITCM、数据在 DTCM ⇒ 取指/访存周期固定 |
| | **无抢占**：TIM2 是 NVIC 最高优先级（USART1 = 0x80 最低） |
| | **单写者**：DO 面只有一个驱动者 |
| **③ ★❌ 已被推翻的替代方案** | 曾设计"**写影子 → 硬件定时器触发锁存到引脚**"（`DCL_DO_LATCH=1`：影子 → MDMA ch0 → `GPIOE_ODR`），**意图是让引脚时刻由硬件锚定、与 CPU 无关**。 |
| | **实测推翻**：`MDMA CTBR.TSEL` 扫遍 0…15 **全部照常工作** ⇒ **通道在自循环、不消费任何请求源** ⇒ **引脚时刻 = CPU 最后一次写影子 + 0.12 µs**。 |
| | ⇒ 该链**没有**锚定，反而**更差**：**1 档引脚 σ 54~60 ns vs 0 档 3.6 ns（差 15 倍）**。 |
| | ⇒ 交付档 = **`DCL_DO_LATCH = 0`（CPU 直写）**。**"输出由硬件锚定"从未达成**（见 `RETRACTIONS.md` P6）。 |
| **判据** | `build/CMakeCache.txt` 的 `DCL_DO_LATCH=0`；`0x39 op=16` 的 Σe/Σe² 算 σ；LA 外部复核（CH4←PA8） |
| **反例（什么会打破它）** | 任何人重新开 `DCL_DO_LATCH=1`；出现第二个写 `GPIOE_ODR` 的驱动者；把输出段搬出 ITCM；在输出段引入分支/循环 |
| **权威源** | `README.md` §七 · `docs/ARCH-TIMELINE-CPU-MDMA.md` · §5.3 |

### G2 —— **拍周期确定性 = 99.95 µs（跨度 90 ns）**

| | |
|---|---|
| **效果** | 拍基 **99.95 µs（−0.05%）**；`period_min/max` 跨度 **90 ns**；且**与扫描负载无关** |
| **保证** | **硬件定时器 TIM2**（不是软件延时、不是 OS tick）；**`ARR` 是编译期常量**（= 拍长 × 时钟）；**NVIC 最高优先级**（不被任何外设打断）；**ISR 内无阻塞等待** |
| **判据** | `0x38` 的 `period_min/max`（**注意：断言时基活着** → `0x39 op=21` 自检 Δ≠0）；LA 外部复核 |
| **★ 边界（成立条件）** | **仅在"ISR 能在拍内跑完"时成立**。实测：FLASH·混合路由 **41166 cyc = 102.9% 拍** ⇒ 周期塌成 41334~41910、极差 **576 cyc** ⇒ **超载后周期由 ISR 时长决定，不再由定时器决定** |
| **反例** | ISR 内加阻塞操作（实测血证：`adc_read` 16 次平均 = 4.1 ms/10 ms；flash 擦除阻塞 **210.6 ms** ⇒ 看门狗复位）；把实时量挂主循环（主循环一圈 **0.37 ms** = 3.7 个拍） |
| **权威源** | §四 时基与仪器 · `2026-09-16.md`（TIM5 换时基） |

### G3 —— **拍内按时完成（WCET 可算）** ← ★ 本项目的**核心命题**

| | |
|---|---|
| **效果** | 承诺"**每拍花多少周期是编译期就能算出的量**" |
| **保证** | **R3 静态表**：每拍 = 扫 N 条**定长 16 B** 路由，每条 = `读源 → 一个白名单原语 → 写目标`；**无循环 / 无递归 / 无动态分派 / 无数据相关分支** |
| | **逐条实测标价**：19 个原语每个都有实测 cyc（`k_op_cost_itcm`，最贵 PID 145） |
| | **分档（div0/1/2 + phase）**：把长尾摊到不同拍，用**桶表**只跑该相位该跑的条数（实测收益 **2.59×**） |
| | **静态门**：部署期 `engine_prog_budget > EXEC_DEPLOY_BUDGET(26000)` ⇒ **拒收** |
| | **动态门**：运行期 `di > EXEC_BUDGET_CYCLES(32000)` ⇒ `g_isr_overrun++` |
| **★ 边界（2026-09-18 已实测闭合）** | 见 `docs/exp-2026-09-18-overload/`：**静态门结构上不可达** —— 实测最重合法载荷 `budget = **18560**`（门 26000）且 **ACK**；而唯一能超额的越界 op 被**门序**以 `bad op` 先拒（不是 `exec budget exceeded`）⇒ 余量 **1.40×** |
| | **动态门可达且有效**（需模型外负载）：FLASH 扫描路径下 N=64 ⇒ `ov=0`（emax 95.8% 门）；N=72 ⇒ **`ov=1`**（107% 门）。阈值**精确卡在 16000 tick**；未过门的 4 档 `ov` 全为 0 |
| | **拍没被拉长** ✅ —— 空引擎 / DIRECT×128 / PID×128 / FLASH×72 四种负载 `pmax` **均 ≈20010 tick** |
| | ★★ 但 ⇒ **`ov == 0` 对任何合法程序都不可能失败**（最重合法只到门的 **66.8%**）⇒ **它仍是空判据**，动态门只是**模型外负载的兜底**（见 §3） |
| **反例** | ① 动态分派（函数指针/switch 落在数据上）② 循环 ③ 在原语里做阻塞外设事务 ④ ISR 内 libc `memcpy`（实测 71241 cyc ⇒ 拍周期塌成 1360~78640） |
| **权威源** | `docs/CORE-ENGINE.md` 四公理 · `ARCH-H723.md` §4.4 · §四 |

### G4 —— **热更新 ≤ 1 拍（逻辑 = 数据）**

| | |
|---|---|
| **效果** | 上传一段程序 ⇒ **本拍就用新表**，不存在"已受理但还用旧表"的中间态；`reload_lat = 1` |
| **保证** | **STAGING / ACTIVE 双表**（部署只写 staging）；**单字节 `RELOAD` 标志 = 原子**；ISR **在扫描之前**整段切换；**桶表必须与路由同拍切**（否则表与桶不一致）；**状态表先全清再拷**（新程序绝不继承旧积分残留）；切换用 **ITCM 字拷贝**（不用 libc `memcpy`） |
| **判据** | `deploy_seq / applied_seq / reload_lat`（`0x38`）；重载那一拍 ISR 变长可观测 `g_reload_cyc`（实测 ~3.6 µs） |
| **反例** | 状态表不清 ⇒ 饱和积分残留 ⇒ **上电满功率冲击**；桶表与路由不同拍 ⇒ 扫到错段；用 libc `memcpy` ⇒ 拍周期塌 |
| **权威源** | `ARCH-H723.md` §3.7 |

### G5 —— **掉电保持 / 改逻辑不重烧（程序持久化）**

| | |
|---|---|
| **效果** | `.dcl → 编译 → 通信上传 → 落 SD → 上电自动装载`，**不碰 flash 烧录** |
| **保证** | 上传 = `0x45 PROG_BEGIN / 0x46 PROG_DATA / 0x47 PROG_COMMIT`（事务式）；落盘 = **SD 卡 A/B 双副本 + 单调 seq + CRC32 + 写完回读 `memcmp`**；**装载时重跑与上传时同一套静态校验**（`prog_validate` 共用实现）；**`min_fw`/`req_caps` 上传期 + 装载期双点校验** |
| **判据** | `0x48 PROG_STATUS` 对账（`txn_begin/commit/abort` + 开机装载结果 + 卡上载荷头）；**五道闸** |
| **❌ 已被降级的替代方案** | 曾用**内部 flash 双副本 A/B**（扇区 6/7）。**实测**：擦 128 KB 时 ISR 卡死 **210.6 ms** ⇒ 喂狗停 ⇒ 看门狗复位 ⇒ **`DCL_PERSIST_SAVE=0`，持久化一律走 SD** |
| **反例** | 升 `LOG_VERSION` ⇒ 当新卡重建 ⇒ 从 LBA1 覆写**毁卡**；SD 卡两个写者；`SD_TMOUT_DATA` 往小里挤 |
| **权威源** | `docs/REF-program-contract.md` · §六 · `2026-09-15.md` 块22/23 |

| | |
|---|---|

### G7 —— **闭环搬进片内（每拍执行）**

| | |
|---|---|
| **效果** | 位置环**每拍**跑（10 kHz 执行频率），而不是 PC 在环（13.5 Hz） |
| **保证** | R3 静态表（环 = 若干条路由）；**反馈回填进拍内**（AS5600 从主循环搬进 ISR ⇒ 反馈率 163 Hz → **~1 kHz**）；**斜坡在固件当积分器**（程序只需"何时换目标"，不需在程序里做累加器） |
| **★ 诚实边界** | **执行频率 ≠ 带宽**。带宽上限 = **反馈更新率** ⇒ 阻塞路 163 Hz / 拍内 ~1 kHz。真实对比：**执行频率 ×700，带宽 ×6（阻塞）/×40（拍内）** |
| **实测收益** | A/B 阶跃：片内 **0.635 s** vs PC 在环 **2.115 s** = **3.3×**；机制**已更正为"控制周期 ⇒ 极限环"**，不是"快" |
| **★ 负结果** | **纯滞后项判据 FAIL**（`A−B = −9 ms`）⇒ 跟踪滞后上**没有收益**；`PC→引擎 单次受理+传输 = 15.1 ± 4.3 ms`，而原以为的 `87 ms` 里大头是 **ZOH 40 ms（PC 环 12.5 Hz 的 T/2）+ 测量口径 36 ms** |
| **反例** | 环在 ③ 层但**总线与驱动共用**（单写者被破 ⇒ 本项目已栽两次：TIM3 两个驱动者、SD 卡两个写者）；"每拍必须发生"的动作落进**主循环** |
| **权威源** | §5.27/§5.28 · commit `4b510a0` |

## §4 反面：**什么会一次性打破多条保证**

这些是跨条目的"共同杀手"，值得单独记：

| 杀手 | 打破哪些保证 | 血证 |
|---|---|---|
| **超载**（ISR 跑不完一个拍） | G2（周期由定时器定）· G3（WCET） | FLASH·混合 41166 cyc = 102.9% ⇒ 周期 41334~41910 |

## §5 这份图谱本身的用法

1. **加新效果时**：先问"它靠哪条根机制？" —— 如果答案是"靠约定"而不是"靠机制"，那它迟早会漂。
2. **改任何一条保证的载体时**：回到本表找该条的**反例列**，先确认没踩。
3. **引用本表任何"效果"时**：必须同时引用它的**诚实边界**（★ 那几行）——
   本项目已经因为"只引结论不引边界"撤回过两次数字（`87 ms`、`带斜坡 ~1100 rpm`）。
4. ★ **"设计意图"与"实际保证"必须分开写**。G1 的 `③` 栏就是范例：**曾经的设计意图不仅没生效，还更差 15 倍**。
