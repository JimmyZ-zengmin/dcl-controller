## 0. 一句话现状

**"用这个系统 = 写 DCL 程序" 这条链现在是通的**：
程序**走通信上传 → 落 SD 卡（A/B 双副本）→ 上电自动装载进引擎**，
全程**不碰 flash 烧录**，且每一环都有能失败的判据。
引擎内核（100 µs 硬拍 / ISR 全在 ITCM / 19 原语 / 热重载 / 下载前静态校验）**未受影响**。

## 1. ★ 新增的对外接口（`0x45`–`0x4A`）

| 码 | 名称 | 载荷 → 应答 |
|---|---|---|
| `0x45` | PROG_BEGIN | `[total_len:u32][crc32:u32][prog_id:u32][prog_ver:u16][min_fw:u16][req_caps:u32]` → `[total_len:u32]` |
| `0x46` | PROG_DATA | `[offset:u32][chunk...]` → `[next_offset:u32]`（**必须顺序、不跳不重**） |
| `0x47` | PROG_COMMIT | 空 → `[rc:u32][budget:u32]` |
| `0x48` | PROG_STATUS | 空 → **96 B**（见 §2） |
| `0x49` | PROG_ERASE | 空 → `[rc:u32]` |
| `0x4A` | DEVICE_DESC | 空 → `[fw:u16][cap_lo:u16][cap_hi:u16][n:u16]` + `n×[device_type:u16][product_code:u16][revision:u16]` |

**`0x48` 的 96 字节布局**（★ 它同时是"程序存储体检表"和"事务对账表"）：
```
+0  part_ok       +4  ab_valid(bit0=A bit1=B)   +8  seq_a      +12 seq_b
+16 crc_a         +20 crc_b                      +24 len_a      +28 len_b
+32 active(0=A 1=B 0xFFFFFFFF=无)                +36 ok_n       +40 fail_n
+44 reject_n      +48 last_rc                    +52 txn_begin  +56 txn_commit
+60 txn_abort     +64 boot_rc                    +68 boot_loaded
+72 deploy_routes +76 deploy_seq
+80..92  ★ 从卡上读回的载荷头 16 字节（判"我到底读回了什么"）
```

## 2. ★★ AXI 真实地图（**320 KB 已用满 —— 加缓冲前必须先看这张表**）

| 区间 | 占用者 | 大小 |
|---|---|---|
| `0x24000000`–`0x24000600` | 引擎诊断结构固定区（`SD_DIAG`/`BB_DIAG`/`SD_CFG`/`BOOT_AXI`）；**协议 `0x20 READ` 的放行窗口** | 1.5 KB |
| **`0x24000600`–`0x24003000`** | ★ **唯一空档** —— 程序存储缓冲在此（`0x24000800` / `0x24002800`） | ≈10.5 KB |
| `0x24003000` / `0x24003100` | MDMA 锁存快照 / 链表节点（`do.c`） | — |
| `0x24004000`–`0x24040000` | 黑匣子环（`BB_SLOTS=960` × 256 B = **240 KB**） | 240 KB |
| `0x24040000`–`0x24050000` | 日志冻结区 `SD_STAGE` | 64 KB |

★ `prog_store.c` 里有**构建期 `#if/#error`**：缓冲地址越出那个空档就**编译不过**。
★ `blackbox.h` 原写"AXI 完全空闲 / 128 KB / 512 槽" —— **三处都是过期的**，已更正。
  **照过期注释找空档的代价是白查一整轮**（缓冲落进环里，每拍被覆写）。

## 3. ★ SD 卡分区（S3）

```
LBA0                     日志头（扩展段 h[112]=LOG_END, h[113]="LEND"）
LBA1 .. LOG_END          日志数据区（环形回卷）
g_sd_prog_a .. +15      程序副本 A（16 块 = 8 KB）
g_sd_prog_b .. +15      程序副本 B
LOG_END = capacity - 1 - 32     ← 由**容量**算出，不是硬编码
```
★ **绝不升 `LOG_VERSION`**（一升版本 `sd_log_open` 就当新卡重建 ⇒ 从 LBA1 覆写毁掉卡上记录）。
★ 旧卡无该字段 ⇒ 不影响任何既有校验（`h[0]/h[1]/h[2]/h[6]` 四条照旧）⇒ 向后兼容。
★ **`s_log_blk` 必须钳位**：旧卡游标可能超出新上限，不钳则 `cap_data - s_log_blk` **下溢**、写飞出卡外。

## 4. 四个真 bug（**都是同族的，看一般化那一列**）

| # | 症状 | 根因 | 一般化 |
|---|---|---|---|
| 1 | 整条 SD 路崩（`blk_this_boot=0, batch_err=3099`） | 我按 HAL 骨架重写 `sd_read_block` ⇒ **它返回的数据是错的** ⇒ 日志头读不对 ⇒ 当新卡重建 | **"半个对齐"比不对齐更坏**：只抄 while 骨架、换掉其下的数据搬运机制（IDMA→手工排 FIFO）= 没对齐前提 |
| 2 | `PROG_RC_WRITE` 写超时 | 缓冲在 **DTCM**，而 SDMMC 的 **IDMA 读不到 TCM 端口** | 外设 DMA 能到哪块内存**按外设成立**，不能按"上次那个能"类推 |
| 3 | 读回载荷头 = `"DLBK"`（`BBLOG_REC_MAGIC`） | 缓冲撞进黑匣子环（960 槽 × 256 B = 240 KB） | **"当前完全空闲"这类注释活不过两周** |
| 4 | 正常批写被判超时 | `SD_TMOUT_DATA` 被我挤到 200 万（≈250 ms） | **超时给够 + 调用方声明阻塞窗口**；挤超时是用判据掩盖慢 |

### 4.1 ★★ 两条**方法学**教训（比 bug 更值钱）
1. **`pyocd halt` 会把核留在停住状态** —— 我据此得到过一整串假结论（"`g_tick_count` 冻结 / ISR 死了 / 板子不复位"）。
   干净 `pyocd reset` 后不发 halt，串口立刻全好。
   **而 `0x48` 的应答本身就带 `txn_*` 计数 ⇒ 根本不需要 SWD。** ⇒ 违反了自己写的第 1 条纪律（观测先走协议内通道）。
2. **构建闸门不要用管道把门**：`build.sh | grep … && flash` —— `grep` 的退出码掩盖构建失败 ⇒ **烧了旧镜像**并据此误判一轮。
