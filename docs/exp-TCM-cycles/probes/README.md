# 一次性判别探针（§A3.8 那张"六假设排除表"的**证据**）

> **为什么放在版本控制里**：这五个脚本原先只住在 `.tmpctl/`（**被 gitignore**）。
> 而 §A3.8 的排除表每一条都靠它们产出 —— 脚本一旦不在仓里，**那张表就变成不可复跑的**。
> 这正是本项目早些时候在 `docs/exp-2026-09-18-overload/README.md` §1 记过的同一个缺口
> （"文档引用了一个下一位拿不到的脚本"）。⇒ 迁进来，**信息不丢，只换住处**。
>
> 它们是**一次性探针**（硬编码了当时的偏移与假设），**不是通用工具** —— 
> 通用工具是 `tools/h723_tick_ring.py`。留在这里的是**证据**，不是产品。

## 每个脚本排除了什么

| 脚本 | 做法 | 排除了哪个假设 | 关键读数 |
|---|---|---|---|
| `probe_ring2.py` | 只读 2 个字 + `0x38`，不做大读 | 提供**健康基线** | 环写/samples = **1.004 / 0.999 / 0.999** |
| `probe_ring3.py` | 读头 → 256 字大读 → 再读头 | **② 大读打扰环** | 大读前后 Δ 正常；环写 +2097/0.2 s ≈ **10.5 kHz** |
| `probe_ring4.py` | STOP/START 后静默 0.05 / 1.5 / 1.5 s | **③ 静默 1.5 s 触发** | 静默 1.5 s 后环写 = **15104** ✓ |
| `probe_ring5.py` | 同进程：只发 0x22 → 插一次 0x38 → 再只发 0x22 | **④ `0x38` 触发**；并给出**最小可用序列** | 插 `0x38` 前后 Δ环写 = Δtick 完全同步；阶段 3 静默后环写 = **15037** ✓ |
| `probe_close.py` | 同进程 open→读→close 三轮 | **⑥ 关串口把板子按进复位**（§10.4 那条陷阱）| `tick` 单调 **6.28M → 6.31M → 6.33M**；三轮 **环写 == samples − 100** |

★ `probe_ring5.py` 的**阶段 3** 就是"最小可用序列"：
`STOP → START → deploy → STOP → START → 静默 1.5 s → 读` ⇒ 环写 = 15037（预期 ~15000）。

## 用法与前提

```bash
export PATH="/usr/bin:/bin:/mingw64/bin:/c/Windows/System32:$PATH"
export DCL_PORT=COM22
python docs/exp-TCM-cycles/probes/probe_ring5.py     # 建议先跑这个（含最小序列）
```

★ 前提：板上必须是**带环形缓冲的实验档**（`OFF_EXEC_RING` 在 `engine.h`）。
交付档没有这个域，读数会是垃圾。查询/恢复见 `tools/h723_restore_delivery.sh`。

## ★ 当前未决（2026-09-18 收尾时的状态）

**同样的最小序列，探针脚本健康（`tick` 百万级），而 `tools/h723_tick_ring.py` 每次运行都读到 `tick≈70`
—— 连 `pyocd reset` + 等 12 s 之后也一样。**

⇒ 元凶在**两个脚本开头的差异**里。目前唯一可见的差别是收发顺序：
- 探针：`Dcl(...)` → `sleep(0.4)` → **先 `0x22`** → 再 `0x38`
- 工具：`Dcl(...)` → `sleep(1.0)` → **先 `0x38`** → …

**下一步（一行假设，先验这个）**：把工具开头改成先发一次 `0x22`，看 `tick` 是否还是 70。
