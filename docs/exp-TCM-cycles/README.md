# TCM 周期确定性实验设计（`exp-TCM-cycles`）

> **这份设计在回答一个问题**：DCL 能不能把"每拍耗时"从**实测标定**升级为**精确可算**，
> 从而把周期从"硬件划分的调度器"降级为"纯采样契约"，让调度决策在运行期**可证地**做？
>
> **一句话判据（整个计划的总判据）**：
> **逐拍预测 = 逐拍实测（在事先声明的界内），且这个界不随构建漂移。**
>
> 状态：**设计完成，未执行**。执行前不要引用本文任何数字。
> 相关：`docs/ARCH-GUARANTEE-MAP.md`（R1 零等待 TCM）· `docs/exp-2026-09-18-overload/`（成本表与门）

## 0. 为什么必须先做地基：把"TCM 固定访问"拆成三条断言

"TCM 的访问时间真的固定吗"其实是三个强度完全不同的断言，混在一起谈会得出错误结论：

| # | 断言 | 强度 | 现状 |
|---|---|---|---|
| ① | **无 cache ⇒ 访问代价与"之前访问过什么"无关** | 最强 | 架构保证（TCM = SRAM + 固定映射，无 tag/替换） |
| ② | **零等待 ⇒ 存储器时延固定** | 中 | 架构保证（TCM 与 CPU 同频；ITCM/DTCM 是分开的 64 位接口） |
| ③ | **每次访问 = 固定 N 个 CPU 周期，且不受他人影响** | 最弱 | ⚠️ **不保证**，有三个漏洞面（见 §3） |

★ **① 才是最值钱的一条**，而且它是真的。注意一个反直觉的点：
**即使 TCM 是"固定 3 个周期"而不是 1 个，只要它固定且与历史无关，可加性与可枚举性就都成立。**
⇒ **"固定"比"快"重要。** 本项目需要的是前者。

★ 而真正的不确定性在隔壁：**TCM 归零的是「存储器」的不确定性，不是「执行」的不确定性。**
流水线（双发射 / load-use 冒险 / FPU 转发 / 动态分支预测 / `VDIV` 变时延）不受 TCM 影响。

## 1. 实验台的前置条件（不做这四条，后面全部无效）

| # | 前置 | 为什么 |
|---|---|---|
| P1 | ★ **必须用一个"剥离控制应用"的独立构建**（腾出 ITCM 放微基准） | ITCM 已被实测占满（见 `src/i2c_sm.h` 里的实测记录），塞不进微基准。★ 而且**时钟/电源配置必须逐字复用交付档**，否则测的不是这颗芯片的真实配置 |

★ **P1 的那个构建开关目前尚不存在，需要新加**（本设计暂称它为 BENCH 构建；这只是命名建议，
不是既有设施）。本仓库的 `ref_claims_check` 闸门会核"文档里引用的 `文件:行` 处是否真有那个符号"，
所以本文**只对确实存在的设施写 `文件:行`** —— 这条纪律本身是被闸门逼出来的（见 §10 末尾）。
| P2 | ★ **程序自持时基**：固件在 boot 时自己开 `DEMCR.TRCENA` 并用 `DWT_CYCCNT` | `pyocd` 断开时会写 `TRCENA=0` ⇒ DWT 静默死（本项目已实测）。**烧录后让板子自己重启，全程只走协议读数**（协议能读的一律用协议） |
| P3 | ★ **布局冻结 + 布局稳定性自检** | 本项目刚发现：同一个 `--stat min` 口径在两个构建上给 PID **363 / 401 cyc**（差 10%），原因未隔离。⇒ 基准内核的**反汇编必须人核一遍**（确认"写的是这个序列"），并且**用两个只差一个无关常量的构建各跑一次**，若结果漂移则先解决布局敏感性 |
| P4 | ★ **测量台自检（已知答案的正对照）** | `src/clock.h:84` 已记载 **AXI SRAM 每个总线周期要 2 个 CPU 周期**。⇒ 用同一套台子量 AXI SRAM，**必须**量出 ≈2×。★ 量不出 ⇒ 台子坏了，后面所有数字作废 |

**操作纪律（铁律 0：观测不得改变被测对象）**：
- 基准内核运行期间**屏蔽中断**（否则"变慢"可能只是被抢了）
- 内核体内**必须用 `volatile` 或内联汇编**，否则编译器会把重复访问 CSE 掉，测到的是一个空循环
- 两次时基读之间加 `__DSB()`，防止读被重排
- `DWT_CYCCNT` 是 32 位，400 MHz 下 **10.7 s 回绕** ⇒ 用模减
- 同一配置**不要跨 pyocd 会话**比较（每次连接都会复位）

**方法学（复用本项目已建立、且已被信任的那套）**：
- **两点法消常数项**：同一内核用 `REP=256` 与 `REP=128` 各跑一次，
  斜率 = `(T256 − T128)/128` ⇒ 精确消掉函数序言/时基读取的固定开销
- **宏展开消循环开销**：`#define R4(X) X X X X` / `R256(X) = R4⁴(X)` ⇒ 体内无循环，
  循环开销不是"被抵消"而是**根本不存在**
- ★ 两个手段都要用：宏展开消掉循环，两点法消掉序言

## 2. E1 —— TCM 访问固定性（地基一）

**目的**：直接回答③。**这是最坏结果必须先排除的那个实验。**

### 方法
ITCM 内一段宏展开的重复访问；前后读 `DWT_CYCCNT`；`K` 次重复，记录**每次**的 per-access 周期。

### 变体矩阵

| 变体 | 取值 | 为什么要它 |
|---|---|---|
| 宽度 | 8 / 16 / **32** / **64** 位 | 64 位在 M7 上**可能是 2 拍** |
| 对齐 | 对齐 / 非对齐 | 非对齐的代价与是否固定 |
| 指令 | `LDR` / `LDM` / `STM` / `PUSH` | ★ 见 §3 漏洞 2 |
| 数据落点 | **DTCM** / ITCM 字面量池 / **AXI SRAM**（对照） | 两条 TCM 接口是否真并行；AXI 是 P4 的已知答案 |
| 干扰 | **MDMA 空转 / MDMA 满载** | ★ 见 §3 漏洞 1 |

### 判据（每条都能失败）
| # | 判据 | 失败意味着 |
|---|---|---|
| **C1.1** | 每个变体在 K 次重复中 `max − min == **0**`（恰好 0，不是"很小"） | 访问本身不固定 ⇒ **R1 柱子需重估** |
| **C1.2** | 对齐 32 位 `LDR` from DTCM 的 per-access 周期 **= 事先写下的预测值**（预测先写、再测） | 预测错了 ⇒ 我们对 M7 的理解有洞 |
| **C1.3** | ★ **正对照**：MDMA 满载时若极差仍为 0 ⇒ 该干扰通道**到不了我们** | 极差 > 0 ⇒ 已**定位到干扰通道**（同样是好结果，见 §3 漏洞 1） |
| **C1.4** | ★ **反向判据**：数据放 AXI SRAM 必须显著慢（≈2×，见 P4） | 量不出差异 ⇒ 台子无效，本实验**判无效而非通过** |

★ C1.3 的两种结果**都是可交付的**——依据 AMC 20-193 §5.3 note b：
"能证明到不了你的干扰通道不必缓解"。⇒ 极差 0 = 写一条证据收工；极差 > 0 = 通道已枚举，接下来才谈分区。

### 产出
一张 `(宽度 × 对齐 × 指令 × 落点)` 的 **per-access 周期表 + 极差列**。
**极差列全是 0 ⇒ 断言③在你们的系统上成立。**

## 3. E3 与 E1 并行 —— 干扰通道枚举（三个漏洞面）

### 漏洞 1：TCM 不是 CPU 独占的（最现实）
H7 的 TCM 挂在 AHB 总线矩阵上（AHBS 从口），DMA/MDMA 可访问。
**而本项目已经有这条通道在跑**：`src/blackbox.h:26` ——
"MDMA ch1 软触发（**拍尾**，数据就绪后），源=SHM 紧凑区（**DTCM，经 SBUS**）"。

⇒ **只要 MDMA 在扫描窗内访问 DTCM，CPU 的 DTCM 访问就可能被插入等待。**
这不是架构能排除的，只能靠实测或分区。**E1 的 MDMA 变体就是在测它。**

### 漏洞 2：多寄存器访问 TCM 本来就不是"一拍"
Cortex-M7 系列的 errata 里有一类条目，触发条件是
`STRD / STM / PUSH / VPUSH / VSTR.64 / VSTM` **访问 TCM** 时
（见 Infineon CYTVII-B-E（Cortex-M7 核）errata）。⇒ 64 位/多寄存器访问是**被拆成多周期**的。

★ **对 DCL 的直接影响**：**热重载那次 `memcpy` 路由表（128×16B）走的正是这条路**，
而 F5 量到的"重载上界 188 tick"依赖这条路径的稳定性 ⇒ **值得单独测一次**。

### 漏洞 3：流水线（真正的残余不确定性）
"TCM 零等待"不保证：双发射能否真发 2 条 · load-use 冒险 · FPU 阻塞/转发 · 动态分支预测。
**而 `src/primitives.h` 里几乎全是数据相关分支**（`prim_lpf:85` 三路、`prim_pid:101` anti-windup、
`prim_deadband:124`、`prim_edge`、`prim_hyst`）。⇒ 这部分由 **E2** 覆盖。

### E3 的其余通道（判"到得了/到不了"，两种都要证据）
| 通道 | 怎么验 | 已知/预期 |
|---|---|---|
| SDMMC IDMA → AXI | 扫描期间开 SD 写 | 未知 |
| 通信 DMA（UART） | 扫描期间跑满通信 | 未知 |
| 其他 IRQ 抢占 | 一个高优先级 IRQ 按已知频率翻转 | 未知（需查 NVIC 优先级） |
| ★ **ISR 可达的 flash `.rodata` stall** | **`-DDCL_ITCM_ENABLE=0` 对照构建** | **已知到得了** ⇒ 用作 E3 的**正对照** |
| CPU 自身 AXI 访问 | 表放 AXI 而非 DTCM | 已知 2 周期（`clock.h:84`） |

★ 用 `DCL_ITCM_ENABLE=0`（`src/itcm.h:35-37` 就是"故意把热函数留在 flash 用来复现缺陷"的对照构建）
做 E3 的正对照 —— **这是本项目现成的资产，成本几乎为零。**

## 4. E2 —— 可加性（地基二）

**目的**：决定"逐条求和"这个模型能不能用。**这是"精确计算"与"理论作品"的分界线。**

### 方法（三点设计）
| 程序 | 内容 | 实测 |
|---|---|---|
| A | N 条全 op X | `T_A` |
| B | N 条全 op Y | `T_B` |
| C | N/2 X + N/2 Y | `T_C` |

预测 `T_C ≈ (T_A + T_B)/2`；**偏差 = 可加性误差**。

### 变体
- `(X,Y)` 组合：**DIRECT+PID**（最便宜+最贵）· PID+LPF（两个都用 FPU）· DIRECT+ARITH（整/浮混合）· 两个都用乘法
- **排列**：`X…X Y…Y`（块状） vs 交错 ⇒ 若两者不同，说明**存在流水线状态效应**
- **规模**：N = 32 / 64 / 128 ⇒ 看偏差是否随 N 变（常数项 vs 线性项）

### 判据
| # | 判据 | 失败意味着 |
|---|---|---|
| **C2.1** | `\|T_C − (T_A+T_B)/2\| ≤ ε`，ε **事先声明**（建议先按 2% 或 8 cyc 试） | 求和模型不成立 |
| **C2.2** | ★ **主动搜索时序异常**：在 K 组配置里报出**最大偏差**（不是"没找到就宣布没有"） | 偏差大 ⇒ 必须做"邻域建模"，成本上一个量级 |
| **C2.3** | 块状 vs 交错：若差异 > ε ⇒ **顺序敏感**，则"求和"连形式都不对 | 同上 |
| **C2.4** | 偏差随 N 的**缩放行为**要能解释（常数项 or 线性项） | 解释不了 ⇒ 有未建模的机制 |

★ C2.2 的写法很关键：**"我们试了 K 组，最大偏差 X%"是一个可证伪的陈述**；
而"求和成立"不是。**这是本项目一贯的判据形态。**

## 5. E4 —— 端到端逐拍对齐（把 E1~E3 合起来）

**目的**：产出整个计划的总判据，也是"确定性可审计"的**唯一形态**。

### 方法
1. 固件把**每一拍**的 `di`（ISR 时长）写进环（黑匣子已有，`g_eng_cyc_*` 也有）
2. 离线用**路由表 + 成本表 + 相位**算出**逐拍预测值**
3. 逐拍比对

### 判据
| # | 判据 | 失败意味着 |
|---|---|---|
| **C4.1** | **每一拍**（不是最值）`\|实测 − 预测\| ≤ 界`，界事先声明 | 模型不到位 |
| **C4.2** | **最坏拍在测之前就被指名**，且实测的最坏拍就是它 | 说明我们不知道最坏拍在哪（★ 今天的模型正是如此：它算**平均**不算最坏拍） |
| **C4.3** | ★ **反例必须红**：在扫描窗内注入已知扰动（如强制 MDMA 突发）⇒ C4.1 必须失败 | 注入后仍通过 ⇒ 判据测不出干扰，**判无效** |
| **C4.4** | 同一条判据在**两个只差无关常量的构建**上给出同一个界 | 界随构建漂移 ⇒ 不可审计（★ 这正是今天发现的 10% 漂移） |

★ C4.2 特别值得注意：**今天门的口径是"平均每拍上界"**，而真实最坏拍是
`C_div0 + max over t∈[0,lcm(10,64)=320) (D1[t%10] + D2[t%64])`。
而这个精确值**今天就能算、几乎免费**（320 个候选），**根本不需要等 E1~E4**。
⇒ 建议把它从本计划里**拆出来单独先做**（见 §7）。

## 9. 这个计划本身失败的方式（诚实登记）

1. **布局敏感性未解决**（今天发现 10% 漂移）⇒ 若 E1 的极差不是 0 而是"随构建变的 10%"，**分不清是 TCM 不固定还是布局在漂**。⇒ **P3 必须先做完**，否则 E1 的结果不可解释。
2. **ITCM 满** ⇒ bench 构建必须剥离应用；剥离后时钟/电源路径若被顺带改动，测的就不是交付配置。
3. **DWT 本身的不确定性**：读 `DWT_CYCCNT` 要几个周期，且 DWT 可能受调试单元影响。两点法能消掉常数项，但**消不掉"读数本身抖动"** ⇒ P4 的已知答案是唯一的校准手段。
4. **`DCL_BENCH` 构建本身是新代码** ⇒ 它自己可能引入不确定性。"测量工具必须先被测量"（本项目的 P4 就是这个意思）。

# 附：序 0 执行结果（精确最坏拍聚合，2026-09-18）

**工具**：`tools/h723_worst_tick.py`（新增）

## A0.1 方法

不再"假设"分档行为，而是**从板上读回真实状态**再算：

- 读**正在跑的桶表**（`shm + 0x4480`，220×u16）与**路由表**（`shm + 0x0840`，128×16B），
  经 `0x22 READ_BURST` 读（**不是** pyocd）
- ISR 的每拍成本（`engine.c:586-597`，已核实）：
  `cost(t) = C_div0 + D1[t%10] + D2[t%100]`，周期 = lcm(10,100) = **100**
- 精确最坏拍 = `C0 + max over t∈[0,100) (D1[t%10] + D2[t%100])`

判据分三类，**不许混谈**：A 类＝我的读数可信吗；B 类＝固件的既有不变量成立吗；C 类＝门是不是安全上界。

## A0.2 ★ 先被推翻的两个自己的推论

| 我原先的说法 | 实测 | 结论 |
|---|---|---|
| "`dclc` 从不设相位位 ⇒ 所有慢档路由挤在 phase 0 ⇒ 模型低估最多 10/64 倍" | 读回相位集合 = **0..9 均匀** | ❌ **错**。已核实 `engine.c:983-992`：**deploy 建表时忽略载荷的相位字段，按轮转法分配**（`ph = q1++ % 10` / `q2++ % 100`）⇒ **摊薄假设是被固件强制执行的**，不是"没人管的假设" |
| "div2 的桶号是 `tick % 64`" | 代码是 `tick % BUCKET_DIV2_PHASES`，而 `BUCKET_DIV2_PHASES = 100` | ❌ 我照了 `engine.h:167` 的**旧注释**。代码对（10 ms），注释错 ⇒ **一处"同一语义两处存放"** |

## A0.3 三个数（交付档 ITCM，最贵原语 PID = 145 cyc）

| 程序 | 模型（门用的摊薄上界） | `worst_isr`（正在跑） | `worst_reboot`（重启后） | 模型/最坏 |
|---|---|---|---|---|
| 128 × PID **div1** | 1920 (4.80% 拍) | **1885** (4.71%) | 1885 | 0.98× ✅ 紧 |
| 128 × PID **div2** | 384 (0.96% 拍) | **290** (0.72%) | **435** (1.09%) | 见下 |

**div1 结论：摊薄模型是紧的安全上界**（1920 ≥ 1885，仅差 ceiling 余量），且最坏桶 13 条 == 均匀值 13 条。
⇒ **"门算平均不算最坏拍"这个担忧，在有轮转相位分配的前提下不成立。**

## A0.4 ★★ 但 div2 撞到一个真缺陷（已在案，本次首次给出触发用例 + 量化）

`docs/audit/REVIEW-MIGRATION-FIDELITY.md` **#4**（标"迁移引入"）早已记录：
**两条建桶路径语义不同**，且当时就写明"**现有没有用例覆盖（T17 只有 1 条 div2 ⇒ phase=0 不触发）**"。

本次用 **128 条 div2** 触发，判据 B1/B2/C3 全红，影响首次被量化：

| 判据 | 结果 |
|---|---|
| A1 桶区间恰好铺满 `[0,128)` | ✅ 读数可信 |
| A2 桶表计数总和 == n_routes | ✅ |
| C1 工具模型 == 固件自报 budget | ✅ 384 == 384 |
| **C2 `worst_isr` ≤ 模型** | ✅ 290 ≤ 384 ⇒ 门覆盖**正在跑**的布局 |
| **C3 `worst_reboot` ≤ 模型** | ❌ **435 > 384** ⇒ 门**不覆盖重启后**的布局 |
| **B1 死槽不变量 `cnt2[64..99]==0`** | ❌ 桶 64..99 里有 **36 条**路由（`engine.h:183` 宣称它被断言恒 0） |
| **B2 `period` 相位 == 桶归属** | ❌ **36 条不符** ⇒ period 里的相位是垃圾 |

**根因**（`engine.c:987-992` vs `:354-357`）：

| 路径 | 触发 | 定槽依据 | 可达桶 |
|---|---|---|---|
| `engine_stage_program`（**deploy**） | `0x10` | **未截断**的 `ph = q2++ % 100` | 0..99 |
| `engine_build_buckets`（**开机装载**） | `persist.c:220` | `period` 里**被截断**的相位 | 0..63 |

`period` 是 u8：`dv | (uint8_t)(ph << 2)` ⇒ `ph ≥ 64` 时 `ph<<2` 溢出被截断（`64<<2 = 0x100 → 0`）。

**影响（量化）**：同一份程序 deploy 后最坏拍 **290**，重启后 **435**（**1.50×**），
而门算 **384** —— **夹在两者之间** ⇒ 对正在跑的布局是安全上界，**对重启后的布局不是**。

**为什么现在还不算"超载风险"**：`MAX_ROUTES=128` 封顶 ⇒ 混叠最坏桶 ≤ 3 条 ⇒
最坏拍 ≤ 3×145 = 435 cyc = 拍的 **1.1%**（FLASH 档 3×432 = 1296 = 3.2%）。
⇒ **量级上无害，但它是一条"宣称≠实现"的实例，且让所有按 `period` 反推桶的独立校验失真（假红/假绿）。**

## A0.5 ★ 这个缺陷对"精确量化"的意义（比它的量级重要得多）

> **同一份程序，两条装载路径 ⇒ 两套桶分布 ⇒ 两个不同的最坏拍。**

而"精确量化程序执行周期"的前提是 **表的语义与装载路径无关**。
⇒ **这是第一个实验就撞到的 blocker，而且它不在 TCM、不在流水线、不在除法** ——
它在**建表器的一致性**上。这一类问题的修法（把"周期数"与"相位模"分成两个常量、
相位分配用 6 位域上限、或把 phase 挪到 `RouteEntry_t` 的空闲字节）都不需要新硬件。

## A0.6 顺带确认的两件事

1. **`g_reload_cyc` 协议读不到**：`0x22` 有地址范围闸门 `eng_valid_rrange`
   （`main.c:3325` / `engine.c:1132`），只放行 SHM 区 + 少量诊断窗；
   `g_reload_cyc` 在 `0x200002B8`（DTCM 普通全局）**不在范围内** ⇒ NAK `bad range`。
   ⇒ "精确归因热重载拍"（登记已久的后续项）的**具体做法 = 在 SHM 观测区镜像一个槽**。
   ★ 但见 §A1.1 —— **不需要它也能精确测出重载拍**。
2. **实测锯齿确认存在**：128×div1 ⇒ `emin=512` / `emax=3666` TB tick（1024 / 7332 cyc）。
   ★ 后续（§A1）查明：`emin` 是**空引擎窗口**、`emax` 是**部署那一拍**，两者都不反映稳态。

# 附三：E4 第一步 —— 逐拍 `di` 环形缓冲（**已就位，但取数窗口有未解释的异常**）

## A3.1 已建成的设施（可用）

`engine.h` 新增（同一个 DSL 保留洞尾部，`0x3C90 < 0x4000`）：

| 域 | 内容 |
|---|---|
| `OFF_EXEC_RING_HDR` (0x3880) | u32[4]: `[0]`=写计数（单调）`[1]`=最后一拍的 tick |
| `OFF_EXEC_RING` (0x3890) | u32[256]: 逐拍 `di`（TB tick），槽 = 写计数 & 255 |

- 由 **ISR 直接写 SHM**（不经主循环镜像 ⇒ 无滞后），成本 3 次 DTCM 写 + 1 次加
- 上位机读法：**先读环、再读头**，只采信头里写计数之前的条目 ⇒ 无需加锁
- `stats_reset()`（STOP/START）同时把写计数清零 ⇒ 与统计同窗口
- ✅ **已实测证明它在动**：探针（不做 STOP/START）读出 1 秒内 **写计数 +10082、tick +10082**、
  `0x38.samples` +10297 ⇒ **环确实每拍写一次**，与 RUN 拍速率一致

## A3.2 ★ 未解释的异常（**因此下面的直方图不可用**）

`tools/h723_tick_ring.py` 的判据设计是**纯结构性的**（不依赖成本模型）：
由桶表算 `nrun(t) = n_div0 + cnt1[t%10] + cnt2[t%100]`，则实测 `di` 的**不同取值个数**
应等于 `nrun` 的取值个数，且**各取值的频次**应等于该 `nrun` 在 `t∈[0,100)` 里的出现次数。

实测（128×PID **div1**，两次独立运行结果一致）：

```
结构预测: nrun = 12 (占 20/100 拍) 与 13 (占 80/100 拍)   ← 只有两个取值
实测:     13 个不同取值, 频次 8/2/1/1/2/3/33/3/1/3/8/2/1  ← 合计仅 68 拍
```

**两个问题，都还没解释清楚**：

1. ★ **窗口只有 ~68 拍**，而 `time.sleep(1.5)` 在 10 kHz 下应是 ~15000 拍。
   且两次运行**都是 ~68**、取值簇**一模一样** ⇒ **不是随机复位，是可复现的**。
   - 已知：不做 STOP/START 时，环绕 10082/s 正常推进
   - 已知：`stats_reset()` 会把写计数清零
   - ⇒ **矛盾锁定在「STOP/START 之后」这一段**。候选：① 板子在该窗口内自愈复位
     （交付档 `DCL_LOOP_RESET=1`，主循环停滞 ≥1.2 s 会复位）；② 环写只在某条件下发生；
     ③ 读数的时序有问题（先读环再读头，跨了窗口）
   - **下一步（最省事的判别法）**：START 之后**立刻**读一次环头，隔 0.5 s 再读一次。
     `w` 从 5→68 说明它中途停了；`w` 从 5→5000 说明是读数/窗口的问题。
2. ★ **`di` 的取值散得比预期宽**：本应只有"跑 12 条"和"跑 13 条"两个取值，
   实测却跨 1318~1482（**164 TB = 328 cyc**）。这与"典型拍均值跨窗口极差 0.06 cyc"
   （§A1.5）**不矛盾**（均值稳 ≠ 逐拍稳），但它说明
   **逐拍成本不是"本拍跑多少条"的函数** —— 这正是 E4 要回答的问题。

⇒ **结论：设施建成且已验证在动；但"逐拍对齐"这一步的取数必须先修好，
在那之前不发布任何逐拍结论。** 这是本项目"SKIP ≠ PASS"的同一条纪律：
**数据不可用就判不可用，不许拿一张解释不了的直方图去凑结论。**

# 附二：E1 的系统级形态 —— 拍级可重复性与干扰通道（2026-09-18）

## A1.0 ★★ 第一个成果是**仪器**，不是结论

第一版工具被两个污染源搞坏了，而**两个污染源都不是被测对象**：

```c
uint8_t was_run = SHM_U8(g_shm, OFF_CTRL_ENGINE_RUN);
if (!was_run) { stats_reset(); }        /* STOP→START 转变时清统计 */
```

（R 个独立稳态窗口，成本极低）。

## A1.1 ★★★ F5 的"重载上界"是错的（差 4.6 倍）

**每条原语的成本依赖程序的数据/参数** —— 这正是 `src/primitives.h` 里那些数据相关分支
（`prim_lpid:101` anti-windup、`prim_lpf:85` 三路、`prim_deadband:124`）的后果，

"**也跟着程序的数据/参数走**"。

## A1.3 ★ `EXEC_MAX` 不是"稳态最坏拍"—— 它被一个已知的周期事件主导

`src/blackbox.c:310`：

```c
samp = (s_bb_kicks <= 3u) || ((s_bb_kicks & 0x3FFu) == 0u);   /* 每 1024 拍一次重活 */
```

⇒ `EXEC_MAX` 量到的是**黑匣子每 1024 拍的那次重活**，不是稳态抖动的上界。

|---|---|---|---|
| bb=**on** | 8376 | 8496 | 120 TB |
| bb=**off** | 8376 | 8482 | 106 TB |
| **差** | 0 | **14 TB = 28 cyc** | ← **MDMA kick 的代价** |

## A1.4 干扰通道结论（三值判定，SKIP 不许读成 PASS）

| 判据 | 效应 | 窗口内散布 | 判定 |
|---|---|---|---|
| **R2 MDMA（黑匣子开/关）** | 14 TB = **28 cyc** | 4 TB | ★ **有影响** —— 该通道**到得了**扫描体，代价 ≈ 28 cyc/（每 1024 拍那次）|
| **R3 铁律 0（主机是否轮询）** | 0 | 4 TB | **SKIP：分辨率不足**，不许读成 PASS |

★ R2 是本项目**第一次把一条干扰通道定量到 cyc**。28 cyc 相对 40000 cyc 的拍长可忽略，
但它现在是一个**有数字的、可复跑的证据**，而不是"应该没影响"。

## A2. E2 —— 可加性：**不成立，但非可加性是「可算的项」**（★ 本轮最重要的结果）

**工具**：`tools/h723_additivity.py`

### A2.1 三点设计（基线自动抵消）

div0 程序每拍跑全部路由 ⇒ `均值 = 基线 + Σ 单价`。于是

```
mean(A)=base+N·c_X   mean(B)=base+N·c_Y   mean(C)=base+N(c_X+c_Y)/2
⇒ (mean(A)+mean(B))/2 与实测 mean(C) 应当**逐位相等**
```

而均值分辨率实测 **0.02~0.06 cyc** ⇒ 任何 > 0.1 cyc 的非可加性都跑不掉。

### A2.2 首轮：可加性**明确不成立**，而且**顺序本身就是成本**

| 组合 | 块状偏差 | **交错偏差** | 排列差 |
|---|---|---|---|
| DIRECT+PID | +40.2 | **+351.8** | 311.6 |
| LPF+PID | +32.4 | **+724.7** | 692.4 |
| CMP+SCALE | +14.2 | **+707.1** | 692.9 |
| DIRECT+LPF | +16.9 | **+325.6** | 308.7 |

窗口内散布仅 **0.02~0.58 cyc** ⇒ 全是信号。块状偏差**全部同号为正** ⇒ **系统性、有结构**。

### A2.3 块大小扫描：非可加性是一条**精确的律**

假设是"相邻 op 变化 ⇒ 分派分支预测失败一次"。扫块大小（同分子、不同排列）：

| 块大小 | 1 | 2 | 4 | 8 | 16 | 32 | 64 |
|---|---|---|---|---|---|---|---|
| 转变数 | 127 | 63 | 31 | 15 | 7 | 3 | 1 |
| **DIRECT+PID 偏差** | 351.7 | 660.2 | 340.4 | 180.1 | 100.0 | 59.9 | 40.1 |
| **LPF+PID 偏差** | 724.5 | 372.7 | 196.4 | 108.7 | 64.4 | 42.8 | 32.4 |

拟合：

| 原语对 | 斜率 k | 截距 c | 拟合质量 |
|---|---|---|---|
| DIRECT+PID | **10.0 cyc/转变** | +30 | **6/7 点精确命中**（`10t+30`）；bs=1 是离群 |
| **LPF+PID** | **5.50 cyc/转变** | +26.1 | ★ **R² = 1.0000（全部 7 点）** |

⇒ **`cost(程序) = Σ_i c(op_i) + k(相邻 op 对) × (相邻 op 变化次数) + c₀`**

**这条律是"精确量化"能否成立的答案：能，只需在模型里加一项「相邻 op 转变计数」
——而那个量在 deploy 时从路由表直接数出来，零成本。**

★ 两个副产品：
1. **k 随原语对而变**（10.0 vs 5.5）⇒ 它是一张可按 `(op_i, op_{i+1})` 枚举的表
   （至多 19×19），不是一个通用常数。
2. **`h723_op_sweep.py` 的单价为什么偏高**（实测部署程序 PID 122 cyc/条 vs 表 145）：
   那张表是**全表同一原语**测的 ⇒ **转变数 = 0**，只反映"无转变"的那一半。
   ⇒ "成本表跟着代码走"这条规矩要加两句：**也跟着程序的数据/参数走**、
   **还跟着路由表的 op 排列走**。

### A2.5 ★★ 残差检验：模型能**预测**，不只是能**拟合**

判据 B4：用拟合出的 `(k, c)` 去**预测**每个点的均值，残差必须 ≤ 1 cyc。

| 块大小 | 转变数 | 实测偏差 | 预测偏差 | 残差 |
|---|---|---|---|---|
| 1 | 127 | 724.57 | 724.57 | **0.00** |
| 2 | 63 | 372.50 | 372.55 | **+0.05** |
| 4 | 31 | 196.66 | 196.53 | **−0.12** |
| 8 | 15 | 108.48 | 108.53 | **+0.05** |
| 16 | 7 | 64.62 | 64.52 | **−0.09** |
| 32 | 3 | 42.41 | 42.52 | **+0.11** |
| 64 | 1 | 32.61 | 31.52 | −1.09 ← 离群（已排除出拟合）|

**⇒ 拟合内各点 |残差| 最大 = 0.12 cyc，而转变数跨度是 3 → 127（42 倍）。**

★★ **这是"精确量化"从"也许可能"变成"已经可以"的那一刻**：
模型不再是"事后编出来的解释"，它**在没参与拟合的点上给出 0.12 cyc 精度的预测**。
（判据 B4 能失败：残差 > 1 cyc 就红。DIRECT+PID 那一组就不满足，已如实登记。）

★ 诚实边界：
1. `k` 只测了 **2 个原语对**（DIRECT+PID 10.0 / LPF+PID 5.50）⇒ 通用化需要一张
   `(op_i, op_{i+1})` 表（至多 19×19）。**在那之前，"精确量化"只在这两个对上被证明。**
2. 残差 0.12 cyc 是**均值**的对齐精度；逐拍最坏拍的预测尚未验证（那是 E4）。
3. `c₀ ≈ 26~30 cyc` 的**来源未隔离**（候选：每次扫描调用的分派入口、桶边界）。
   它在"同一程序内"是常数，所以不影响 A/B 对比；但跨程序形状时是否恒定**没验过**。

### A2.6 两个方法论教训（都是本轮踩出来的）

1. ★★ **拟合必须对离群点稳健，而且离群点必须被点名**。DIRECT+PID 的全点 R² 只有 **0.42**
   —— 单看这个数会**丢掉整条律**。真相是 6/7 点精确命中 `10t+30`，唯一的离群是
   **bs=1（严格交替）**：那是分支预测器能完美学习的周期模式，所以它反而便宜。
   ⇒ 已把"剔除离群后重拟合 + **点名离群点**"做进工具的判据（若剔完仍低 ⇒ 真的不是这条律）。
2. ★★ **混淆项必须先消掉再解释现象**。第一版 `mk()` 让**所有路由共用 `state_offset`**
   ⇒ 多条 PID/LPF 串成一条串行依赖链 ⇒ 转发停顿取决于相邻同类路由的距离 ⇒
   会造出"某个块大小处偏差峰值"的假象。改成**每条路由各占一个状态槽**后重测，
   数字几乎不变（351.42 vs 351.67 / 659.96 vs 660.24）⇒ **混淆项被排除，效应是稳健的**。
   ★ 这一步不做，A2.3 的律就站不住 —— 因为无法排除「是共享状态造的假律」。

## A1.5 换仪器之后：**问题第一次被回答了**（2026-09-18 同日晚些时候）

### 换的是什么
在 SHM 的 DSL 保留洞（`[0x3840,0x4480)` 内**明确未分配**的那段，`engine.h` 有名字也有尺寸断言）
新增三个只读观测域：`OFF_TIMING_EXEC_SUM_LO/HI`（`g_isr_cyc_sum` 是 u64）与
`OFF_TIMING_EXEC_SUM_N`（**与 sum 同口径的拍数**）。全部只在**主循环**镜像，**ISR 只多一条自增**。

★★ **必须同时加 `SUM_N`，否则算出来的不是均值**：
`g_isr_cyc_sum` 在每个 `di≠0` 的拍累加，而既有的 `g_isr_n` **只在 RUN 拍**自增
（`main.c:1459`）⇒ `sum/g_isr_n` 分子分母**不同口径**。症状一眼可见：
算出的"均值" **8550.76 > 同窗口的 `EXEC_MAX` 8504** —— 均值不可能超过极大值。
（同族：§5.23「差分量的分子与分母必须同口径」；§A1.0 的读偏斜也是同一个坑的第二形态。）
★ 而且 sum 与 SUM_N 必须在**同一次 `0x22` 突发**里读，否则两次读之间窗口前进几十拍，
均值被系统性抬高。

### 结果（128×PID div0 稳态，每组 5~6 个独立窗口，每窗口 ≈13,500 拍）

| 量 | 值 | 跨窗口极差 |
|---|---|---|
| `EXEC_MIN` | 8386 TB tick | **1 种**（完全稳定）|
| **均值（典型拍）** | **8405.7 ~ 8405.9 TB** | **0.01 ~ 0.03 TB = 0.02 ~ 0.06 cyc** |
| `EXEC_MAX` | 8502 ~ 8504 TB | 2 ~ 4 TB |

分布形状：**均值只比最小值高 19.8 TB（39.6 cyc），而最大值比均值高 98.2 TB（196 cyc）**
⇒ 绝大多数拍贴着最小值，少数拍显著更高（黑匣子每 1024 拍那次重活）。

### 结论（第一次有数字）

1. ★★ **典型拍在 0.02 ~ 0.06 cyc 的精度上完全可复现** —— 独立窗口、各 ~13,500 拍，
   均值逐位相同。**"TCM 访问时间不固定"这个担忧，在典型拍上没有证据。**
2. ★ **存在的偏差是"结构性的、周期性的"，不是"随机的"**：偏离集中在少数已知的
   周期重活上（可枚举、可建模），而不是弥散在每一拍上。
   ⇒ 这对"精确量化"是**好消息**：可枚举的偏差能算进去，随机的不能。
3. ★ **MDMA 干涉通道判定为「有影响」**：典型拍代价 **0.132 TB = 0.26 cyc/拍**
   （窗口内散布 0.030 TB ⇒ 分辨率足够）⇒ 该通道**到得了**扫描体。
   量级可忽略，但它是**有数字的证据**。
4. **R3 铁律 0 判 SKIP**：轮询效应 0.022 TB (0.04 cyc) < 噪声底 0.105 TB ⇒
   **不能声称"观测不改变被测对象"**，只能说"没有证据表明有影响"。
5. `EXEC_MIN ≠ EXEC_MAX` 恒成立（div0 程序本应每拍等长）⇒ **"拍内等长"不成立**，
   但偏离**全部来自已知的周期事件**。

### 这一步的元教训（值得单独记）

**"极值"回答不了"典型值"的问题**，而本项目已经因为这件事栽过两次（§5.27 / §5.28）。
本次是第三次，而且**前两次的结论就写在 `main.c:1140-1144` 的注释里**：
"极差 ≠ 典型抖动: 62 万个样本里只要有 2~3 个偏离, 极差就成了那个数。"
⇒ **换仪器（补累积量）之后，同一个问题从"答不了"变成"0.06 cyc 精度可答"。**
成本：1 个 SHM 域 + 3 行主循环 + 1 条 ISR 自增。
