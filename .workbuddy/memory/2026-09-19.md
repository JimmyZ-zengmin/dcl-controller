## ★★★ 核心新发现：`PLAN-multi-axis-v1.md` 的 **B3「ITCM 已满」是陈旧前提**
直接从本次构建的 map 量得（不是推断、不是引用旧文档）：

| 符号 | 值 | 含义 |
|---|---|---|
| `.itcm_text` | **0x3544 = 13,636 B** | ITCM 实际代码占用 |
| `.itcm_vectors` | 0xFC00（1024 B）| 向量表钉在 ITCM 尾 |
| 余量 | **0xC6BC = 50,876 B（77.6%）** | 可再加代码的空间 |

⇒ **ITCM 占用 20.8%，不是 100%。** 而三处权威文档仍写着"64/64 KB 100% 满"：
`docs/PLAN-multi-axis-v1.md:21/29/33`（并把 B3 列为**多轴第一件必须先做的事**）·
`RULES-DETAIL.md` §5.4 · §十七。
★ 判据：`build/dcl_h723.map` 里 `.itcm_text` 的 size；或用 `arm-none-eabi-size`。
★ 影响：**多轴的三个"阻塞"里，B3 实际上不阻塞** —— 剩下两个（第二编码器撞 0x36、台架没有第二驱动器）
才是真阻塞。而按虚前提"先腾 ITCM"会花掉一整轮做**不必要**的结构手术，
且手术本身有回归风险（本项目 ITCM 是 §0.3 那场卡死的现场）。
★ 这是本项目自己的族（§5.36/§5.99 同源）：**"文档漏了同步"会让人照错前提做决策**，
而它这次伪装成了"保守"（腾余量看起来总是安全的）。**保守的错前提也是错前提。**

## 第二轮：架构优势 vs 工业控制行业（用户追问）

### 行业基准（已核，2026-09-19 检索）
- **伺服三环**：电流环 **50~100 µs（10~20 kHz）**，带宽 500 Hz~1 kHz；速度环 200~500 µs（2~5 kHz）；
  位置环 0.5~1 ms（1~2 kHz）。★ **硬规律：内环带宽 ≥ 5× 外环**（Ki 分离），违反即振荡。
- EtherCAT 同步周期 125 µs、DC 同步 <100 ns、上千从站。

### 结论：唯一可诚实宣称的不可超越点
**不是"控制性能"，是"执行成本可证 + 算法可热换"**：
- 行业三属性（高执行频率 / 用户态可重编程 / 成本事先可证）**没人同时占住**。
  驱动器占①（算法在固件、只调参数）；PLC 占②（周期 ms 级）；③ 只有航电 WCET 工具（AbsInt aiT 那类）
  能做，但全二进制 + 保守 + 昂贵 + **与现场热更新互斥**。
- 我方已有的**闭式论证**（设计层定理，非判据）：`128 路由 × 145 cyc = 18560 ≤ 部署门 26000
  ≤ 运行判据 32000 < 拍长 40000` ⇒ **合规程序在交付档不可能超载**。
  ⚠ 边界：只对**路由成本项**成立；且 FLASH 档成本更高（实测门边界 105/106 DIRECT）⇒ 门只在 FLASH 档有牙。
- **最能落地的差异**：`examples/h723_step_stall_recover.dcl` 的失步检测算法 —— 3 行 DCL、10 kHz 跑、
  可热换。**驱动器上要换固件；PLC 上要等 ms 级。** 这才是那一格。

### 不能赢的轴（如实）
电流环（差 3 个数量级，**结构性到不了**：单 CPU 全包 + 无 FPGA + 反馈走 I²C。且三环 5× 分离规律
⇒ 最内环缺席会钉死外两环天花板）· 反馈带宽（I²C ≈1 kHz vs BiSS/EnDat 10~40 kHz）· 多轴插补 ·
现场总线（只有 Modbus RTU）· 安全认证 · IEC 61131-3 工具链。
★ σ 3.6 ns 输出抖动确实赢，但要说明**它是"孤立"赢的**（环路里没有网络），与 EtherCAT 的
"<100 ns 跨上千节点同步"不同量纲，不可直接比。

### 最高杠杆的下一步（单一件事）
**反馈源从 AS5600 I²C 换成 SPI / ABZ 增量式** ⇒ 1 kHz → 10~40 kHz。
一石二鸟：① 闭环带宽上一个数量级 ② **顺带解掉多轴 B1 阻塞**（AS5600 固定 0x36 才需要 I²C mux；
SPI 有片选 / ABZ 直接进定时器）。属**②层外设能力**（版本化 + 能力位），不是新驱动、不动①层架构。

## 第三轮：architecture 上限（脱离现状）与优劣势组合

### 判定标准（用户要求"别看现状看架构"）
**改它要动 `_Static_assert` 布局 / 动 S3 逐字节兼容 / 动"无分支线性扫描"⇒ 架构性；否则实现选择。**

| 看似劣势 | 分类 | 真正限它的 |
|---|---|---|
| 反馈带宽 1 kHz | ❌ 实现选择 | SPI/ABZ ⇒ 10~50 kHz（②层） |
| 单轴 | ❌ 实现选择 | 台架 + 路由预算 |
| 拍速率 100 µs | ⚠️ 半架构 | ★ **被主循环服务需求钉住，不是被 ISR** |
| 路由数 128 | ✅ 架构性 | SHM 布局约束 + S3 兼容 |
| f32 单一数据面 | ✅ 架构性 | 引擎数据面 |
| 无分支/等代价 | ✅ 架构性 | 就是护城河本身 |
| 无 trig | ⚠️ 半 | LUT 是官方替代 |

### 架构上限（逐条算，不看现状）
1. ★★ **拍速率上限不是 ISR 钉的** —— 现 ISR 只吃 ~28% 预算（128 路由拉满）。真约束是
   "**主循环一圈 0.37 ms 必须在两拍间跑完**"⇒ 拍缩到 10 µs 主循环被饿死 37×。
   ⇒ 分母 = "主循环还要服务多少"，不是"扫描要多久"。`IO_IN_ISR` 那批搬运**是在为提速腾路**。
2. **算力上限 = 预算/最贵原语 = 40000/145 ≈ 275 条**（按 80% 判据 = **220 条**）。
   而表容量钉在 128 ⇒ ★ **真瓶颈是表容量，不是算力**。抬到 220 是纯架构代价。
3. ★★ **轴数上限是"逻辑上限"，不是"I/O 上限"** —— 脉冲由硬件定时器发，加轴不花脉冲 CPU，
   只花控制逻辑的路由。⇒ 可"多轴简单逻辑"或"少轴复杂逻辑"自由分配。
4. **资源三堵墙（本次从 map 实测）**：ITCM 13,636/65,536 = **20.8%（松）** ·
   DTCM 52,928/131,072 = **40.4%（松）** · **AXI SRAM 已满（仅剩 ≈10.5 KB）← 真瓶颈**。
5. **模式切换 tick 级不可能**（热重载走协议 = ms 级）⇒ 想 tick 级只能**预部署多套 + 状态位选**。

### 六组优劣势组合（每组的产出都是现有方案给不出的）
1. 无分支·等代价 + 成本线性可算 ⇒ **路由当预算分配**（FPGA 式资源分配思维）
2. f32 单数据面 + 全静态包络 ⇒ **完整可证资源契约（时间+内存+I/O）**——认证要的东西
3. 反馈带宽偏低 + 脉冲硬件生成 ⇒ **轴数 = 逻辑上限，非 I/O 上限**
4. 模式切换 ms 级 + 程序部署前已证 ⇒ **预部署多套 + 状态位切换 = 结构自适应且时序已证**
5. 无 trig + LUT 256 点可上传 ⇒ **查表式轨迹规划（把"算"换成"存"）**
6. 两速率比例被钉 + 分层边界明确 ⇒ **快慢分界可按需重划**（拿提速换服务）

### 三条必须承认的架构性劣势（不是缺陷，是取舍的另一面）
1. **无分支 = 无快路径** ⇒ 效率换可预测性。"只在 error 大时算 PID"做不到——CMP+SEL 比直接算还贵。
2. **单写者 / 无抢占** ⇒ 拍内没有优先级；**扫描顺序本身就是优先级顺序**（拓扑序 = 执行序，
   所以延迟也是可算的，不只成本）。
3. **f32 单一数据面** ⇒ 不能做计数/长累加类任务（多圈绝对位置会漂）。

## 第四轮：市场调研（用户指出前几轮是"自嗨"，要求面向工业现场）

### ★★ 用户的关键批评（成立，已接受）
**"保证任何合规程序都不可能超载"是自嗨 —— 别的产品也能在范围内保证。**
⇒ 我把"我们独有的性质"当成了"客户会付钱的理由"，这是**从技术倒推市场**。**入场券 ≠ 卖点。**

### 现场真金白银在为什么付钱（调研数据）
1. **开发/调试成本**（非标自动化最大痛点）：**电控逻辑调试占项目周期 40%**（机械干涉 35%）·
   图纸冻结→首件合格平均 **28 个工作日** · "**现场调试周期不可控 = 最大成本陷阱**" ·
   "经验掌握在个人手中，**人走经验断**；代码复用率低；要求全栈实时调试能力，**培养周期极长**"。
2. **停机/稼动率**：旧产线**单次故障恢复平均 47 分钟**、OEE 长期 **62%**；标杆 ≥98.6% 稼动率。
3. **失步**：开环步进根本问题（须预留 **~30% 转矩余量**防堵转）。中国闭环步进
   **28.6 亿（2023）→ 50 亿（2027）**；全球闭环步进驱动 **$4.13 亿**（占步进驱动的 55.4%）；
   增速最快下游 **实验室自动化 +11.2%**，**医疗 24.1% + 实验室 18.4%** 合计 42.5% 的价值。
4. **算法自由度/开放性**：PC-based 运动控制器中国 **8 亿元（2025，+15.8%）**，固高 **32%**。
   ★ **Klipper（11.7k star）证明大众愿为"规划在高层 + 执行在 MCU"额外买一台树莓派**，
   代价是**单点故障 + 复杂度**。行业已把"**驱控一体集成技术**"列为主要创新方向。
5. **8 轴以上高端多轴国产化率 <15%**（明确缺口；但插补需 trig/矢量，是我们的弱项）。

### 市场盘子（口径有冲突，只取结构占比）
中国运动控制器约 250 亿元（创投智库口径）：**PLC 41% / 专用控制器 31% / PC-based 28%**。
⚠ **与 MIR 睿工业不一致**（其 PC-based 卡+嵌入式仅 8 亿元）⇒ 统计范围不同，**不取绝对值**。

### 特质 → 痛点 → 会不会付钱（逐条筛，剔除自嗨）
| 特质 | 对应痛 | 付钱? |
|---|---|---|
| 每拍成本可算 | —— | ❌ **自嗨（入场券）** |
| 完整资源包络 | 认证行业 | ⚠️ 弱（得先走过认证） |
| **程序即数据 + 热换** | 开发/调试成本（占 40%） | ✅ 但**表达力不够** |
| **每拍观测 + 黑匣子 + 失步自检** | 停机/OEE（47 min·62%） | ✅ 直接 |
| **逻辑与运动同拍闭环** | 专用控制器（31%） | ✅ **最硬** |
| 单板无主机 | Klipper/PC-based 的主机代价 | ⚠️ 已被 Duet 部分占 |

### 结论：该占的是"专用控制器"那块 31%
理由：这块的本质是"**通用 PLC 做不了这个工艺**"⇒ 客户**已经在为它付钱**；但买到的是**专机**
（换工艺 = 换控制器）；而我们的特质（**可编程 + 每拍闭环**）正好解它。且这块壁垒是
**工艺 know-how**，不是品牌（PLC 那块是品牌壁垒，进不去）。
⇒ 定位一句话：**"一台能随工艺改的专用控制器"**（= 驱控一体 + 用户可编程）。

### 如实差距（不做完这些，上面全是空气；按"现场工程师会不会用"排序）
① **表达力最大缺口**：无 HMI、无 ST/梯形图、无现场总线 ⇒ 现场工程师不会写 `.dcl`；
② 反馈 I²C 1 kHz → SPI/ABZ（专用控制器场景是硬门槛）；③ 没有现场总线接不进产线
（EtherCAT 已覆盖 78% 新增出货）；④ 无例程/文档/工具链生态。

## 第五轮：专用控制器的**性能需求**与**可妥协项**（用户定调：确定性是入场券，要谈性能）

### ★ 性能必须归层（否则优化错对象）
| 量级 | 归谁 | 我们已有的硬件链 |
|---|---|---|
| **µs 级** | **硬件触发链**（CPU 到不了） | TIM3 发脉冲 + **TIM4 从模式硬件数脉冲**（"走 N 步"零中断/零 ITCM）·
DMAMUX 路由 · MDMA 影子锁存链（`DCL_DO_LATCH=1` 对照档，交付档走 CPU 直写） |
| **100 µs 级** | **拍内路由表**（唯一能放"算法"的地方） | 10 kHz 扫描 + 19 原语 |
| **ms 级** | **主循环** | 协议 / SD / 诊断 / 落盘 |

⇒ **结论①**：专用控制器级的响应靠**把事件接进硬件链**，不是缩短拍长。
⇒ **结论②**：拍内是真战场（硬件无算法、主循环太慢）。

### ★ 拍长下限的分解（最坏程序 128×PID@div0，100 µs 拍 = 40,000 cyc）
- 引擎扫描 **18,560 cyc（46.4%）** ← 由**路由数**决定，想缩就少写
- 非引擎固定开销 **1,084 cyc（2.7%）** ← ★ **唯一"白占"、可直接妥协的一项**
  （黑匣子每拍搬 256 B · ADC · RTC 锁存 · I²C 状态机 · 顺序域 · Modbus）
- ISR 合计 **19,644 cyc（49.1%）**；余量 20,356 cyc
- 拍长下限 = `max(ISR 最坏时间, 主循环服务需求 / (1 − ISR 占比))`
⇒ 缩短拍长只有三条路：**① 砍非引擎开销 ② 减路由数 ③ 把主循环的活搬走**。
（单位换算：`C_other=542 TB`、`C_scan≈33~55 TB/op`，TB→cyc 因 `tb_cyc()`=TIM5 5 ns
⇒ **×2**；此换算关系本身是 §5.40 家族的坑，引用时必须带上。）

### ★ 可妥协清单（按代价排序）
| 妥协项 | 现在 | 可变成 | 代价 |
|---|---|---|---|
| 黑匣子 | 每拍搬 256 B | **触发式（故障前后 N 千拍）** | 平时无历史 |
| Modbus | 每拍（门之外） | 主循环每轮一次 | 响应慢 ≤0.4 ms |
| RTC 锁存 | 每 64 拍 | 每 1000 拍 / 按需 | 时间戳粗 |
| 路由数 | 128 | 32 / 64 | 逻辑少写 |
| 能力面 | 全开 | 档位化 | 不能同时要 |
| **AI/DI 更新率** | 10 ms | **提到每拍**（反向取舍） | ISR 变长，换带宽 |

### ★ 不可妥协的五条红线（动了架构就失去意义）
① **输出的硬件时刻**（σ 3.6 ns，唯一物理级指标）② **热代码 ITCM 常驻**（动了引入取指不确定性）
③ **无分支线性扫描**（动了成本不可算）④ **单写者**（动了非确定）
⑤ **喂狗钉在拍 ISR**（动了看门狗发现不了 ISR 卡死）

### ★ 建议：把"拍长"做成**档位契约**（控制档 / 标准档 100 µs / 服务档 500 µs）
行业里"周期"是**型号属性**（买错换型号）；我们能把它做成**参数**，且每档的**能力边界声明清楚 + 实测过**。
⇒ 这张档位表本身就是卖点。
