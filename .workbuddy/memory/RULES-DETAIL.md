## 〇、最贵的十二条（先读这段；细节在对应节）

1. **用这个系统 = 写 DCL 程序，不是改固件**（§1）。要新能力**先判层**。
2. **不得把实时量挂主循环**（主循环 0.37 ms，拍 100 µs）。每拍动作 → ISR/引擎。
3. **新增 SHM 域必须登记到唯一冷启动入口 `cold_start_reset()`**，否则被 `0x13 RESET` 抹掉（§1.8）。
4. **判"物理状态"看引脚实读（`IDR`/`PE9`），不看逻辑位**。`PE9=1` 才是使能（§6.15）。
5. **黑匣子槽头是 `[0]magic [1]tick [2]seq [3]ctrl`**；环是**"变化才记"** ⇒ **跨度必须由 tick 算，不能由槽数算**（§3）。
6. **"设了就算"必错**：凡配置量都要"目标值 vs 读回值"核对（`BRR` 16× / `PCSEL` / 极性 / 限时小值）。
7. **过闸门/构建绝不用管道**（管道退出码是最后一条命令的 ⇒ 判红照样提交 / 烧旧镜像）（§11.8）。
8. **判据必须能失败**，并配"**不该红的不红**"的反向判据（§2.3）。
9. **"值相同 ⇒ 不做"是危险判定**；切换上下文必须让缓存失效（§11.4）。
10. **"还欠着什么"必须配对计数，不能用 bool**（§4.12）。
11. **门必须带引用计数、住在资源定义处；先验参再拿门**（§4.5/§4.10）。
12. **测量期间不许做别的事**（命令通路是上位机墙钟定时的）（§10.13）。
13. **`dclc` 自动分配必须跳过"固件保留槽"** —— 否则程序写的值被固件每拍覆写**且不报错**（§5.17）。
14. **构建脚本的"已知间歇失败重试"也必须判退出码** —— 否则门过 → **烧旧镜像**（§4.2② / §11.8 同族）。

## 一、架构使用规约（强制）

```
① 引擎核心  烧录   改它 = 换固件(必走 A/B + 12 套回归)
② 外设能力  随核心版本化 + 能力位; 做成"通用事务 op"(I2C/SPI/UART) + 具名设备
③ DCL 程序  通信上传 + 持久化(SD)      ④ 程序工程  上位机侧: .dcl 源 + 清单 + 编译产物
```
| 问题 | 放哪层 |
|---|---|
| "**怎么算**"（逻辑/连续/顺序）| ③ 程序 |
| "**和外设怎么说话**" | ② 外设能力，**不是**新驱动 |
| 需要**新的每拍行为 / 实时保证** | ① 核心 |
| 只是"**给上位机看的量**" | SHM + `obs_anchor()`，**不是**加协议 op |

1. **观测先走协议内通道**（`0x38`/`0x22`/SHM）；pyocd 是最后手段。
2. **控制先走程序面**（`0x10 DEPLOY` + `0x11 START`），不要直怼寄存器"模拟"。
3. **要新能力先判层**。**不要默认改固件**（I2C 那次弯路就是这么走的）。
4. **每拍动作 → 引擎/ISR；服务性动作 → 主循环。** 主循环一圈 **0.37 ms**，拍 **100 µs**。
   ★★ **GAP-6 判层推论**：外设"多步操作"不能靠主循环跑阻塞事务 ⇒ 正解 = 照 `adc_poll` 做**拍内每拍推进一步的状态机**（四约束：拍内推进／标价+预算门／总线独占门／就绪门）。
   ★★ **适用边界**：判"要不要拍内"看两问 —— ① 在控制回路里吗？② 把主循环堵到**可测**程度吗？判据 = `WDT_STAT.loop_gap_max_undecl` + ISR 超预算次数。★ 反例：**AS5600 留主循环没问题**（≈450 µs、`loop_gap_max_undecl=0`）⇒ **判据由测量决定，不由规则措辞决定**（契约 §3.6/§3.6.1）。
5. **实验代码独立成 patch**（`docs/exp-<日期>-<主题>/`）；交付物里不出现脚手架。
6. **运行期改动复位即恢复**；不得污染持久化配置。
7. **每条判据都要能失败**，配对照证明它会红。
8. ★★ **新增 SHM 域必须登记到单一冷启动入口**（`cold_start_reset()`）。反例：`IX_MAGIC` 只在开机写一次 ⇒ 被 `0x13 RESET` 抹掉 ⇒ G6-3 事务区失联。

**三条红线**
1. **程序里不得出现任何物理引脚号或总线地址**（`dcl_static_check.py` 编译期拒绝）。
2. **不得破坏单写者**。★ 已两次踩到：`TIM3` 两个驱动者；**SD 卡两个写者**。
3. **不得把实时量挂在主循环上。**

## 二、时基与仪器纪律

**2.1 pyocd 会静默杀死 DWT（设计行为，无捷径）**：pyOCD issue #1540 —— 会话 disconnect 时写 `DEMCR.TRCENA=0`；J-Link 同款。`pyocd reset` 救不回，只有**断电重上电**（`-Oresume_on_disconnect=false` 实测无效）。
- ★★★ **正解在固件**：别拿调试单元当生产时基。✅ 已落地（`src/timebase.{c,h}`，`DCL_TIMEBASE` A/B）：**交付档 = TIM5**（32 位，200 MHz ⇒ 5 ns），DWT 留第二路径。
- ★ **单位随档变**：拍 = **20000**（非 40000）、ISR 最长 ≈ **818**。写死 40000/±64 的判据按 `TB_HZ` 换算（`h723_jitter` 已改读 `op=21`）。
- **健康度** `0x39 op=21`：`[0]档(1=TIM5) [1]频率 [2]自检Δ(=0 即死) [4]dwt_dead [6/7]pmin/pmax`。
- ★★ `g_per_cyc_*` 住 DTCM、**跨复位不丢**（只有 `0x13` 清）⇒ 复位后读 `0x38` 是**上一纪元残留** ⇒ **活性判据必须 `0x13 RESET` → `0x11 START` → 等 ~1 s → 看 `pmin` 非 0**。
- ★★ **缺口**：交付固件**没有 `0x39 op=7`（重新校时）** ⇒ 时基死在协议面上无法自证。
- 只读观测用 **`connect_mode=halt`**（`attach` 在某些 CMSIS-DAP 上初始化不了 AP）。★ **读固件全局量前绝不能 `-c reset`**（启动清零=自毁证据）。**收尾必须 `-c go`**。
- ★ 纪律：**`pyocd reset` 不要放收尾** —— 构建 → flash → **让板子自己重启（断电/按 RESET）** → 之后全程只走协议。

**2.2 逻辑分析仪**：网格 16 MS/s ⇒ 62.5 ns、24 MS/s ⇒ 41.67 ns，**用时间戳整除性反推采样率**。`wait_capture` 报 `ReadTimeout` 时数据往往已拿到，但**要查完整性**（37.7/61.1 µs 异常短间隔 = USB 丢数据，该档作废）。2 通道可 24 MS/s；8 通道上限 12 MS/s。

**2.3 判据禁忌**：① **空判据**（恒 0/1 ⇒ 分支没走到 ⇒ 永远通过。★ 处方：**"登记"与"裁决"拆两段**）；② **形状判据 > 幅度判据**；③ **先判掉量化伪影**（簇间距 = 采样网格）；④ **同一性对照**（A/B 先 sha 比对 + 同采样率）；⑤ **反向判据**（"不该红的不红"）—— 只有能失败的判据**还不够**；⑥ **口径与被测量同量纲**（"请求上限 ≠ 响应上限"：一常量两语义 ⇒ 通信域永久 busy）；⑦ **"覆盖不到/前置没满足"判 SKIP 或中止**，不许变 PASS，也不许变一堆红；⑧ **跨时刻/跨通道的"等值"判据必须给物理噪声底容差**（AS5600 1 LSB = 0.0879° ⇒ ±1 LSB）。

## 三、黑匣子（飞行记录仪）—— 取证主力，口径极易读错

- 环 `0x24004000` 起，**960 槽 × 256 B = 240 KB**。槽 = `[4 字头][60 数据字]`。
- ★★★ **头字段真值（`blackbox.h:29-33`）**：`[0]=magic "DLBK"` `[1]=tick` `[2]=seq` `[3]=ctrl(run<<24|n_routes)`。
  ★ 把 `[1]` 当 seq、`[2]` 当 tick ⇒ 时间跨度错 **3.96×**（血证：报出"31000 Hz ⇒ 4651 rpm"）。
- ★★★ **环是"变化才记"**（`blackbox.c:345`：内容没变 ⇒ **不写、不占槽、不增 seq**，计 `s_bb_skipped`）
  ⇒ **物理跨度由变化率决定**：变化率 ~25% ⇒ 记录率 ~1000/s ⇒ 跨度 **380 ms**；**轴不动时记录率降到 173~571/s ⇒ 跨度自我拉长到 452~473 ms**（可当"轴真没动"的旁证）。
  ★ `blackbox.h:71` 与 3 个工具写的 "960 槽 = 96 ms" 只是 **@10 kHz 逐拍全量**的算法；**交付行为不是**。
  ⇒ **`span = (tick[last]-tick[first])/10000` 秒，绝不能 槽数 × 拍长。**
- 取值：**pyocd API 单会话**（`connect_mode=halt`）读满 240 KB ≈ 1.4 s；commander 单次只 ~60 KB ⇒ 读不全。
  ★ **运动中途 halt** 才拿得到稳态段（TIM3 硬件定时器 halt 期间照发 ⇒ 不是"停下来再测"）。
- ★ **量纲自检**：`data[0]=SENSOR[0]`(raw 0..4095)、`data[1]`=角度 ⇒ `|deg − raw×360/4096| ≤ 0.001°`。
- ★ **荒谬值 = 线索**：报出物理上不可能的转速时，**先查分母/字段口径**。

## 四、程序持久化 + 内存地图

`.dcl` → 编译 → `0x45/46/47` 上传 → SD A/B 双副本 → 上电自动装载（不碰 flash）。
`0x45` BEGIN / `0x46` DATA / `0x47` COMMIT / `0x48` STATUS(96B) / `0x49` ERASE / `0x4A` DEVICE_DESC。
- ★ `0x48` 96B：+52/+56/+60 = `txn_begin/commit/abort`；+64..76 = 开机装载结果；+80..92 = 从卡读回的载荷头 ⇒ **验收全走协议，不需 SWD**。
- ★★ **五道闸门**：① 帧 CRC16 ② 清单 CRC32+total_len ③ 写后回读 memcmp ④ A/B + 单调 seq ⑤ **装载时再跑同一套静态校验**（`prog_validate`，上传与装载**共用实现**）。
- ★ 发布前必做**"运行态 vs 持久态"对账**（曾出现引擎 `nr=2`、卡上 `nr=128`）。

**4.1 AXI 地图 / SD 分区 —— 唯一真值源 `docs/STATUS-2026-09-16.md` §2/§3**（不抄第二份）
AXI **320 KB 已用满**，唯一空档 ≈10.5 KB（`0x24000600`–`0x24003000`）；黑匣子环 240 KB；`prog_store.c` 有构建期 `#if/#error` 守空档。
SD：`LBA0` 日志头（`h[112]=LOG_END`）· `LBA1..LOG_END` 日志环 · 卡尾 A/B 程序区 · `LOG_END=capacity-1-32`。
- ★ **绝不升 `LOG_VERSION`**（升了 `sd_log_open` 当新卡重建 ⇒ 从 LBA1 覆写**毁卡**）。
- ★ **`s_log_blk` 必须钳位**（旧卡游标可能超新上限 ⇒ 下溢 ⇒ 写飞出卡外）。
- ★ **不许按 HAL 骨架把 `sd_read_block`"半对齐"重写**（丢 IDMA ⇒ 数据错 ⇒ 当新卡重建 ⇒ SD 路崩）。
- ★ **SD 源缓冲必须在 AXI**（SDMMC IDMA 读不到 DTCM；**外设 DMA 能到哪块内存按外设成立，不能类推**）。

**4.2 两条方法学铁律**：① **`pyocd halt` 会把核留在停住状态** ⇒ 据此得过一整串假结论（**协议能读的一律用协议**）；② **闸门不用管道把门**（见 §11.8）。

## 五、引擎与配置陷阱（一条一行；血证见 git log）

- **5.1** **一个绑定跨两个寄存器 ⇒ 必须同一函数改**：定时器 DMA 请求 = 路由（`DMAMUX1_Cn`）+ 门控（`TIMx_DIER`），只改一半 ⇒ **静默失效**（读回全对）。见 `trig_source_apply()`。
- **5.2** **MDMA 通道寄存器只在 `CCR.EN=0` 时可写**（否则静默忽略）；清 `EN` 后**不能只靠写 `CCR` 重新使能**。
- **5.3** ★★★ **输出锁存链实测**：只有 `MDMA_CH0_CCR.EN=0` 会停；`DMAMUX1_C8=0`、`DMA2_S0_CR.EN=0`、`CTBR.TSEL` 扫 0…15 **照常工作** ⇒ **MDMA 通道在自循环，不消费任何请求源**；**引脚时刻 = CPU 最后一次写影子 + 0.12 µs** ⇒ **"计算与输出解耦、硬件锚定引脚时刻"未达成** ⇒ 让路/关黑匣子**注定无效**。
- **5.4** ★★ **ITCM 已 100% 占满（64 KB）** ⇒ 加 `DCL_ITCM` **不再是免费动作**；"ISR 可达却在 flash"**优先改结构**（实例：`i2c_bus_release()` 改 ISR 置标志、主循环放门）。
- **5.5** ★★ **门/守卫必须住在"资源的定义处"**；**门必须带引用计数**（单一 owner 表达不了"有几层在用"）。
- **5.6** ★★ **同一表达式在两个调用点语义可以不同**：`owner != SM` 在 AS5600 处对、在 `dev_bind_service` 处**自己就走 SM** ⇒ 空闲时判忙 ⇒ **提交全成功而 `ok_n/err_n` 永不动**。正解写"**有人占且不是我**"。★ 抓到它的是**为可解释性加的 `skip_n`** ⇒ **加计数器划算**。
- **5.7** ★★★ **"谁的结果"必须被显式携带**：发起时记号（`my = g_i2c_sm_req_n`）、完成时广播号（`i2c_sm_done_req()`，住资源处）；不等 ⇒ 丢弃重发。
- **5.8** ★★ **两个码空间数值重叠 ⇒ 不能共用一槽**；**一个计数只能回答一个问题** ⇒ 拆 `ok_n/err_n/skip_n/rej_n`。★ **判据：解释这个数时需要用"或者"就必须拆。**
- **5.9** ★★★ **"完成态"与"实时态"必须分开** ⇒ **完成记录** `{req,status,len}`（完成即快照，**受理新请求即失效**），取数只走 `take_result(my,…)`。
- **5.10** ★★★ **不要为一个准备拒绝的请求去占用资源** ⇒ **先验参、再拿门**（否则引用计数泄漏 ⇒ `owner` 永久卡死，症状离真因极远）。
- **5.11** ★★ **用原始位定性**：假报警"`SENSOR[15]` 变成 `6.5e-21`" ⇒ 原始 u32 = `0x1DF70200` = `fw_ver|cap<<16` ⇒ 是**串帧**（`0x01` 载荷被当 `0x22` 应答）。★ 最坏巧合：`0x22` 读 1 字的应答也是 4 字节 ⇒ **长度判据也分不开** ⇒ 加固：读**两个字** + 连续两次同值 + 打印原始 u32。
- **5.12** ★★★ **"还欠着什么"必须配对计数，不能用 bool**：延迟释放曾是 bool 且受理时清 0 ⇒ **每次泄漏 1 个引用**（`refs=61`、`owner=SM` 冻结而状态机 idle）⇒ 配对计数（完成 +1、主循环 `while` 还清）+ 删受理处清 0 + 主循环**引用计数对账**（`g_i2c_ref_leak_n`）。★★ 一处修复消掉三个看似无关的症状（含**跑测顺序依赖**）。
- **5.13** ★★★ **内部路径不得扰动对外协议的握手状态**：装载恢复复用 `dev_bind_submit()` 并 `REQ_SEQ+1` ⇒ 上位机撞号 ⇒ **之后全假 PASS 且无症状** ⇒ 抽 `db_validate_apply(seq)`，**共用校验、不共用握手/计数器**。★ 同族：`0x48` 应答**只能追加**（96→104 B）⇒ **对既有应答长度的"等值"判据都是陷阱**（与 `cap == 0x0DF7` 同族 ⇒ 认口用**必备位掩码**）。
- **5.14** ★★★ **流式解析器必须有超时**（"大 deploy 偶发失聪"）：根因 = 接收环 512 B（≈44 ms）而主循环会停顿 + `fp_feed()` PAYLOAD 态**无超时** ⇒ 停在半帧永久失聪。⇒ `FRAME_ASSY_TIMEOUT_TICKS=500` + `RX_RING_SZ 512→4096` ⇒ **120 次部署 0 事件**（修前 8/120）。★ 通用：① **环大小只降概率、超时才能自愈**；② **判"有没有新字节"要看"本轮真的消费了字节"**，不能看索引变没变。
- **5.15** ★★★ **一个默认极性可以同时弄反"使能/失能/安全态"**：映射 `conducting = (pol==0)?ena:ena^1` ⇒ **`PE9=1` 才是使能**；`g_step_ena_pol` 复位默认 0 与实机相反 ⇒ `ena(1)`=**失能**、上电"安全态"=**通电**。现象 = "**电机自己在响 + 轴不动**"。⇒ **判据必须看引脚实读**（逻辑位会说反话且**不是恒 0/1** ⇒ 不满足空判据特征 ⇒ 没人怀疑）。⇒ **处方：驱电机的脚本开工先 `sub=5 arg=1` 并断言 `PE9==1`**。

- **5.16** ★★★ **脉冲频率的周期被量化到 1 µs**（2026-09-17 标定定案）

- **5.17** ★★★ **`dclc` 的自动分配必须跳过"固件保留的 WIRE 槽"**（2026-09-17 修）
  血证：`sel der = wire[65]` 而 **`WIRE[65]` 是固件每拍写入的运动镜像**（`STEP_MOT_SLOT_LIMIT_AP`）
  ⇒ 程序算出的值**每拍被覆写** ⇒ 现象 = "**程序在写槽、硬件一动不动**"（`WIRE[16]/[17]` 被引擎覆写那次同一族）。
  ★ 成因：`OUTPUT TO wire[n]` 的槽是**解析前预登记**的（钉住的槽安全），而**自动分配只跳过钉住的**、
  不认识固件保留区 ⇒ 槽一紧张就越过 64。`step.h` 写的"自动分配上限 64"只是**约定，没有代码在守**。
  ⇒ 处方（两条 + 一处防漂移）：① 自动分配跳过保留集；② 显式 `OUTPUT TO` 落保留槽 **报错**；
  ③ **保留集从 `src/step.h` 的 `STEP_MOT_SLOT_*_AP` 自动读**（手抄必漂移）。
  ★★ **"一律禁用 ≥64"是过度保守** —— 实测固件只占 64/65；而引擎里 **`SEL` 吃 4 个 wire 槽**、
  **`CONST` 也占 1 个** ⇒ 60 行的运动安全程序在 `wire[0..63]` 里就溢出。

- **5.18** ★★ **③层 DCL 的三条口径**（2026-09-17 编译期实测，别再猜）
  · `THR=` 只认**数字字面量**（CONST 名/信号都不行）⇒ 拿**算出来的量**当门限要先 `SUB` 造差值再与 0 比
  · `BY=` / `FROM` 只认**已声明的 CONST 名或信号**（内联字面量报"未定义信号"）⇒ 负数也要先 CONST

- **5.19** ★★★ **"指令 vs 引脚实读"的失配必须**归因**，不能只给总数**（2026-09-17）

  **`do_poll`/`do_outputs_safe`/诊断三处共用同一个 `do_mask_effective()`** 且**不偷改上位机字段**；

- **5.20** ★★★ **"判据的速率"必须与被测量的速率匹配；而"降档"不是万能解**（2026-09-17 实机定案）
  - 血证：失步检测程序**每拍**判"编码器没动"，而编码器由绑定表**每 10 拍才回填一次** ⇒
    `dab` 呈 **1:10 占空比**（9 拍 0、第 10 拍 10 倍；实测读回 `33 / 0 / 48 / 0`）
    ⇒ `TON PT=200ms` 要**连续 200 拍**"没跟上"，每 10 拍必被尖峰复位 ⇒ **永远不触发**
    （现象 = "电机真的失速了，检测器毫无反应"）。
  - ★★★ 而"把判据降到与传感器同速（`PERIOD=1ms`）"**走不通**：固件有**跨档速率检查**
    （`main.c:1838`）：`慢消费者读快生产者 = 欠采样 ⇒ NAK "rate mismatch"`，
    判据是 `生产者 div < 消费者 div 即拒`；而且**"下游必须同档或更慢"会一路传染** ——
    连 `OUTPUT` 都躲不掉（`OUTPUT` **不接受 `PERIOD=`**，其正则要求精确匹配行末）⇒ 实测两次被拒。
    ⇒ **正解 = 一阶低通**（`LPF <n> FROM <sig> T=<τ秒>`，α = dt/(τ+dt)），τ ≫ 采样周期：
    输出 ≈ 平均速率、纹波 <25%，且 `LPF` 在 div0 ⇒ 不触发跨档检查。
  - ★ **单位不受档位影响**：`RATE` 除的 `dt` 就是**该路由自己的周期**（`engine.c:283`：
    `dt = MID?DT_MID : SLOW?DT_SLOW : DT_FAST`）⇒ `RATE` 恒为"每秒"。
  - ★★ 教训一般化：**给一个"慢采样"的信号做"每拍"判据时，先问"这个量多久才更新一次"** ——
    否则做出的是一条**永远不触发**的判据（比误报更坏：它看起来在工作）。
- **5.21** ★★★ **③层程序要"跑起来"还有两道非编译期的门**（2026-09-17 全踩过）
  1. **`SRC_HMI` 在 H723 上没实现**（`engine.c`：`case SRC_HMI: return 0.0f;` +

- **5.22** ★★ **主机→程序的输入槽必须"被当作输入引用"才不会与内部信号撞车**（2026-09-17 修）

- **5.23** ★★★ **"期望为 0/小"的判据必然是假绿 ⇒ 必须先配"正对照"**（2026-09-17 阶段三定案）

## 六、DO 输出路径 —— `DCL_DO_LATCH = 0` 是交付值

0 档 = CPU 直写 `GPIO_BSRR`，σ = **1.4 cyc = 3.6 ns**；1 档 = 影子 + MDMA 锁存，σ = 5.2 cyc = 13.0 ns、**引脚抖动 ≈54~60 ns** ⇒ 差 ~15 倍。切 0 档**无功能损失**。★ "输出由硬件锚定"在 1 档**本来就不存在**（见 5.3）。
- **抖动判据**：别用 LA 测 20~60 ns（网格 62.5 ns ⇒ 量化 σ 就 25 ns）；固件里累積 `Σ(d−40000)`、`Σ(d−40000)²`（u64，`op=16`）★ 累積**偏差**而非 d。★★ **口径必须写清**：那次"写"写的是影子还是引脚。
- **两个编译期坑**：① **CMake 开关可能根本没接线**（**必须 grep 到接线**）；② **`#endif` 必须在函数收尾 `}` 之前**。

  ★ 后四道闸门自带 `--selftest` 与覆盖度自报（覆盖不足 ⇒ 判**无效**，不是"干净"）。★★ **契据改了必须同步 `docs/claims.md`**，否则构建红；未覆盖项必须 `--allow-uncovered <理由>`。★ claims **八类**：A 结构/B 拒绝码/C 能力位/N 留位/C2 完备性/D `file:line` 漂移/E 判据存在性/**F 门面一致性**。★★ **F 是后补的**：claims 只管"契据⇄代码"，**管不到 发布说明/GAP 表/README** ⇒ 曾同现 **6 处过期状态** ⇒ **门面写错比没写更坏**，F 会抓文档里写错的**符号名**。

## 十一、装置属性与"会响的失败"

- **10.1 ★★★ 装置属性（极性/行程/限位逻辑）必须"显式声明"，未声明就 fail-closed。** 工业做法 = 硬件跳线/DIP 或工具配置存卡（`8132.cfg`/ESI/CiA301 `0x1018`）。⇒ `CMakeLists` 里做成**三态**（`-1` 未配置/`0`/`1`），写进 `build.sh` 交付 DEFAULTS，并出现在"生效开关(读自 CMakeCache)"清单 ⇒ **可见才算声明**。★ **未声明 ⇒ 拒绝使能（NAK+原因）+ 落回物理失能**（默认值本身就是"对硬件的假设"，而**"看起来接受了其实跑错"是三者里最坏的**）。★★ **极性未声明时"使能/失能"根本没有定义** ⇒ 那一档只能用**物理**语言（`drive_opto(conducting)`），**不能**走按 `pol` 翻译的函数（否则算出相反电平，fail-closed 反而通电）。★★ **"安全态"分两问**：**按器件**（导通=失能？取决于驱动器）与**按轴**（停止后要不要保力矩 —— **垂直轴去使能 = 掉力滑车**），两者正交不要用一个量表达 ⇒ 上电/停止态由 `stop_hold` 决定，极性只决定"**怎么**通电"。
- **10.2 ★★ 判"物理状态"看 `IDR`，不看逻辑位**（同 5.15）。⇒ 把**"指令 vs 实读"不一致**做成**计数器**（对齐运动卡 `SVON` 输出 + `RDY` 输入 / PLCopen `MC_Power` "等 Statusword"）。★ 核对必须放**主循环**（引脚由 DO 面在**拍上**写；在写函数里立刻比**必然误报**），并**连续 2 次**去瞬态。
- **10.3 ★★ `pyocd reset` 后有"偶发停答、会自愈"窗口**（3/3）：reset 后立刻 `0x38` TIMEOUT，显式 `go` 也**不能马上**恢复，**~5~10 s 自愈**。★ 判"板子死没死"用 **SWD 读 `g_tick_count` 两次**（在变 ⇒ CPU 在跑 ⇒ 是协议面的事）。
- **10.4 ★★ 裸 `serial.Serial` 不释放 DTR/RTS ⇒ 把板子按在复位上**（血证 2026-09-11 记过，2026-09-17 才发现两个运动工具**一直**没跟上）⇒ 一律用 `h723_modbus.open_serial()`。
- **10.7 ★★★ 别在"传感器噪声底"上做等值比较**（必然间歇误报，**两处副本**）：断言"状态机读数 == 阻塞读数"逐位相等，而两次读**不同时刻** ⇒ 在 **±0.5 LSB**（AS5600 1 LSB = 0.0879°）上比 ⇒ 报 `937 vs 936`（**恰差 1 LSB**）。⇒ 按**物理噪声底**给容差（±1 LSB），并写清"**为什么这不会放过真缺陷**"（串 lane/字节序错会差**远大于 1**）。★ 同族：`while(odr!=idr)` 忙等、按字节数判内容。
- **10.8 ★★★ `stop_hold`（按轴保力矩）三条规律**：① **与极性正交**：`hold=1` ⇒ 静止**通电**（垂直轴必须）/ `hold=0` ⇒ **断电**（水平空载省热）。实测 `hold=1 ⇒ IDR(GPIOE)=0x0F00`（PE9=1）/ `hold=0 ⇒ 0x0D00`（PE9=0）。② ★★★ **"上电即通电"是最容易被当成故障的正常状态**：**嗡嗡响（斩波）+ 发热（保持电流）+ 轴不动（无脉冲）= 同一物理状态** ⇒ 先问 `hold` 与 `PE9`，别先怀疑驱动器/接线。③ ★★ **改策略量必须立即作用**（`step_set_stop_hold()` 原只改变量 ⇒ `sub=12 arg=0` 后 `PE9` 仍为 1）⇒ 修法：**若当前无脉冲 ⇒ 立刻按新策略重算**。★ 凡"改了要等下次事件才生效"的配置都要问：**这次算不算已生效？**
- **10.9 ★★ 判断"轴动不动"要用"方向口径"对齐**：`longrun` 理论值**恒取正**而套件不设 `dir` ⇒ 报"偏差 **−199.4%**"（实测 −894.7°/理论 900°）⇒ **按实际 `dir` 取符号**（既有纪律：凡方向/极性/符号一律实测再写死常量）。

## 十二、③层（DCL 程序）与"让程序驱动外设"

- **11.1 ★★★ ③层输出面只有 `wire[]`**：`dclc.py` 的 `OUTPUT <name> TO <dst>` **只接受 `wire[<n>]`**，写 `TO actuator[12]` **直接编译失败** ⇒ "让程序驱动外设"的**载体只能是 `wire[]`**（谁读它由服务方决定）。★★ **`WIRE` 是"热端"**：bench 128 条路由**覆盖全部 WIRE 槽** ⇒ 判"程序面"必须在**已部署本程序（或引擎 STOP）**状态下做。★ 槽归属：**服务方保留的槽，程序内必须只有一个写者**。
- **11.2 ★★★ `dclc` 自动分配上限 = 64（`wire[0..63]`）** ⇒ **固件保留的观测/镜像槽必须 >63**（实测被抢：`LT lo=wire[16]`、`LOGIC drive=wire[17]`）★ 而**被 `OUTPUT` 显式钉住的槽安全**。
- **11.3 ★★★ `0x20 READ`/`0x23 WRITE_BURST` 要【绝对地址】= `g_shm + 偏移`**，不是 SHM 偏移（传偏移 ⇒ NAK "bad addr"）。★ `g_shm` 从 `0x38` 的 **+23** 读。★ 血证：回归里"读 `n_routes`"**一直返回 -1** 的真因就是它 ⇒ **"读不到"先怀疑自己的地址/格式，别先怀疑固件**。
- **11.4 ★★★ "值相同 ⇒ 不做"是危险判定 —— 切换上下文必须让缓存失效**：运动服务的请求值缓存是函数内 static，**切换运动源/重新部署不清** ⇒ 判"无变化"⇒ **程序在写槽、硬件一动不动**。★ 与"重放旧表被静默忽略（`req_seq` 撞号）"**同一族**：**把"值相同"当成"无事发生"**。★ 判"变化"应比 **请求值 vs 上次请求值**（不是 vs 硬件现状）—— 否则"限时到期自动停脉冲"会被服务**立刻拉回来** ⇒ 安全网失效。
- **11.5 ★★ 驱动+电机有"最低有效频率"**（实测）：15 Hz 下 `rate=15/CC1E=1/PA6 确实翻转`（脉冲真发出去了）而**轴纹丝不动**（`raw` ±1 LSB）；同板 500 Hz 长跑 **−0.0%**；**脚手架直控 15 Hz 同样不动** ⇒ 与"程序面"无关。⇒ P 控制在小误差时压到下限 ⇒ **电机不动、闭环卡住** ⇒ 处方：`hz_min` 取**实测可用下限**或误差带外做 **bang-bang**。★ 与审计 **D3**（"限时字段有不可用下界"）**同一族**。★★ **上界同族**（§13）：**从静止突加 >16500 Hz 必失速**。
- **11.6 ★ 编码器槽位**：`sensor[0]` = **raw（0..4095）**，`sensor[1]` = **角度（0..360）**。★ 血证：用 `sensor[0]` 当角度 ⇒ `err=-742` ⇒ **量纲错会给出"完全不可能的物理量"**。★ `examples/h723_pid_demo.dcl` 注释写"`sensor[0]` 不被任何组件回填"**已失效**。
- **11.7 ★★ `h_device_desc()` 是 ackbuf 闸门的盲区**：用**变量偏移** `put16le(r + k,…)`，而 `h723_ackbuf_check.py` 只认 `ack(r,<数字>)` 与 `put32(r + <数字>)` ⇒ **不受闸门保护**（已从 64 扩到 96 并注明最大 k=66）。
- **11.8 ★★★ 过闸门绝不用管道**（同 4.2②）：`python X 2>&1 | tail -4 && git commit` ⇒ **退出码是 `tail` 的（恒 0）** ⇒ **判红照样提交**（**第三次踩同族**；同族：`build.sh | grep … && flash` ⇒ 烧了旧镜像）。⇒ 处方：`python X > /tmp/g.txt 2>&1; RC=$?; tail /tmp/g.txt; [ "$RC" = 0 ] || exit 1`。
- **11.9 ★★ "位带别名"陷阱**：提出"`TIM3 UEV → DMA(NDTR=N) → 目的 = `TIM3_CCER.bit0` 位带别名 ⇒ 搬 N 次硬件自清 `CC1E`"并写进 README + commit。★ **错**：**每次搬的都是同一位** ⇒ **第 1 个脉冲就清掉 `CC1E`** ⇒ 只走 1 步。⇒ **"N 次搬运"只有搬"不同位置"才有累积语义**。★ 方案要**从第 1 次执行推一遍**，不能只推"最后一次落在哪"。
- **11.10 ★★★ "走 N 个脉冲自停"正解 = 让另一个定时器硬件数脉冲**（零中断/零DMA/零ITCM）：
  `TIM3_CR2.MMS=010`（TRGO←UEV，只改这 3 位）+ `TIM4_SMCR = SMS=111 | TS=010`（ITR2=TIM3）⇒ `TIM4_CNT` 就是"已发多少脉冲"。
  ★ ST ITR 表（TIM4 行）：`ITR0=TIM1 · ITR1=TIM2 · **ITR2=TIM3** · ITR3=TIM8`。★ **TIM2=拍定时器、TIM5=交付时基 ⇒ 都不能用；TIM4 空闲** ✓（不用通道引脚 ⇒ 只需 `RCC_APB1LENR_TIM4EN`）。
  ★ **TIM4 是 16 位** ⇒ 单次上限 65535 步（40.9 圈 @1600 步/圈），超出**明确钳位**。
  ★★★ **但 N 取 65535（= `ARR`）是刀锋**：到点判据 `CNT >= goal` 而 CNT 在 65535 后**回绕到 0** ⇒ 只有恰好采到那一瞬才算到点 ⇒ **周期性漏判、多跑若干整圈**。血证：`走 65535 步 @60000 Hz` 表观只有 **5193 Hz**（= 60000/11.5）⇒ **N 必须 ≤ 60000**。
  ★ 到点由**主循环**停 ⇒ 多走 ≤1 圈；**实测超发可达 +9.3%（700→765）** ⇒ 判据必须带容差；★ **但 `TIM4_CNT` 精确记录实际步数 ⇒ 是"已知量"不是误差**。
  ★ 三个计数必须分开：`done`（到点）/`abort`（被限时或停机打断）/`rej`（被拒）。★ v2 硬件精确停：`TIM4` CC 事件 → **一次普通 DMA** 把 0 写进 `TIM3_CCR1`（**不需要 MDMA**）。
- **11.11 ★★ 判"计数器准不准"的容差口径是"起止时刻对不齐"，不是计数误差**：`step(N)` 下发生效要一次命令往返（p99 56.8 ms），"到点停"由主循环做 ⇒ 500 Hz 下 250 ms = **125 步** ⇒ 判据只能取"**两条独立路径（硬件计数 vs 编码器换算）都落在 [N, N+容忍] 且互相差 ≤ 容忍**"，**不是逐位相等**。★ 要逐位对齐必须让两者**同时起止**（v2）。

## 十三、运动台架实测数字（阶段 0~2，2026-09-17）

**全部经"闭环标定"**：`走 N 步` → `TIM4_CNT`（硬件脉冲）+ AS5600 **绝对**角 ⇒ **零时间假设**。
- **步/圈 = 1574.4**（名义 1600，−1.6%）：`counts/step` 中位数 **2.6017**，6 行峰峰 **0.91%**，正反对称。
  ★ **前提：仅当 N < 800（=180°）时有效** —— N=1400（315°）会走错解卷绕分支（**垃圾行，非数据**）。
- **拍长 = 99.95 µs（−0.05%）**：黑匣子 (Δenc, Δtick) × counts/step × T3 真实 Hz ⇒ `tick` 独立反解确认。
- **脉冲率 = `1e6/floor(1e6/f)`**（1 µs 周期量化，见 5.16）⇒ **定量结论必须引 `rate_actual`**。
- **★ 失速边界（突加，从静止）**：15000~16500 Hz ⇒ 比值 1.007~1.012 ✓；**16750 起 = 0.000**
  ⇒ 拐点 **16500~16750 Hz = 619~628 rpm**（**拉起频率 pull-in**）
- **★ 决定性对照**：先在 8000 Hz 转起来再**突跳**到 18000/24000/31000 ⇒ 比值 **1.010/1.016/1.011** ✓
  ⇒ **排除"固件拒发高频"** ⇒ 失败只在"**从静止起转**" = 斜坡收益的机理所在
- **★ 失速不自愈**：突加 20000 后等 0.4 s / 2.0 s 都是 0.000 ⇒ **持续通电流**（= 客户"响 + 不转 + 发热"三现象同一物理态，与 §10.8② 同源）
- **★ 斜坡上限（pull-out）**：31000~50000 ⇒ 0.998~1.007 ✓；**80000 起 = 0.000**
- **全频段跟随线性度**：28 点比值 0.995~1.018，**所有非 1.000 部分由 5.16 的量化逐行解释**（24000⇒+1.6%、60000⇒+4.2%、周期整除档⇒0.998~1.000）⇒ **无随速度增长的丢步，线性度 ≤0.5%（1~60 kHz）**
  ★★ **但存在一个 −1.6% 的固定比例因子，且其归属不可分**：静态标定 counts/step = **2.6017**，而 1/8 微步名义值是 2.56。
  用 2.6017 算 ⇒ 电机比脉冲**慢 1.6%**；用 2.56 算 ⇒ **恰好 1.000**。
  ⇒ 数据分不开"**AS5600 角度刻度有 −1.6% 增益误差**"与"**驱动器微步刻度差 1.6%**"。
  ⇒ **只能说"线性度 ≤0.5%"，不能说"绝对跟随精度 ≤0.5%"**（红线：别把不可分的量说成已测的量）。

## §5.38 ★★ 脚本必须在**任何外部命令之前**导出 `PATH`（本机 bash 起来时 `PATH` 为空）

- **实测（2026-09-18）**：在裸 bash 下 `bash build.sh` **直接失败**：

- **根因**：`build.sh` **完全没有 `export PATH`**；

## §5.40 ★★★ "一个数当界限"前先证明它是界限；"最好情况"不能当"最坏情况"

- **背景**：`engine.c` 的预算模型要给两条扫描体（ITCM / FLASH）定价。
  第一版用**一个标量** `OP_COST_PATH_NUM/DEN = 303/100`（斜率比 3.03）。
- **证伪**：逐原语两点法实测两条路径的比值是 **2.98× ~ 4.41×**（DIRECT 4.41 / PID 2.98）
  ⇒ 标量**既不是上界也不是下界**，是**中枢值**。
- **方向一（低估 ⇒ 放行超载）**：标量档实测（`python tools/h723_path_cost_criteria.py --mode scalar`）
  ACK 了 **128×DIRECT**（模型自报 21760 cyc = 54% 拍），**实跑 30988 cyc = 77.5% 拍**
  ⇒ **超了门自己承诺的 26000 cyc 1.19 倍**，而运行期兜底 `ov`（80% 拍 = 32000 cyc）**未触发**
  ⇒ **这条失守不会被 `ov` 兜住 ⇒ 静态门是承重的**。
  ★ 且**标量档的门的拒绝路径对 DIRECT-only 程序结构性不可达**：
  门边界在 `153×170 = 26010`，而 **153 > MAX_ROUTES(128)**
  —— 钉住这点用的是 N=129 被**条数门**（`counts exceed max`，`main.c:1790`）拦下。
- **方向二（最好情况当最坏情况）**：历史两张成本表都取 `g_eng_cyc_min` = **最好情况**。
  ITCM 零等待 ⇒ min≈max（交付表无害，F1 = 1.014 佐证）；
  但 FLASH 走 L1 I-cache ⇒ min 只给 PID **363 / 401**，而**部署程序**的 emax 斜率实测 **434**
  ⇒ 在 **min 表档**上 **71×PID 被 ACK**，实跑 **33592 cyc = 84% 拍** ⇒ ★ **`ov = 1`**。

- ★★ **两条元教训**：
  ① **标量在"最贵的那个原语"上恰好安全（440 vs 432）⇒ 所以没人会怀疑它**
     —— 一个近似"在样本的最坏点上看起来是对的"完全不能说明它安全；
  ② **运行期计数器不是门**：`ov` 抓到了超载，但程序**仍留在板上每拍超载**，
     只被记了一笔。静态门与运行期判据**不可互相替代**。
- 正解落地：`k_op_cost_itcm[]` / `k_op_cost_flash[]` 两张**逐原语**表，
  `engine_op_cost()` 按 `BOOT_SEL` 选表，标量已删。

## §5.41 ★★★ 判据口径必须与被测对象自洽，否则"判据坏"会伪装成"被测对象坏"

- **实测**：`tools/h723_budget_fidelity.py` 的 **F2** 原式 `emax ≤ EXEC_BUDGET_TB × 0.80`
  = **64% 拍**；而**静态门本身**允许引擎占 **65% 拍**，再加非引擎 ISR（≈7% 拍）
  ⇒ 总 ISR ≥ 72% 拍 ⇒ **FLASH 档（静态门承重）任何近门程序必然 FAIL**。
- ★★ **危险在于症状方向**：它会报"动态门余量不足 ⇒ 负载不健康"，
  而被测对象其实完全合规 ⇒ **又一次"工具把矛头指向错误方向"**（与 §5.39 同族）。
- **正解**：阈值改成对**拍长**取余量（`--margin 0.80` ⇒ 与动态门 80 µs 同口径），
  改后自洽（实测 72.1% 拍 ✅）。
- ★★★ **纪律**：立判据时必须先算「**被测对象的合法域能不能落进判据的通过域**」——
  落不进 ⇒ 判据口径错，不是对象坏。

## §5.42 ★★★ 工具的隐含前提会随固件改变而静默失效（比"硬编码常数"更隐蔽）

## §二十一 执行时间"可算性"（STA 路线）—— 2026-09-18 的三条新纪律

> 背景：需求是"**用算出来的界代替人工划周期**"（不是"每一步都精确"）。

### §5.43 ★★★ **跳转表的项序 ≠ 代码布局序**；猜布局会安静地造出一张假表

- **实测**：按"19 个 `tbh` 目标按地址排序，相邻两个之间 = 该原语的代码"切区间 ⇒
  `LPF` 得 **255 条**、`PID` 只有 **7 条**、`SR` 的区间长度算出**负数**。
- **真值**：目标按 **op 号**排，地址上**不单调**（主表最后一项 `0x120C` 反而是地址最大的）。
  正解 = 从每个目标**沿控制流走**，遇**第一条回边**即止（19/19 个区间各恰 1 条回边）。
- ★ 危险之处：那张假表**每一行都有数字**，看起来完全正常。
- ★ 同族：**两个不同的序被当成了同一个序**（§5.23"分子分母同口径"的排序版）。

### §5.44 ★★★ **特征数必须与样本数相称**；LOO 是"能预测"与"只是拟合"的分界

- **实测**：用 8 个指令类特征在 **19 个原语**上做最小二乘 ⇒
  **中位 LOO 误差 29.1 cyc**，而"只数指令条数"单变量基线只有 **5.6 cyc** ⇒ **加权模型更差**；
  且拟合出**物理上不可能**的负系数（`fp −4.60` / `alu −8.69`）。
- ⇒ **8 特征 / 19 样本 = 过定参数化**。若不看 LOO 只看拟合内残差，它会"看起来很准"。
- ★ 纪律：**任何"结构→成本"的回归必须报 LOO 误差，并给出单变量基线做对照**；
  系数出现反物理符号即判**无效**，不许解释。

### §5.45 ★★★ **零自由度交叉检验**是识别"混淆项"的最便宜手段

- 做法：`K = median(实测_i / 结构量_i)`（只是取中位，**不是优化**），预测 `= K × 结构量`。
  ⇒ 残差是**真残差**，无法靠过拟合掩盖问题。
- **实测结果**：`K = 6.167 cyc/指令`，**13/19 个原语残差 >25%**，最大 **174 cyc（205%）**。
- ★★ **而失败模式本身就是线索**：指令数 **26→42** 的 5 个原语，实测成本**纹丝不动（74~85）**
  ⇒ 不可能是真实执行成本 ⇒ 指向**切出的"区间"混进了共享尾码（epilogue）**，
  被算进了**每一个** case ⇒ **该表的"指令数"列是被污染的**。
- ★ 纪律：**先做零自由度检验，再考虑拟合。** 拟合会掩盖混淆项，零自由度检验会暴露它。

### §5.46 ★★ 把"未算"与"算不出"分开记账

- 本平台已完成的结构事实（可复算、不需连板子）：扫描体 **599 条指令**、
  **`prim_exec` 无独立符号（19 个原语全部内联）**、op 分派是 **3 个 `tbh` 跳转表**、
  分派语义 **`subs #1` ⇒ 表项 i 对应 op = i+1**、**逐原语区间可机器判定**（19/19 各 1 条回边）。
- 未算的 9 项已逐条登记并分类（`ARCH-EXECTIME-COMPUTABILITY.md` §5）：
  **其中没有一项被证明"算不出来"** —— 分别是"方法没做完"（共享尾码/依赖链/分类表）、
  "只能算界"（`VDIV` 操作数相关、分支预测、存储缓冲）、"需要另外的实验"（Flash 取指、AXI 争抢、观测口径）。
- ★ 纪律：**"还没算"和"算不出来"是两件事**；汇报时必须分开写，否则会把"进度"读成"结论"。

### §5.47 ★★ 观测量与要解释的量必须是同一个（否则比对无意义）

- **实测**：`di` 量的是**整段 ISR**（含 `bb_kick`/`adc_poll_kick`/`rtc_latch`/`i2c_sm_tick`），
  而结构侧要解释的是**引擎扫描段** ⇒ 两者**不是同一个量**，比对会得出无意义的差。
- ★ **但"减出来"这条路已实测可行**：黑匣子开关（`0x39` op=4）对照，
  `--bb on/off` 得 **1375.3 vs 1375.5 TB**（标准误 1.8）⇒ `bb_kick` 每拍净成本 ≈ **0**，
  说明"逐个关掉拍内工作看 `di` 变化"的减法路子可控。
  （★ 同时**修正了一条旧归因**：原以为"少数拍显著更高"来自黑匣子每 1024 拍的重活 —— 至少不是每拍那次。）

### §5.48 ★★★ 四个 CFG 陷阱：每个都"数字照出、结论全错"（2026-09-18 步 A 实得）

全部发生在同一个函数（`engine_scan_itcm`，599 条 / 71 基本块）上，**四次都静默**：

| # | 陷阱 | 症状（都不报错） | 正解 |
|---|---|---|---|
| T1 | **按地址排序猜布局** | `LPF` 255 条 / `PID` 7 条 / `SR` 区间**为负** | **跳转表项序 ≠ 代码布局序** |
| T2 | **`tbh` 没有后继** | 可达图断链 ⇒ "可达 8 条"比**自己的入口块**（12 条）还小 | `tbh` 目标在**表数据**里，必须读 ELF 字节 |
| T3 | **表长靠猜** | 按固定 40 项读 ⇒ 19 个 op 全变 283 条；而判据**居然"通过"**（预测值全同 ⇒ 残差只剩常数）= **假绿** | 用**下一个基本块起址**截断表 |
| T4 | **在带环图上求最长路径** | 尾块→分派块→case→尾块 成环；DFS 触深度上限**返回 0 而不报错** | 环上最长路径**无定义**，必须换口径 |

- ★★ **教训**：共同形态是 **"程序不崩、数字照出、结论全错"**。
  "判据必须能失败"在这里救不了 —— 因为**判据在跑，只是输入错了**。
  **唯一有效的防线是让口径互相约束**：例如"可达条数 ⊇ 入口块条数"这条，
  是 T2 上**唯一亮红灯**的地方（8 < 12）。

### §5.49 ★★★ 假绿的第二种形态：**预测值没有区分度**

- **实测**：两种口径（可达闭包 / 入口→尾块路径集）都给出**中位残差 3.9~6.0 cyc、超差 2~3/19**，
  看起来远好于"入口块"口径（中位 33.0、超差 **11/19**）。
- **真相**：它们对**每个 op 都给出几乎相同的数**（283 / 330 条），因为
  **循环里任何一个 case 都能经"尾块 → 分派块"到达其它所有 case**。
  一个对谁都一样的预测值，残差就只剩"实测均值"一项 ⇒ 中位残差自然小。
  症状在秩相关上暴露：**Spearman ≈ 0 / 0.08**。
- ⇒ **判据必须同时报"区分度"**（预测值的极差 / 秩相关），否则"平均值预测器"永远最优。
- ★ 这是 §5.23「期望为 0/小 ⇒ 假绿」的**同族新形态**：那里是"判据太弱"，
  这里是"**预测器太弱反而显得准**"。

### §5.50 ★★★ 纯控制流结构量**不足以**确定逐原语成本（本轮硬结论）

- 四种口径全部试过（地址序区间 / 入口块 / 可达闭包 / 入口→尾块路径集），
  在**比例形式**下没有一种能同时做到"区分原语"与"低残差"。
- 最干净的"入口块条数"口径：K = 9.500 cyc/指令，中位|残差| **33.0 cyc**，**11/19 超 25%**；
  与实测的 **Spearman 秩相关 = 0.641** ⇒ **有信息、但不是充分统计量（在比例形式下）**。
- **根因**：`P(入口) ∩ P⁻¹(尾块)` 里 `P⁻¹(尾块)` **就是整个函数**（谁都能走到尾块）；
  而"哪条路由被处理"由**运行期的 op 值**决定 —— 那是**数据**，不是结构。

### §5.51 ★★★ 结构量必须用**仿射**形式（比例形式必然错），且截距要能与独立量自洽

- **线索来自数据**：入口块只有 **2 条**的 `DIRECT` 实测 **56 cyc**；4~5 条的 `AND/OR/NOT` 实测
  **71~78 cyc**。若成本 ∝ 条数，这些点该逼近 0 ⇒ **存在 ~60 cyc 的地板**。
- **实测（LOO 留一）**：

  | 形式 | 中位\|残差\| | 最大 | 平均相对 |
  |---|---|---|---|
  | 比例 `K·n` | 35.4 | 193.5 | 56.4% |
  | **仿射 `c0 + m·n`** | **8.0** | 63.1 | **13.2%** |

  `cost ≈ 67.7 + 1.16 × (入口块条数)`，**c0 > 0**。
- ★★ **两个离群点正好是物理上应该离群的**（比"误差小"更有说服力）：
  · **PID** 残差 **+56.5** —— 它含 **`vdiv`**，而 ARM 文档 VDIV 是 **2~14 cyc 操作数相关**
    ⇒ 结构模型**不可能**算准它（这条**预言**在实测中被命中）
  · **DIRECT** 残差 **−14.0** —— 空操作，固定项占比最大，方向也符合预期
  · 其余 17 个全部 ≤ 18.3 cyc（多数 < 10），无系统偏差
- ★ **自洽性判据（值得复用）**：截距 67.7 ÷ 共享尾块 27 条 = **2.5 cyc/条**，
  与斜率 **1.16 cyc/条** **同一量级** ⇒ "固定开销"与另一个独立量出的"每路由共用尾块"
  **互相印证**。**两个独立路径得到一致结论，比单路径的低残差可信得多。**

### §5.52 ★★ 依赖链（关键路径）在这个微核上是**最差**的预测量

- 按 STA 第三步实现 def-use 依赖链（权重取 Cortex-M7 **文档**延迟）：

  | 量 | Spearman(·, 实测) |
  |---|---|
  | **依赖链（关键路径）** | **+0.180** ← 最差 |
  | 串行和 | +0.586 |
  | 入口块条数 | **+0.641** ← 最好单项 |

- ⇒ **本内核是「吞吐受限」，不是「延迟受限」**：关键路径最差正说明
  **不是"等最长依赖"在决定时间**。这些原语体是直线代码，M7 双发射 + 转发让独立指令重叠
  ⇒ **总工作量**比**最长依赖**更能解释时间。
- ★★ **重要边界：照搬 FPGA 要抄"结构可算"的精神，不是"关键路径"这个具体量** ——
  FPGA 的组合逻辑是**真串行**（信号必须沿路径传播），而超标量 CPU 的直线代码**可以重叠**。
  ⇒ 类比必须在"哪一层原理相同"上说清，否则会把一个不适用的量当目标。

### §5.53 ★★ 相关系数越界不报错 ⇒ `Spearman` 必须自带区间断言与**平局秩**

- **实测**：`Spearman = -8.576 / -11.439` —— **超出 [-1, 1] 是数学上不可能的**，而程序不报错。
- **根因**：秩写成 `rx = {v: i for i, v in enumerate(sorted(xs))}` ——
  **平局（相同数值）会让多个样本映到同一个秩下标**，秩和不再守恒 ⇒ ρ 跑到区间外。
- **正解**：**平均秩**（average rank），即 Pearson-on-ranks；并**断言 ρ ∈ [-1, 1]**。
- ★ 加断言后重算，之前那个 `0.639` 变成 `0.641` ⇒ **结论没变，但两个数现在都可信了**。
- ★ 同族：**能算出数、但数没有意义**。与"环比 -199.4%"（§10.9）同类。
  ⇒ 纪律：**凡是相关系数，先加区间断言；凡是比值，先写单位**（§5.34）。

### §5.54 ★★ **缩放不变性不是稳健性** —— 秩统计量对正缩放天然免疫

- 步 C 的 J4 判据写的是"把全部占用同乘/同除 1.5 倍，看 Spearman 是否保持"。实测：
  `+0.583 → +0.583`（完全不变）⇒ 判据**通过**。
- **但这是数学必然, 不是证据**：Spearman 只看**秩**, 而正缩放**不改变秩**。
  ⇒ 把这个当"模型稳健"会**系统性高估**结论强度。
- **真正该做的稳健性检验**：**换一个独立的构建/程序**, 看同一套文档表是否仍给出同样的排序。
- ★ 同族：§5.49（"预测值没有区分度"却被判据读成"效果好"）——
  **都是判据的数学性质被误读成物理结论。**

### §5.55 ★★★ 结构模型现状：**"能排序"有证据, "能算绝对值"还没有**

- **能排序**（有证据）：`Spearman(入口块条数, 实测) = 0.641`；
  仿射形式 `cost ≈ 67.7 + 1.16n` 的 **LOO 中位残差 8.0 cyc**（§5.51）。
- **不能算绝对值**（步 C 失败）：把拟合系数换成 **Cortex-M7 文档占用**后
  `Spearman` 掉到 **0.583**，且 **19/19 全部低估**。
- ★★ **缺口被定位得很干净**（这是失败里最有价值的产出）：
  · `c0_结构`（共享尾块 27 条按文档表累加）= **34 cyc**
  · A″ 从实测拟合的截距 = **67.7 cyc**
  ⇒ **缺的是一块 ~34 cyc 的"每路由固定开销", 它不在我量的那个尾块里**
    （尾块只解释了固定开销的**一半**）。
  ⇒ 下一步应去**找这块开销**（候选: 分派块本身、`read_source` 的分支、
    每路由的 `src`/`wb` 有限性检查），**而不是继续调占用表**。
- ★ 另一个反直觉发现：**文档占用权重不如"裸条数"**（0.583 < 0.641）。
  因为文档表把多数类记为 1、除法记 14 ⇒ PID 的相对位次被**推得过高**。
  ⇒ **"更细的模型"不一定更好** —— 细分必须有对应的信息量支撑。

### §5.56 ★★★ 缺失的固定开销：逐块补齐的过程，与"偏保守估计"必须与"模型正确"分开记

- 步 C 的缺口: `c0_结构 34`（只算共享尾块）vs 实测截距 67.7。逐块补:

  | 口径 | 固定开销 | 结构下限 | 与实测下限 56 之差 | 残余中位 | **结构 ≥ 实测** |
  |---|---|---|---|---|---|
  | 只尾块 | 34 | 34 | **−22** | +29 | **0/19** |
  | 尾块 + 分派块(8) | 42 | 42 | −14 | +21 | 0/19 |
  | 尾块 + 分派 + 每路由前导(56) | 98 | 98 | **+42** | −35 | **19/19** |

- ★★ **分派块必须按"每路由"计价**: 它在步 A 里被归为**循环携带**（每圈一次）——
  但**一圈只处理一条路由**, 所以"每圈一次"**就是"每路由一次"**。
  归类在"逐 op 结构量"上没错（它不区分 op）, 在"逐路由固定开销"上**漏了**。
- ★★ **第三步的结果必须分开说，否则会被读成"成功"**:
  · ✅ 拿到**成立的方向性界**: **19/19 满足 `结构 ≥ 实测`**, **没有反例**
  · ❌ 但**不紧**: 98 vs 56, **过估 ~75%**
  · ⚠️ 而且那句"每路由前导 = 56 cyc"**本身可疑**: 地址区间 `0x0D3C..0x0DE6`(47 条) 里
    含**"路由非 ACTIVE ⇒ 跳过"那条分支的腿**, 它**不是每路由都执行**
  ⇒ 所以 98 这个数**同时含"漏算"与"多算"**, 它"碰巧"给出 19/19,
    **不能当作模型正确的证据**。
- ⇒ 纪律: **"偏保守的估计"与"模型正确"是两件事, 必须分开记**;
  一个"碰巧全过"的界, 若其构成里同时有已知的漏算与多算, 它**只是运气**, 不是验证。
- ★ 剩余缺口的方向（点名）: 前导里"每路由只走一条腿"的分支
  （ACTIVE 判定 / period 三档分派 / `read_source` 按 src_type 分派）
  ⇒ 结构侧必须按**路径**计价而不是按区间求和 —— 这正是 STA-17 线性走地址失败的同一原因。

### §5.57 ★★ "紧"与"零实测输入"目前只能二选一（现状声明）

- **拟合形式准**: `cost ≈ 67.7 + 1.16n`, **LOO 中位残差 8.0 cyc** —— 但系数**来自实测**。
- **文档形式零实测但松**: 按 ARM 文档占用计价 ⇒ **结构 ≥ 实测 19/19 成立**, 但**过估 ~75%**。
- ⇒ **把"紧"与"零实测输入"同时做到, 是明确且唯一的下一步。**
- ★ 汇报时必须**同时给出这两个数**, 只报一个会让人以为已经做成了。

### §5.58 ★★★ 显式区间计价：**区间重叠不会让任何下游判据报警**（因为它只会让界更松）

- 步 C1b 把"每路由固定开销"拆成显式地址区间。第一版把 `common` 写成 `0x0D8A..0x0E5C`,
  **把 `dispatch` 包了进去**; `tail` 又与 `skip_leg` 相叠 ⇒ **同一段代码被计两次**。
- ★★ **危险之处**: 这个错误**不会让任何结果判据变红** ——
  重复计价只会让固定开销**变大**, 而"界更松"永远是**安全**方向
  ⇒ **没有任何下游判据会报警**。它必须由**结构断言**来抓:
  ```python
  for i in range(len(spans)-1):
      if spans[i][1] > spans[i+1][0]:   # 区间重叠 ⇒ 报出来
  ```
- ⇒ 纪律: **凡是把一段代码按区间/类别切开计价, 必须加"两两不相交"的机器断言。**
  这是 §5.23「分子分母同口径」在"覆盖划分"上的形态。

### §5.59 ★★ 现状对齐（2026-09-18 步 C1b 收口）——**界成立但不紧**

| 口径 | 固定开销 | 结构下限 | 与实测下限 56 之差 | **结构 ≥ 实测** | 过估比 |
|---|---|---|---|---|---|
| 只尾块+分派 | 34 | 34 | −22 | **0/19** | —（欠估）|
| + 活跃前导 | 91 | 91 | +35 | **19/19** | 1.62× |
| **+ 不相交区间（最全）** | **112** | 112 | +56 | **19/19** | **2.00×** |

- ✅ **成立**: 文档侧（零实测输入）能给出**无反例**的保守上界 **19/19**。
- ❌ **不紧**: 过估 **2.0×**（判据要求固定开销落在 56~80, 实测 112 ⇒ 未通过）。
- ⚠️ 另有一处**已知的不相交问题尚未修**: `tail`(0x0E5C..0x0E9C) 与
  `skip_leg`(0x0E98..0x0E9C) 仍相叠 —— 机器断言已把它报出来, 留着是因为
  "跳过腿"究竟算不算每路由开销**本身还没定性**（桶化后稳态不出现, 但可能出现）。
- ⇒ **汇报用语**: 只能说"**拿到了成立的界**", 不可以说"执行时间已经能算出来"。

### §5.60 ★★★ "分组拟合"会把一条曲线切成几段, 再把局部斜率当成物理常数

- **实测（E-A, 2026-09-18）**：我先前按 division 分成三组各自拟合, 得到三个斜率
  （53 / 61 / 88 TB per 条）并据此断言"**div0 的每路由成本只有 div1 的一半（2.1 倍差）**"。
- **真相**：三个 division 的 `nrun` **取值范围完全不同**（0.16~1.28 / 1.6~12.8 / 16~128）
  ⇒ 每组只覆盖曲线的一小段, 各自的**局部斜率**被误读成"division 改变了每路由成本"。
- **用单一 `(C_base, m)` 拟合 PID 全部 12 个点**：
  `cost ≈ 583.4 + 61.13 × nrun`，**最大偏差 33.5 TB = 67 cyc**
  （对 8402 TB 是 **0.4%**）—— 包括那个曾"差 2.1 倍"的 div0 n=128（偏差 **−6.1 TB**）。
- ⇒ **纪律：要比较"不同组的斜率", 必须先确认各组的自变量范围重叠；
  否则先铺满全域再拟一条线。**
  ★ 这是"分组掩盖了自变量范围"的经典错误, 而它**只在汇总时报错, 单组内看不出来**。

### §5.61 ★★ 桶数不花钱（假设被两个独立实验否证）

- **假设**：`cost = C_base + C_bucket × buckets_per_tick + C_route × nrun`
- **E-A（拟合）**：`C_bucket = −0.05 TB ≈ 0`
- **E-B（独立对照, 更强）**：把 `nrun` **钉在 1.0**, 只让每拍桶数变：

  | op | 1 桶/拍 | 10 桶/拍 | 100 桶/拍 | 极差 |
  |---|---|---|---|---|
  | DIRECT | 596.4 | 602.1 | 600.6 | **5.7 TB (11 cyc)** |
  | PID | 653.4 | 660.0 | 655.9 | **6.6 TB (13 cyc)** |

  ⇒ 每拍桶数 ×100, 成本只变 ~6 TB ⇒ **每桶 ≈ 0.06 TB (0.12 cyc)**
- ⇒ **销案。`nrun` 是唯一驱动量。**
- ★ **旁证**：E-B 里 `PID − DIRECT = 57 TB`, 与 E-A 的"每 op 截距差 18.7 TB"方向一致
  ⇒ **两个独立实验互相印证, 比单个拟合可信得多。**
- ★ 同时纠一个口径错误: `bpt = min(n, nbuckets)` **错**。
  桶表按 `t % M` **分相**执行, 每拍只命中**一相**:
  `div0 ⇒ 1`, `div1 ⇒ min(n,10)`, `div2 ⇒ min(n,100)`。
  **表的规模 ≠ 每拍执行数。**

### §5.62 ★★★ 逐原语边际成本 `m_op` 实测（19 个原语全表）—— 结构量仍解释不了

- `m_op = (cost(n=128) − cost(n=32)) / 96`（div0, TB tick）:
  `DIRECT 29.5 · SCALE/RATE/NOT 35.0 · OR 35.5 · MUX 36.5 · ARITH 37.0 · CMP 37.5 ·
   CLAMP 38.5 · HYST/AND 39.0 · SR 39.1 · CNT 41.0 · DEADBAND 42.0 ·
   EDGE/TIMER 45.0 · LUT 46.0 · LPF 49.5 · **PID 64.0**`
- 判据: C-1 区分度 **2.17×** ✅ ·
  C-2 `Spearman(m_op, 入口块指令数) = +0.734` ❌（目标 >0.8）·
  C-3 `Spearman(m_op, 文档占用和) = +0.644` ❌ ·
  C-4 文档占用**不如**裸指令数 ⇒ **文档表在原语层也没带来信息** ·
  C-5 `DIRECT` 最便宜（29.51）✅
- ★ **三行反例直接说明结构量为何不够**:
  `AND` 入口块 **5 条** → 78 cyc/条 ; `HYST` **12 条** → 78 cyc/条 ;
  `LUT` **9 条** → **92 cyc/条**（比 8 条的 CMP(75) 和 19 条的 TIMER(90) 都贵）。
  ⇒ **指令条数与实测边际成本的排序对不上** ⇒ 再次指向"吞吐受限, 有效工作 ≠ 指令条数"。
- ⇒ **可用公式（本轮最实用产出）**:
  `cost ≈ C_base + c0_op + m_op × nrun`
  —— `C_base ≈ 565~583 TB`（单一常数, 与桶数无关）, `c0_op`/`m_op` 是**19 个原语的常数表**。
  **38 个数, 一次标定, 所有程序通用。**

### §5.63 ★★ `mk()` 的第三类同类缺陷: 缺 `ROUTE_FLAG_WIRE2` 导致 5 个原语测不到

- **实测**：E-C 第一轮 19 个原语里 **5 个取数失败**（CNT/ARITH/AND/OR/SR）。
  日志显示 deploy 被 NAK：`this op needs wire2 source (set ROUTE_FLAG_WIRE2 or wire2_idx!=0)`。
- 根因在**上位机**：`tools/h723_tick_ring.py` 的 `mk()` 没给路由带第二输入。
  ★ 这是**同一族的第三次**：
  ① `mk()` 在 `n>255` 崩在 `struct.pack` · ② payload 字段错位（`div` 落进保留字节）
  · ③ 缺 `ROUTE_FLAG_WIRE2`。
  **三次的症状都是"板子没反应/工具报错", 而根因全在上位机。**
- ⇒ 纪律：**"板子不响应"先查上位机构造的帧**, 再查板子。
  本项目的既有教训（"把上位机的失败误归因到板子"）已经犯了三次。

### §5.64 ★★★ 从某次构建量出来的**绝对地址**一律动态求（同一个下午失效两次）

| # | 硬编码的东西 | 失效原因 | 症状 |
|---|---|---|---|
| 1 | `SHM_SEEN = 0x20004E80` | 加 E-D 的 SCAN 域 ⇒ `g_shm` +32 字节（→`0x20004EA0`）| 报 **"板子不健康"** —— 而板子完全正常（samples 在涨/run=1）|
| 2 | `TBL = 0x0DF4`（分派表）| 重编译 ⇒ `engine_scan_itcm` **平移 +0x50**（`0x0CF0→0x0D40`）| 判据在**空集**上跑（`rows` 全空）—— 不报错, 只是"没结果" |

★ **两次都发生在同一天**, 且两次的失效都**伪装成别的问题**
（一次像"板子坏了", 一次像"分析无输出"）。

- **正解**：
  · SHM 地址 —— **问 `0x38` 要**（那正是它的用途）
  · 分派表地址 —— **扫 `tbh` 动态求**；表长按**下一个基本块起址**截断（§5.48 的 T3）
  · fall-through 目标（`bhi` 的目标）—— **也动态求**, 不写 `0x0E56`
- ★ 结构性认识: 这类工具把"**分析某一次构建**"得到的绝对地址,
  当成了"**分析这个程序**"的常量。
  ⇒ 凡"从 ELF/map 里量出来"的数, 都要问一句：**换个构建它还会对吗？**

### §5.65 ★★ 「空」被读成「值」—— 本轮第三次

- E-F 里 `CMP` / `ARITH` 的结构量算出来是 **0 条指令**。
  输出的表**照样打印这一行**, 比值算成 `0.00` 或 `29.51`。
  ⇒ **0 条指令的 op 不可能存在** —— 那个 `0` 的含义是"**算不出来**", 不是"测量为 0"。
- 根因: 这两个 op 的入口块以**无条件跳转**结尾, 而闭包逻辑把"跳走"当终止
  ⇒ 主口径与回退口径**都拿不到东西**。
- ★ 同族三次: §5.49（预测值没有区分度 ⇒ 残差只剩常数项, 看着很准）
  · §5.55（"能排序"被读成"能算绝对值"）· **本条（"算不出"被读成"值为 0"）**
- ⇒ 纪律: **凡输出里出现 0/空/常数, 先问"这是测出来的还是没测到"**;
  表里出现不可能的取值（0 条指令的 op、常数预测器）时, **判据必须报"无效"而不是继续算**。

### §5.66 ★★ 两把尺子混在一个统计量里 ⇒ 测的是尺子, 不是物理

- E-F 中 **11/19 行**用了"回退口径"（含跳转目标的闭包, 系统性更大）,
  **8/19 行**用了"主口径"（直落闭包, 更小）。
- 两组混在一个 Spearman 里 ⇒ 相关系数从 STA-12 的 **0.734** 掉到 **0.429**。
  ★ **不是模型变差了, 是这一版的度量更脏。**
- ⇒ 纪律: **换口径必须整列换**; 若必须混用, 则**分层报**, 不许合成一个相关系数。
- ★ 但也要守住一条: 即使度量脏, **"比值跨 20×"这个结论仍成立** ——
  因为若真存在恒定比值, 脏度量**不会把它打散成 20×**。
  ⇒ **"脏数据能排除什么"与"脏数据能支持什么"是两件事**, 要分开写。

### §5.67 ★★ "能不能算"取决于**怎么定义"算"**（现状声明, 防止过度宣称）

- 若要求"**零实测输入**" ⇒ **还没有**: E-F 排除了最直接的一条路
  （指令级吞吐下界 `max(指令/2, 访存, 浮点)` 与 `m_op` 的比值跨 **20×**）。
- 若接受"**19+2 个与程序无关的常数, 一次标定**" ⇒ **已经有了**:
  E-C 已证明 `m_op` 是**原语的属性**（与程序无关）
  ⇒ 程序装载时, **预算 = 桶表（算出来的）+ 常数表（一次标定）**。
- ★ 而这恰好满足原始需求: **"程序一装载, 预算就是算出来的, 不是人填的"。**
- ⇒ 汇报时必须**写明用的是哪个定义**, 否则"能算/不能算"会各说各话。
- ⬜ 仍值得做的一条（未做）: **沿子跳转表展开每个 op 的完整代码**,
  以得到干净区间后重做 E-F（`CMP`/`ARITH` 目前算不出来, 见 §5.65）。
