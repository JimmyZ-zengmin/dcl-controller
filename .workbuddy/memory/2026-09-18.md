# 2026-09-18（再续）—— 缩段长重跑：**仍判 SKIP，但阻断点被精确定位**（不是硬件不够，是解码器不够 + 环语义未定案）

## 做法
1. **压缩周期到环保留跨度以内**：三角波段长 600→**100 ms**（周期 0.2 s）、
   正弦段长 250→**35 ms**（周期 0.21 s）；斜率随之 = A/段长 = 12000 Hz/s。
2. **消除第二个真值源**：两支工具（`h723_traj_bb_verify.py` / `h723_traj_verify.py`）
   的段长改为 **`read_dwell()` 从 `.dcl` 里读**（原来各写一份常量 —— 改了 .dcl 就会静默算出错的周期/覆盖度）。
3. 采集时补上 **`sub=22 arg=1` + `sub=20 arg=10`**（把编码器回填提到 ~1 kHz）。

## 一路上抓到的三个错（全部是我这边的）
1. ★★★ **解码器：按 `seq` 排序是错的** —— `seq` **会在环内回绕**（实测 36480…38399 然后 0…1919）
   ⇒ 按 seq 切段会**切出假的不连续段** ⇒ 只取到 128 条（覆盖度 0.33）⇒ **误判 SKIP**。
   看起来像"环太小"，其实是**解码器不够**。
2. ★★ **记录率的归因**：离线统计每个通道的变化次数 ⇒ 是 **4 个通道交错**（SENSOR[0] 编码器 + 
   **SENSOR[8]/[9]/[10] 三个模拟输入**）⇒ 记录率 ~2.5 kHz、**编码器回填其实 ~600 Hz**。
   ⇒ **我上一轮说的"编码器回填只有 90 Hz"是错的** —— 那个数字来自"4 倍交错的 Δraw ÷ 1 个间隔的 Δt"，
     又一次**分子/分母口径不一致**（已由滑窗修正）。
3. ★ **我自己的判据 bug**：L3 阈值要 Δt>90 ms 而窗口只有 51 ms ⇒ 体量恒 0（**假 FAIL**）⇒ 改成"体量<5 判无效"。

## ⛔ 阻断点（精确定位）
同一份 dump **三种排序给出三个互相矛盾的跨度**：
- 按 `seq` 取最新连续段 → **128 条**
- 按 `slot` → **960 条**（slot 不连续处仅 2）
- 按 `tick` → **跨 20.035 s**（而"陈旧残余"计数为 0）

⇒ **环的"写指针/水位"语义未定案**。按本项目纪律（**别把结论建在没解释的机制上**），
`h723_traj_bb_verify.py` 已加**一致性闸门**：检出这种矛盾就**拒绝给结论**（退出码 **2** = 判无效）。
⇒ 下一步应读 **SD 日志头里的环元数据**，或**从固件侧确认写指针语义** —— **不再在 PC 侧猜**。

## 仍然成立（这部分证据可靠）
- 命令侧 `WIRE[12]` **峰值 = A = 1200**（在 51/67 ms 的窗口里）
- 该窗口内**累积速率 ≈1067 Hz = 0.89A**（与"斜坡仍在爬升"一致）⇒ **命令通路通、轴在按命令转**

  **若把映射表缩到只留需要的几路（①层），环保留跨度可从 ~0.4 s 升到 ~1.6 s** ⇒ 1.2 s 周期也能验
