## 一、架构使用规约（强制）

```
① 引擎核心  烧录   改它 = 换固件(必走 A/B + 12 套回归)     ② 外设能力  随核心版本化 + 能力位
③ DCL 程序  通信上传 + 持久化(SD)                          ④ 程序工程  上位机侧: .dcl 源 + 清单 + 产物
```
**判层表**：怎么算 ⇒ ③ 程序 ｜ 和外设怎么说话 ⇒ ② 外设能力（**不是**新驱动）｜
需要新的每拍行为/实时保证 ⇒ ① 核心 ｜ 只是给上位机看的量 ⇒ SHM + `obs_anchor()`（**不是**加协议 op）

**实验八条**（细节 §1）：① 观测先走协议内通道（`0x38`/`0x22`/SHM），pyocd 是最后手段；
② 控制先走程序面（`0x10 DEPLOY`+`0x11 START`）；③ **要新能力先判层，不要默认改固件**；
④ **每拍动作 → ISR/引擎，服务性动作 → 主循环**（主循环 0.37 ms，拍 100 µs）；
⑤ 实验代码独立成 patch；⑥ 运行期改动**复位即恢复**；⑦ 每条判据都要能失败；
⑧ **新增 SHM 域登记到 `cold_start_reset()`**。
★ **GAP-6 判层推论**：外设"多步操作"不能靠主循环跑阻塞事务 ⇒ 照 `adc_poll` 做**拍内每拍推进一步的状态机**。
★ **适用边界由测量决定**：AS5600 留主循环没问题（≈450 µs、`loop_gap_max_undecl=0`）⇒ 判据是
`WDT_STAT.loop_gap_max_undecl` + ISR 超预算次数（契约 §3.6/§3.6.1）。

**三条红线**：① 程序里不得出现任何物理引脚号/总线地址（`dcl_static_check.py` 编译期拒）；
② **不得破坏单写者**（已两次踩到：`TIM3` 两个驱动者、**SD 卡两个写者**）；③ 不得把实时量挂主循环。

## 二、时基与仪器（要点；细节 §2）

- ★★★ **别拿调试单元当生产时基**：pyocd 会话断开时写 `DEMCR.TRCENA=0`（issue #1540，J-Link 同款）
  ⇒ DWT 静默死，只有**断电重上电**能救。✅ 已落地：**交付档时基 = TIM5**（32 位/200 MHz ⇒ 5 ns）。
- ★ **单位随档变**：拍 = **20000**（非 40000）、ISR 最长 ≈ **818**（`h723_jitter` 已改读 `op=21`）。
- 健康度 `0x39 op=21`：`[0]档(1=TIM5) [1]频率 [2]自检Δ(=0 即死) [4]dwt_dead [6/7]pmin/pmax`。
  ★ `g_per_cyc_*` 跨复位不丢 ⇒ **活性判据 = `0x13 RESET`→`0x11 START`→等 ~1 s→`pmin` 非 0**。
- 只读观测用 **`connect_mode=halt`**；★ **读固件全局量前绝不能 `-c reset`**；**收尾必须 `-c go`**。
- ★ 工具链：**`pyocd reset` 不放收尾** —— 构建 → flash → **让板子自己重启** → 之后全程只走协议。
- **逻辑分析仪**：网格 16 MS/s ⇒ 62.5 ns、24 MS/s ⇒ 41.67 ns，**用时间戳整除性反推采样率**；
  `ReadTimeout` 时数据往往已到，但要查完整性（37.7/61.1 µs 异常短间隔 = USB 丢数据）。
- **判据禁忌**：① 空判据（恒 0/1）；② **形状判据 > 幅度判据**；③ 先判掉量化伪影；
  ④ 同一性对照（A/B 先 sha + 同采样率）；⑤ **反向判据**；⑥ 口径与被测量同量纲；
  ⑦ 覆盖不到/前置没满足判 **SKIP 或中止**；⑧ 跨时刻/跨通道"等值"必须给物理噪声底容差（AS5600 1 LSB = 0.0879°）。

## 三、黑匣子（取证主力；细节 §3）

- 环 `0x24004000` 起，**960 槽 × 256 B = 240 KB**；槽 = `[4 字头][60 数据]`。
- ★★★ **头字段 `[0]magic "DLBK" [1]tick [2]seq [3]ctrl`** —— 读反过（时间跨度错 **3.96×**，报出"4651 rpm"）。
- ★★★ **环是"变化才记"** ⇒ **物理跨度随变化率变**（实测 **380 ms**；轴不动时记录率掉到 173~571/s、跨度拉到 452~473 ms）。
  ★ `blackbox.h:71` 的 "960 槽 = 96 ms" 只是"逐拍全量"算法 ⇒ **跨度必须 `(tick[last]-tick[first])/10000` 秒**。
- 取值：**pyocd API 单会话**（halt）读满 240 KB ≈ 1.4 s；commander 单次只 ~60 KB。
  ★ **运动中途 halt** 才拿得到稳态段（TIM3 硬件照发脉冲）。
- ★ 量纲自检：`data[0]=SENSOR[0]`(raw) / `data[1]`=角度 ⇒ `|deg − raw×360/4096| ≤ 0.001°`。

## 四、程序持久化 + 内存地图（要点；细节 §4）

`.dcl` → 编译 → `0x45/46/47` 上传 → SD A/B 双副本 → 上电自动装载（不碰 flash）。
`0x48` 96B：+52/56/60 = `txn_begin/commit/abort`；+64..76 = 开机装载结果；+80..92 = 卡上载荷头。
★★ **五道闸门**：帧 CRC16 / 清单 CRC32+total_len / 写后回读 memcmp / A/B+单调 seq /
**装载时再跑同一套静态校验**（`prog_validate`，上传与装载**共用实现**）。★ 发布前必做**"运行态 vs 持久态"对账**。
★ AXI **320 KB 已用满**（唯一空档 ≈10.5 KB @`0x24000600`）；SD 分区**真值源 `docs/STATUS-2026-09-16.md` §2/§3**；

## 五、引擎/配置/③层 规则索引（§5.1–§5.27，**细节在 `RULES-DETAIL.md`**）

- **§5.1** 一个绑定跨两个寄存器（`DMAMUX1_Cn` + `TIMx_DIER`）⇒ 必须同一函数改，否则**静默失效**。
- **§5.2** MDMA 通道寄存器只在 `CCR.EN=0` 时可写；清 `EN` 后不能只靠写 `CCR` 重新使能。
- **§5.3** ★★★ **输出锁存链实测**：只有 `MDMA_CH0_CCR.EN=0` 会停 ⇒ MDMA 在**自循环**、
  **引脚时刻 = CPU 最后一次写影子 + 0.12 µs** ⇒ **"硬件锚定引脚时刻"未达成**，让路/关黑匣子**注定无效**。
- **§5.4** ★★ **ITCM 64/64 KB 100% 满** ⇒ 加 `DCL_ITCM` **不是免费动作**；"ISR 可达却在 flash"**优先改结构**。
- **§5.5** 门/守卫必须住**资源定义处**；**门必须带引用计数**。
- **§5.6** ★★ 同一表达式在两个调用点**语义可以不同**（`owner != SM`）⇒ 写"**有人占且不是我**"。
  ★ 抓到它的是**专为可解释性加的 `skip_n`** ⇒ **加计数器划算**。
- **§5.7** ★★★ **"谁的结果"必须被显式携带**（发起记号 + 完成广播号；不等 ⇒ 丢弃重发）。
- **§5.8** ★★ 两个码空间数值重叠 ⇒ 不能共用一槽；**一个计数只能回答一个问题**（解释它时要用"或者"就必须拆）。
- **§5.9** ★★★ **"完成态"与"实时态"必须分开**（完成记录 `{req,status,len}` 快照；受理新请求即失效）。
- **§5.10** ★★★ **不要为准备拒绝的请求去占用资源** ⇒ **先验参、再拿门**。
- **§5.11** ★★ **用原始位定性**（假报警 `6.5e-21` = 串帧 `0x1DF70200`）；`0x22` 读 1 字的应答也是 4 B ⇒
  加固：读 2 个字 + 连续两次同值 + 打印原始 u32。
- **§5.12** ★★★ **"还欠着什么"必须配对计数，不能用 bool**（延迟释放曾是 bool ⇒ 每次泄漏 1 引用）。
  ★★ 一处修复消掉三个看似无关的症状。
- **§5.13** ★★★ **内部路径不得扰动对外协议的握手状态** ⇒ **共用校验可以、共用握手/计数器不行**。
  ★ 同族：`0x48` 应答**只能追加** ⇒ **对既有应答长度的"等值"判据都是陷阱**（认口用**必备位掩码** `(cap&0x0DF7)==0x0DF7`）。
- **§5.14** ★★★ **流式解析器必须有超时**（`FRAME_ASSY_TIMEOUT_TICKS=500` + `RX_RING_SZ 512→4096`）。
  ★ **判"有没有新字节"要看"本轮真的消费了字节"**，不能看索引变没变。
- **§5.15** ★★★ **一个默认极性可以同时弄反"使能/失能/安全态"** ⇒ **`PE9=1` 才是使能**；
  **判据必须看引脚实读**。★★ 工具自身读超时也要按实测标定（往返 **p99 56.8 / max 63.6 ms**）。
- **§5.16** ★★★ **脉冲频率的周期被量化到 1 µs**：`rate_actual = 1e6/floor(1e6/f)`（7/7 命中；
  24000⇒24390 +1.62%、60000⇒62500 +4.17%）⇒ **定量结论必须引 `rate_actual`，不要用请求值**。
- **§5.17** ★★★ **`dclc` 自动分配必须跳过"固件保留的 WIRE 槽"**（保留集**从 `step.h` 自动读**；
  显式钉到保留槽**报错**）。★ "一律禁用 ≥64"是**过度保守**（`SEL` 吃 4 槽、`CONST` 占 1 槽）。
- **§5.18** ★★ **③层 DCL 三条口径**：`THR=` 只认数字字面量；`BY=`/`FROM` 只认已声明名；`CONST` 不认科学计数法。
  ★ 自证纪律：先 `dclc --dump` 只编译，比"传上去再试"快一个量级。
- **§5.19** ★★★ **"指令 vs 引脚实读"的失配必须归因**（`op=19 sub=24`：`mismatch_n ≡ hi_n + lo_n` + 快照）。
  ★★★ 判据要点：**注入后必须"改变意图"**才逼得出来（否则对照档**假绿**）。
- **§5.20** ★★★ **"判据的速率"必须与被测量的速率匹配；降档不是万能解**：
  编码器每 10 拍回填 ⇒ 每拍判据会看到 1:10 占空比 ⇒ `TON` **永远凑不满**；
  降 `PERIOD` 会被固件跨档检查拒（`main.c:1838`，且**一路传染到 `OUTPUT`**）⇒ **正解 = `LPF`**。
- **§5.21** ★★★ **③层程序"跑起来"还有两道非编译期的门**：`SRC_HMI` **H723 未实现**（deploy 拒）；
  `OUTPUT` **不接受 `PERIOD=`**。⇒ `--dump` 只过编译期，**"编译通过" ≠ "能部署"**。
- **§5.22** ★★ **主机→程序的输入槽必须"被当作输入引用"**（登记 + **预扫**），否则被内部信号抢槽。
- **§5.23** ★★★ **"期望为 0/小"的判据必然是假绿 ⇒ 必须先配"正对照"**；
  **差分量的分子分母必须同口径**（正对照当场抓出 3.2× 的测速器 bug）。
- **§5.24** ★★ **`SEQ` 步号 1 起**（`engine.c:474`：`out_wire = step_cur + 1`）⇒ 门限按 0.5 写会**恒真**。
- **§5.25** ★★ **引擎有 `LUT`（`prim_lut` 带线性插值）而 `dclc` 未暴露** ⇒ ③层写不出查表（**待补**）。
- **§5.26** ★★ **"能做"与"能验收"是两件事**（多轴：资源够，但三个真阻塞）。
- **§5.27** ★★★ **PC 侧差分测速在本装置上不可用**（编码器回填率与 PC 轮询率**拍频**）：
  实测 `Δt` 稳定 37 ms、而 `Δraw` 中位 **2**（1200 Hz 应有 123）⇒ **极值/分位数全不可信**；
  **只有 `ΣΔraw / 总时长` 免疫**；**形状类判据一律走片内黑匣子（1 kHz）**。
- **§5.28** ★★★ **黑匣子的「记录率」≠ 被测量的「更新率」**（2026-09-18 实测）
  环是**变化才记** ⇒ 记录率由「任一映射通道变化」决定（运动时实测 **~2.5 kHz**），
  而**编码器回填只有 ~90 Hz**（≈11 ms/次）⇒ 逐记录的 `Δraw/Δtick` 是 **0 或 ~34 counts**
  ⇒ 算出 **32812 Hz** 这种荒谬值（真值 ~1200）。**换到黑匣子后，逐记录差分**仍然**不可用**。
  ⇒ 速度口径必须用**滑窗累积**（窗宽 ≥ 被测量更新间隔）：实测 20 ms 仍偏 **1.6×**，
    而 51 ms 窗口只剩 1 个点 ⇒ **唯一站得住的是 `ΣΔraw/总时长`**（与 §5.27 同一条规矩，尺度不同）。
  ⇒ ★★ 推论（工具层）：环的**保留跨度 = 960 槽 ÷ 变化率**（运动时 ~2.5 kHz ⇒ 只留 **~0.4 s**）
    ⇒ **1.2 s 周期的形状验收做不了**；三条出路：缩短段长(≤50 ms) / 扩环(①层) / 只留一路映射(①层)。
  ★ 环槽位规则**已查证**：`slot = seq % 960`（`(seq-slot)%960` 对 960 槽全为 0）；
    而 dump 里**可能有多段不连续的 seq**（陈旧残余）⇒ 解码**必须取「最新连续段」**，
    不能全局按 seq 排序（那会把不同年代混在一起，算出「跨度 19.7 s / 间隔 20.6 ms」的跨代假数）。

## 六、装置属性与"会响的失败"索引（§10.1–§10.9）

- **§10.1** ★★★ 装置属性（极性/行程/限位逻辑）**必须显式声明，未声明 fail-closed**（`CMakeLists` 三态 +
  `build.sh` DEFAULTS + 出现在"生效开关"清单里）。★ **极性未声明时"使能/失能"没有定义** ⇒ 只能用**物理**语言。
  ★★ **"安全态"分两问**：按器件（导通=失能？）与按轴（要不要保力矩）——正交，不要用一个量表达。
- **§10.2** 判物理状态看 `IDR`；**核对必须放主循环**并**连续 2 次**去瞬态。
- **§10.3** `pyocd reset` 后有 **~5~10 s 偶发停答自愈窗**；判"板子死没死"用 SWD 读 `g_tick_count` 两次。
- **§10.4** ★★ **裸 `serial.Serial` 不释放 DTR/RTS ⇒ 把板子按在复位上** ⇒ 一律 `open_serial()`。
- **§10.7** ★★★ 别在**传感器噪声底**上做等值比较（两处副本，`937 vs 936` = 恰 1 LSB）⇒ 给物理噪声底容差。
- **§10.8** ★★★ `stop_hold` 三条：① 与极性正交（`hold=1 ⇒ IDR=0x0F00` / `0 ⇒ 0x0D00`）；
  ② **"上电即通电"最容易被当成故障**（响+热+轴不动 = 同一物理态）；③ **改策略量必须立即作用**。
- **§10.9** 判"轴动不动"要按**实际 `dir`** 取符号（否则报 −199.4% 这种假数）。
- §10.5/§10.6 已并入 §9（回归前置闸门 / 判据发射器命名）。

## 七、③层"让程序驱动外设"索引（§11.1–§11.11）

- **§11.1** ★★★ ③层输出面**只有 `wire[]`**（写 `actuator[]` 直接编译失败）；★ **`WIRE` 是"热端"**；
  **服务方保留的槽，程序内必须只有一个写者**。
- **§11.2** ★★★ `dclc` 自动分配上限 64 ⇒ **固件保留的观测/镜像槽必须 >63**（实测被抢过 `wire[16]/[17]`）。
- **§11.3** ★★★ `0x20 READ`/`0x23 WRITE_BURST` 要**绝对地址** = `g_shm + 偏移`；`g_shm` 在 `0x38` 的 **+23**。
- **§11.4** ★★★ **"值相同 ⇒ 不做"是危险判定**；判"变化"比**请求值 vs 上次请求值**（不是 vs 硬件现状）。
- **§11.5** ★★ 驱动+电机有**最低有效频率**（15 Hz 下脉冲真在发而轴不动）⇒ P 控制压到下限会卡住。
  ★★ **上界同族**：突加 >16500 Hz 必失速。
- **§11.6** `sensor[0]` = raw(0..4095)、`sensor[1]` = 角度(0..360)；用错会给出"完全不可能的物理量"。
- **§11.7** `h_device_desc()` 是 ackbuf 闸门盲区（变量偏移）⇒ 缓冲大小只能靠人数。
- **§11.8** ★★★ **过闸门绝不用管道**（退出码是最后一条命令的）⇒ 先重定向到文件、再单独读 RC。
- **§11.9** ★★ **"位带别名"陷阱**：搬同一位 N 次 ≠ 搬 N 个位置 ⇒ **从第 1 次执行推一遍**。
- **§11.10** ★★★ **"走 N 步"正解 = 另一个定时器硬件数脉冲**（`TIM3_CR2.MMS=010` + `TIM4_SMCR SMS=111|TS=010`）；
  ★★★ **N=65535 = `ARR` 是刀锋**（回绕 ⇒ 漏判 ⇒ 多跑整圈）⇒ **N ≤ 60000**；到点由主循环停（超发实测 +9.3%）。
  ★ v2 硬件精确停：`TIM4` CC 事件 → 一次普通 DMA 把 0 写进 `TIM3_CCR1`。
- **§11.11** 判"计数器准不准"的容差口径是"**起止时刻对不齐**"，不是计数误差；**不是逐位相等**。

```bash
export PATH="/usr/bin:/bin:/mingw64/bin:/c/Windows/System32:$PATH"   # shell 初始化脚本坏了, 必须显式 export
bash build.sh                     # 六道闸门: 零警告 + ISR 调用树 + 应答缓冲区 + ③层静态 + 契据可机检

```
- ★ 串口**按能力字认**（两个 CH340，别取"第一个"）；号会变（COM21→COM22）⇒ 一律 `find_board()`；
  ★ 找到后**必须 `export DCL_PORT`**；★★ **串口独占**（并发会互相吃帧）。
- **`0x39 op=19 sub`**：`0`=快照(**96 B**：偏移 76/80/84/88/92 = `GPIOA_IDR`/`GPIOE_IDR`/`CCMR1`/`CCR1`/`ARR`；
  **+8 `ena`(逻辑位) 与 +80 `PE9`(实读) 必须分开看**) `1`rate `2`dir `3`ena `4`limit `5`enapol `6`stop+rest
  `11`设备态(32B) `12`stop_hold `13`运动源(只写) `14`运动态(32B，+0=src) `15`走N步 `16`脉冲计数态(32B)
  `17`斜坡斜率 `19`斜坡态(32B，**+12=rate_actual**) `20`AS5600周期 `21`通道态 `22`sm_mode `23`tick态 `24`失配归因(32B)
  ★ **加字段只能追加**；★ `sub=13 arg=1` = 程序面，`0` = 脚手架（**默认**）；★ 定位是**临时脚手架**，③层不得依赖。
- **协议**：`[SYNC 0xC0/0xC1][CMD][LEN:2][PAYLOAD][CRC16-CCITT]`；`FRAME_PAYLOAD_MAX=6150`；`0x38` → **51 B**。
- **能力字 `0x7DF7`**（`0x0DF7 → +DEVBIND 0x1000 → +PERSIST 0x2000 → +FRAME_V2 0x4000`）；
  **认口用必备位掩码**，**别等值**。★ **契据改了必须同步 `docs/claims.md`**（八类 A/B/C/N/C2/D/E/F；

  ★ 客户端**异常退出也要 `finally` 复位回 v1**。
- **`0x39 op=23 sub=0`** = 重新执行开机装载（与开机同一条路）。★ 新增这类口子**必须抽成唯一实现**。

## 九、回归与测量纪律（细节 §9）

1. ★★ **先回 bench 态**（`0x49 PROG_ERASE` + 复位；空卡上电 = `n_routes=128/run=1`）。

## 十、运动台架实测数字（阶段 0~3；细节 §13）

- **步/圈 1574.4**（`counts/step` 中位 **2.6017**，峰峰 0.91%，正反对称）；★ **仅当 N < 800（180°）有效**。
- **拍长 99.95 µs**（−0.05%，独立反解确认）；**脉冲率 = `1e6/floor(1e6/f)`**（1 µs 量化）。
- **失速边界**：突加（从静止）拐点 **16500~16750 Hz = 619~628 rpm**；**已在转动时突跳 31 kHz 正常**
  ⇒ 排除"固件拒发高频"；**失速不自愈**（持续通电流）；**斜坡上限 ≥50000 Hz**。
- **全频段跟随线性度 ≤0.5%**（1~60 kHz，28 点，非 1.000 部分全由 1 µs 量化解释）；
  ⚠️ 有一个 **−1.6% 固定比例因子，归属不可分**（AS5600 刻度 vs 驱动器微步刻度）⇒ **不许说"绝对跟随精度 ≤0.5%"**。
- **反馈率**：`sub=22 arg=1` + `sub=20 arg=10` ⇒ AS5600 **~1 kHz**；阻塞路径 ~163 Hz。
- **A/B 阶跃响应**：PC 在环 **2.115 s** vs 片内 **0.635 s** = **3.3×**（两侧 ±2.5%）。
- **失步自动检测（③层程序，上板通过）**：突加 18000 Hz ⇒ **1.17 s 触发**（遮蔽窗 900 ms + 去抖 200 ms）、
  `nfail=1`、`der=0.25`、**轴恢复 99.2%**。★ 这是目前**最强的对外主证据**（把现场"响+不转+发热"变成确定性行为）。
- ★ **阶跃/三角/阶梯正弦轨迹**：程序侧与固件侧都忠实（`wire[58]`=1200、`rate_actual`=1200），
  但**PC 侧差分测速失效**（§5.27）⇒ **形状验收待黑匣子**。
- ★★ **多轴**：固件侧资源够（TIM1/8/12~17 空闲、**PE10/PE11 是预留位**、TIM1/TIM8 **有 RCR**），
  **三个真阻塞**：① 第二个编码器（AS5600 **地址固定 0x36** ⇒ 需 I2C mux/第二总线）
  ② 第二个驱动器/电机（**台架没有**）③ **ITCM 已满**。
