## 一、★★★ 架构使用规约（强制，用户要求写入）

**一句话：用这个系统 = 写 DCL 程序，不是改固件。** 固件（引擎核心）是平台，烧录=换机器；DCL 程序是资产，走通信上传 + SD 持久化。

```
① 引擎核心  烧录     改它 = 换固件(必走 A/B + 12 套回归)
② 外设能力  随核心版本化 + 能力位；做成"通用事务 op"(I2C/SPI/UART) + 具名设备, 非"每芯片一条命令"
③ DCL 程序  通信上传 + 持久化(SD)
④ 程序工程  上位机侧: .dcl 源 + 清单 + 编译产物
```

| 问题 | 放哪层 |
|---|---|
| "**怎么算**"（逻辑/连续/顺序） | ③ 程序 |
| "**和外设怎么说话**" | ② 外设能力，**不是**新驱动 |
| 需要**新的每拍行为 / 实时保证** | ① 核心 |
| 只是"**给上位机看的量**" | SHM + `obs_anchor()`，**不是**加协议 op |

### 实验七条
1. **观测先走协议内通道**：`0x38` / `0x22 READ_BURST` / SHM；pyocd 是最后手段。
2. **控制先走程序面**：`0x10 DEPLOY` + `0x11 START`；不要直怼寄存器"模拟"。
3. **要新能力先判层**（上表）。**不要默认改固件** —— I2C 那次弯路就是这么走的。
4. **每拍动作 → 引擎/ISR；服务性动作 → 主循环。** ★★ 别把实时量挂主循环：主循环一圈实测 **0.37 ms**（2026-09-16 直接实测；原 1.28~1.54 ms 是**反推值**，作废），拍 100 µs。
   ★★ **推论（GAP-6 判层）**：外设"多步操作"**不能靠主循环跑阻塞事务**（无标价、无预算门，违公理④）⇒ **正解 = 照 `adc_poll` 做"拍内每拍推进一步的状态机"**（`CORE-ENGINE.md` §3.1）。四条硬约束：① 拍内推进 ② 标价+预算门 ③ **总线独占门** ④ **就绪门**（跨拍 ⇒ 程序面拿到"上次结果+就绪标志"）。
   ★★ **适用边界（读源码+实测后补，别过度套用）**：判"要不要拍内"看**两问** —— ① 在**控制回路**里吗？ ② 把主循环堵到**可测**程度吗？②的现成判据 = `WDT_STAT` 的 **`loop_gap_max_undecl`**（未声明停拍数）+ ISR 超预算次数。
   ★ 实测反例：**AS5600 留在主循环没问题**（10 ms 轮询 + 两次阻塞读 ≈450 µs；`loop_gap_max_undecl = 0 拍`、ISR 最长 2.11 µs、超预算 0）。⇒ **判据由测量决定，不由规则措辞决定。** 契约 §3.6 裁决、§3.6.1 边界。
5. **实验代码独立成 patch**：`docs/exp-<日期>-<主题>/`；交付物里不出现实验脚手架。
6. **运行期改动复位即恢复**；**不得污染持久化配置**。
7. **每条判据都要能失败**，配对照（A/B 构建或对照配置）证明它会红。
8. ★★ **新增 SHM 域必须登记到"单一冷启动入口"**（`cold_start_reset()`）。反例：`IX_MAGIC` 只在开机写一次 ⇒ 被 `0x13 RESET` 抹掉 ⇒ 整个 G6-3 事务区失联。

### 三条红线
1. **程序里不得出现任何物理引脚号或总线地址**（IEC 61131-3 / CODESYS / Zephyr 三边一致）。
2. **不得破坏单写者**：同一 SHM 槽、同一张卡只允许一个权威写者。★ 已两次踩到：`TIM3` 两个驱动者；**SD 卡两个写者**（日志从 LBA1 回卷 + `sd_dump_write` 写 LBA3000000 落在日志区内）。
3. **不得把实时量挂在主循环上。**

## 二、时基与仪器纪律

### 2.1 ★★★ pyocd 会静默杀死 DWT（根因是**设计行为**，无捷径）
- pyOCD 维护者在 issue #1540 明说：**会话 disconnect 时主动写 `DEMCR.TRCENA=0`**，且"只在 `pyocd reset` 之类做完整 connect/disconnect 时发生"。SEGGER KB 说明 J-Link **同款**（免得 WFI/WFE 省电时留时钟）⇒ **不是 pyocd 的 bug**。
- ⇒ `DWT_CYCCNT` 冻结在 0；**`pyocd reset` 救不回**，只有**断电重上电**能恢复。★ 实测否定：`-Oresume_on_disconnect=false`（pyocd 0.45.1）**照样弄死时基**。
- ★★★ **正解在固件**：**别拿调试单元当生产时基**。✅ **2026-09-16 已落地**（`src/timebase.{c,h}`，`DCL_TIMEBASE` A/B 开关，commit `8ba2f98`）：**交付档 = TIM5**（APB1 32 位自由运行，200 MHz ⇒ 5 ns），DWT 留作**第二条独立路径**。⇒ **不再需要"用完 pyocd 就断电"**。
- ★ **单位随档而变**：拍 = **20000**（不是 40000）、ISR 最长 ≈ **818**（≈1636 cyc）。**凡写死 40000/±64 的判据必须按 `TB_HZ` 换算**（`h723_jitter` 已改读 `op=21` 自适应）。
- **时基健康度**：`0x39 op=21` → `[0]档(1=TIM5) [1]频率 [2]自检Δ(**=0 即死**) [4]dwt_dead 计数(在涨=DWT 被调试器关了但统计照常) [6/7]pmin/pmax`。
- ★★ **`g_per_cyc_*` 住 DTCM、跨复位不丢**（只有 `0x13` 冷启动才清）⇒ 复位后读 `0x38` 会看到**上一纪元残留值**，看起来"时基活着"。
  ⇒ **活性判据必须走：`0x13 RESET` → `0x11 START` → 等 ~1 s → 看 `pmin` 是否非 0。**
- ★★ **缺口（待补）**：交付固件里 **`0x39 op=7`（重新校时）不存在** ⇒ 时基死在协议面上无法自证，DWT 派生套件（`h723_jitter`）会给**伪影失败**。
- 只读观测面用 **`connect_mode=halt`**（挂核不复位）；`attach` 在某些 CMSIS-DAP 上初始化不了 AP。★ **读固件全局量前绝不能 `-c reset`**（启动清零 = 自毁证据）。**会话收尾必须 `-c go`**。
- ★ 工具链纪律：**把 `pyocd reset` 从收尾步骤拿掉** —— `构建 → pyocd flash → 让板子自己重启（断电/按 RESET）→ 之后全程只走协议`。

### 2.2 逻辑分析仪（Original Logic）
网格 16 MS/s ⇒ 62.5 ns、24 MS/s ⇒ 41.67 ns，**用时间戳整除性反推采样率**（别猜"最小相邻间隔"，那值可能是 37 µs）。`wait_capture` 报 `ReadTimeout` 时数据**往往已拿到**可照常 export，**但要查完整性**（出现 37.7/61.1 µs 异常短间隔 = USB 丢数据，该档作废）。2 通道可 24 MS/s；8 通道上限 12 MS/s；数字通道不支持可配阈值。

### 2.3 四类假判据（本项目反复吃过）
① **空判据**（观测量恒为 0/1：分支没被走到，或时钟没在走 ⇒ 永远通过）；② **形状判据 > 幅度判据**（证"事件被移动了"用"整段平移 50 µs"）；③ **先判掉量化伪影**（直方图簇间距恰等于采样网格 = 量化，不是抖动）；④ **同一性对照**（A/B 两档先 sha 比对，再确认同一采样率）。

## 三、程序持久化 + 内存地图

**链路**：写 `.dcl` → 编译 → `0x45/46/47` 上传 → SD A/B 双副本 → 上电自动装载（不碰 flash）。实测 `上传→复位` ⇒ `boot_loaded=1`、`0x38 n_routes=7 applied=1` ✓
- `0x45` BEGIN / `0x46` DATA / `0x47` COMMIT / `0x48` STATUS(96B) / `0x49` ERASE / `0x4A` DEVICE_DESC
- ★ `0x48` 96B：+52/+56/+60 = `txn_begin/commit/abort`；+64..76 = 开机装载结果；+80..92 = 从卡读回的载荷头 ⇒ **验收全走协议，不需 SWD**。
- ★★ **"不能上传漏错"五道闸门**：① 帧 CRC16 ② 清单 CRC32+total_len ③ 写后回读 memcmp ④ A/B + 单调 seq ⑤ **装载时再跑同一套静态校验**（`prog_validate`，上传与装载共用实现）。
- ★ 发布前必做**"运行态 vs 持久态"对账**（曾出现引擎跑 `nr=2`、卡上 `nr=128` 的测试残留）。

### 3.1 ★★★ AXI 真实地图（320 KB **已用满**）—— 加缓冲前先看
| 区间 | 占用者 |
|---|---|
| `0x24000000`–`0x24000600` | 诊断结构固定区（`SD_DIAG`/`BB_DIAG`/`SD_CFG`/`BOOT_AXI`）；**协议 `0x20 READ` 放行窗口** |
| `0x24000600`–`0x24003000` | ★ **唯一空档 ≈10.5 KB**（`s_pay`@0x24000800, `s_blk`@0x24002800） |
| `0x24003000` / `0x24003100` | MDMA 锁存快照 / 链表节点 |
| `0x24004000`–`0x24040000` | 黑匣子环（`BB_SLOTS=960` × 256 B = 240 KB） |
| `0x24040000`–`0x24050000` | 日志冻结区 `SD_STAGE` |

★ `prog_store.c` 有**构建期 `#if/#error`** 守空档。★ `blackbox.h` 原注释"AXI 完全空闲/128 KB/512 槽"**三处全过期**。

### 3.2 SD 分区（`sd.c`）
`LBA0` 日志头（`h[112]=LOG_END`, `h[113]="LEND"`）· `LBA1..LOG_END` 日志环 · `g_sd_prog_a..+15`/`g_sd_prog_b..+15` 程序 A/B · `LOG_END = capacity-1-32`
- ★ **绝不升 `LOG_VERSION`**（升了 `sd_log_open` 当新卡重建 ⇒ 从 LBA1 覆写毁卡）。
- ★ **`s_log_blk` 必须钳位**（旧卡游标可能超新上限 ⇒ `cap_data - s_log_blk` 下溢 ⇒ 写飞出卡外）。
- 四个坑（同族：**"半个对齐"或"过期注释"**）：① `sd_read_block` **不许按 HAL 骨架"半对齐"重写**（丢 IDMA ⇒ 数据是错的 ⇒ 当新卡重建 ⇒ SD 路崩）⇒ 保留 IDMA + 只认 `DATAEND`（不认 `DBCKEND`）+ 读完关干净数据通路（`SD_DCTRL &= ~DTEN` → 等 `DPSMACT` 落 → `SD_ICR = STA_STATIC`）；② **SD 源缓冲必须在 AXI**（SDMMC IDMA 读不到 DTCM；**外设 DMA 能到哪块内存按外设成立，不能类推**）；③ **`SD_TMOUT_DATA` 不许往小里挤**（200 万 ≈ 250 ms，正常批写常超 ⇒ 判超时 ⇒ 日志停摆）⇒ 超时给够 + 调用方声明阻塞窗口（`block_window_begin/end`）；④ **"当前完全空闲"这类注释活不过两周** ⇒ 容量断言要么 `_Static_assert`，要么集中成唯一地图。

### 3.3 两条方法学铁律
1. **`pyocd halt` 会把核留在停住状态** ⇒ 据此得过一整串假结论（"tick 冻结/ISR 死了/cmd_count=0"）。**协议能读的一律用协议。**
2. **构建闸门不要用管道把门**：`build.sh | grep … && flash` ⇒ `grep` 退出码掩盖构建失败 ⇒ **烧了旧镜像**。用 `$?` 或先落盘再判。

## 四、引擎与配置陷阱

**4.1 一个绑定跨两个寄存器 ⇒ 必须同一个函数改**：定时器 DMA 请求 = **路由（`DMAMUX1_Cn` 请求号）+ 门控（`TIMx_DIER` 的 `UDEx`/`CCxDE`）**，只改一半 ⇒ **静默失效**（读回全对、功能一动不动）。见 `main.c: trig_source_apply()`。★ 同族："一个语义两处存放"。

**4.2 MDMA 通道寄存器只在 `CCR.EN=0` 时可写**（`CTCR/CTBR/CBNDTR/CSAR/CDAR/CLAR`，否则**静默忽略**）；清 `EN` 后**不能只靠写 `CCR` 重新使能** ⇒ 需完整重初始化或复位。

**4.3 ★★★ 输出锁存链真实行为（实测，推翻 `do.c` 原注释）**：只有 `MDMA_CH0_CCR.EN=0` 会停；`DMAMUX1_C8=0`+`DIER` 无 DMA 使能位、`DMA2_S0_CR.EN=0`、`CTBR.TSEL` 扫 0…15 三组否决**照常工作**。⇒ **MDMA 通道在自循环，不消费任何请求源**；**引脚时刻 = CPU 最后一次写影子 + 0.12 µs**（NOP 扫掠 3.9 ns/轮）。⇒ **"计算与输出解耦、引脚时刻由硬件锚定"当前未达成** ⇒ 让路/关黑匣子这类"分离两条时间线"的手段**注定无效**。

**4.4 ★★ ITCM 已 100% 占满（64 KB/64 KB）** ⇒ **"给函数加 `DCL_ITCM`" 不再是免费动作。** 遇到"**ISR 可达却在 flash**"时**优先改结构**（挪到主循环 / 置标志延迟处理），不要先想着搬代码。★ 实例：`i2c_bus_release()` 在 flash 而状态机在 ISR 里收尾 ⇒ 改成 **ISR 置 `release_pending`、主循环 `i2c_sm_service()` 放门**（代价：总线多持 ≈0.37 ms）。

**4.5 ★★ 门/守卫必须住在"资源的定义处"，不能放在调用点**（G6-2）。放主循环只在"我以为的那个调用点"有效 —— **多一个调用者就静默穿透**。★ **门必须带引用计数**：单一 owner 只表达"**谁**在用"，表达不了"**有几层**在用" —— 别人一次成对的 acquire/release 就会把占用顺手放掉（实测 G2/G5 双 FAIL）。

**4.6 ★★ 同一个表达式在两个调用点，语义可以不同**（G6-4 我自己的错，上机抓到）。
`i2c_bus_owner() != I2C_OWNER_SM`：在 AS5600 那处是"我要避开 SM"（对），
在 `dev_bind_service` 那处**自己就走 SM** ⇒ 空闲时 `owner==NONE`、`NONE != SM` ⇒ **每轮都判忙**。
现象 = **提交全成功、`n_valid` 正常，而 `ok_n/err_n` 永远不动**（30 PASS / 3 FAIL）。
⇒ 判据写"**有人在占且不是我**"（`owner != NONE && owner != SM`），不要写成 `== BLOCKING`
（将来出现第三个 owner 时前者仍对、后者静默放行）。
★ 抓到它的是**专为"判据可解释"新加的计数器** `skip_n`：涨到 3327 并**冻结**在"表空⇒提前 return"。
⇒ **为可解释性加的计数，顺带把静默空转变成了可读指纹** —— 加计数器是划算的。

**4.7 ★★★ "谁的结果"必须被显式携带**（G6-4 缺陷 2，与 §8 的协议层缺陷 §7.1 是同一个病）。
状态机只有一个 `s_rbuf`，而使用者有两个 ⇒ 只查 `status == OK` 只证明"**有人**成功了"，
**不证明"是你要的那次"** ⇒ 别人插入并完成后，他的读数会被写进**你的**目标槽（全程无报错）。
⇒ 处方：**发起时记下自己的号**（`my = g_i2c_sm_req_n`），**完成时广播是哪一号完成的**
（`i2c_sm_done_req()`，住在**资源处**）；不等 ⇒ **丢弃重发**，绝不"按成功用"（新码 `I2C_SM_ST_STOLEN`）。
★ 同族：协议层"应答不带命令码/序号 ⇒ 客户端分不清应答是不是自己的"（`STATUS-2026-09-16` §7.1）。
★ 判据写法：**多写者共享一个暂存区** ⇒ 收尾方必须能回答"这个结果是我的吗"。

**4.8 ★★ 两个**码空间**数值重叠 ⇒ 不能共用一个槽**（G6-4）。`DB_RC_*`(0..8) 与 `I2C_SM_ST_*`(0..7)
混在一个 `last_err` 里 ⇒ `last_err=2` 分不出是"序号非单调"还是"事务成功"。
且**一个计数只能回答一个问题**：`err_n` 一度被"轮询失败"与"上传被拒"共用 ⇒ "err 在涨"**无法解释**。
⇒ 拆成 `ok_n / err_n / skip_n / rej_n` 四个计数 + `reject` / `last_err` 两个独立槽。
★ 何时必须拆：**当你解释这个数字时需要用"或者"** —— 那就是拆的信号。

## 五、DO 输出路径定案 —— `DCL_DO_LATCH = 0` 是交付值

**0 档 = CPU 直写 `GPIO_BSRR`（一次 32 位写覆盖 16 路）**，σ = **1.4 cyc = 3.6 ns**（那次写就是写引脚，引脚抖动 ≈3.6 ns）；
**1 档 = 影子 + MDMA 锁存**，σ = **5.2 cyc = 13.0 ns**、**引脚抖动 ≈54~60 ns**（LA：PE0 σ≈60 ns / `PE0−PA8`=125±45 ns）⇒ 差约 15 倍。切 0 档**无功能损失**（BSRR 一次 32 位写同样是原子"输出帧"、输出沿还提前 ~300 ns，并消掉 ~350 万次/秒 AHB4 写与 MDMA AXI 链表流量）★ 因为"输出由硬件锚定"在 1 档**本来就不存在**（见 4.3）。1 档保留作对照。

- **抖动判据**：别用 LA 测 20~60 ns（网格 62.5 ns ⇒ 量化 σ 就 25 ns，档间 σ 还波动 40 ns）；要在固件里累積 `Σ(d−40000)`、`Σ(d−40000)²`（u64，`0x39 op=16` 读回）。★ 累積**偏差**而非 d 本身。★★ **口径必须写清**：那次"写"写的是影子还是引脚。
- **两个编译期坑**：① **CMake 开关可能根本没接线**（注释称可被 `-DDCL_DO_LATCH=0` 覆盖，CMakeLists 从未 `set(...CACHE...)`+传 `-D`）⇒ 凡声明"可由 CMake 覆盖"的宏，**必须去 CMakeLists grep 到接线**。② **`#endif` 必须在函数收尾 `}` 之前**，否则报错落在文件末尾、很难查。

## 六、外设排障（TB6600 步进 / 光耦）

**6.1 ★★★ 真因：共阳 + 5 V 光耦 + 3.3 V 逻辑 = 从根上不成立**：3.3 V 推挽的"高"**关不断** 5 V 光耦（链上仍有 `5−3.3=1.7 V` > LED 的 Vf）；**开漏也救不了** —— `DS13313 Rev 5` Table 7 里 **PE8/PE9 = `TT_ha`（3.3 V 容忍，非 FT）**，PA6 同为 TT 类 ⇒ 高阻被外部拉到 ~4.5 V，**超绝对最大额定值**。★★ **正解：光耦正端从板 5 V 改接板 3.3 V** ⇒ 压差 0 ⇒ 彻底关断且**保住 MCU 只做 sink**。★ 一般化：**"驱动能力够不够" 与 "供电域是否与逻辑高电平一致" 是两件事**。

**6.2 物理解线判据（最干净）**：★★ **"同一根线两端读数不同" = 断路**（`PA6` 与 `PUL−` 本该等电位却差 4.4 V）。**万用表 DC 档量方波 = 读平均值**（500 Hz/50% ⇒ ≈1.65 V）⇒ 判接线必须先把信号变**静态电平**（`0x39 op=19 sub=7/8` 把 PA6 从 TIM3 摘下来输出确定电平）。★ **成对读两档**才分得开"线断"与"LED 不导通"。★ PA6 网络名 `DCMI_PIXCLK`（板上有摄像头座）。

**6.3 这块 TB6600 的 `ENA` = 「光耦导通 = 失能」**（与多数相反）⇒ 极性必须实测（"无论 PE9 高低都失能 ⇒ 电机永远不转"，而寄存器读回全对）。★ 实测法：拔插 `ENA−` 看轴锁不锁。

**6.4 ★★★ 整数取整造成"时基失真"且随负载变化**：`dm = dt / 10u;`（`dt` ≈ 主循环一圈，不是固定 1 ms）。判据：**固定倍率的时钟错只能给恒定倍率**；倍率**随主机负载变** ⇒ 一定是"丢多少取决于负载"的机制。★ 修法：**限时存"目标拍号"，一次减法判到期，不做除法**。★ 同处"**一个值两个语义**"：`0` 既是『不限时』又是『已到期』⇒ 小限时吃光后变**无限跑** ⇒ 拆成 `armed`(bool)+`tick`(u32)。

**6.5 判据必须跟着可切换的极性走**："安全态 = `PE8~PE11` 全 1"在 `ENA 极性=1` 时**永远是错的** ⇒ 凡"极性可运行期切换"的量，判据要在**同一档极性**下求值，否则静默退化成空判据。★ 安全态判据用 **`IDR`**（引脚实际电平），不是 `ODR`。

**6.6 ★★ 栈越界在观测面上完全看不见 ⇒ 只能靠静态检查**：`h_pin_pattern()` 里 `uint8_t r[40]` 却写了 68 字节，不报错不崩，只写坏调用者的栈，且读回来的字段**全是合理值**。⇒ **凡"往 `r+offset` 写"的应答块，必须数一遍最大偏移 vs 缓冲区大小。**

## 七、Git 纪律

- ★★ **本仓库不要用 `git stash`**（`git stash push -- src/` 时 `.git/refs` 树 + pack 数据一起消失，报 "not a git repository"）。★ 任何 git 维护前先 `cp -r .git ../.git_bak_<日期>`。
- ★ 事故后第一步：**`git status`** + **读 `.git/logs/HEAD`（reflog 通常完好）** ⇒ 能告诉你"最后提交是什么""是否都已推送"。**只要都已推送，恢复永远无损。**
- ★ 提交用 **`git add <具体路径>`**，绝不用 `git add -A`；提交前 `git diff --cached --name-status`，提交后 `git diff --stat <上个提交> HEAD -- src/` 核验"源码一字未动"。
- ★★★ **`refs/remotes/**` 在本机写不进去且静默返回 0**（环境级缺陷）：`git fetch` 打印成功、`rc=0`，但 `packed-refs` 不变、无松散文件 ⇒ **`git status` 永远误报 `[ahead N]`**。隔离实测：`update-ref refs/heads/x` 正常；`update-ref refs/remotes/origin/foo` **rc=0 且把 `origin/` 目录删掉**。
  ⇒ ★ **判据：写完必须 `git show-ref` 确认**；★★ **同步状态的权威判据是 `git ls-remote <remote> refs/heads/main`，不是 `git status`。**
  ⇒ ★ **治标修法（本机唯一有效）**：`mkdir .git/refs/remotes/origin`（`dcl` 同）→ `printf '%s\n' <hash> > .git/refs/remotes/origin/main` → `git status -sb` 立刻变 `## main...origin/main`。
- 两远程：`origin`=H723PLC、`dcl`=dcl-controller，**都推**（`remote.pushdefault=dcl`）。
