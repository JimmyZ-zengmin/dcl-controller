# 项目长期记忆 — 9.10 H723newest (DCL 确定性控制引擎)

## 一、测试仪器纪律（踩过坑的，必须遵守）

### pyocd 会静默杀 DWT
**pyocd / 调试器会话退出时调试域断电 ⇒ `DWT_CTRL.CYCCNTENA` 被清 ⇒ `DWT_CYCCNT` 冻结在 0。**
固件的 `dwt_enable()` 在启动时跑过，之后没人再打开它。
⇒ **凡是 DWT 派生的观测量，用之前必须先用 `0x39 op=7` 重新校时**（它返回两次 CYCCNT，Δ=0 即无效）。
⇒ **凡 DWT 派生的观测量，判据里必须含"时钟在走"这一条**，否则它是永远通过的空判据。
（2026-09-14 实测：`g_ppat_wr_n` 涨到 101 万而 `min/max/last/分档` 全是 0。）

### 逻辑分析仪（Original Logic）
- 网格：16 MS/s ⇒ 62.5 ns；24 MS/s ⇒ 41.67 ns。**用时间戳整除性反推采样率**
  （不能用"最小相邻间隔"猜，那个值可能是 37 µs）。
- `wait_capture` 会报 `ReadTimeout`，但数据往往**已经拿到**了，可以照常 export；
  **不过要检查完整性**（出现 37.7/61.1 µs 这类异常短间隔 = USB 丢了数据，该档作废）。
- 2 通道可上 24 MS/s；8 通道上限 12 MS/s。
- 数字通道不支持可配阈值（不要传 `digitalThresholdVolts`）。

### 判据设计（本项目反复吃过的四类假判据）
1. **空判据**：观测量恒为 0/1（分支从没被走到，或时钟没在走）⇒ 判据永远通过。
2. **形状判据 > 幅度判据**：要证明"事件被移动了"，用"整段平移 50 µs"这种形状判据，
   它不受噪声/量化影响。例：`PE0 − PA8` 相位。
3. **先判掉量化伪影**：直方图上出现**间距恰好等于采样网格**的簇 ⇒ 那是量化，不是抖动。
4. **同一性对照**：A/B 两档先做 sha 比对，确认不是同一份数据；
   再确认两档用的是**同一个采样率**。

## 二、架构与配置陷阱

### 一个绑定跨两个寄存器 ⇒ 必须由同一个函数改
定时器的 DMA 请求 = **路由（`DMAMUX1_Cn` 请求号）+ 门控（`TIMx_DIER` 的 `UDEx`/`CCxDE`）**。
只改一半 ⇒ **静默失效**（寄存器读回来全对、功能一动不动）。
见 `src/main.c: trig_source_apply()`。（2026-09-14 踩到）
★ 同族：以前是"**一个常量两用**"（请求上限≠响应上限），这次是"**一个语义两处存放**"。

### MDMA 通道寄存器只在 EN=0 时可写
`CTCR/CTBR/CBNDTR/CSAR/CDAR/CLAR` 写入前必须 `CCR.EN=0`，否则**静默忽略**。
且清 `EN` 后**不能只靠写 `CCR` 重新使能** ⇒ 需要完整重初始化或复位。

### ★★★ 输出锁存链的真实行为（2026-09-14 实测，推翻原注释）
`do.c` 里写的"七级触发链 TIM2_UP→DMAMUX1→DMA2_S0→TC→MDMAMUX→MDMA→ODR"**不成立**。
实测四个否决：
- `DMAMUX1_C8=0` + `DIER` 无 DMA 使能位 → 锁存**照常工作**
- `DMA2_S0_CR.EN=0` → 锁存**照常工作**
- `MDMA CTBR.TSEL` 扫 0…15 → **全部照常工作**
- `MDMA_CH0_CCR.EN=0` → **停**（⇒ 写入者确实是 MDMA）

⇒ **MDMA 通道在自循环，不消费任何请求源。**
⇒ **输出引脚时刻 = CPU 最后一次写影子 + 0.12 µs**（NOP 扫掠线性：3.9 ns/轮）。
⇒ **"计算与输出解耦、引脚时刻由硬件锚定"当前未达成**；PE0 σ≈60 ns 中 ~45 ns 来自此环节，
   CPU 侧只贡献 ~26 ns。
⇒ 方案②/让路/关黑匣子这类"分离两条时间线"的手段**注定无效**（两条线本来就没通过请求相连）。

## 六、DO 输出路径定案 (2026-09-14) —— `DCL_DO_LATCH = 0` 是交付值

### 结论
**默认 = 0 = CPU 直写**（`GPIO_BSRR` 一次 32 位写覆盖 16 路）。
1 档（影子 + MDMA 锁存）**保留作"改前行为"对照**，不再是交付值。

### 依据（固件侧 DWT σ，2.5 ns 分辨率，两轮完全一致 ⇒ 可复现）
| 档 | σ(写入间隔) | 引脚抖动 |
|---|---|---|
| **0 档** CPU 直写（那次写就是写引脚） | **1.4 cyc = 3.6 ns** | **≈3.6 ns** |
| 1 档 影子+MDMA 锁存（那次写只写影子） | 5.2 cyc = 13.0 ns | **≈54~60 ns**（LA 实测 PE0 σ≈60ns / `PE0−PA8`=125±45ns） |
⇒ 差约 15 倍。切 0 档**无功能损失**：BSRR 一次 32 位写同样是原子"输出帧"；
   输出沿还提前 ~300ns；并消掉 ~350 万次/秒的 AHB4 持续写与 MDMA 的 AXI 链表流量。
   ★ 因为"输出由硬件锚定"在 1 档**本来就不存在**（见 §二 的锁存链真实行为）。

### 抖动判据的正确做法（可复现 > 分辨率）
- **不要用 LA 测 20~60ns 量级的抖动**：网格 62.5ns ⇒ 量化 σ 就 25ns；且同配置档间 σ 波动 40ns。
- **要在固件里累積偏差**：`Σ(d−40000)` 与 `Σ(d−40000)²`（u64），`0x39 op=16` 读回，
  上位机算 σ。★ 累積"偏差"而不是 d 本身，避免大数相减的精度损失。
- ★★ **口径必须写清楚**：那次"写"到底写的是影子还是引脚 —— 决定了 σ 能不能直接代表引脚抖动。

### 两个编译期坑（都踩过）
- **CMake 开关可能根本没接线**：`do.h` 注释写"可被 `-DDCL_DO_LATCH=0` 覆盖"，
  但 CMakeLists 从未 `set(...CACHE...)` + 传 `-D`。⇒ **凡声明"可由 CMake 覆盖"的宏，
  必须去 CMakeLists 里 grep 到它的接线**，否则那是个假开关（本轮第一次 `-D` 毫无作用）。
- **`#endif` 必须放在函数收尾 `}` 之前**：否则该分支被选中时，`}` 也被条件编译掉 ⇒
  `expected declaration or statement at end of input`，且报错位置在文件末尾，很难查。

## 七、外设排障的三条"从这次学到的"（2026-09-15，TB6600 步进）

### ① 万用表 DC 档量方波 = 读**平均值** ⇒ 判接线必须先把信号变成**静态电平**
500 Hz / 50% 方波在 DC 档上是 ≈1.65 V。于是"线通（被光耦 LED 钳到 ~1.2 V）"与
"线断（浮空 ~4.5 V）"在表上只差一点点，**判不了**；而且"脉冲还在不在跑"本身是变量
（有**限时**，到点自动停 ⇒ 停下来后引脚 = 静态低 = 0 V）。
⇒ 新增 `0x39 op=19 sub=7/8/9/10` = **把 PA6 从 TIM3 上摘下来、输出确定的静态电平**。
`tools/h723_stepper_test.py probe low|high|af|od`。★ 判据要**成对读两档**才分得开
"线断"与"LED 不导通"。

### ② ★★ "同一根线两端读数不同" = 断路，这是最干净的判据
`PA6 = 0.116 V` 而 `PUL− = 4.5 V` —— 这两点本来是一根线的两端。差 4.4 V ⇒ **必然没连通**。
比任何间接推理都硬。**先找"两个本该等电位的点"，再看它们等不等。**

### ③ ★★ 栈越界在观测面上**完全看不见** ⇒ 只能靠**静态**检查
`h_pin_pattern()` 里 `uint8_t r[40]` 却写了 68 字节（`ack(r,68)`）—— 运行不报错、不崩，
只会写坏调用者的栈。★ 最阴：读回来的 17 个字段**全是合理值**，越界一点痕迹都没有。
⇒ **凡"往 `r + offset` 写"的应答块，必须数一遍最大偏移 vs 缓冲区大小**，
这是**静态**判据，动态读数永远发现不了。

### ④ PA6 的网络名是 `DCMI_PIXCLK`（板上有摄像头座）
⇒ 该脚可能挂了座子上的器件（上下拉/ESD）。若 `probe` 时 **U9 pin19 自己就不跟随**，
第一嫌疑是它，不是软件。见 `docs/HARDWARE-PINOUT.md` §4.1。

## 八、步进/TB6600 闭环（2026-09-15 收口，另一会话主导审计，我复核并补根因）

### ① ★★★ 真因：**共阳 + 5 V 光耦 + 3.3 V 逻辑 = 从根上不成立**
- **3.3 V 推挽的"高"关不断 5 V 光耦**（mA 档实测两档电流差 ≈ 0）：
  高电平时链上仍有 `5 − 3.3 = 1.7 V`，**高于 LED 的 Vf**。
- **开漏也救不了**：`DS13313 Rev 5` Table 7 —— **PE8/PE9 = `TT_ha`（3.3 V 容忍，非 FT）**，
  PA6 同为 TT 类 ⇒ 开漏高阻被外部拉到 ~4.5 V，**超绝对最大额定值**。
- ★★ **正解：把光耦正端从板 5 V 改接板 3.3 V** ⇒ 高电平时压差 **0** ⇒ 彻底关断，
  且**保住 MCU 只做 sink**（不倒灌进 TT 脚）。
  ⇒ **"共阳 + 3.3 V" 才是同时满足"不倒灌"与"关得断"的组合。**
- ★ 教训一般化：**"驱动能力够不够" 与 "供电域是否与逻辑高电平一致" 是两件事**；
  只考虑前者就会把问题误判成"必须加缓冲器件"。

### ② 这块 TB6600 的 **ENA = 「光耦导通 = 失能」**（与多数相反）⇒ 极性必须实测
**无论 PE9 高低都失能 ⇒ 电机永远不转**，而所有寄存器读回全对。
★ 实测法：拔插 `ENA−` 看轴锁不锁。

### ③ ★★★ 整数取整会造成"**时基失真**"，且**随负载变化** —— 与"配置全对≠功能可用"同族
    uint32_t dm = dt / 10u;   /* dt ≈ 主循环一圈, 不是固定 1ms */

- 判据：**固定倍率的时钟错只能给恒定倍率**；若倍率**随主机负载变** ⇒ 一定是"丢多少取决于负载"的机制。
- 实测（零运动，`g_step_deadline_tick` 的递减与 `CC1E` 无关）：静默 648.9/秒（−35.1%）、
  密轮询 789.1/秒（−21.1%）；反推主循环一圈 **1.54 ms / 1.28 ms**，两档都落在 `floor(dt/10)=1`
  ⇒ 指纹 = "每次记 1 ms、真实过了 1.3~1.5 ms"。
- ★ **修法：限时存"目标拍号"，一次减法判到期，不做除法** ⇒ 无取整、无累计误差、与主循环快慢无关。
- ★ 同处还有"**一个值两个语义**"：`0` 既是『不限时』又是『已到期』⇒ 小限时被提前吃光后会变成**无限跑**。
  ⇒ 必须拆成 `armed`(bool) + `tick`(u32)。

### ④ 判据必须**跟着可切换的极性走**
"安全态 = `PE8~PE11` 全 1"这条判据在 `ENA 极性=1` 时**永远是错的**（那时 `PE9=0` 才是"不导通"）。
⇒ 凡"有效极性可运行期切换"的量，判据要在**同一档极性**下求值，否则它会静默退化成空判据。
★ 且安全态判据要用 **`IDR`（引脚实际电平）**，不是 `ODR`（我以为写了什么）。

### ⑤ 现场接口
- 板子在 **COM21**；`0x39 op=19` 应答 **96 B**（偏移 76/80/84/88/92 = `GPIOA_IDR`/`GPIOE_IDR`/实时 `CCMR1`/`CCR1`/`ARR`）。
- 工具：`tools/h723_stepper_test.py`（`safe`/`probe`/`idrwatch`/`pulse`/`ena`/`enapol`/`dir`）；
  `docs/audit/h723_limit_tick_probe.py`（零运动时基探针）。
- 审计文档在 `docs/audit/`（该目录已有 AUDIT / RESPONSE 配对惯例）。

## 九、★★★ 架构使用规约（**强制**，2026-09-15 用户明确要求写入 memory）

> 这一节回答三个问题：**怎么用这个系统？实验怎么做？调试器怎么用？**
> 违反它不会立刻报错，但一定会以"行为不对、查不出来"的形式还回来。

### 9.0 一句话
**用这个系统 = 写 DCL 程序；不是改固件。**
固件（引擎核心）是**平台**，烧录它 = 换一台机器；DCL 程序是**资产**，走通信上传 + 持久化。

### 9.1 分层与"该放哪一层"的判据

```
① 引擎核心 Engine Core     烧录        改它 = 换固件(必须重新回归)
② 外设能力 Peripheral Ops  随核心发布、版本化 + 能力位声明
   ★ 做成"通用事务 op"(I2C/SPI/UART) + 具名设备驱动, 而非"每芯片一个专用命令"
③ DCL 程序 Program         通信上传 + 持久化(SD)
④ 程序工程 Project         上位机侧: .dcl 源 + 清单 + 编译产物
```

| 问题 | 放哪层 |
|---|---|
| 它是"**怎么算**"（逻辑/连续/顺序）？ | ③ 程序 |
| 它是"**和外设怎么说话**"？ | ② 外设能力（通用事务 op / 具名设备），**不是**新驱动 |
| 它需要**新的每拍行为 / 实时保证**？ | ① 核心（必走 A/B + 12 套回归） |
| 它只是"**给上位机看的量**"？ | 进 SHM + `obs_anchor()` 登记，**不是**加协议 op |

### 9.2 做实验必须**按架构做**（七条）
1. **观测先走协议内通道**：`0x38 ENGINE_STATUS` / `0x22 READ_BURST` / SHM。pyocd 是最后手段。
2. **控制先走程序面**：`0x10 DEPLOY` + `0x11 START`；不要直接把寄存器怼成某个值来"模拟"。
3. **要新能力，先判层**（9.1 的表）。**不要默认"改固件"** —— 那正是 I2C 那次走的弯路。
4. **每拍必须发生的动作 → 引擎/ISR；服务性动作 → 主循环**。
   ★★ **别再把实时量挂到主循环上**：主循环一圈实测 **1.28~1.54 ms**，而拍是 100 µs。
   `step_tick` 限时（D2/D3/D4）与 macro 的忙等就是这样坏掉的。
5. **实验代码独立成 patch**：`docs/exp-<日期>-<主题>/`（README + patch + raw + 脚本 + analysis）。
   **交付物里不出现实验脚手架**。
6. **运行期改动必须复位即恢复**；**不得污染持久化配置**。
7. **每条判据都要能失败**，并配对照（A/B 构建或对照配置）证明它真的会红。

### 9.3 pyocd 纪律（**谨慎使用**，用前先读这一节）
- ★★★ **pyocd 会静默杀 DWT**：会话退出 ⇒ 调试域断电 ⇒ `CYCCNTENA` 被清 ⇒ `DWT_CYCCNT` 冻结在 0。
  ⇒ **凡 DWT 派生的观测量，用前必须先用 `0x39 op=7` 重新校时**（它返回两次 CYCCNT，Δ=0 判无效）；
  ⇒ **凡 DWT 派生的判据，必须含"时钟在走"这一条**，否则它是永远通过的空判据。
- ★★ **读固件全局量之前绝不能 `-c reset`** —— 启动会清零它们，"读之前先复位"= 自毁证据。
- 只读观测面用 **`connect_mode=halt`**（挂核不复位）；`attach` 在某些 CMSIS-DAP 上初始化不了 AP。
- **工具收尾必须 `-c go`**（恢复运行）。
- **能用协议表达的，一律不用 pyocd**。

### 9.4 ★★ 用**标准化操作**替代"影响系统"的操作（对照表）

| 会扰动系统的做法（禁止） | 标准化替代 |
|---|---|
| pyocd 直写 GPIO 摇引脚 | `0x39 op=19 sub=7/8`（静态电平探针，可回读 `IDR`） |
| pyocd 改 TIM3 寄存器试频率 | `0x39 op=19 sub=1`（报**实际**频率，不是请求值） |
| pyocd 读一堆全局量 | `0x38` + `0x22 READ_BURST`（走 SHM） |
| 为了看一个量就加一条新协议 op | 进 SHM + `obs_anchor()` 登记 |
| 反复 start/stop 让电机停在某处 | 固件内**定长/定位原语**（D4，待补） |
| 改固件来支持一个新传感器 | ② 层外设能力（通用事务 op / 具名设备） |
| 直接改持久化扇区 | `0x43 PERSIST`（**当前 NAK**，见 §八①）→ 改走 SD |
| 用"无脉冲时引脚电平"判有没有脉冲 | ★ **必须在 `CC1E=1` 时判**，且看 `IDR`（AF+`CC1E=0` 时引脚是高阻，读数无意义） |

### 9.5 三条**红线**
1. **程序里不得出现任何物理引脚号或总线地址**（IEC 61131-3 / CODESYS / Zephyr 三边一致）。
2. **不得破坏单写者**：同一 SHM 槽、同一张卡，只允许一个权威写者。
   ★ 已两次踩到：`TIM3` 两个驱动者（门守一处漏一处 → C1）、**SD 卡两个写者**
   （日志从 LBA1 回卷 + `sd_dump_write` 写 LBA3000000，落在日志区内）。
3. **不得把实时量挂在主循环上**。
