## 一、★★★ 架构使用规约（强制）

**用这个系统 = 写 DCL 程序，不是改固件。**
```
① 引擎核心  烧录    改它 = 换固件(必走 A/B + 12 套回归)
② 外设能力  随核心版本化 + 能力位; 做成"通用事务 op"(I2C/SPI/UART) + 具名设备, 非"每芯片一条命令"
③ DCL 程序  通信上传 + 持久化(SD)      ④ 程序工程  上位机侧: .dcl 源 + 清单 + 编译产物
```
| 问题 | 放哪层 |
|---|---|
| "**怎么算**"（逻辑/连续/顺序）| ③ 程序 |
| "**和外设怎么说话**" | ② 外设能力，**不是**新驱动 |
| 需要**新的每拍行为 / 实时保证** | ① 核心 |
| 只是"**给上位机看的量**" | SHM + `obs_anchor()`，**不是**加协议 op |

### 实验八条
1. **观测先走协议内通道**（`0x38` / `0x22` / SHM）；pyocd 是最后手段。
2. **控制先走程序面**（`0x10 DEPLOY` + `0x11 START`），不要直怼寄存器"模拟"。
3. **要新能力先判层**（上表）。**不要默认改固件** —— I2C 那次弯路就是这么走的。
4. **每拍动作 → 引擎/ISR；服务性动作 → 主循环。** 主循环一圈实测 **0.37 ms**，拍 100 µs；**别把实时量挂主循环**。
   ★★ **GAP-6 判层推论**：外设"多步操作"不能靠主循环跑阻塞事务 ⇒ 正解 = 照 `adc_poll` 做**拍内每拍推进一步的状态机**（四约束：拍内推进 / 标价+预算门 / 总线独占门 / 就绪门）。
   ★★ **适用边界**：判"要不要拍内"看两问 —— ① 在控制回路里吗？② 把主循环堵到**可测**程度吗？（判据 = `WDT_STAT.loop_gap_max_undecl` + ISR 超预算次数）。★ 反例：**AS5600 留在主循环没问题**（≈450 µs、`loop_gap_max_undecl=0`）⇒ **判据由测量决定，不由规则措辞决定**（契约 §3.6/§3.6.1）。
5. **实验代码独立成 patch**（`docs/exp-<日期>-<主题>/`）；交付物里不出现脚手架。
6. **运行期改动复位即恢复**；不得污染持久化配置。
7. **每条判据都要能失败**，配对照证明它会红。
8. ★★ **新增 SHM 域必须登记到单一冷启动入口**（`cold_start_reset()`）。反例：`IX_MAGIC` 只在开机写一次 ⇒ 被 `0x13 RESET` 抹掉 ⇒ 整个 G6-3 事务区失联。

### 三条红线
1. **程序里不得出现任何物理引脚号或总线地址**（`dcl_static_check.py` 编译期拒绝）。
2. **不得破坏单写者**。★ 已两次踩到：`TIM3` 两个驱动者；**SD 卡两个写者**。
3. **不得把实时量挂在主循环上。**

## 二、时基与仪器纪律

**2.1 pyocd 会静默杀死 DWT（设计行为，无捷径）**：pyOCD issue #1540 —— 会话 disconnect 时主动写 `DEMCR.TRCENA=0`；J-Link 同款 ⇒ 不是 bug。`pyocd reset` 救不回，只有**断电重上电**（`-Oresume_on_disconnect=false` 实测也无效）。
- ★★★ **正解在固件：别拿调试单元当生产时基**。✅ 已落地（`src/timebase.{c,h}`，`DCL_TIMEBASE` A/B，`8ba2f98`）：**交付档 = TIM5**（32 位，200 MHz ⇒ 5 ns），DWT 留作第二路径 ⇒ **不再需要"用完 pyocd 就断电"**。
- ★ **单位随档变**：拍 = **20000**（非 40000）、ISR 最长 ≈ **818**。凡写死 40000/±64 的判据按 `TB_HZ` 换算（`h723_jitter` 已改读 `op=21`）。
- **健康度** `0x39 op=21`：`[0]档(1=TIM5) [1]频率 [2]自检Δ(=0 即死) [4]dwt_dead [6/7]pmin/pmax`。
- ★★ `g_per_cyc_*` 住 DTCM、**跨复位不丢**（只有 `0x13` 清）⇒ 复位后读 `0x38` 看到的是**上一纪元残留**，看起来"时基活着" ⇒ **活性判据必须走 `0x13 RESET` → `0x11 START` → 等 ~1 s → 看 `pmin` 非 0**。
- ★★ **缺口**：交付固件**没有 `0x39 op=7`（重新校时）** ⇒ 时基死在协议面上无法自证。
- 只读观测用 **`connect_mode=halt`**（`attach` 在某些 CMSIS-DAP 上初始化不了 AP）。★ **读固件全局量前绝不能 `-c reset`**（启动清零=自毁证据）。**收尾必须 `-c go`**。
- ★ 工具链纪律：**`pyocd reset` 不要放在收尾** —— `构建 → flash → 让板子自己重启（断电/按 RESET）→ 之后全程只走协议`。

**2.2 逻辑分析仪**：网格 16 MS/s ⇒ 62.5 ns、24 MS/s ⇒ 41.67 ns，**用时间戳整除性反推采样率**。`wait_capture` 报 `ReadTimeout` 时数据往往已拿到，但**要查完整性**（37.7/61.1 µs 异常短间隔 = USB 丢数据，该档作废）。2 通道可 24 MS/s；8 通道上限 12 MS/s。

**2.3 四类假判据**：① **空判据**（观测量恒 0/1 ⇒ 分支没走到，或时钟没在走 ⇒ 永远通过）；② **形状判据 > 幅度判据**；③ **先判掉量化伪影**（簇间距恰等于采样网格 = 量化）；④ **同一性对照**（A/B 先 sha 比对 + 确认同一采样率）。

## 三、程序持久化 + 内存地图

写 `.dcl` → 编译 → `0x45/46/47` 上传 → SD A/B 双副本 → 上电自动装载（不碰 flash）。
- op：`0x45` BEGIN / `0x46` DATA / `0x47` COMMIT / `0x48` STATUS(96B) / `0x49` ERASE / `0x4A` DEVICE_DESC。
- ★ `0x48` 96B：+52/+56/+60 = `txn_begin/commit/abort`；+64..76 = 开机装载结果；+80..92 = 从卡读回的载荷头 ⇒ **验收全走协议，不需 SWD**。
- ★★ **五道闸门（不能上传漏错）**：① 帧 CRC16 ② 清单 CRC32+total_len ③ 写后回读 memcmp ④ A/B + 单调 seq ⑤ **装载时再跑同一套静态校验**（`prog_validate`，上传与装载**共用实现**）。
- ★ 发布前必做**"运行态 vs 持久态"对账**（曾出现引擎 `nr=2`、卡上 `nr=128` 的残留）。

**3.1 AXI 地图 / SD 分区 —— 唯一真值源 `docs/STATUS-2026-09-16.md` §2/§3**（不再抄第二份）
AXI **320 KB 已用满**，唯一空档 ≈10.5 KB（`0x24000600`–`0x24003000`），黑匣子环占 240 KB；`prog_store.c` 有构建期 `#if/#error` 守空档。
SD：`LBA0` 日志头（`h[112]=LOG_END`）· `LBA1..LOG_END` 日志环 · 卡尾 A/B 程序区 · `LOG_END=capacity-1-32`。
- ★ **绝不升 `LOG_VERSION`**（升了 `sd_log_open` 当新卡重建 ⇒ 从 LBA1 覆写**毁卡**）。
- ★ **`s_log_blk` 必须钳位**（旧卡游标可能超新上限 ⇒ 下溢 ⇒ 写飞出卡外）。
- ★ **不许按 HAL 骨架把 `sd_read_block`"半对齐"重写**（丢 IDMA ⇒ 数据错 ⇒ 当新卡重建 ⇒ SD 路崩）。
- ★ **SD 源缓冲必须在 AXI**（SDMMC IDMA 读不到 DTCM；**外设 DMA 能到哪块内存按外设成立，不能类推**）。

**3.2 两条方法学铁律**：① **`pyocd halt` 会把核留在停住状态** ⇒ 据此得过一整串假结论（**协议能读的一律用协议**）；② **构建闸门不要用管道把门**（`build.sh | grep … && flash` ⇒ `grep` 退出码掩盖构建失败 ⇒ **烧了旧镜像**）。

## 四、引擎与配置陷阱

**4.1 一个绑定跨两个寄存器 ⇒ 必须同一个函数改**：定时器 DMA 请求 = **路由（`DMAMUX1_Cn`）+ 门控（`TIMx_DIER`）**，只改一半 ⇒ **静默失效**（读回全对）。见 `trig_source_apply()`。

**4.2 MDMA 通道寄存器只在 `CCR.EN=0` 时可写**（否则静默忽略）；清 `EN` 后**不能只靠写 `CCR` 重新使能**。

**4.3 ★★★ 输出锁存链真实行为（实测，推翻 `do.c` 原注释）**：只有 `MDMA_CH0_CCR.EN=0` 会停；`DMAMUX1_C8=0`、`DMA2_S0_CR.EN=0`、`CTBR.TSEL` 扫 0…15 **照常工作** ⇒ **MDMA 通道在自循环，不消费任何请求源**；**引脚时刻 = CPU 最后一次写影子 + 0.12 µs** ⇒ **"计算与输出解耦、引脚时刻由硬件锚定"未达成** ⇒ 让路/关黑匣子**注定无效**。

**4.4 ★★ ITCM 已 100% 占满（64 KB）** ⇒ "给函数加 `DCL_ITCM`"**不再是免费动作**；遇"ISR 可达却在 flash"**优先改结构**。★ 实例：`i2c_bus_release()` 在 flash ⇒ 改成 ISR 置 `release_pending`、主循环放门（代价：多持 ≈0.37 ms）。

**4.5 ★★ 门/守卫必须住在"资源的定义处"**，不能放调用点。★ **门必须带引用计数**：单一 owner 只表达"谁在用"，表达不了"有几层在用"。

**4.6 ★★ 同一表达式在两个调用点，语义可以不同**。`owner != I2C_OWNER_SM`：在 AS5600 处是"我要避开 SM"（对），在 `dev_bind_service` 处**自己就走 SM** ⇒ 空闲时 `NONE != SM` ⇒ **每轮都判忙**。现象 = **提交全成功、`n_valid` 正常，而 `ok_n/err_n` 永远不动**。⇒ 写"**有人在占且不是我**"（`owner != NONE && owner != SM`）。★ 抓到它的是**专为可解释性加的计数器** `skip_n`（涨到 3327 后冻结）—— **加计数器是划算的**。

**4.7 ★★★ "谁的结果"必须被显式携带**。状态机只有一个 `s_rbuf` 而使用者有两个 ⇒ `status == OK` 只证明"**有人**成功了"。
⇒ **发起时记下自己的号**（`my = g_i2c_sm_req_n`）、**完成时广播是哪一号**（`i2c_sm_done_req()`，住**资源处**）；不等 ⇒ **丢弃重发**（`I2C_SM_ST_STOLEN`）。

**4.8 ★★ 两个码空间数值重叠 ⇒ 不能共用一个槽**（`DB_RC_*` 0..8 与 `I2C_SM_ST_*` 0..7 混在一个 `last_err`）。且**一个计数只能回答一个问题** ⇒ 拆 `ok_n/err_n/skip_n/rej_n`。★ **何时必须拆：解释这个数字时需要用"或者"。**

**4.9 ★★★ "完成态"与"实时态"必须分开**。只有一份 `s_status` ⇒ 被拒请求会**覆写**它 ⇒ 收尾方**丢弃自己的好数据并计一次错**。
⇒ **完成记录** `{req, status, len}`（完成那刻快照，**受理新请求即失效**），取数只走 `take_result(my,…)`。★ 凡"多写者共享一个暂存区"，答案必须来自**快照**而非"现在看一眼"。

**4.10 ★★★ 不要为一个你准备拒绝的请求去占用资源**。`i2c_sm_request()` 先拿门再验参 ⇒ 非法参数分支 `return 0` 不放门 ⇒ **引用计数泄漏** ⇒ `owner` 永久卡 `SM`。症状**离真因极远**（所有依赖阻塞路径的判据一起红）。⇒ **先验参、再拿门**。
★ 判据写法：**"没跑到该分支 ⇒ 本判据无效，不是通过"**。

**4.11 ★★ 用原始位定性，不要只看解码值**。假报警"`SENSOR[15]` 被改成 `6.5e-21`" ⇒ 原始 u32 = `0x1DF70200` = `fw_ver|cap<<16` ⇒ 那是 **`0x01` 的载荷被当成 `0x22` 的应答**（**串帧**），不是固件问题。★ 最坏巧合：`0x22` 读 **1 个字**的应答也是 **4 字节** ⇒ **长度判据也分不开**。⇒ 加固：读**两个字** · 连续两次同值 · 打印原始 u32。

**4.12 ★★★ "还欠着什么"必须记账（配对计数），不能用 bool**（最隐蔽的一条）。延迟释放原是一个 bool，且**受理新请求时被清 0** ⇒ 恰在服务函数之后完成的那次释放被丢掉 ⇒ **每次泄漏 1 个引用**（实测 `refs=61`、`owner=2(SM)` 冻结，而状态机 idle）。
⇒ **配对计数**（完成 +1，主循环 `while` 还清）+ 删受理处清 0 + 主循环**引用计数对账**（违反则当圈归还，计入 `g_i2c_ref_leak_n`）。
★ **bool 只能表达"欠/不欠"，表达不了"欠几次"** —— 凡"延迟做某事"的账都要计数。
★★ **一处修复消掉三个看起来无关的症状**：①`refs` 泄漏 + AS5600 饿死；②**跑测顺序依赖**；③`dev_bind_test` 只能跑到 53/1/2（修后 55/0/1）。

**4.13 ★★★ 内部路径不得扰动"对外协议的握手状态"**。装载恢复第一版复用 `dev_bind_submit()` 并先 `REQ_SEQ + 1u`；而 `submit` 在 `req == done` 时**静默 return** ⇒ 上位机若自维护序号，**第一次恢复后就撞号** ⇒ **之后每条判据都在旧表上跑 ⇒ 全假 PASS 且无症状**。
⇒ 抽出 `db_validate_apply(seq)` —— **共用校验**，但装载传 `seq = 0` ⇒ **绝不碰 `REQ_SEQ`/`DONE_SEQ`**。
★ 一般化：**"共用同一套校验"是对的，"共用握手/计数器"是错的**。写复用时先问：**这次调用算不算"一次对外交互"？**
★ 同族：`0x48` 应答**只能追加**（96→104 B）；**任何对既有应答长度的"等值"判据都是陷阱**（与 `cap == 0x0DF7` 同族）。

**4.14 ★★★ 流式解析器必须有超时（不能永久卡在半帧）** —— "大 deploy 偶发失聪"定案。
根因 = ① **接收环只有 512 B**（≈44 ms 数据）而主循环 `sd_log_poll()` **会停顿** ⇒ 丢字节；② `fp_feed()` 在 PAYLOAD 态**只存字节、无超时** ⇒ **停在半帧上永久失聪**。
★ 决定性复现：注入"声明 4096、实发 200"的半帧 ⇒ 等 2 s/5 s 都不恢复；**补足字节才恢复** ⇒ 表现为"下一次又好了"。
⇒ 修：`FRAME_ASSY_TIMEOUT_TICKS=500`（超时即复位 ⇒ **自愈**）+ `RX_RING_SZ 512→4096` ⇒ **120 次部署 0 事件**（修前 8/120）。
★ 两条通用教训：① **流式解析器必须能"丢字节后重同步"** —— 环大小只降低概率，**超时才能保证自愈**；② ★★ **判"有没有新字节"要看"本轮真的消费了字节"**，不能看某个索引变没变（第一版用 `payload_idx`，帧头阶段恒 0 ⇒ **分段帧全被误杀**，被**我自己的反向判据**抓住）。
⇒ **只有"能失败"的判据还不够，还要有"不该红的不红"的反向判据。**

**4.15 ★★★ 一个默认极性可以把"使能/失能/安全态"三个语义同时弄反**（2026-09-16 现场定案）
映射（TB6600 光耦，`step.c:96` `conducting = (pol==0) ? ena : ena^1`）：**`PE9=1` 才是使能**。
⇒ `g_step_ena_pol` **复位默认 0** 与实机接线相反 ⇒ `ena(1)` = **失能**；`ena(0)` / `step_stop_safe()` / `step_init()` 的"**上电安全态**" = **通电**。
现象 = "**电机自己在响 + 轴不动**"（**同一处反相的两个面，不是两个故障**）。
★ **判据必须看引脚实读（`PE9`/`IDR`），不能看逻辑位（`ena`）** —— 逻辑位在真实状态上说反话，且**不是恒 0/1** ⇒ 不满足"空判据"特征 ⇒ 没人怀疑。
⇒ **处方：任何要驱动电机的脚本，开工先 `op=19 sub=5 arg=1` 并回读断言 `PE9==1`**（不成立就抛错判"无效"，不许当硬件故障解读）。
★★ **工具自身的读超时也要按实测标定**：命令通路往返 **p99 56.8 / max 63.6 ms**，而脚本曾用 **50 ms** ⇒ **约 1~2% 的读"必然"超时**。**一次读失败 ≠ 链路异常**，判它之前必须**重试**。
★ 同族纪律：**凡"设了就算"的量都要"目标值 vs 读回值"核对**（`enapol` / `BRR` 16× / ADC `PCSEL` / 限时小值静默失效）。
★ 详细（A/B、三处反相表、固件修法三选一）：`RELEASE-v2.1.0.md` **§6.1** + `H723-MOTION-QUALITY-AUDIT.md` **§16**。

## 五、DO 输出路径 —— `DCL_DO_LATCH = 0` 是交付值

0 档 = CPU 直写 `GPIO_BSRR`，σ = **1.4 cyc = 3.6 ns**；1 档 = 影子 + MDMA 锁存，σ = 5.2 cyc = 13.0 ns、**引脚抖动 ≈54~60 ns** ⇒ 差 ~15 倍。切 0 档**无功能损失**（并消掉 ~350 万次/秒 AHB4 写）。★ 因为"输出由硬件锚定"在 1 档**本来就不存在**（见 4.3）。
- **抖动判据**：别用 LA 测 20~60 ns（网格 62.5 ns ⇒ 量化 σ 就 25 ns）；固件里累積 `Σ(d−40000)`、`Σ(d−40000)²`（u64，`op=16`）★ 累積**偏差**而非 d 本身。★★ **口径必须写清**：那次"写"写的是影子还是引脚。
- **两个编译期坑**：① **CMake 开关可能根本没接线** ⇒ **必须去 `CMakeLists` grep 到接线**；② **`#endif` 必须在函数收尾 `}` 之前**（否则报错落在文件末尾）。

## 六、外设排障（TB6600 / 光耦 / 步进）
★★ 细则已收进技能 `mcu-opto-input-bringup` 与 `stepper-motion-quality-acceptance`。只留**不能再踩的**：
- ★★★ **共阳 + 5 V 光耦 + 3.3 V 逻辑从根上不成立**（3.3 V 推挽的"高"**关不断** 5 V 光耦；开漏也不行 —— `DS13313 Rev 5` Table 7 里 **PE8/PE9/PA6 是 `TT_ha`（非 FT）**，高阻被拉到 ~4.5 V **超绝对最大额定值**）⇒ **正解：光耦正端从 5 V 改接 3.3 V**。
- **物理解线判据**：**"同一根线两端读数不同" = 断路**。**万用表 DC 档量方波 = 读平均值** ⇒ 判接线先把信号变**静态电平**（`op=19 sub=7/8`）。★ PA6 网络名 `DCMI_PIXCLK`。
- ★★ **栈越界在观测面上完全看不见 ⇒ 只能靠静态检查**：`h_pin_pattern()` 里 `uint8_t r[40]` 却写了 68 字节 ⇒ 只写坏调用者栈，读回字段**全是合理值**。⇒ **凡"往 `r+offset` 写"的应答块，必须数一遍最大偏移 vs 缓冲区大小。**

## 七、Git 纪律

- ★★ **本仓库不要用 `git stash`**（`.git/refs` 树 + pack 数据一起消失，报 "not a git repository"）。维护前先 `cp -r .git ../.git_bak_<日期>`。
- ★ 事故后第一步：**`git status`** + 读 **`.git/logs/HEAD`（reflog 通常完好）** ⇒ **只要都已推送，恢复永远无损**。
- ★ 提交用 **`git add <具体路径>`**（绝不用 `git add -A`）；提交后 `git diff --stat <上个提交> HEAD -- src/` 核验"源码一字未动"。
- ★★★ **`refs/remotes/**` 在本机写不进去且静默返回 0**（环境级缺陷）⇒ **`git status` 永远误报 `[ahead N]`**。
  ⇒ ★ 写完必须 `git show-ref` 确认；★★ **同步状态的权威判据是 `git ls-remote <remote> refs/heads/main`，不是 `git status`。**
  ⇒ ★ 治标（本机唯一有效）：`mkdir .git/refs/remotes/origin` → `printf '%s\n' <hash> > .git/refs/remotes/origin/main`。
- ★ **`git commit -m` 里反引号会被 bash 命令替换** ⇒ 提交失败（报错像"文件没进暂存区"）⇒ **写消息文件 + `git commit -F`**。
- 两远程：`origin`=H723PLC、`dcl`=dcl-controller，**都推**（`remote.pushdefault=dcl`）。

## 九、回归跑测规程（**14 条，全是踩过才写的**）

1. ★★ **先回 bench 态**：`0x49 PROG_ERASE` + 复位。空卡上电填 bench profile = `n_routes=128 / run=1`。SD 上留着程序会让 `h723_w2_probe` 假失败 —— 那是**板态不是回归**。
2. ★★ **判据 = "有没有出现新的失败模式"，不是"PASS 数不低于某值"**。`h723_w2_probe` **自身非确定**（同固件连跑三次 13/1、11/3、13/1）；`h723_persist` 基线 **7/19**。
3. ★ A/B 必须**先固定板态**（同板 / 同判据 / 同 prep）；`git show <rev>:file > file` 取旧文件做对照前**先确认工作区没有未提交编辑**（会静默覆盖）。
4. ★★ **脚本的状态复原必须放 `finally`**，判据 FAIL 时也要还原。★ **"上一条测试留下的板态"是本项目最常见的假故障源**（三次同形）。
5. ★★ **别用"还有别人在写"的槽/寄存器**：`SENSOR[15]` 有引擎路由写；`WIRE[0]` 被 `SENSOR[0]` 镜像。bench 的 **128 条路由恰好覆盖全部 128 个 WIRE 槽** ⇒ **"没人写的 WIRE 槽"不存在**；要恒定空闲值只能靠**源类型**（`i%3==2 ⇒ SRC_CONST`），首选 `WIRE[17]=0.005`。
6. ★ **先读脚本的用法/前置条件**：`h723_seq.py --wipe` 明写"跑其它回归前必须先 wipe"（我们两次都没做）。
7. ★★★ **串口是独占资源**（同 8 速查）。症状：一个进程发 `0x01`，另一个的密轮询把它当 `0x22` 应答吃掉（读到 `0x1DF70200`）。**一个错误三天症状。**
8. ★★ **客户端唯一可用的"归属"判据是长度**（ACK 帧 cmd 都是 `0x00`）⇒ 见 4.11 的加固。
9. ★★★ **别用"当前固件的读数"去归因"历史缺陷"**：**回归判据**（当前版本上量）≠ **归因判据**（必须钉住版本与前置状态）⇒ 用它当后者结论会与真因相反（真发生过）。★ 做归因前先写清"这条判据能区分哪两个假设"。
10. ★★★ **先判掉"采样混叠"，再谈结论**：单次采样在**周期性**系统上可能是**确定性的**（实测 `period=1` 遇上跨 8 拍事务 ⇒ 连采 10 次得 `[2,1,2,1,…]`，窗口真实占 ~50% 却报"0/6 轮在飞"）⇒ **burst 采样**（连采 3 次取任一命中）；"覆盖不到"判 **SKIP** 不是 FAIL（**误报会被自己人关掉**）。
11. ★★ **判据发射器必须命名为 `record(...)`**（仓库约定，E 类闸门按它找判据）。用 `ok(...)` ⇒ 闸门判"判据不存在"。★ **那不是误报**：追不了 = 闸门白建。
12. ★★ **提交信息/注释必须描述"代码里实际是什么"**，不是"我要求了什么"⇒ 写前先 `git diff --cached`。
13. ★★★ **别在测量期间做别的事**：命令通路是**上位机墙钟**定时的 ⇒ **你加载 CPU = 直接改变被测对象**。实测同一条 `roundtrip`：忙时累积 **−11.69°**、空机 **−0.79°**（**单调**）⇒ 跑"复现性/时序"类判据时**机器必须空**。

## 十、装置属性与"会响的失败"（2026-09-17，GAP-13 P0 落地时补）

**10.1 ★★★ 装置属性（极性/行程/限位逻辑…）必须"显式声明"，且未声明就 fail-closed。**
- 工业做法：**硬件跳线/DIP**（雷赛 DMC2210 有"板卡跳线设置"专章；ADLINK 限位 NO/NC 用板上 DIP）
  或**工具配置存卡**（ADLINK `8132.cfg` / ESI / CiA 301 `0x1018`）。
- ⇒ 在 `CMakeLists` 里做成**三态**（`-1` 未配置 / `0` / `1`），**写进 `build.sh` 的交付 DEFAULTS**，
  并出现在"生效开关(读自 CMakeCache)"清单里 —— **可见**才算声明。
- ★ **未声明 ⇒ 拒绝使能（NAK + 原因）+ 落回物理失能**。理由：现在默认值本身就是"对硬件的假设"，
  而**"看起来接受了，其实跑错"是三者里最坏的一种**（无报错、只有值是错的）。
- ★★ **"使能/失能"这两个词在极性未声明时是没有定义的** ⇒ 那一档只能用**物理**语言
  （`drive_opto(conducting)`），**不能**走按 `pol` 翻译的函数 —— 否则会算出**相反**的电平，
  fail-closed 反而把驱动器通了电（我在 P0 里真犯过）。
- ★★ **"安全态"要分两问**：**按器件**（导通=失能？取决于驱动器）与**按轴**
  （停止后要不要保力矩 —— **垂直轴去使能 = 掉力滑车**）。两者正交，不要用一个量表达。
  ⇒ 上电/停止态由 `stop_hold`（按轴）决定；极性只决定"**怎么**通电"。

**10.2 ★★ 判"物理状态"必须看引脚实读（`IDR`），不看逻辑位。** 逻辑位（`ena`）会在真实状态上**说反话**，
且**不是恒 0/1** ⇒ 不满足"空判据"特征 ⇒ 没人怀疑。⇒ 把**"指令 vs 实读"不一致**做成**计数器**
（对齐运动卡 `SVON` 输出 + `RDY` 输入 / PLCopen `MC_Power` "等 Statusword"）。
★ 核对必须放在**主循环**（引脚由 DO 面在**拍上**写入；在写函数里立刻比会**必然误报**），并做**连续 2 次**去瞬态。

**10.3 ★★ `pyocd reset` 之后有一段"偶发停答、会自愈"窗口**（3/3 复现）：reset 后立刻 `0x38` TIMEOUT，
显式 `go` 也**不能马上**恢复，**~5~10 s 自愈**（`SUPPORTED-SCOPE` §4 记的"静置 ~60 s 会自愈"同族）。
★ 判"板子死没死"用 **SWD 读 `g_tick_count` 两次**（在变 ⇒ CPU 在跑 ⇒ 是协议面的事）。

**10.4 ★★ 三个审计工具共用的一处老缺陷：裸 `serial.Serial` 不释放 DTR/RTS ⇒ 把板子按在复位上。**
血证 2026-09-11 就记过；2026-09-17 才发现 `h723_motion_probe.py` / `h723_stepper_motion.py` **一直**没跟上
⇒ 一律用 `h723_modbus.open_serial()`（它把"释放复位"变成结构事实）。

**10.5 ★★★ 回归必须装"前置条件闸门"，否则前置没满足会伪装成"一片回归失败"。**
血证：**SD 卡未被识别**（`g_sd_part_ok=0` / `g_sd_rca=0` / `g_sd_init_stage=5`，**SWD 读 RAM** 得到）
⇒ `0x49 PROG_ERASE` 失败 ⇒ **bench 态建不起来** ⇒ 25 套件整片红 —— 而那些红**不是回归**。
⇒ `tools/h723_full_regress.sh` step 0 现在：`0x49` 必须 ACK（重试）+ 复位后**耐心轮询 70 s** + 用
**`0x38` 的 `r[22]=run`**（代码里唯一权威处）判 bench，任一不满足就 **exit 1 并给排查指引**。
★ 同族：**"覆盖不到/前置没满足"必须判 SKIP 或中止，不许变成 PASS，也不许变成一堆红。**

**10.6 ★★ `docs/claims.md` 的 E 类闸门按"含 `record(` 且含证据串"的那一行找判据** ⇒
**用 `print` 说出的结论不算判据**。★ 那不是误报：**契据追不到判据 = 闸门白建**。

**10.7 ★★★ 别在"传感器的噪声底"上做等值比较 —— 那是一条必然间歇误报的判据。**
血证（2026-09-17，**两处副本**）：`i2c_sm_test` J1 与 `i2c_gate_test` G3 都断言"**状态机读数 == 阻塞路径读数**"
**逐位相等**，而两次读**不同时刻** ⇒ 在 **±0.5 LSB**（AS5600 1 LSB = 0.0879°）上比较
⇒ 回归里报 `读数=937 vs 阻塞=936`（**差恰好 1 LSB**）。
⇒ 处方：**按传感器的物理噪声底给容差**（±1 LSB），并在判据里写清"**为什么这不会放过真缺陷**"
（串 lane / 字节序错会给出**远大于 1** 的差）。
★ 一般化：**"等值"是一种把噪声底当阈值的写法** ⇒ 任何跨时刻/跨通道的一致性判据都要先问
"这两个量的**物理分辨力**是多少"。同族：`while(odr!=idr)` 式忙等、按字节数判内容。

**10.8 ★★★ `stop_hold`（按轴保力矩）的三条实践规律**
1. **上电/停止态由它决定，与极性正交**：`hold=1` ⇒ 静止态**通电**（垂直轴必须）；
   `hold=0` ⇒ **断电**（水平空载用，省热）。★ 实测电气后果：`hold=1 ⇒ IDR(GPIOE)=0x0F00`（PE9=1=通电）/
   `hold=0 ⇒ 0x0D00`（PE9=0=断电）。
2. ★★★ **"上电即通电"是最容易被当成故障的正常状态**：表现为 **嗡嗡响（斩波）+ 发热（保持电流）+
   轴不动（无脉冲）**。三个现象**同一个物理状态**。⇒ 现场看到这三件，先问 `hold` 与 `PE9`，
   别先怀疑驱动器/接线。（不是故障 —— 但**空载台架没必要**。）
3. ★★ **改这类"策略量"必须立即作用**（否则就是"看着设了、其实没设"）：
   `step_set_stop_hold()` 原来只改 `g_step_stop_hold` 就返回 ⇒ 引脚不变（实测 `sub=12 arg=0` 后 `PE9` 仍为 1）。
   修法：**若当前无脉冲（处于静止态）⇒ 立刻按新策略重算**。
   ★ 凡"改了之后要等下一次事件才生效"的配置，都要问：**这次算不算已经生效？**

**10.9 ★★ 判断"轴到底动不动"要用"**方向口径**"对齐，否则会报出 −199.4% 这种假数。**
血证：`longrun` 的理论值**恒取正**，而套件不设 `dir` ⇒ 接着 `dir=1` 的命令跑时实测为负，
于是报"偏差 **−199.4%**"（实测 −894.7° / 理论 900°）。
⇒ 处方：**按实际 `dir` 取符号**（本项目既有纪律："凡方向/极性/符号，一律实测再写死常量"）。

## 十一、③层（DCL 程序）与"让程序驱动外设"（2026-09-17，PLAN-step-motion-v1 落地时补）

**11.1 ★★★ ③层的输出面只有 `wire[]`** —— `tools/dclc.py` 的 `OUTPUT <name> TO <dst> FROM <sig>`
**只接受 `wire[<n>]`**；写 `TO actuator[12]` **直接编译失败**。
⇒ 任何"让 DCL 程序驱动外设"的设计，**载体只能是 `wire[]`**（"谁读它"由服务方决定）。
⇒ ★★ **`WIRE` 是"热端"**：bench profile 的 128 条路由**覆盖全部 128 个 WIRE 槽**
⇒ 判"程序面"的结论必须**在已部署本程序（或引擎 STOP）的状态**下做，不能在 bench 态做。
⇒ ★ 槽归属契约：**服务方保留的槽，程序内必须只有一个写者**（判据要能查）。

**11.2 ★★★ `dclc` 的自动分配上限 = 64（`wire[0..63]`）** ⇒ **固件保留的观测/镜像槽必须 >63**。
实测被抢：`LT lo = wire[16]`、`LOGIC drive = wire[17]` ⇒ 引擎每拍覆写 ⇒ 镜像失效。
★ 而**被 `OUTPUT` 显式钉住的槽安全**（编译器的"先钉后配"会跳过它们）。

**11.3 ★★★ `0x20 READ` / `0x23 WRITE_BURST` 要的是【绝对地址】= `g_shm + 偏移`，不是 SHM 偏移。**
传偏移 ⇒ `NAK "bad addr"`。★ `g_shm` 从 `0x38` 的 **+23**（非对齐打包）读。
★ 血证：回归闸门里那句"读 `n_routes`"**一直返回 -1** 的真因就是它 —— 看起来像"读不到"，
其实是**地址口径错**。**"读不到"要先怀疑自己的地址/格式，不要先怀疑固件。**

**11.4 ★★★ "值相同 ⇒ 不做"是危险判定 —— 切换上下文时必须让缓存失效。**
血证：运动服务的"请求值缓存"是函数内 static，**切换运动源/重新部署不清** ⇒
"上次请求"与"这次请求"相同 ⇒ 判"无变化"⇒ **什么都不做** ⇒ 表现为"程序在写槽、硬件一动不动"。
★ 与"重放旧表被静默忽略（`req_seq` 撞号）"**同一族**：**把"值相同"当成"无事发生"。**
★ 注意：判"变化"应比 **请求值 vs 上次请求值**（不是 vs 硬件现状）—— 否则"限时到期自动停脉冲"
会被服务**立刻拉回来** ⇒ 安全网失效。

**11.5 ★★★ 驱动+电机有"最低有效频率"，远高于 TIM3 的 15 Hz 下界**（实测）
15 Hz 下 `rate=15 / CC1E=1 / PA6 确实在翻转`（脉冲真的发出去了）而**轴纹丝不动**（`raw` 只有 ±1 LSB）；
同一块板 500 Hz 长跑 **−0.0%**。**脚手架直控 15 Hz 同样不动** ⇒ 与"程序面"无关。
⇒ 后果：**P 控制在小误差时把频率压到下限 ⇒ 电机不动 ⇒ 闭环卡住**。
⇒ 处方：`hz_min` 取**实测可用下限**，或误差带外做 **bang-bang**。
★ 与审计 **D3**（"限时字段有不可用下界"）**同一族**：**"字段有不可用下界"在本项目是反复出现的形态。**

**11.6 ★ 编码器槽位**：`sensor[0]` = **raw（0..4095）**，`sensor[1]` = **角度（0..360）**
（`src/as5600.h` 的 `AS5600_SENSOR_RAW/DEG`）。
★ 血证：用 `sensor[0]` 当角度 ⇒ `err = -742`（140 − 882）—— **量纲错会给出"完全不可能的物理量"**，一眼可辨。
★ 顺带：`examples/h723_pid_demo.dcl` 的注释写"`sensor[0]` **不被任何组件回填**"**已失效**
（AS5600 正在回填它）⇒ 该例程的设计前提不成立。

**11.7 ★★ `h_device_desc()` 是 ackbuf 闸门的盲区**：它用**变量偏移** `put16le(r + k, …)`，
而 `tools/h723_ackbuf_check.py` 只认 `ack(r,<数字>)` 与 `put32(r + <数字>)`
⇒ 该函数**不受闸门保护，缓冲大小只能靠人数**（本次已从 64 扩到 96 并注明最大 k=66）。

**11.8 ★★★ 过闸门**绝不用管道** —— 管道会把闸门的退出码换成最后一个命令的。**
血证（2026-09-17，**我第三次踩同族**）：`python tools/ref_claims_check.py 2>&1 | tail -4 && git commit …`
⇒ **管道的退出码是 `tail` 的（恒 0）** ⇒ **闸门判红，`&&` 照样往下走，照样提交了**。
★ 与 §3.2 记的 `build.sh | grep … && flash`（烧了旧镜像）**同一条**。
⇒ 处方：**先重定向到文件、再单独读**：
`python X > /tmp/g.txt 2>&1; RC=$?; tail /tmp/g.txt; [ "$RC" = 0 ] || exit 1`。

**11.9 ★★ "位带别名"是个陷阱：它让"写同一位"看起来像"可重复的计数动作"。**
血证（2026-09-17）：我提出"`TIM3 UEV → DMA(NDTR=N) → 目的 = `TIM3_CCER.bit0` 的位带别名
`0x42008400`` ⇒ 搬满 N 次硬件自己清 `CC1E`" 并写进了 README + commit。
★ **错**：**每次搬运写的都是同一位** ⇒ **第 1 个脉冲就把 `CC1E` 清掉** ⇒ 只走 1 步。
⇒ 一般化：**"N 次搬运"只有搬"不同的位置"才有累积语义**；搬同一位 = N 次同一个动作。
★ 教训：**方案要"从第 1 次执行推一遍"**，不能只推"最后一次落在哪"。

**11.10 ★★★ "走 N 个脉冲自停"的正解 = 让<另一个定时器>硬件数脉冲（零中断/零DMA/零ITCM）。**
```
TIM3_CR2.MMS = 010                        # TRGO ← 更新事件 UEV（只改这 3 位；对 PWM 输出无影响）
TIM4_SMCR   = SMS=111(外部时钟模式1) | TS=010(ITR2)   # ★ ITR2 = TIM3
⇒ TIM4_CNT 每来一个 TIM3 UEV +1  ⇒ **它就是"已发多少脉冲"**
```
- ST ITR 表（TIM4 行）：`ITR0=TIM1 · ITR1=TIM2 · **ITR2=TIM3** · ITR3=TIM8`
- ★ **候选筛选**：**TIM2 = 拍定时器**、**TIM5 = 交付档时基** ⇒ **都不能用**；**TIM4 空闲** ✓
- TIM4 **不用任何通道引脚** ⇒ GPIO 不用配；只需 `RCC_APB1LENR_TIM4EN`
- **TIM4 是 16 位** ⇒ 单次上限 **65535 步**（40.9 圈 @1600 步/圈），超出**明确钳位**
- 到点由**主循环**停 ⇒ 多走 ≤1 圈；★ **但 `TIM4_CNT` 精确记录实际步数 ⇒ 是"已知量"不是误差**
- ★ 三个计数必须分开：`done`（到点）/ `abort`（被限时或停机打断）/ `rej`（被拒）
  —— 合并成一个就回答不了"这次是走到了还是被打断了"
- ★ v2 硬件精确停：`TIM4` 的 CC 比较事件 → **一次 DMA** 把 0 写进 `TIM3_CCR1`（普通 DMA，**不需要 MDMA**）

**11.11 ★★ 判"计数器准不准"的容差口径：那是"起止时刻对不齐"，不是计数误差。**
`step(N)` 下发生效要一次命令往返（p99 56.8 ms），"到点停"由主循环做（≤0.37 ms）
⇒ 500 Hz 下 250 ms = **125 步**。⇒ 判据只能取"**两条独立路径（硬件计数 vs 编码器换算）
都落在 [N, N+容忍] 且互相差 ≤ 容忍**"，**不是逐位相等**。
★ 要逐位对齐必须让计数器与编码器**同时起止**（v2）。**别把"时刻对不齐"误判成"计数错"。**
