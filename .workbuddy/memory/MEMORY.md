## 一、★★★ 架构使用规约（**强制**，用户要求写入 memory）

**一句话：用这个系统 = 写 DCL 程序；不是改固件。** 固件（引擎核心）是平台，烧录=换机器；DCL 程序是资产，走通信上传 + SD 持久化。

### 1.1 四层与"该放哪一层"
```
① 引擎核心  烧录        改它 = 换固件(必走 A/B + 12 套回归)
② 外设能力  随核心版本化 + 能力位声明；做成"通用事务 op"(I2C/SPI/UART) + 具名设备, 非"每芯片一条命令"
③ DCL 程序  通信上传 + 持久化(SD)
④ 程序工程  上位机侧: .dcl 源 + 清单 + 编译产物
```
| 问题 | 放哪层 |
|---|---|
| "**怎么算**"（逻辑/连续/顺序） | ③ 程序 |
| "**和外设怎么说话**" | ② 外设能力（通用事务 op/具名设备），**不是**新驱动 |
| 需要**新的每拍行为 / 实时保证** | ① 核心 |
| 只是"**给上位机看的量**" | SHM + `obs_anchor()` 登记，**不是**加协议 op |

### 1.2 实验七条
1. **观测先走协议内通道**：`0x38` / `0x22 READ_BURST` / SHM；pyocd 是最后手段。
2. **控制先走程序面**：`0x10 DEPLOY` + `0x11 START`；不要直接怼寄存器"模拟"。
3. **要新能力先判层**（1.1）。**不要默认改固件** —— I2C 那次弯路就是这么走的。
4. **每拍动作 → 引擎/ISR；服务性动作 → 主循环**。★★ 别把实时量挂主循环：主循环一圈实测 **1.28~1.54 ms**，拍是 100 µs。
5. **实验代码独立成 patch**：`docs/exp-<日期>-<主题>/`；**交付物里不出现实验脚手架**。
6. **运行期改动复位即恢复**；**不得污染持久化配置**。
7. **每条判据都要能失败**，配对照（A/B 构建或对照配置）证明它会红。

### 1.3 pyocd 纪律
- ★★★ **pyocd 会话退出 ⇒ 调试域断电 ⇒ `CYCCNTENA` 被清 ⇒ `DWT_CYCCNT` 冻结在 0**。
  ⇒ 凡 DWT 派生的观测量**用前必须 `0x39 op=7` 重新校时**（返回两次 CYCCNT，Δ=0 判无效）；凡 DWT 派生的判据**必须含"时钟在走"**，否则是永远通过的空判据。
- ★★ **读固件全局量前绝不能 `-c reset`**（启动清零它们 = 自毁证据）。
- 只读观测面用 **`connect_mode=halt`**（挂核不复位）；`attach` 在某些 CMSIS-DAP 上初始化不了 AP。**收尾必须 `-c go`**。

### 1.4 用标准化操作替代"影响系统"的操作
| 禁止 | 标准化替代 |
|---|---|
| pyocd 直写 GPIO 摇引脚 | `0x39 op=19 sub=7/8`（静态电平探针，可回读 `IDR`） |
| pyocd 改 TIM3 试频率 | `0x39 op=19 sub=1`（报**实际**频率） |
| pyocd 读全局量 | `0x38` + `0x22 READ_BURST`（走 SHM） |
| 为看一个量加新协议 op | 进 SHM + `obs_anchor()` |
| 反复 start/stop 把电机停某处 | 固件内**定长/定位原语**（D4，待补） |
| 改固件支持新传感器 | ② 层外设能力 |
| 直接改持久化扇区 | `0x43 PERSIST`（**当前 NAK**）→ 改走 SD |
| 用"无脉冲时引脚电平"判有无脉冲 | ★ 必须 `CC1E=1` 时判且看 `IDR`（AF+`CC1E=0` 时引脚高阻） |

### 1.5 三条红线
1. **程序里不得出现任何物理引脚号或总线地址**（IEC 61131-3 / CODESYS / Zephyr 三边一致）。
2. **不得破坏单写者**：同一 SHM 槽、同一张卡只允许一个权威写者。★ 已两次踩到：`TIM3` 两个驱动者（门守一处漏一处 → C1）；**SD 卡两个写者**（日志从 LBA1 回卷 + `sd_dump_write` 写 LBA3000000，落在日志区内）。
3. **不得把实时量挂在主循环上。**

## 二、DCL 程序持久化（2026-09-16 打通，全链实测通过）

**链路**：写 `.dcl` → 编译 → `0x45/46/47` 上传 → SD A/B 双副本 → 上电自动装载（不碰 flash）。实测 `上传→复位` ⇒ `boot_loaded=1`、`0x38 n_routes=7 applied=1` ✓
- `0x45` BEGIN / `0x46` DATA / `0x47` COMMIT / `0x48` STATUS(96B) / `0x49` ERASE / `0x4A` DEVICE_DESC
- ★ **`0x48` 96B**：+52/+56/+60 = `txn_begin/commit/abort`；+64..76 = 开机装载结果；+80..92 = 从卡读回的载荷头 ⇒ **验收全走协议，不需 SWD**。
- ★★ **"不能上传漏错"五道闸门**：① 帧 CRC16 ② 清单 CRC32+total_len ③ 写后回读 memcmp ④ A/B + 单调 seq ⑤ **装载时再跑同一套静态校验**（`prog_validate`，上传与装载共用一份实现）。
- ★ **发布前必做"运行态 vs 持久态"对账**（曾出现引擎跑 `nr=2`、卡上却是 `nr=128` 测试残留）。

### 2.1 ★★★ AXI 真实地图（320 KB **已用满**）—— 加缓冲前先看这张表
| 区间 | 占用者 |
|---|---|
| `0x24000000`–`0x24000600` | 诊断结构固定区（`SD_DIAG`/`BB_DIAG`/`SD_CFG`/`BOOT_AXI`）；**协议 `0x20 READ` 放行窗口** |
| **`0x24000600`–`0x24003000`** | ★ **唯一空档 ≈10.5 KB**（`s_pay`@0x24000800, `s_blk`@0x24002800） |
| `0x24003000`/`0x24003100` | MDMA 锁存快照 / 链表节点 |
| `0x24004000`–`0x24040000` | 黑匣子环（**`BB_SLOTS=960`** × 256 B = **240 KB**） |
| `0x24040000`–`0x24050000` | 日志冻结区 `SD_STAGE` |

★ `prog_store.c` 有**构建期 `#if/#error`** 守空档。★ `blackbox.h` 原注释"AXI 完全空闲/128 KB/512 槽"**三处全过期**，已更正。

### 2.2 SD 分区（`sd.c`）
`LBA0` 日志头（`h[112]=LOG_END`, `h[113]="LEND"`）· `LBA1..LOG_END` 日志环 · `g_sd_prog_a..+15`/`g_sd_prog_b..+15` 程序 A/B · `LOG_END = capacity-1-32`
- ★ **绝不升 `LOG_VERSION`**（升了 `sd_log_open` 当新卡重建 ⇒ 从 LBA1 覆写毁卡）。
- ★ **`s_log_blk` 必须钳位**（旧卡游标可能超新上限 ⇒ `cap_data - s_log_blk` 下溢 ⇒ 写飞出卡外）。

### 2.3 四个坑（**同族：都是"半个对齐"或"过期注释"**）
1. **`sd_read_block` 不许按 HAL 骨架"半对齐"重写**（把 IDMA 换成手工排 RX FIFO ⇒ **数据是错的** ⇒ 日志头读不对 ⇒ 当新卡重建 ⇒ SD 路崩）。⇒ **保留 IDMA 原实现 + 两处最小修复**：**只认 `DATAEND`（不认 `DBCKEND`）** + **读完后把数据通路关干净**（`SD_DCTRL &= ~DTEN` → 等 `DPSMACT` 落 → `SD_ICR = STA_STATIC`）。
2. **SD 源缓冲必须在 AXI**：SDMMC 的 **IDMA 读不到 DTCM**（TCM 端口不在 AHB 矩阵上）。★ 外设 DMA 能到哪块内存**按外设成立**，不能类推。
3. **`SD_TMOUT_DATA` 不许往小里挤**（200 万 ≈ 250 ms，而 128 块批写+卡内编程常超它 ⇒ 正常写被判超时 ⇒ 日志停摆）⇒ **超时给够 + 调用方声明阻塞窗口**（`block_window_begin/end`）。
4. **"当前完全空闲"这类注释活不过两周**：容量类断言要么 `_Static_assert`，要么集中成唯一地图。

### 2.4 ★★ 两条方法学铁律
1. **`pyocd halt` 会把核留在停住状态** ⇒ 据此得过一整串假结论（"tick 冻结/ISR 死了/cmd_count=0"），干净 `pyocd reset` 后不发 halt 立刻全好。**协议能读的一律用协议**。
2. **构建闸门不要用管道把门**：`build.sh | grep … && flash` ⇒ `grep` 退出码掩盖构建失败 ⇒ **烧了旧镜像**并误判一轮。用 `$?` 或先落盘再判。

## 三、测试仪器纪律

**3.1 逻辑分析仪（Original Logic）**：网格 16 MS/s ⇒ 62.5 ns、24 MS/s ⇒ 41.67 ns，**用时间戳整除性反推采样率**（不能猜"最小相邻间隔"，那值可能是 37 µs）。`wait_capture` 报 `ReadTimeout` 时数据**往往已拿到**可照常 export，**但要检查完整性**（出现 37.7/61.1 µs 异常短间隔 = USB 丢数据，该档作废）。2 通道可 24 MS/s；8 通道上限 12 MS/s；数字通道不支持可配阈值。

**3.2 四类假判据**：① **空判据**（观测量恒为 0/1：分支没被走到，或时钟没在走 ⇒ 永远通过）；② **形状判据 > 幅度判据**（证"事件被移动了"用"整段平移 50 µs"，不受噪声/量化影响）；③ **先判掉量化伪影**（直方图上间距恰等于采样网格的簇 = 量化，不是抖动）；④ **同一性对照**（A/B 两档先 sha 比对，再确认同一采样率）。

## 四、引擎与配置陷阱

**4.1 一个绑定跨两个寄存器 ⇒ 必须同一个函数改**：定时器 DMA 请求 = **路由（`DMAMUX1_Cn` 请求号）+ 门控（`TIMx_DIER` 的 `UDEx`/`CCxDE`）**，只改一半 ⇒ **静默失效**（读回全对、功能一动不动）。见 `main.c: trig_source_apply()`。★ 同族：以前是"一个常量两用"（请求上限≠响应上限），这次是"一个语义两处存放"。

**4.2 MDMA 通道寄存器只在 `CCR.EN=0` 时可写**（`CTCR/CTBR/CBNDTR/CSAR/CDAR/CLAR`，否则**静默忽略**）；清 `EN` 后**不能只靠写 `CCR` 重新使能** ⇒ 需完整重初始化或复位。

**4.3 ★★★ 输出锁存链的真实行为（实测，推翻原注释）**：`do.c` 写的"七级触发链 TIM2_UP→DMAMUX1→DMA2_S0→TC→MDMAMUX→MDMA→ODR"**不成立** —— `DMAMUX1_C8=0`+`DIER` 无 DMA 使能位、`DMA2_S0_CR.EN=0`、`CTBR.TSEL` 扫 0…15 三组否决全部**照常工作**，只有 `MDMA_CH0_CCR.EN=0` 会停。⇒ **MDMA 通道在自循环，不消费任何请求源**；**引脚时刻 = CPU 最后一次写影子 + 0.12 µs**（NOP 扫掠线性 3.9 ns/轮）。⇒ **"计算与输出解耦、引脚时刻由硬件锚定"当前未达成**（PE0 σ≈60 ns 中 ~45 ns 来自此环节）⇒ 让路/关黑匣子这类"分离两条时间线"的手段**注定无效**。

## 五、DO 输出路径定案 —— `DCL_DO_LATCH = 0` 是交付值

**0 档 = CPU 直写 `GPIO_BSRR`（一次 32 位写覆盖 16 路）**，σ = **1.4 cyc = 3.6 ns**（那次写就是写引脚）；
**1 档 = 影子 + MDMA 锁存**，σ = 5.2 cyc = 13.0 ns、**引脚抖动 ≈54~60 ns**（LA：PE0 σ≈60 ns / `PE0−PA8`=125±45 ns）。
⇒ 差约 15 倍，切 0 档**无功能损失**（BSRR 一次写同样是原子"输出帧"、输出沿还提前 ~300 ns，并消掉 ~350 万次/秒 AHB4 写与 MDMA AXI 链表流量）★ 因为"输出由硬件锚定"在 1 档**本来就不存在**（见 4.3）。1 档保留作对照。

- **抖动判据**：别用 LA 测 20~60 ns（网格 62.5 ns ⇒ 量化 σ 就 25 ns，档间 σ 还波动 40 ns）；要在固件里累積 `Σ(d−40000)`、`Σ(d−40000)²`（u64，`0x39 op=16` 读回）。★ 累積"偏差"而非 d 本身，避免大数相减损失精度。★★ **口径必须写清**：那次"写"写的是影子还是引脚。
- **两个编译期坑**：① **CMake 开关可能根本没接线**（注释称可被 `-DDCL_DO_LATCH=0` 覆盖，但 CMakeLists 从未 `set(...CACHE...)`+传 `-D`）⇒ 凡声明"可由 CMake 覆盖"的宏，必须去 CMakeLists grep 到接线。② **`#endif` 必须在函数收尾 `}` 之前**，否则报错落在文件末尾、很难查。

## 六、外设排障（TB6600 步进 / 光耦 / 时基）

**6.1 ★★★ 真因：共阳 + 5 V 光耦 + 3.3 V 逻辑 = 从根上不成立**：3.3 V 推挽的"高"**关不断** 5 V 光耦（链上仍有 `5−3.3=1.7 V` > LED 的 Vf）；**开漏也救不了** —— `DS13313 Rev 5` Table 7 里 **PE8/PE9 = `TT_ha`（3.3 V 容忍，非 FT）**，PA6 同为 TT 类 ⇒ 高阻被外部拉到 ~4.5 V，**超绝对最大额定值**。★★ **正解：光耦正端从板 5 V 改接板 3.3 V** ⇒ 压差 0 ⇒ 彻底关断且**保住 MCU 只做 sink** ⇒ **"共阳 + 3.3 V" 才同时满足"不倒灌"与"关得断"。** ★ 一般化：**"驱动能力够不够" 与 "供电域是否与逻辑高电平一致" 是两件事**。

**6.2 物理解线判据（最干净）**：★★ **"同一根线两端读数不同" = 断路**（`PA6` 与 `PUL−` 本该等电位却差 4.4 V）。**万用表 DC 档量方波 = 读平均值**（500 Hz/50% ⇒ ≈1.65 V）⇒ 判接线必须先把信号变**静态电平**（`0x39 op=19 sub=7/8` 把 PA6 从 TIM3 摘下来输出确定电平）。★ 判据要**成对读两档**才分得开"线断"与"LED 不导通"。★ PA6 网络名 `DCMI_PIXCLK`（板上有摄像头座）。

**6.3 这块 TB6600 的 `ENA` = 「光耦导通 = 失能」**（与多数相反）⇒ 极性必须实测（"无论 PE9 高低都失能 ⇒ 电机永远不转"，而寄存器读回全对）。★ 实测法：拔插 `ENA−` 看轴锁不锁。

**6.4 ★★★ 整数取整造成"时基失真"且随负载变化**：`dm = dt / 10u;`（`dt` ≈ 主循环一圈，不是固定 1 ms）。判据：**固定倍率的时钟错只能给恒定倍率**；倍率**随主机负载变** ⇒ 一定是"丢多少取决于负载"的机制。★ 修法：**限时存"目标拍号"，一次减法判到期，不做除法**（无取整、无累计误差、与主循环快慢无关）。★ 同处"**一个值两个语义**"：`0` 既是『不限时』又是『已到期』⇒ 小限时被吃光后变**无限跑** ⇒ 拆成 `armed`(bool)+`tick`(u32)。

**6.5 判据必须跟着可切换的极性走**："安全态 = `PE8~PE11` 全 1"在 `ENA 极性=1` 时**永远是错的** ⇒ 凡"极性可运行期切换"的量，判据要在**同一档极性**下求值，否则静默退化成空判据。★ 安全态判据用 **`IDR`**（引脚实际电平），不是 `ODR`。

**6.6 ★★ 栈越界在观测面上完全看不见 ⇒ 只能靠静态检查**：`h_pin_pattern()` 里 `uint8_t r[40]` 却写了 68 字节，不报错不崩，只写坏调用者的栈，且读回来的字段**全是合理值**。⇒ **凡"往 `r+offset` 写"的应答块，必须数一遍最大偏移 vs 缓冲区大小。**

## 七、Git 纪律

**7.1 通则**（源自 2026-09-14 一次 `.git` 损坏）
- ★★ **本仓库不要用 `git stash`**（`git stash push -- src/` 时 `.git/refs` 树 + pack 数据一起消失，报 "not a git repository"）。★ 任何 git 维护前先 `cp -r .git ../.git_bak_<日期>`。
- ★ 事故后第一步：**`git status`** + **读 `.git/logs/HEAD`（reflog 通常完好）** ⇒ 能告诉你"最后提交是什么""是否都已推送"。**只要都已推送，恢复永远无损。**
- ★ 提交用 **`git add <具体路径>`**，绝不用 `git add -A`；提交前 `git diff --cached --name-status`，提交后 `git diff --stat <上个提交> HEAD -- src/` 核验"源码一字未动"。
- 两远程：`origin`=H723PLC、`dcl`=dcl-controller，**都推**（`remote.pushdefault=dcl`）。

**7.2 ★★★ `refs/remotes/**` 在本机写不进去且静默返回 0**（2026-09-16 查清，环境级缺陷）
- 症状：`git fetch` 打印 `089fd97..1c20347 main -> origin/main`、`rc=0`，但 `packed-refs` 值不变、无松散文件 ⇒ **`git status` 永远误报 `[ahead 27]`**。
- 隔离实测：`update-ref refs/heads/x` 正常；`update-ref refs/remotes/origin/foo` **rc=0 且把 `origin/` 整个目录删掉** ⇒ **只有"写 `refs/remotes/**`"这一步静默失败。**
- ★ **判据：写完必须 `git show-ref` 确认真的落进去**；★★ **同步状态的权威判据是 `git ls-remote <remote> refs/heads/main`，不是 `git status`。**
- ★ **治标修法（本机唯一有效）**：手工写松散引用 —— `mkdir .git/refs/remotes/origin`（`dcl` 同）→ `printf '%s\n' <hash> > .git/refs/remotes/origin/main` → `git status -sb` 立刻变 `## main...origin/main`。

## 八、速查

```
bash build.sh                     # 零警告硬闸门 + ISR 调用树闸门
pyocd flash -t stm32h723xx -O connect_mode=under-reset build/dcl_h723.hex
pyocd reset                       # 之后串口 0x39 op=7 重新校时(DWT)
export PATH="/usr/bin:/bin:/mingw64/bin:/c/Windows/System32:$PATH"   # shell 初始化脚本坏了, 必须显式 export
```
- ★ 串口**按能力字认**（两个 CH340，认能力字 **0x0DF7**，别取"第一个 CH340"）；历史上 COM18，步进台架那次 COM21。
