## 速率实测 (`tools/mb_rate_test.py`) —— 能不能跟上 100µs / 1ms 节拍

**115200 8N1 的时间预算**（字节时宽 86.8µs, 线速 11520 B/s）:
| 量 | 值 |
|---|---|
| 8B 帧 | 694.4 µs = **6.94 个 100µs 拍** |
| 8B 帧 + 必需帧间隔(3.5 字符=303.8µs) | **998.3 µs ≈ 恰好 1ms** |
| 8B 往返 + 帧间隔 | 1692.7 µs |
| 每 100µs 拍最多 | **1.152 字节** |

**实测**:
| 项 | 结果 |
|---|---|
| 单向灌满 (PC→板子, 帧间零间隔 5s) | **11540 B/s = 线速的 100.2%** ⇒ 物理上限已被打满 |
| 流水线往返 8B↔8B (PC 侧) | mean **3.933 ms** ⇒ **254 次/秒** |
| 双向字节率 (8B↔8B) | PC→板子 2035 B/s = 板子→PC 2035 B/s **(完全对称)** |
| 非对称载荷 8B→133B | 446 B/s vs 7418 B/s ⇒ 差异**纯粹由载荷大小决定** |

**★ 归因 (必须说清, 否则会低估链路)**: 线上理论往返只要 1.69ms, 实测 3.93ms,
多出的 **2.24ms 是 PC 侧 USB 开销**(CH340 的 1ms USB 轮询 + 驱动栈 + pySerial reset/flush),
**不是链路能力**。⇒ MCU 直连时往返应逼近 1.69ms ⇒ 事务率 ~590 次/秒。

**结论**:
1. **100µs 拍: 做不到。** 一次往返 16.9 拍, 字节吞吐 1.152 B/拍 —— 连半条 8B 帧都完不成。
   差 15~17 倍。通信口**本来就不该跟控制拍对齐**(控制环 µs~百µs / 现场总线 ms 是 PLC 常规分层)。
2. **1ms 拍: 单向理论刚好卡住**(998µs/1000µs, 余量 2µs ⇒ 不推荐), **往返不成立**(1693µs), **2ms 才稳**。
3. **双向线速是对称的** —— 同一条半双工总线、同一波特率; 实测差异全部来自载荷大小。
   要对称就发对称载荷。
4. 若真要跟上 100µs 一次往返: 波特率需 **≥1.78 Mbaud**(当前 15 倍)。
   H723 侧没问题 (PCLK1=100MHz), **瓶颈在 USB-485 dongle**(CH340 上限 2 Mbps);
   2 Mbaud 时 8B 往返 ≈90µs, **刚好压线**。⇒ 本质上该换接口(SPI/CAN-FD/以太网)而不是提速串口。

★ 又一次"自造测量假象"的教训: 初版把 `1000.0/mean*1e3` 写成 `1000.0/(mean)*1e3`,
  打印出"256216263 次/秒" —— **数量级离谱的读数必须当场怀疑自己的算式**。
 (一次 ORE 都没有)**
- `USART2 CR1 = 0x2000000D` 由固件自己读回 ⇒ FIFOEN 确实生效

### ★★ 我上一轮的错误结论 (必须记住的教训)
"模块 TTL 侧接反" **是错的, 已作废**。它的依据是"485 收发器驱动总线时会**本地回显**到
自己的 TXD", 但**多数半双工收发器在 DE=1 期间会禁用接收, 本来就不回显**
⇒ "板子发时 PD6 不动"**不能**证明接错脚。
⇒ **教训: 判据所依赖的器件特性必须先被独立验证, 不能在推理里当公理用。**
  (这与 BRR"算得对但公式错"、TLE"ORE 未清"是同一条: 前提错, 推理再干净也没用。)

### 另修两个**测试工具**缺陷 (曾把正确行为判成 FAIL)
- `mb_master_test.py`: 写区地址少加 1 (`0x9C80`=40064 落只读区) ⇒ 固件的**正确拒绝**
  被读成"写不进去"; 且写只读区的异常判据写死 `0x83`, 而该项发 **0x06** (应为 `0x86`)
  ⇒ 该项**永远 FAIL**。
  ⇒ 同族铁律: 判据里写死的常量必须与"这一项实际发什么"对上。
�现路径: 干净固件里每轮扫描固定多出 1 字节 0x00 + 1 次 FE，一眼看出是自造的。
   修法: 恢复顺序 = AF 选择 → PUPDR 上拉 → **最后**才接 AF。
   ⇒ 通用教训: **诊断动作的"复原顺序"也会造出被测信号**；先置低（输入+下拉）后复原时，
     PUPDR 必须早于 MODER。
2. **扫 GPIOA 时不能边扫边打印** —— 观察窗 USART1_TX 就是 PA9，把它设成输入的那一刻起
   打出去的字全丢在空气里（第一版 16 行 PAxx 一行都没回来）。⇒ 采样结果先存本地、
   恢复之后再统一打印。
3. `build.sh` 的"生效开关"清单正则 `[A-Z_]*` **不含数字** ⇒ `DCL_MIN_UART2` 漏列。
   而这一段的目的正是"别被 CMake 缓存骗"，漏一个开关就是留一个静默洞。已修为 `[A-Z0-9_]*`。
