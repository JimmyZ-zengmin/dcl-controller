## ★ 方法论 (写进 README 与 skill)
- **频率/时序类结论必须用 LA 外部证据** —— SWD 在 CPU 跑不住时会失步,
  会给出完全错误的结论 (曾据此误判"300~340MHz 断崖", LA 实测 450MHz 正常)
- 用 SWD 读"运行态"寄存器前**不要先 reset** —— `pyocd reset halt` 会把 RCC 打回复位默认值
- 测频工具判据: 跳变数 < 200 一律判"没在跑"(否则少量跳变也会算出"正确频率")

## 阶段 1 完成 (提交 08dca52) — 拍定时器 + 空拍骨架

### 验收对照 (方案 §8 阶段 1) 全部达成
- TIM2 100μs 拍 (ARR=20000-1 @ TIMxCLK 200MHz) ✓
- DWT 测空拍 ISR: **min/max/last = 79/95/95 cyc**, 均值 94.99 cyc
  对照 S3: 49 cyc @240MHz = 204ns;  本平台 95 cyc @400MHz = 237ns
- ★**拍周期抖动 = 0 个 CPU 周期** (min=max=last=40000 cyc → <2.5ns)
  比 LA 的 62.5ns 分辨率更细 → 两条独立路径一致, NVIC 入口延迟恒定
- LA 外部复核: 100.0000us, 众数 96.1%, 偏差 0.000%

### ★★ 关键发现: flash 常驻 ISR 成本被"代码布局/取指"主导
- 同一份 ISR 的不同构建: 86 cyc (首版) / 79~95 (改 calibrate 后) / **98 (模式2, 删了10条统计指令)**
- **代码更少反而更慢** → 加 10 条指令的成本 < 对齐/取指波动
- ⇒ flash 常驻代码 WCET 在 ±10% 量级不可预测
- ⇒ **阶段 2 搬 ITCM 是必要性, 不是优化** (这是阶段 2 的核心假设, 待验证)

### DWT 标定 (证明计数可信)
- nop×1000 (noinline + volatile 计数) → 9050 cyc ≈ 9.05 cyc/迭代 (合理小整数)
- 读对开销 1 cyc
- ★**权威标定**: 拍周期 40000 cyc ÷ LA 实测 100.0000us = **400.00 MHz**
  → 内部计数频率被外部仪器独立确认 (比 nop 循环硬得多)

### ★ 踩坑 (已写进 README 纪律 6/7)
1. **默认 halt 连接在目标调试态异常时报 `No cores were discovered`**;
   `connect_mode=under-reset` 能恢复。读**运行态**统计必须**单会话**完成
   (连接 → reset → sleep → 读), 否则重连语义上等于从头开始
2. **产出 ELF 无扩展名**: CMake 目标是 `build/dcl_h723` (不是 .elf)
3. **`--gc-sections` 会回收无人读的全局** (`volatile` 也保不住):
   `g_isr_mode` 就这么从符号表消失 → 报告值改从源码解析
4. **nop 标定必须 noinline + volatile 计数**: 否则编译器把不同迭代数的循环
   优化成不同形状 → 首版 n=1000 得 1602cyc / n=2000 得 60007cyc, 差分算出
   58 cyc/迭代这种荒谬值
