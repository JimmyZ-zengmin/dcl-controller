# 运动剖面验收：测量口径的"逐级升级"

## 这个技能解决什么

你要判"它到底按命令转了没有 / 速度曲线的形状对不对"，但**判据反复给出矛盾或荒谬的值**
（例：算出 32812 Hz、跨度 429478 s、峰值 3.26×A、比值 1.309 既不像升也不像降）。
根因**几乎从不在硬件**，而在：**判据的速率/口径与被测量不匹配**。

★ 核心原则：**先判"这条判据能不能用"，再判"它通过还是失败"。**
不能用的判据要判 **SKIP（无效）**，绝不能判 FAIL —— 那等于把自己的估计器噪声当成硬件缺陷。

---

## 第 0 步：先写出"能失败"的判据，并把预测写在跑测之前

例：改前预测"0 相速度均值应随斜率变（≈0.575A）"⇒ 实测 686 ≈ 690 ⇒ **预测被定量命中**才算验证。
没有预测的"跑完看着还行"不是验证。

---

## 第 1 级：PC 侧差分测速 —— 默认**不可用**，先量它

- 采样 = 读协议帧的墙钟（实测 ~27 Hz）；被测量 = 编码器回填（实测 ~600 Hz~1 kHz）。
- **两者会拍频**：`Δt` 很稳（37 ms），而 `Δraw` 中位数只有 **2**（该有 123）、偶尔 230。
- ⇒ **极值/分位数全不可信**；唯一免疫的是 **`ΣΔ/总时长`**（累积量）。
- 判据若必须用极值/分位数 ⇒ **立刻升到第 2 级**，不要在 PC 侧调参。

## 第 2 级：片内黑匣子（在片环）—— 快，但**保留跨度 = 槽数 ÷ 变化率**

- 环是"**变化才记**"⇒ 跨度不是"槽数 × 拍长"（那会错 4 倍量级）。
  **跨度必须 `(tick[last] - tick[first]) / 频率`**。
- **记录率 ≠ 被测量更新率**：实测运动时记录率 ~2.5 kHz，而编码器回填只有 ~600 Hz
  ⇒ 逐记录的 `Δraw/Δtick` 是 **0 或 ~34 counts** ⇒ 算出 32812 Hz。
  ⇒ 速度必须用**滑窗累积**（窗宽 ≥ 一次回填间隔）；窗不够长时只剩累积量可靠。
- **槽位规则**：`slot = seq % 槽数`（可用 `(seq - slot) % N == 0` 验证）；
  但 `seq` **可能回绕** ⇒ **解码别按 seq 排序**（会切出假的不连续段，把 960 条看成 128 条）。
  正解：**按 `tick` 排序**；若时间轴出现非单调 ⇒ 说明 dump 混了多次上电。
- 容量不足的症状：**保留跨度装不下一个周期** ⇒ 形状判据只能判 SKIP。
  ⇒ 出路：**缩短待测周期** / 扩环 / 减少被记录的通道（后两者是改固件）。

## 第 3 级：SD 卡日志 —— 31 GB 大环，但有三个坑

1. **日志是"开机时"开的**：卡插晚/换卡后必须**显式重开**（本装置：写 `SD_CFG[8]=1` + 魔数）。
   ⇒ 症状：卡上扫遍都是空闲（**那几次运行根本没记**），而人会先怀疑"窗口在别处"。
2. **判"在不在记"的硬判据**：读"本次已写块数"（`s_log_blk` 一类）在**跑测前后的差**：
   `Δ>0` = 真进卡；`Δ=0` = 先去解决"没在记"，别分析卡。符号地址用 **`nm` 解析**，别抄 map。
3. **必须切上电段**：`tick`/`seq` **每次上电归零** ⇒ 跨段算时间会读出 429478 s（5 天）这种数。
   切法：`seq` 回减 **或** `tick` 倒退 ⇒ 新上电。然后**只判含目标的那些段**
   （★ 别盲取"最新段"—— 运动常发生在**上一次上电**里）。
4. 找窗口：先看**写指针涨了多少块**，再决定往回扫多远（别用固定值）。

## 第 4 级：**位置域**判据（形状问题的终解）

速度是**导数**、噪声大（本装置噪声底实测 **84~92%**）；位置是**积分**，平滑得多。
⇒ 形状判据做在位置上：

1. **解卷绕** `raw`（单圈计数 ⇒ 单调序列）：逐记录 Δ 远小于半圈即可安全解卷绕。
2. **半周期位移比**：`实测位移 / 模型位移`（模型 = 斜坡 A↔下限 + 平顶）。
   - ★ **必须按方向（升/降）分开报**：混着算中位数会给出**既不像升也不像降**的 1.309 ⇒ 假信息。
3. **斜坡窗二次拟合**：在**模型预测的斜坡窗**内拟合 `pos(t) = a·t² + b·t + c`，
   `|a|` 应 ≈ `slope × (counts/step) / 2`。
   ⇒ 这是"斜坡是否按声明执行"的**定量**判据（实测对照 0.40 → 交付 0.99）。

---

## 三个必备闸门（缺一个判据就会说谎）

| 闸门 | 做法 | 为什么 |
|---|---|---|
| **噪声底闸门** | 在"本该恒定"的区段量 `std/mean` ⇒ >15% 就**判 SKIP** | 否则把估计器噪声判成硬件缺陷 |
| **弱判别闸门** | 参数靠"反认"时，若各候选结果几乎相同 ⇒ **认不出就判 SKIP** | 别给一个"漂亮的 0.999" |
| **正对照闸门** | "期望为 0/小"的判据，先配一条"期望为大"的正对照 | 否则轴不动时它必然通过（空判据） |

## A/B 对照构建（结构性修复的唯一证据）

- 加**编译开关**（`DCL_XXX=1` 交付 / `0` 改前行为），并把它登记进构建脚本的"生效开关"清单。
- **对照档必须能编过**：新增的静态量/累加器要用同一 `#if` 包住，
  否则 `-Werror=unused-variable` 直接失败 ⇒ **"对照档编不过 = 没有对照"**。
- 判据两侧都要给：对照 **FAIL**（量到病）+ 交付 **PASS**（落回 1）。
- 烧录报 `programmed 0 bytes, skipped` **不一定是错误**（产物与板上固件逐字节相同）；
  但**"构建失败却烧旧镜像"是真事故** ⇒ **每步判构建的 RC**。

## 本装置已定案的坑（复用前先读）

- `rate_actual = 1e6 / floor(1e6/f)`：脉冲频率被量化到 1 µs ⇒ 定量结论**必须引 `rate_actual`**。
- **`hz == 0` 是"立即停"并绕过斜坡**（安全语义）⇒ 用 0 表达"该减速了"会拿到"停"；
  要做下降斜坡必须写**非 0 的下限**或阶梯序列。
- 斜坡推进若按"拍→ms 向上取整"算（`dt_ms=(dt+9)/10`）而主循环快于 1 ms
  ⇒ 实际 slew = 声明 × (1 ms / 主循环周期) ≈ **2.7 倍**。
  ⇒ 判据：**运动过程中连读斜坡态**（`rate_out` 几乎无中间值 = 没在爬）+ 位置域位移比。
