### 1.3 硬件差异策略 [R]

为了防破解，三型号必须用**物理不同的硬件**布局，不能只靠软件锁：

| 型号 | MCU | 封装 | 以太网 | 编码器接口 | 外部RAM |
|------|-----|------|-------|-----------|---------|
| SVD-2100 | STM32H723VGT6 | LQFP100 | ❌ 无 | AM26C32 差分收 | ❌ |
| SVD-2200 | STM32H723ZGT6 | LQFP144 | DP83848 工程口 | AM26C32 + DB9 | 可选 |
| SVD-2300 | STM32H723ZGT6 | LQFP144 | DP83848 + LAN9252 | AM26C32 + DB9 | ✅ W25Q64 |

> LQFP100 比 LQFP144 少 44 个引脚，即使抄板也无法焊上缺少的外设。这个差异不可绕过。
> R：但 H723VGT6 和 H723ZGT6 的 SDK 完全兼容，固件只需要改 pinmux 配置。

### 2.3 编码器接口定义 [C]

```
DB9 连接器 (母头, 驱动器侧):
  ┌─────┐
  │1   5│  1: VCC (+5V 编码器供电, 200mA max)
  │  ⬡  │  2: GND
  │6   9│  3: CLK+ (SPI SCK, 驱动器→编码器)
  └─────┘  4: CLK- (差分)
           5: DATA+ (SPI MISO, 编码器→驱动器)
           6: DATA- (差分)
           7: INDEX+ (增量式的 Z 信号)
           8: INDEX-
           9: SHIELD (接机壳地)

兼容:
  - BiSS-C (Siko EAM360, Tamagawa TS5700)
  - SSI (MA702)
  - 增量 TTL (AM26C32 直接接收)
  - 增量 1Vpp (需额外比较器电路, SVD-2200+)
```

**评估：** [C] 这个接口定义兼容三种编码器协议，AM26C32 处理差分→单端，剩下的 H723 SPI+DMA 直接读。不需要协议芯片。

## 3. 固件架构

### 3.1 MCU 资源分配

```
TIM1:       中心对齐 PWM — 6路互补 + 刹车输入
  CH1/CH1N: U 相
  CH2/CH2N: V 相
  CH3/CH3N: W 相
  BKIN:     COMP1 过流直驱
  TRGO:     OC4REF → ADC1 注入组触发

TIM2:       编码器模式 (增量) / 自由运行 (无编码器时)
  CH1/CH2:  编码器 A/B 相输入 (增量模式)
  UDE:      DMA 触发 (不关持续搬运用)
  
TIM3:       备用编码器接口
TIM5:       启动定时器 (32-bit, 秒级)
TIM6:       DMA 触发 (备用)

ADC1:
  注入组 (同步采样):
    IN1:      U 相电流 (INA240 输出)
    IN2:      V 相电流
    IN3:      W 相电流
    IN4:      DC Bus 电压
  规则组 (顺序采样):
    IN15:     温度 NTC
    IN16:     Vrefint (内部参考)

DMA1:
  Stream0:   ADC1 注入组 → DTCM_ADC_RAW (CIRC, 不关)
  Stream1:   SPI1_RX → DTCM_ENCODER (CIRC, 不关)
  Stream2:   TIM2_UP → SHADOW → SPI1_TX (编码器时钟)

DMA2:
  Stream5:   SHADOW → TIM1_CCR123 (不关持续输出)
```

**评估：** [C] DMA Stream 分配合理，DMA1 有 8 个 Stream 只用了 3 个，DMA2 只用了 1 个，冗余充分。

### 3.2 内存映射 [C]

```
DTCM (0x20000000, 128KB):
  0x0000-0x00FF:  ENGINE_REGION (引擎状态, ~256 bytes)
  0x0100-0x01FF:  DTCM_ADC_RAW (DMA 持续写入)
      ├─ 0x0100:   Iu (DMA 写)
      ├─ 0x0104:   Iv (DMA 写)
      ├─ 0x0108:   Iw (DMA 写)
      └─ 0x010C:   Vbus (DMA 写)
  0x0200-0x02FF:  DTCM_ENCODER (DMA 持续写入)
      └─ 0x0200:   编码器位置 (SPI DMA 写)
  0x0300-0x030F:  SHADOW (CPU 写, DMA 读)
      ├─ 0x0300:   SHADOW_CCR1 (U 相占空比)
      ├─ 0x0304:   SHADOW_CCR2 (V 相占空比)
      └─ 0x0308:   SHADOW_CCR3 (W 相占空比)
  0x0400-0x07FF:  PARAM_BLOCK (PI 系数, 限幅值, 只 CPU 写)
  0x0800-0x13FF:  STACK (3KB, 够用)
  0x1400-0x1FFF:  保留给未来功能

RAM_D1 (AXI SRAM, 0x24000000, 512KB):
  未使用——留给 MDMA 日志/批量数据处理

RAM_D2 (SRAM1+SRAM2, 0x30000000, 288KB):
  未使用——如有需要可放非实时数据
```

**评估：** [C] DTCM 128KB 只用了一小部分。ADC_RAW 和 ENCODER 的地址是 DMA 写的、CPU 读的——DMA 和 CPU 的端口物理隔离，零仲裁。

### 3.3 主循环结构

```c
// 伺服 V2.1 — 无中断连续计算主循环
// UIE=0 for ALL timers

void servo_loop(void) {
    while (1) {
        // 1. 读输入 (DMA 已写好的最新值)
        uint32_t now    = TIM2_CNT;                   // 1 cyc, 时间戳
        uint32_t Iu     = *DTCM_ADC_RAW;               // 1 cyc LDR
        uint32_t Iv     = *(DTCM_ADC_RAW + 1);
        uint32_t Iw     = *(DTCM_ADC_RAW + 2);
        uint32_t Vbus   = *(DTCM_ADC_RAW + 3);
        int32_t  pos    = *DTCM_ENCODER;               // 1 cyc LDR

        // 2. 安全检查 (每次迭代)
        if (Vbus > VBUS_OV_THRESH) { emergency_stop(); }
        if (Iu > IU_OC_THRESH)     { emergency_stop(); }  // COMP 已经硬件刹了

        // 3. 启动状态机
        switch (motor_state) {
        case IDLE:      check_enable();  break;
        case ALIGN:     do_align(now);   break;
        case OPENLOOP:  do_openloop(now); break;
        case CLOSED:    do_closedloop(pos, Iu, Iv, Iw, now); break;
        case FAULT:     do_fault();      break;
        }

        // 4. 通讯检查 (每 ~1000 次迭代)
        if ((TIM2_CNT & 0x3FF) == 0) {
            modbus_poll();
            check_remote_enable();
        }
    }
}
```

**评估：** [C] 结构清晰。无 ISR，所有定时器 UIE=0，CPU 占满 100%。通讯只在迭代间隙检查，不打断实时路径。

### 3.4 启动序列 [R]

无 ISR 的启动序列必须全部基于 TIM5 被动计时：

```
上电 → 初始化:
  1. 配置 TIM5 (32-bit, ARR=0xFFFFFFFF, 不分频 → 每 2.08ns 计数)
  2. 记录 start_time = TIM5_CNT
  3. 状态 = ALIGN

状态机 (CPU 在 while(1) 中检查 now - start_time):
  ALIGN (持续 100ms):
    → 输出固定电压矢量 (Ud=固定, Uq=0)
    → 电机轴自动转到已知位置
    → 100ms 后: start_time = now, 状态 = OPENLOOP
  
  OPENLOOP (持续 500ms):
    → 输出旋转磁场, 从 0Hz 到 10Hz 线性加速
    → 编码器开始输出有效位置
    → 检查编码器位置是否稳定 (连续 10 次读数单调)
    → 稳定后: 状态 = CLOSED

  CLOSED:
    → 正常电流环/速度环/位置环
    → 如果位置误差 > 阈值 → 回到 FAULT
```

**评估：** ⚠️ [R] ALIGN 持续 100ms 是传统方法，但 V2.1 的 CPU 在 while(1) 中每 50ns 迭代一次——ALIGN 状态下 CPU 会白白空转 100ms。这也太浪费了。

**缓解：** ALIGN 状态下 CPU 可以同时做通讯、参数自检、预热。100ms 不会是浪费的。
