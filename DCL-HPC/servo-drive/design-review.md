## 一、整体判断

**SVD-2100 (基础版 ¥499) 可行度：80%**

没有不可逾越的技术障碍。剩下的 20% 风险集中在：
1. 硬件打板回来调通（PCB layout 质量决定）
2. INA240 共模抑制在实际 PWM 开关环境中的表现
3. SPI + DMA 读编码器在 >1m 线缆下的信号质量

**如果今天立刻启动，6-8 周可以出第一个转起来的原型。**

## 三、关键风险深度分析

### 风险 #1：INA240 输出噪声 [R]

```
PWM 开关瞬间 (电流变化率 di/dt ≈ 1A/100ns):
  INA240 输入:        ┌─────────┐         ┌─────────┐
                    ──┘         └─────────┘         └──
                      ↑ 开关尖峰
  INA240 输出:         ╱╲
                     ╱    ╲
                    ╱        ╲───────────────
  ADC 采样时刻:                     ↑
                                   在 PWM 中点采样，避开开关瞬态

注入组触发: TIM1_TRGO (OC4REF)
  - 中心对齐模式下，OC4REF 在载波谷底和峰顶产生
  - 开关瞬态在死区结束后的边沿，离谷底/峰顶有 ~500ns 间隙
  - ADC 注入组在触发后需 371ns 才开始转换 → 实际采样点已远离开关瞬态
  - → 理论上安全
```

**缓解：** 在 INA240 输出加二阶 RC 低通滤波（100Ω + 10nF + 100Ω + 10nF），截频 ~80kHz。对 1-2kHz 电流环没有影响，对 16kHz PWM 纹波有 -40dB 衰减。

### 风险 #2：固件故障时 DMA 持续输出旧占空比 [R]

```
场景: CPU 检测到过流 → 写 SHADOW_CCR1=0
      但 DMA2_S5 正在 CIRC 运行:
        DMA 刚刚读走了 SHADOW_CCR1 (旧值, 高占空比)
        CPU 立即写了 SHADOW_CCR1=0
        但 DMA 要等下次触发 (1μs 后) 才会搬 0
      在这 1μs 内, 电机多受了一拍高占空比
      → 对于过流场景, 1μs 可能致命

解决方案: 故障时必须用硬件刹车, 不能等 DMA。
  INA240 → COMP → TIM1_BKIN: <100ns 硬件路径 (已经设计)
  CPU 检测到故障后的软件响应只是辅助, 不作为安全依赖。
```

**结论：** [C] 硬件刹车路径已设计，故障安全不依赖软件。

### 风险 #3：编码器 SPI 线缆长度 [R]

```
SPI @ 5MHz：
  时钟周期 = 200ns
  线缆 3m 往返延迟 ≈ 3m × 2 × 5ns/m ≈ 30ns
  延迟占时钟周期的 15%，在差分传输 (AM26C32) 下可以可靠工作。

但实际风险在于：
  - 电机线 (U/V/W) 和编码器线在同一个线槽内
  - PWM 开关产生的高频干扰 (10-50MHz) 会耦合到编码器线
  - 导致 SPI 数据位出错 → 位置跳变 → 电流环误判

缓解:
  1. 编码器线使用双屏蔽 TRVVP, 屏蔽层驱动器端接地
  2. SPI 时钟用差分传输 (AM26C32 收发), 不是单端
  3. 编码器数据加 CRC/奇偶校验 (BiSS-C 标准支持)
  4. CPU 读到的位置值做合理性检查: 连续两次差值不能大于 MAX_DELTA
```

**结论：** [R] 需要实测验证，没有理论上的死结。

## 五、结论

> **SVD-2100 (基础版 ¥499) 可以做。**
>
> 设计层面没有死结，所有评估为 [R] 的问题都有已知的缓解方案。剩下的只是执行——打板、焊接、写代码、调参数。
>
> 第一阶段目标不是"完美伺服"——是"确认 V2.1 架构在真实电机上能转"。8 周内让松下 50W 电机转起来，电流环带宽 >1kHz，Modbus 能通讯。这就够了。
>
> **第一步，买元器件。**
