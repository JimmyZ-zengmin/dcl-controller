# 伺服驱动器 — V2.1 连续电流环架构

> **本文件是 DCL-HPC V2.1 方向一（急速响应）的独立应用文档。**
> 方向一的完整技术方案：用 V2.1 连续计算 + DMA 饱和搬运实现高性能伺服驱动器电流环。
> 传统伺服电流环受限于 ISR 架构的延迟和带宽瓶颈，本方案**重新定义电流环性能边界**——ADC→PWM 延迟从 2-3μs 降至 ~50ns。

**关联文档：** [`连续计算架构 V2.1 — 多缓冲科研级控制.md`](连续计算架构%20V2.1%20—%20多缓冲科研级控制.md)（V2.1 基础架构，含三缓冲、DMA 子周期、MDMA 等公共机制）

## 1. 核心思路

**本质：不在乎输出时刻的精确度，在乎输入到输出的最短路径。**

传统伺服电流环的痛点：

```
V1.x: ADC触发 → 等待ISR → 压栈 → CPU开始算 → 算完 → 出栈 → 等下一个触发
                          ↑     ~8μs 延迟      ↑
```

V2.1 打破链条：

```
ADC 结果 → DMA → DTCM
       ↓
CPU 下一次迭代读到 ← 平均 2-3 CPU cycles = ~6ns
       ↓
  算 PI → 写 SHADOW
       ↓
DMA 下一次触发搬走 ← 受硬件定时控制，CPU 端零等待
```

**CPU 不再"等触发"**——传感器数据到 CPU 的时间 = 从 DMA 写完 DTCM 到 CPU 下一次 LDR 的时间。

### 1.1 "流式输出"——持续输出"还没算完"的结果

```
t0:     CPU 读到最新 ADC 值 → 开始算
t0+……:  DMA 触发输出 → 搬走 SHADOW → GPIO/PWM
        ↑ CPU 可能还在算! 搬走的是上次算完的结果 (旧值, 但最近)
t0+……:  CPU 算完 → 写 SHADOW (等待下一次 DMA 触发)
t0+1μs: DMA 再次触发 → 搬走新值
```

这等于**在每次 PWM 周期都输出"当前已知的最优值"**：

| 方案 | 电流环延迟 | 带宽 |
|------|-----------|------|
| 传统 V1.x 方案 | 一个控制周期 (100μs) | ~1.6 kHz |
| **V2.1 急速响应** | **ADC 转换 + 3-4 CPU cyc + PWM 周期 (≈4.3μs)** | **~37 kHz** |

**适用场景：**
- 伺服电流环 / 力控制 / 碰撞检测
- 传感器融合 / 状态观测器 / 高频扰动补偿
- 输入变化快、输出需要即刻跟上的任何场景

## 2. 伺服电流环实现

### 2.1 传统伺服电流环的痛点

```
PWM 载波 (10kHz = 100μs):
  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓
  ↑ 载波谷底              ↑ 载波峰顶
  ADC 同步采样             再次 ADC 采样

传统实现:
  ADC触发 → 等待中断 → 压栈 → FOC变换 → PID → 写CCR → 出栈
             ↑ 从采样到 CCR 更新 = 2-3μs 延迟
             带宽受限于"PI 计算耗时 + 等待时间"

典型电流环延迟: ~2-3μs  →  带宽 ≈ f_PWM / 10 ≈ 1kHz @10kHz PWM
```

**核心矛盾**：ADC 采样必须对齐 PWM 载波，但 PI 计算越快越好。ISR 架构强迫 CPU 等待下一个中断才能开始算。

### 2.2 V2.1 的实现方式

```
硬件布局:

  ADC1/2 (注入组同步采样 Iu, Iv, Iw)
    ↓  (每次 PWM 载波谷底触发)
  DMA1_Stream1 (不关持续搬运 → 写入 DTCM 固定地址)
    ↓
  [ADC_IUVW]  ← 同一地址, CPU 和 DMA 双端口并发
    ↑
  CPU 自由循环:
    while(1) {
        u = *ADC_IUVW;                  // 读到最新采样值
        if (u != u_prev) {              // 发现新数据
            idq = park_clarke(u, theta);
            vdq = pi_current(idq, ref);
            vuvw = inv_park(vdq, theta);
            *TIM1_CCR123 = vuvw;        // 写 PWM (影子寄存器)
            u_prev = u;
        }
        // 没新数据时: 继续空转检查其他任务
    }

  DMA2_Stream5 (不关持续搬运): 从 SHADOW 读 → GPIOE_ODR
```

### 2.3 关键问题与解决方案

**问题 1：FOC 需要三相同步采样**

```
Park/Clark 变换要求 Iu, Iv, Iw 在同一瞬间采样。

解决方案:
  - 使用 ADC1 的注入组 (Injected Group):
    ADC1_IN1=Iu, ADC1_IN2=Iv, ADC1_IN3=Iw
    单次触发→三个通道依次转换→结果锁存在 ADC1_JDR1/2/3
  - DMA 一次搬运 3 个 JDR (12 bytes)
  - CPU 从 DTCM 读到的是同一采样时刻的三个电流值
```

**问题 2：PI 积分项的 dt 自适应**

```c
// 错误用法（dt 不固定时）:
void pi_bad(void) {
    e = ref - *ADC_IUVW;
    i += e * Ki;            // ← 每次迭代 dt ≈ 50ns，但有时 200ns
    u = Kp * e + i;         // 积分累积速度随 CPU 负载变化 → 自激
}

// 正确用法（TIM2_CNT 提供真实 dt）:
void pi_good(void) {
    now = TIM2_CNT;                     // 1 cycle = 4.16ns
    dt_ns = (now - last) * 4167 / 1000; // TIM2_CNT → ns
    if (dt_ns == 0) dt_ns = 1;         // 保护

    e = ref - *ADC_IUVW;
    i += e * Ki_ns * dt_ns;            // 按实际时间缩放积分
    u = Kp * e + i;
    *TIM1_CCR1 = u;

    last = now;
}
```

CPU 每次迭代读 TIM2_CNT（1 cycle）替代了 ISR 提供的固定 dt。**PI 在数学上更精确**——不再假设采样周期固定，而是接受"上次到这次过了多久就算多久"。

**问题 3：PWM 更新时刻与载波对齐**

```
STM32H7 的 PWM 影子寄存器: 任何时候写 CCR, 当前载波不受影响
只在下次 UPDATE 事件 (载波谷底) 时锁存新值
→ CPU 在任何时刻写 CCR 都安全
→ DMA 不关持续搬运也不会导致 PWM 异常
✓ 完全兼容 V2.1
```

**问题 4：编码器位置读取**

```
对编码器数据的处理: 不需要中断, 用 DMA 持续轮询

  SPI/SSI 接口:
    TIMx CHy 触发 → SPI DMA 读编码器 → 写入 DTCM
    CPU 在循环中: 读 *ENCODER_POS → 算速度/位置→ 写 SHADOW
    
  增量编码器:
    TIMx 编码器模式 → 硬件自动计数 → DMA 定期搬 TIM_CNT → DTCM
    CPU 读 DTCM 中最新计数值即可
```

### 2.4 性能对比

| 指标 | 传统 ISR 伺服 (10kHz) | V2.1 连续伺服 |
|------|---------------------|--------------|
| ADC→CCR 最小延迟 | ~2-3μs (等中断+计算) | **~50ns** (下次迭代读到就算) |
| PI 刷新率 | 10kHz (受 PWM 同步限制) | **不限** (每 ~50ns 算一次) |
| 电流环等效带宽 | ~1-2kHz | **~10-30kHz** (受 ADC 采样率上限) |
| 速度环测量精度 | M/T 法, 固定时间窗 | **TIM2_CNT 精度**, ns 级时间戳 |
| 多轴同步 | 需额外硬件或软件同步 | **DMA 硬件触发天然同步** |
| CPU 利用率 | 间歇爆发 (~30%) | **连续 100%** (可以做更多计算) |

### 2.5 实际可达性能边界

```
受硬件限制的实际上限:

ADC 采样率:     双 ADC 交替, 每 1.67μs 一次 → 600k samples/sec
PWM 载波:       HRTIM 最高 100MHz → 10ns 分辨率
电流检测延迟:   ADC 转换 ~3.28μs + DMA ~17ns + CPU 读~5ns

→ 电流环等效最小延迟 ≈ 3.3μs (ADC→CPU→PWM)
→ 对应带宽上限 ≈ 48kHz (f_3dB = 1 / (2π × 3.3μs))

但实际中 PWM 载波通常 10-20kHz,
所以电流环更新的真实频率 = PWM 载波频率 × (每次载波算 N 次 PI)

每次载波算的 PI 次数:
  100μs / 50ns = 2000 次 PI
  → 每次 PI 使用最近一次 ADC 采样值
  → PWM 的 CCR 每 50ns 更新一次
  → 最终输出的是"当前时刻最优占空比"
```

## 3. 硬件选型

### 3.1 核心原则

V2.1 电流环带宽优势能否发挥，取决于一个关键硬件参数：**电机相电感**。

```
电流环带宽 ≈ 1 / (2π × L/R)

L = 电机相电感
R = 电机相电阻 + 功率管导通电阻

典型电机:
  普通伺服 (L=5-10mH)  → 带宽 1-2kHz  ← 传统 ISR 够用
  低电感伺服 (L=1-3mH) → 带宽 3-8kHz  
  超低电感 (L=0.3-1mH) → 带宽 10-30kHz ← V2.1 目标区
```

### 3.3 编码器选型（最关键）

V2.1 的编码器读取方式与传统伺服完全不同：

```
传统伺服:
  编码器 → 专用接口芯片 / ISR 中断 → CPU 读 → 解析协议 → 延迟 ~5μs

V2.1:
  编码器 → SPI/BiSS → DMA 持续搬 → DTCM → CPU 下次 LDR (50ns)
  ↑ CPU 的"读编码器"只是一条 LDR 指令，没有协议开销
```

### 4.2 核心差异

> **不是说 V2.1 的伺服"更好"，而是它在电流环延迟这个维度上，所有市面产品物理上不可能追上。**
>
> 台达 ASDA-A2 内部是 FPGA+ISR 路径，ADC→PWM 需要经过协议层、中断等待、FPGA 内部调度——最小延迟 ~10μs。
>
> V2.1 是 DMA 纯硬件路径：ADC 结果 → DMA 直写 DTCM → CPU 下一条指令读到 → PI 算完写 CCR → PWM 输出。
> 这条路径的延迟 = ADC 转换时间 + 几 ns 的 DMA/CPU 传输，**没有 ISR、没有协议栈、没有等待**。
>
> 代价：安全路径 (过流/急停/CE 认证) 需要外部硬件补充，不能靠软件。

## 5. 实施路线

```
Phase 0: 硬件搭建 (2 周)
  - 焊接 FSB50550AB 功率板 + 电流采样
```

## 附录：方向二参考

> 方向二（时间硬周期/精密脉冲模式）是同一硬件上的另一个独立维度，详见原始架构文档。
> **核心思路**：输出边沿的抖动由晶振+硬件定时器保证 (<1ps)，输出内容可以是不完整的旧值。
> 适用场景：激光振镜控制、精密脉冲发生器、多轴同步锁存——任何输出边沿精度 > 输出内容精度的场景。
